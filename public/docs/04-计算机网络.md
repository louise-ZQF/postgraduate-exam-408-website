# 计算机网络

<div class="study-unit" id="u-04-rewrite-intro">

计算机网络从物理传输逐层讲到应用通信，分析每层负责的对象、封装方式和协议过程，并明确公式的适用条件。

</div>

## 第一章 计算机网络基础

<div class="study-unit" id="u-04-rewrite-799de74fd21f">

网络通信把应用数据依次转换为传输层报文、IP 分组、链路帧和物理信号，各层处理不同范围的问题。先理解网络由哪些对象组成、怎样交换数据，再用性能指标计算发送与传播过程。

</div>

<div class="study-unit" id="u-04-rewrite-3779f358de56">

**分层是责任划分，封装是数据组织。** 同一份应用内容在各层有不同单位和地址，后续分析必须始终说明正在讨论哪一层、哪一跳以及哪一种时延。

</div>

### 网络的定义、组成与分类

<div class="study-unit" id="u-04-rewrite-a4934ca1f86e">

计算机网络将能够独立工作的计算机通过链路互连，按照协议交换数据并共享资源。边缘主机运行应用，核心交换与路由设备连接路径；资源子网和通信子网则从资源提供与通信承担的角度划分组成。

</div>

<div class="study-unit" id="u-04-rewrite-00c004387bd3">

按范围可分个人区域、局域、城域和广域，按使用对象分公用、专用，按传输组织又可分广播与点到点。**覆盖范围、物理接线和逻辑通信关系是不同维度**，物理星形未必意味着逻辑上各链路独占。

</div>

<span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="s-3"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="p-2"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="p-3"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-9fb7800cf0a3"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-6b86b273ff34"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-d96eed6626f9"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-d4735e3a265e"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-3e2b65c2ad9b"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-566b717a55ae"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-433d8b0aa1b2"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-06a4c18e0ae8"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-e8e318d3da9b"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-7a7d158ab8c0"></span><span class="legacy-anchor" data-target="s-04-64a5b5fb2867" id="u-04-explain-5974657beb"></span>

### 三种交换方式

<div class="study-unit" id="u-04-rewrite-799b24ef6b2d">

电路交换先建立通路，再连续发送，空闲时也可能占有分配资源；报文交换先收完整报文再转发；分组交换把报文切小，各链路可流水发送，提高共享效率，但增加首部与排队开销。

</div>

<div class="study-unit" id="u-04-rewrite-26e7a4fdf796">

**分组总时间要计首次穿越和后续流水。** 等速率、等长分组、$h$ 条链路的简化模型中，总时间为 $(n+h-1)L/R+hd$，$h$ 数链路而非路由器。若经过两台中间路由器，通常有三条链路；速率不等时应按每跳完成时刻与瓶颈重新排时间轴。

</div>

<div class="study-unit" id="u-04-e4c8f26359dc">

| 交换 | 执行过程 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 电路 | 建立专用通路→连续传数据→释放 | 建立后时延较稳定、无存储转发 | 建立需时间，空闲仍占资源 |
| 报文 | 整个报文到结点后保存，再向下一跳发送 | 不预占专用电路 | 大报文占缓存、转发等待长 |
| 分组 | 报文切成分组，各跳按分组存储转发 | 可流水、线路利用率高 | 分组首部开销，可能排队 / 乱序 / 丢失 |

</div>

### 网络性能指标

<div class="study-unit" id="u-04-rewrite-b6e404cad4b8">

发送时延是把整包比特推上链路的时间 $L/R$，传播时延是信号沿介质走完距离的时间 $d/v$，两者再加处理、排队形成总延迟。速率、实际吞吐和可达带宽也要分别判断，路径吞吐受瓶颈限制。

</div>

<div class="study-unit" id="u-04-rewrite-7cc7b5124940">

例如 1000 B 在 1 Mb/s 链路发送需 8 ms，走 1000 km、传播速度 $2\times10^8$ m/s 又需 5 ms。**提高速率直接缩短前者，不改变同一路径上的传播速度。** Hz 的频带宽与 bit/s 的数据带宽单位不同，时延带宽积则表示传播期间链路可容纳多少比特。

</div>

<div class="study-unit" id="u-04-f10ce4f4f39f">

| 指标 | 含义 / 公式 |
| --- | --- |
| 速率 | 每秒传的 bit，b/s；k/M/G 通常十进制 |
| 带宽 | 最高可达传输速率，b/s；物理信道频带宽则用 Hz |
| 吞吐量 | 实际单位时间通过的数据量，受路径瓶颈等限制 |
| 发送 / 传输时延 | 分组 bit 数 L / 发送速率 R |
| 传播时延 | 距离 d / 信号传播速度 v |
| 总时延 | 发送+传播+处理+排队 |
| 时延带宽积 | 传播时延×带宽，表示链路容纳的 bit |
| RTT（Round-Trip Time，往返时间） | 往返时间，具体是否含其他开销看题设 |
| 利用率 / 丢包率 | 有效占用时间占比 / 丢失分组占比 |

</div>

### 网络协议模型

<div class="study-unit" id="u-04-rewrite-d312edda8a98">

协议规定对等实体通信的语法、语义和时序，服务则是下层给上层的能力。发送时上层完整 PDU 成为下层的数据部分，下层再加入控制信息；接收时反向拆封，不能把每层完整单位都叫同一种数据报。

</div>

<div class="study-unit" id="u-04-rewrite-950740b7c715">

OSI 七层从物理、链路、网络、传输到会话、表示、应用；TCP/IP 常用四层，教学五层把网络接口拆开。**端口对应进程服务，IP 对应网络寻址，MAC 对应本地链路交付**，例如 HTTP 在应用层、TCP/UDP 在传输层、IP/ICMP 在网际层，各自职责不同。

</div>

### 网络接口与服务

<div class="study-unit" id="u-04-rewrite-45cb74b272f9">

协议是同层之间的通信约定，接口是同一系统内相邻层交换信息的边界，服务描述通过接口得到什么能力。服务访问点是使用该服务的逻辑入口，端口可帮助理解传输层的服务寻址。

</div>

<div class="study-unit" id="u-04-rewrite-8a4aee6dc724">

**面向连接与可靠性不是同一属性。** 前者说明使用前是否建立状态，后者说明怎样处理丢失、差错和顺序；有连接不自动代表无差错，无连接也可由上层补充可靠机制。

</div>

## 第二章 物理层

<div class="study-unit" id="u-04-rewrite-ba08f9f3fd25">

物理层把比特映射为能在介质上传播、被接收方识别的信号，关心接口、码元、频宽、噪声与编码。它本身不根据 IP 或 MAC 决定逐包出口。

</div>

<div class="study-unit" id="u-04-rewrite-d1c4517b6dc1">

**信号每秒变化多少个码元，与每秒携带多少比特，需要通过编码联系。** 奈氏与香农分别给特定条件下的理论限制，计算前先检查单位和模型。

</div>

<span class="legacy-anchor" data-target="s-04-db7e507a44e1" id="s-7"></span><span class="legacy-anchor" data-target="s-04-db7e507a44e1" id="p-32"></span><span class="legacy-anchor" data-target="s-04-db7e507a44e1" id="u-04-84283e05ed0c"></span><span class="legacy-anchor" data-target="s-04-db7e507a44e1" id="u-04-cddf10432784"></span><span class="legacy-anchor" data-target="s-04-db7e507a44e1" id="u-04-68bcf0f6098f"></span><span class="legacy-anchor" data-target="s-04-db7e507a44e1" id="u-04-e87ada8eb86e"></span>
<a id="s-04-db7e507a44e1"></a>

### 物理层接口特性

<div class="study-unit" id="u-04-rewrite-05aed83dd4dd">

机械特性说明连接器形状和引脚，电气特性说明电平与相关电气要求，功能特性说明各信号用途，过程特性规定动作先后。看到“某引脚做什么”和“何时有效”时，要分别归入功能与过程。

</div>

<div class="study-unit" id="u-04-rewrite-0e245865fc55">

介质可为双绞线、同轴、光纤或无线，光纤不受电磁干扰。**单工、半双工、全双工描述方向与同时性，串行、并行描述位传输组织**，两组概念不能互换。

</div>

<span class="legacy-anchor" data-target="s-04-outline-8d6471ab78" id="u-04-137a138631a4"></span><span class="legacy-anchor" data-target="s-04-outline-8d6471ab78" id="u-04-outline-2561949748"></span><span class="legacy-anchor" data-target="s-04-outline-8d6471ab78" id="u-04-86f8da9550d7"></span><span class="legacy-anchor" data-target="s-04-outline-8d6471ab78" id="u-04-b02f70eeb7c6"></span>
<a id="s-04-outline-8d6471ab78"></a>

### 信源、信宿与信道

<div class="study-unit" id="u-04-rewrite-ea847923c829">

信源产生信息，信宿接收信息，信号是信息的物理载体，信道是传播通路。原始基带信号可直接传输，也可调制到载波频带，以适应介质和频段要求。

</div>

<div class="study-unit" id="u-04-rewrite-22109ed23776">

**数据速率与传播速度不同。** 一个表示每秒注入多少信息，一个表示信号在介质中走多快；噪声、衰减和有限频带影响识别能力，不能仅因距离变短就认定码元必然能无限加快。

</div>

<span class="legacy-anchor" data-target="s-04-cc554f4c2103" id="s-8"></span>
<a id="s-04-cc554f4c2103"></a>

### 通信指标计算

<div class="study-unit" id="u-04-rewrite-268885075263">

通信计算先区分四个量：Hz 表示频带宽，Baud 表示每秒码元数，bit/s 表示信息速率，dB 表示对数形式的功率比。状态数把码元与比特联系起来，信噪比则约束可靠区分能力。

</div>

<div class="study-unit" id="u-04-rewrite-2c0faee86f8f">

**先把题目数据归到对应物理量，再选公式。** 已给波特率时只需乘每码元信息量，已给 dB 则先还原比例，不能把所有带“频率”的数直接乘在一起。

</div>

<span class="legacy-anchor" data-target="s-04-57c584df91f8" id="s-9"></span><span class="legacy-anchor" data-target="s-04-57c584df91f8" id="p-43"></span><span class="legacy-anchor" data-target="s-04-57c584df91f8" id="u-04-6103ad7eeec8"></span><span class="legacy-anchor" data-target="s-04-57c584df91f8" id="u-04-417efdc56dcb"></span><span class="legacy-anchor" data-target="s-04-57c584df91f8" id="u-04-9ddb17d0da86"></span><span class="legacy-anchor" data-target="s-04-57c584df91f8" id="u-04-d87dcbd08d40"></span><span class="legacy-anchor" data-target="s-04-57c584df91f8" id="u-04-explain-324fde3f41"></span><span class="legacy-anchor" data-target="s-04-57c584df91f8" id="u-04-346d2c7d177e"></span><span class="legacy-anchor" data-target="s-04-57c584df91f8" id="u-04-0a74c657a734"></span>
<a id="s-04-57c584df91f8"></a>

#### 码元

<div class="study-unit" id="u-04-rewrite-24920df3629d">

码元是在给定时长内使用的一种信号状态，若有 $V$ 种可区分状态，一个码元最多编码 $\log_2V$ 比特。四种状态可对应 00、01、10、11，所以每码元带 2 bit。

</div>

<div class="study-unit" id="u-04-rewrite-b4324a219796">

**码元数不是波形跳变次数。** 连续相同状态仍可占多个码元，必须先知道码元持续时间和编码边界；1000 Baud、四状态对应 2000 bit/s，不能误认为一个码元总等于一位。

</div>

<span class="legacy-anchor" data-target="s-04-dc1a2d759146" id="s-10"></span><span class="legacy-anchor" data-target="s-04-dc1a2d759146" id="p-44"></span><span class="legacy-anchor" data-target="s-04-dc1a2d759146" id="u-04-f26d22eedb5e"></span><span class="legacy-anchor" data-target="s-04-dc1a2d759146" id="u-04-127e7e0574ce"></span><span class="legacy-anchor" data-target="s-04-dc1a2d759146" id="u-04-d13d31ee53a7"></span><span class="legacy-anchor" data-target="s-04-dc1a2d759146" id="u-04-48b79ba16ca5"></span>
<a id="s-04-dc1a2d759146"></a>

#### 传输速率

<div class="study-unit" id="u-04-rewrite-4c8214d1b352">

波特率 $B$ 表示每秒码元数，比特率为 **$R=B\log_2V$**。给出 2400 Baud、16 状态时，每码元 4 bit，数据率为 9600 bit/s，不应再额外乘 2。

</div>

<div class="study-unit" id="u-04-rewrite-9d1250b7632a">

频带宽若由上下截止频率给出，则 $W=f_2-f_1$，单位 Hz；网络语境直接给 100 Mb/s 的带宽则已是速率。**同叫带宽也需看单位**，后者不能直接当作 W 代入奈氏准则。

</div>

<span class="legacy-anchor" data-target="s-04-66bcb34e257e" id="s-11"></span><span class="legacy-anchor" data-target="s-04-66bcb34e257e" id="p-45"></span><span class="legacy-anchor" data-target="s-04-66bcb34e257e" id="u-04-6afee2ad6f89"></span><span class="legacy-anchor" data-target="s-04-66bcb34e257e" id="u-04-a900cf7aaa55"></span><span class="legacy-anchor" data-target="s-04-66bcb34e257e" id="u-04-6bc4eacc57b8"></span><span class="legacy-anchor" data-target="s-04-66bcb34e257e" id="u-04-e9741592dfe4"></span><span class="legacy-anchor" data-target="s-04-66bcb34e257e" id="u-04-8892f821bb10"></span><span class="legacy-anchor" data-target="s-04-66bcb34e257e" id="u-04-97bfc25e46d9"></span><span class="legacy-anchor" data-target="s-04-66bcb34e257e" id="u-04-f2aa91e7dced"></span><span class="legacy-anchor" data-target="s-04-66bcb34e257e" id="u-04-f85895ad1114"></span>
<a id="s-04-66bcb34e257e"></a>

#### 奈氏准则

<div class="study-unit" id="u-04-rewrite-c3b8bcf6309e">

理想无噪声低通信道的最大码元速率为 $2W$，结合每码元信息量，数据率上界为 **$2W\log_2V$**。这里的 2 来自理想信道可支持的码元速率，给定实际波特率时不应重复套入。

</div>

<div class="study-unit" id="u-04-rewrite-119a1561fa35">

提高状态数在此理想公式中可增加速率，但实际噪声限制状态能否被分清。若题目同时给状态数、频宽与信噪比，应分别算奈氏和香农上界，再接受较小的约束。

</div>

<span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="s-12"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="p-46"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-7911962131e3"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-9ff22a8cc6a2"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-b9fc3154f8d5"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-d4cbf38919d9"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-b30307bb01ce"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-dddf546f1176"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-26e8486cdd28"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-4caaa0ac1c40"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-63f31d0cf38a"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-explain-37c3778782"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-bd5dc212dfe5"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-7f4d3980a311"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-bb4e81082899"></span><span class="legacy-anchor" data-target="s-04-414c7fcc9a1f" id="u-04-8f5224b78ac2"></span>
<a id="s-04-414c7fcc9a1f"></a>

#### 香农定理

<div class="study-unit" id="u-04-rewrite-abe5b6cd17e5">

有噪声信道容量上界为 **$C=W\log_2(1+S/N)$**，其中 $S/N$ 是平均功率之比。若给信噪比 dB，先用 $10^{\mathrm{dB}/10}$ 还原，例如 30 dB 对应 1000，不是 30。

</div>

<div class="study-unit" id="u-04-rewrite-9ad2acb97a92">

3000 Hz、30 dB 得约 29.9 kb/s；若同时限定四状态，奈氏只允许 12 kb/s，就还要受这个更小上界约束。香农容量是理论极限，实际协议的冗余、编码和实现会使有效速率更低。

</div>

<span class="legacy-anchor" data-target="s-04-3f88a2cd5201" id="s-13"></span>
<a id="s-04-3f88a2cd5201"></a>

### 编码与调制

<div class="study-unit" id="u-04-rewrite-7a20a62a3204">

编码规定数据怎样形成基带波形或线路码，调制规定怎样改变载波的振幅、频率或相位承载数据。二者都在建立数据与信号的映射，但操作对象和使用场景不同。

</div>

<div class="study-unit" id="u-04-rewrite-6539238d578e">

**读波形先找位边界和中点，再根据题设规则解码。** 读星座或调制参数则先数可区分状态，再算每码元位数，不能直接把波形线条数当成信息位数。

</div>

<span class="legacy-anchor" data-target="s-04-a868e8aa8bc3" id="s-14"></span><span class="legacy-anchor" data-target="s-04-a868e8aa8bc3" id="p-53"></span><span class="legacy-anchor" data-target="s-04-a868e8aa8bc3" id="u-04-927a82b4e680"></span><span class="legacy-anchor" data-target="s-04-a868e8aa8bc3" id="u-04-a1ff86362502"></span><span class="legacy-anchor" data-target="s-04-a868e8aa8bc3" id="u-04-d6a14a8f99bf"></span>
<a id="s-04-a868e8aa8bc3"></a>

#### 编码

<div class="study-unit" id="u-04-rewrite-01131f80f24e">

不归零码靠电平表示位，连续同值可能缺少同步跳变；归零码在位内回到零；曼彻斯特每位中间必跳以提供时钟；差分曼彻斯特用位边界是否跳变表示数据，中间跳变主要同步。

</div>

<div class="study-unit" id="u-04-rewrite-443b0c5e3257">

**位值约定可能反转，应以题图为准。** 本文 NRZI 采用边界跳变为 0，不能推广给所有系统；4B/5B 的 5 个线路位携带 4 个数据位，效率为 80%。早期 10 Mb/s 以太网用曼彻斯特，不代表所有高速以太网编码相同。

</div>

<div class="study-unit" id="u-04-4b227777d4dd">

| 编码 | 每 bit 怎么形成波形 | 识别重点 |
| --- | --- | --- |
| NRZ（不归零编码） | 整个 bit 期间保持相应电平 | 连续相同位无跳变，自同步较难 |
| RZ（归零编码） | bit 内先给数据电平，再回零 | 有回零时序，需较高符号速率 |
| NRZI（反向不归零编码） | 本稿约定边界跳变为 0、不跳为 1 | 初始电平需题设，跳变方向无关 |
| 曼彻斯特 | 每位中间必跳，方向表示 0 / 1 | 经典约定向下 1、向上 0，题设可反；每 bit 两个半位电平 |
| 差分曼彻斯特 | 中间必跳同步，起始边界跳变为 0、不跳为 1 | 看边界，不看中间跳变方向判断数据 |

</div>

<a id="s-04-7b3947f4f43b"></a>

#### 调制

<div class="study-unit" id="u-04-rewrite-79e1cc7d2122">

ASK 改振幅，FSK 改频率，PSK 改相位，QAM 联合振幅和相位形成更多状态。16-QAM 有 16 个状态，每码元 4 bit；64-QAM 每码元 6 bit。

</div>

<div class="study-unit" id="u-04-rewrite-693452d79bf7">

**状态更多要求接收方分辨更细，不能脱离噪声条件无限提高有效速率。** 调制将基带信息映射到载波，不是数据链路层给数据加帧首部；频带传输与成帧分属不同问题。

</div>

### 物理层设备

<div class="study-unit" id="u-04-rewrite-ab254e749e8f">

物理层设备处理信号的传播与再生，不解读帧内地址来选择目标。中继器延长一段物理通信范围，集线器将这个功能扩展到多个端口。

</div>

<div class="study-unit" id="u-04-rewrite-2156e0b1397c">

**不识别帧意味着也不能靠 MAC 学习隔离流量。** 判断设备会扩大还是隔离冲突域、是否独占带宽，必须依据它的转发层次，而不是端口数量。

</div>

<span class="legacy-anchor" data-target="s-04-ce2e0877e677" id="s-17"></span><span class="legacy-anchor" data-target="s-04-ce2e0877e677" id="p-70"></span><span class="legacy-anchor" data-target="s-04-ce2e0877e677" id="u-04-b3f186ebcdeb"></span><span class="legacy-anchor" data-target="s-04-ce2e0877e677" id="u-04-d91ab2d19af1"></span>
<a id="s-04-ce2e0877e677"></a>

#### 中继器

<div class="study-unit" id="u-04-rewrite-47b9ac56392f">

数字中继器对收到的信号判决、再生并整形，以改善长距离传播后的质量；模拟放大器则放大波形，噪声也可能一起放大。两者作用不能只用“把信号变大”概括。

</div>

<div class="study-unit" id="u-04-rewrite-5c2065a2045e">

**中继器不学习 MAC、不读取 IP 路由，也不隔离广播或经典冲突域。** 通过它延长共享介质后，传播延迟与冲突检测条件仍需重新满足，不能无限串接而不检查限制。

</div>

<span class="legacy-anchor" data-target="s-04-d6837580079a" id="s-18"></span><span class="legacy-anchor" data-target="s-04-d6837580079a" id="p-71"></span><span class="legacy-anchor" data-target="s-04-d6837580079a" id="u-04-38ec2f342b60"></span><span class="legacy-anchor" data-target="s-04-d6837580079a" id="u-04-f87a28b442af"></span><span class="legacy-anchor" data-target="s-04-d6837580079a" id="u-04-1dfa987a1d60"></span><span class="legacy-anchor" data-target="s-04-d6837580079a" id="u-04-3d17c3a21878"></span><span class="legacy-anchor" data-target="s-04-d6837580079a" id="u-04-c4e82828113a"></span>
<a id="s-04-d6837580079a"></a>

#### 集线器

<div class="study-unit" id="u-04-rewrite-c343fd0efe0b">

集线器是多端口中继器，收到信号后复制到其他端口。接线看起来像星形，逻辑上仍共享同一介质，经典工作在半双工，全部端口处于同一冲突域和广播域。

</div>

<div class="study-unit" id="u-04-rewrite-61ed0a39d090">

**端口标称速率不是每台主机独占速率。** 多站竞争同一带宽，也不能把各口速率直接相加当作独立吞吐；它与按 MAC 选择出口的交换机有本质差别。

</div>

<span class="legacy-anchor" data-target="s-04-1c232baa7769" id="s-19"></span><span class="legacy-anchor" data-target="s-04-1c232baa7769" id="u-04-a9f7e5468d35"></span>
<a id="s-04-1c232baa7769"></a>

## 第三章 数据链路层

<div class="study-unit" id="u-04-rewrite-e526365957c6">

链路层在相邻结点之间把比特组织成帧，识别边界、检测差错，并根据协议选择流量控制、重传或介质竞争机制。每一跳可以采用不同链路协议。

</div>

<div class="study-unit" id="u-04-rewrite-3027779bb386">

**单跳检错与端到端可靠交付是两回事。** 以太网丢弃坏帧而不逐帧重传，TCP 仍可在端点实现可靠字节流；接下来的成帧、检错与 ARQ 分别解决不同问题。

</div>

<span class="legacy-anchor" data-target="s-04-outline-6bd346be51" id="u-04-5990b896c7e8"></span><span class="legacy-anchor" data-target="s-04-outline-6bd346be51" id="u-04-outline-b85856b1f4"></span><span class="legacy-anchor" data-target="s-04-outline-6bd346be51" id="u-04-b478b9594ea1"></span><span class="legacy-anchor" data-target="s-04-outline-6bd346be51" id="u-04-8537a58d801f"></span>
<a id="s-04-outline-6bd346be51"></a>

### 数据链路层的功能

<div class="study-unit" id="u-04-rewrite-04933dc2a711">

链路层需要让相邻两端从连续比特中识别完整帧，并用链路地址交付、校验等机制处理本跳通信。共享介质还需解决谁可以发送，有些协议另外提供确认、重传和流控。

</div>

<div class="study-unit" id="u-04-rewrite-fd1aa3e229f9">

**不能把某个协议的可选能力当作全层统一保证。** 一条链路可靠不代表沿途所有链路可靠，发现错误也不等于自动纠正；应明确讨论的具体协议和服务范围。

</div>

<span class="legacy-anchor" data-target="s-04-3a49414625e6" id="s-20"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="p-72"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-180b1b39f8d9"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-e7f6c011776e"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-841a992f6c86"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-81d294649eda"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-7db4cf46eb80"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-3cbcbcab625e"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-237826c6b005"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-0fcb9cf66124"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-8b69f0004adc"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-explain-91a0656c5e"></span><span class="legacy-anchor" data-target="s-04-3a49414625e6" id="u-04-8e69a437a5b9"></span>
<a id="s-04-3a49414625e6"></a>

### 封装成帧

<div class="study-unit" id="u-04-rewrite-0b30b904bd07">

帧边界必须能与任意有效数据区别开，透明传输保证数据中即使出现类似标志也可原样恢复。字符计数依长度判界，字节填充在特殊字符前加转义，零比特填充在连续五个 1 后插 0，违规编码利用数据不会使用的信号形式。

</div>

<div class="study-unit" id="u-04-rewrite-4b8bc69bebff">

**填充只作用于规定的数据范围，接收端按相同规则去掉。** 例如数据 `111111` 可变成 `1111101`，而旗标 `01111110` 本身不按数据填充。PPP 提供链路协商和 FCS，但通常不靠逐帧序号、ACK 重传保证可靠，点到点链路也不需多站竞争机制。

</div>

### 差错控制

<div class="study-unit" id="u-04-rewrite-e3583d9ad71d">

冗余校验让接收方发现或定位一部分位错误，最小码距为 $d$ 时，最多可检测 $d-1$ 位错误，纠正 $\lfloor(d-1)/2\rfloor$ 位。检错通过只表示没有发现可检测的错误，不是数学上保证原数据完全正确。

</div>

<div class="study-unit" id="u-04-rewrite-ce6414a218a9">

**ARQ 依靠确认和重传，FEC 依靠冗余直接纠正。** 丢失、重复和失序还需要序号、计时与缓存等机制，所以能做 CRC 检错不等于已实现可靠传输。

</div>

<span class="legacy-anchor" data-target="s-04-d4c688a518fa" id="s-22"></span><span class="legacy-anchor" data-target="s-04-d4c688a518fa" id="p-74"></span><span class="legacy-anchor" data-target="s-04-d4c688a518fa" id="u-04-86c84391a3c2"></span><span class="legacy-anchor" data-target="s-04-d4c688a518fa" id="u-04-07b21567a5d2"></span><span class="legacy-anchor" data-target="s-04-d4c688a518fa" id="u-04-20cee4048768"></span><span class="legacy-anchor" data-target="s-04-d4c688a518fa" id="u-04-7902699be42c"></span>
<a id="s-04-d4c688a518fa"></a>

#### 奇偶校验码

<div class="study-unit" id="u-04-rewrite-548f43909ff9">

奇偶校验加一个冗余位，使整个码字中的 1 数满足规定奇偶性。若奇数个位翻转，奇偶性必改变；偶数个位翻转可能仍满足原规则，因此会漏检。

</div>

<div class="study-unit" id="u-04-rewrite-06b653327113">

**普通奇偶校验只给出是否违反奇偶条件，不能定位错误位。** 校验位本身也可能出错，不能将接收方“奇偶性不对”直接解释成某个数据位必错，更不能据此自动纠正。

</div>

#### 循环冗余校验码 CRC

<div class="study-unit" id="u-04-rewrite-f8d0ffa2d064">

生成多项式最高次数为 $r$，对应除数长 $r+1$ 位。发送端给数据补 $r$ 个 0，使用异或做模 2 除法，再把 $r$ 位余数作为 FCS；接收端用同一生成串检验整个码字。

</div>

<div class="study-unit" id="u-04-rewrite-2bcf2f92bab4">

**除数位数与余数位数差 1，余数前导 0 也必须保留。** 数据 `1101`、生成串 `1011` 时，补成 `1101000`，余数为 `001`，发送 `1101001`。非零余数表示检出错，零只表示未检出；普通帧 CRC 不是自动纠错算法。

</div>

#### 海明校验码

<div class="study-unit" id="u-04-rewrite-4b92ad363c05">

海明码把校验位放在 1、2、4、8 等编号处，位置编号的二进制位决定它参加哪些校验组。$n$ 个数据位、$k$ 个校验位实现单错定位需满足 **$2^k\ge n+k+1$**，额外一种状态对应无错。

</div>

<div class="study-unit" id="u-04-rewrite-6fe12fb86af0">

接收后组成综合征，在单错假设下其数值给出错误位置，如按 4、2、1 组排列为 101，就定位第 5 位。**普通单错海明码不能可靠区分所有双错**，再加总奇偶位可形成单错纠正、双错检测，不能把两种码的能力混用。

</div>

<span class="legacy-anchor" data-target="s-04-f1e636dd15f9" id="s-25"></span><span class="legacy-anchor" data-target="s-04-f1e636dd15f9" id="u-04-d6aafccf9e6b"></span>
<a id="s-04-f1e636dd15f9"></a>

### 流量控制和可靠传输

<div class="study-unit" id="u-04-rewrite-c07ccee5b51e">

流量控制避免发送过快压垮接收方，可靠传输则还要识别丢失、重复和失序。滑动窗口限制允许发送或接收的序号范围，确认推进窗口，计时器处理迟迟没有确认的情况。

</div>

<div class="study-unit" id="u-04-rewrite-ecca8503ebd4">

**比较协议时分别看发送窗口、接收窗口、确认方式和重传范围。** SW 每次等一帧，GBN 可以连续发但接收按序一个，SR 缓存窗口内失序帧，三者的序号空间约束也不同。

</div>

<span class="legacy-anchor" data-target="s-04-71e6710a0f2d" id="s-26"></span><span class="legacy-anchor" data-target="s-04-71e6710a0f2d" id="p-93"></span><span class="legacy-anchor" data-target="s-04-71e6710a0f2d" id="u-04-6a26b011d948"></span><span class="legacy-anchor" data-target="s-04-71e6710a0f2d" id="u-04-0cc7c2e6da52"></span><span class="legacy-anchor" data-target="s-04-71e6710a0f2d" id="u-04-24131376bea0"></span><span class="legacy-anchor" data-target="s-04-71e6710a0f2d" id="u-04-30a579e1c76e"></span><span class="legacy-anchor" data-target="s-04-71e6710a0f2d" id="u-04-explain-56ede790e6"></span><span class="legacy-anchor" data-target="s-04-71e6710a0f2d" id="u-04-ea2314a5add6"></span>
<a id="s-04-71e6710a0f2d"></a>

#### 停止等待协议 SW

<div class="study-unit" id="u-04-rewrite-7601f4fc7b12">

发送方发一帧后保存副本并启动计时，收到正确确认才发下一帧，超时则重发。交替序号用于区分新帧与确认丢失引起的重复帧，发送与接收窗口都为 1。

</div>

<div class="study-unit" id="u-04-rewrite-90c30696d80b">

例如帧 0 已交付而 ACK 丢失，重发帧 0 到达时，接收方只重新确认、不重复交给上层。**数据到达与发送方知道它到达是两个状态。** ACK 编号代表已收还是下一期待，要以题设约定为准。

</div>

<span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="s-27"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="p-94"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-8bf67af83a08"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-e4aa7da95219"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-a70305d58ae4"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-056bafe61cd3"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-265dcdfc226c"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-explain-e83ed4096c"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-351beb14cb4d"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-61b26f196a15"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-4871fe2b1282"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-steps-7bff1266ad"></span><span class="legacy-anchor" data-target="s-04-43b04ff3121c" id="u-04-333505a107ce"></span>
<a id="s-04-43b04ff3121c"></a>

#### 后退N帧协议 GBN

<div class="study-unit" id="u-04-rewrite-f639650aed54">

GBN 允许窗口内多帧连续发出，接收方只收当前按序下一帧，失序帧通常丢弃，并用累计 ACK 表示连续前缀。最早未确认帧超时后，从它起重传全部已发未确认帧。

</div>

<div class="study-unit" id="u-04-rewrite-0661f5978516">

例如 1 丢失，随后 2、3 到达也不收，需重发 1、2、3。**“后退”描述重传范围，不是窗口可以忽略确认任意倒移。** $n$ 位循环序号、接收窗口为 1 时，发送窗口最多 $2^n-1$，否则新旧轮次可能混淆。

</div>

<span class="legacy-anchor" data-target="s-04-28abb34768bc" id="s-28"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="p-95"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="u-04-c2e9eecfb741"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="u-04-89d8abfc818d"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="u-04-a230a97fcc07"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="u-04-94963f73d03d"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="u-04-a9ed37377171"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="u-04-9b00bb01b762"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="u-04-e630c78f0968"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="u-04-explain-3f6fd4df71"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="u-04-steps-f87cbb9390"></span><span class="legacy-anchor" data-target="s-04-28abb34768bc" id="u-04-f9cce36a5e5a"></span>
<a id="s-04-28abb34768bc"></a>

#### 选择重传协议 SR

<div class="study-unit" id="u-04-rewrite-2c2dd9f6af62">

SR 对窗口内正确帧分别确认和缓存，缺某帧时后续帧可以先存着，超时通常只重发该帧；缺口补齐后再按序交付连续前缀并滑动窗口，缓存成功不等于已经交付上层。

</div>

<div class="study-unit" id="u-04-rewrite-6e261e56028b">

**发送窗口加接收窗口不应超过序号空间 $2^n$**，等大时各不超过 $2^{n-1}$。若两窗不等，应使用总和约束，不能一律把发送窗口写成一半；它以额外缓存和状态换取较少重复传输。

</div>

<span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="s-29"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="p-108"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="p-109"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-2ca3fc7bade5"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-71b4c9bd2280"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-95186df44f9e"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-5897d0a37c5e"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-0e8805d0fc0d"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-4a44dc153642"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-f5ec8ef644ee"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-a47eb6fff6c0"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-95e4ddbce716"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-41dccb1d9e0d"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-42a3bd01e810"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-explain-e9a237574b"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-fb144266be00"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-cf14e8c5d91e"></span><span class="legacy-anchor" data-target="s-04-1e52974d53c0" id="u-04-ca45be7bcb70"></span>
<a id="s-04-1e52974d53c0"></a>

### 信道利用率

<div class="study-unit" id="u-04-rewrite-df77097b1605">

停等一轮包括数据发送、往返传播和确认发送，数据发送占其中的比例才是利用率。若 $T_D=L/R$，RTT 只含往返传播，则 **$U=T_D/(T_D+RTT+T_A)$**；允许连续发 $W$ 帧时，理想利用率最多扩大为 $W$ 倍并封顶 1。

</div>

<div class="study-unit" id="u-04-rewrite-5dfe40ac255b">

例如发一帧 1 ms、往返传播 9 ms、忽略 ACK，停等为 10%，窗口 5 为约 50%，窗口至少 10 才可能填满等待。**若 RTT 已含某项开销，不能再重复加**；求纯有效载荷速率还要扣首部、填充和重传等成本。

</div>

### 介质访问控制

<div class="study-unit" id="u-04-rewrite-8563c6d94468">

共享介质需要决定谁在何时发送，可以预先划分频带、时间或码字，也可让站点随机竞争，或按令牌轮流获得许可。不同机制在低负载开销、碰撞和最长等待上各有代价。

</div>

<div class="study-unit" id="u-04-rewrite-7cbc2e862a35">

**监听不能消除传播延迟，也不能保证绝不碰撞。** 有线共享介质可边发边检测，无线通常采用避免与确认；判断适用算法前先确认半双工共享还是全双工点到点。

</div>

<span class="legacy-anchor" data-target="s-04-96105a5954e8" id="s-31"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="p-128"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-39da5f0ca007"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-4fc82b26aecb"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-cc8047b8cdb4"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-64941db9cc0a"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-972c11ab0e28"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-b1e6f0dc43d3"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-8f892a65d7e6"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-c5c46cfcfccc"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-9f969a4e055f"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-ba8e4309719a"></span><span class="legacy-anchor" data-target="s-04-96105a5954e8" id="u-04-dba53610440a"></span>
<a id="s-04-96105a5954e8"></a>

#### 信道划分

<div class="study-unit" id="u-04-rewrite-f345c318889f">

FDM 按频带、TDM 按时隙、WDM 按光波长、CDM 按码片区分使用者。固定 TDM 即使某站无数据也保留其时隙，统计 TDM 可按需求分配；理想 CDM 让不同站用正交码叠加传输。

</div>

<div class="study-unit" id="u-04-rewrite-b874b6358b25">

CDM 中发 1 用 $S$、发 0 用 $-S$，接收对叠加信号与本站码做归一化内积，得到 +1、−1 或 0。**正交、同步是此简化计算的前提。** ALOHA 与 CSMA 属随机访问，前者直接竞争，后者先监听；坚持策略决定忙与空闲时如何等待，并非信道静态划分。

</div>

#### 随机访问 CSMA/CD

<div class="study-unit" id="u-04-rewrite-092d1e2451fb">

经典共享半双工以太网先监听，发送中继续检测碰撞，发现后停止有效发送、发干扰信号，再按截断二进制指数退避。全双工交换链路不使用这种碰撞检测退避。

</div>

<div class="study-unit" id="u-04-rewrite-d34b66eaa71f">

**发送时长必须覆盖最坏往返传播 $2\tau$，故最小帧位数至少 $2\tau R$。** 否则发送结束后碰撞才返回，会误判成功。10 Mb/s、51.2 μs 对应 64 B MAC 帧；第 j 次重传取 $k=\min(j,10)$，随机选整数 $r\in[0,2^k-1]$，等待 $r\cdot2\tau$，达到规定重试上限后放弃；帧间间隔 96 bit 时间在 10 Mb/s 时为 9.6 μs，不能把该微秒数套给所有链路。

</div>

#### 随机访问 CSMA/CA

<div class="study-unit" id="u-04-rewrite-fc7265dba87c">

无线站点难以边发边可靠检测冲突，CSMA/CA 用监听、随机退避和 ACK 降低风险。DCF 中按规则等 DIFS，空闲时隙递减计数，介质忙就冻结，重新空闲并满足等待后继续，计数到 0 才发。

</div>

<div class="study-unit" id="u-04-rewrite-25ffd17b8d95">

可选 RTS/CTS 的顺序为 **RTS→SIFS→CTS→SIFS→DATA→SIFS→ACK**。CTS 让接收者附近的隐蔽站也获知预约，其他站按 Duration 更新 NAV；Duration 数的是本帧之后的剩余预约时间，不含本帧自身发送。忽略传播时，RTS 的 Duration 为 $3SIFS+T_{CTS}+T_{DATA}+T_{ACK}$，CTS 为 $2SIFS+T_{DATA}+T_{ACK}$，DATA 为 $SIFS+T_{ACK}$，各 T 表示对应帧发送时长。SIFS 比 DIFS 短使短响应优先，但预约和避免都不保证零碰撞。

</div>

#### 轮询访问 令牌传递协议

<div class="study-unit" id="u-04-rewrite-772bbaf3f5dc">

令牌按逻辑次序交给各站，只有持有者可发送，结束后转交下一站，因而不靠随机竞争决定本轮发送者。在规则和故障条件受控时，可以限制最长等待。

</div>

<div class="study-unit" id="u-04-rewrite-36668651ce78">

**逻辑环描述令牌次序，物理接线不必是环。** 低负载时仍可能等令牌，丢失、重复或站点故障也需专门恢复；无竞争碰撞并不等于没有协议控制开销。

</div>

### 局域网

<div class="study-unit" id="u-04-rewrite-87adce315860">

局域网将有限范围内的设备连接起来，常见以太网和无线 LAN 在介质、访问控制及帧地址上不同，VLAN 再提供不依赖物理位置的逻辑广播域划分。

</div>

<div class="study-unit" id="u-04-rewrite-81dae376764f">

**同处一栋楼不代表处于同一广播域，同一局域网也不保证每条链路共享带宽。** 分析帧长、地址和冲突时，要先明确采用的标准、端口模式和转发边界。

</div>

#### 802.3 以太网

<div class="study-unit" id="u-04-rewrite-475b48d654d9">

以太网提供不保证可靠交付的链路服务，FCS 检出坏帧通常直接丢弃，可靠性可由上层实现。MAC 地址通常为 48 位，标识接口，不等同于主机 IP。

</div>

<div class="study-unit" id="u-04-rewrite-40280cc014f2">

Ethernet II 帧为目的 6 B、源 6 B、类型 2 B、数据 46～1500 B、FCS 4 B，共 **64～1518 B**；前导和定界通常不计入这个帧长，数据不足需填充。IEEE 802.3 的相应字段解释为长度；早期介质和碰撞规则不能无条件推广到全部高速全双工以太网。

</div>

#### 802.11 无线局域网

<div class="study-unit" id="u-04-rewrite-d14f8b25afc3">

基础设施无线 LAN 通过 AP 连接站点，一个基本服务集为 BSS，SSID 标识服务集，多个 BSS 可组成 ESS。无线链路要同时表达当前无线收发者与原始源、最终目的，所以可能使用三个或四个 MAC 地址。

</div>

<div class="study-unit" id="u-04-rewrite-df3bb097fbee">

**地址 1、2 先看本次无线跳的接收者、发送者。** 地址 3 再依 ToDS/FromDS 表达源或目的，四地址场景另补原始源。跨路由后封装已换，本地 AP 发出的帧不能机械沿用远端主机的 MAC，下表按方向分别给出含义。

</div>

<div class="study-unit" id="u-04-b0fbcd0a5293">

| 帧方向 | 地址 1（当前接收） | 地址 2（当前发送） | 地址 3 |
| --- | --- | --- | --- |
| 去 AP | AP | 源站 | 最终目的 |
| 来自 AP | 目的站 | AP | 原始源 |
| AP 间转发、$ToDS=FromDS=1$ | 接收 AP | 发送 AP | 目的；地址 4 再给源 |

</div>

#### 802.1Q 虚拟局域网

<div class="study-unit" id="u-04-rewrite-96679cb9cd5a">

</div>

<div class="study-unit" id="u-04-rewrite-87223192c3bb">

**标签标识所属逻辑域，不代表新增一台物理交换机。** 常见标签增加 4 B，典型最大帧变为 1522 B；不同 VLAN 通信通常需三层转发，主机是否收到带标签帧由端口和配置决定。

### 以太网交换机

<div class="study-unit" id="u-04-rewrite-8798d33a5945">

交换机先根据入口帧学习源 MAC 所在端口，再依据目的 MAC 选择出口。各端口形成独立链路，使多组通信可以并发，区别于集线器对信号的无选择复制。

</div>

<div class="study-unit" id="u-04-rewrite-ab6d14294e9c">

**二层转发表记录 MAC 到端口，路由表记录网络前缀到下一跳。** 不知道目的 MAC 时仍要在允许范围泛洪，交换也不会默认把广播全部隔开，广播域还要结合 VLAN 和路由边界判断。

</div>

<span class="legacy-anchor" data-target="s-04-920e03c58648" id="s-40"></span><span class="legacy-anchor" data-target="s-04-920e03c58648" id="p-176"></span><span class="legacy-anchor" data-target="s-04-920e03c58648" id="u-04-4dcaefb0c6f7"></span><span class="legacy-anchor" data-target="s-04-920e03c58648" id="u-04-764a57bb0de5"></span><span class="legacy-anchor" data-target="s-04-920e03c58648" id="u-04-0d55daa8f0f4"></span><span class="legacy-anchor" data-target="s-04-920e03c58648" id="u-04-368c19e9e4af"></span><span class="legacy-anchor" data-target="s-04-920e03c58648" id="u-04-e1d721991295"></span>
<a id="s-04-920e03c58648"></a>

#### 独占带宽特点

<div class="study-unit" id="u-04-rewrite-97d4ab98da03">

交换机点到点端口可分别使用链路带宽，全双工又允许两个方向同时传送，无经典共享介质碰撞。不同端口对可并发，但还要受交换结构和目标端口容量限制。

</div>

<div class="study-unit" id="u-04-rewrite-001786d3b24b">

**全双工单方向仍为 R，双向合计可为 2R。** 统计交换容量先确认是入出合计还是单向、是否重复计算同一股流；不能把端口速率简单加起来当任意流量条件下都能达到的吞吐。

</div>

<span class="legacy-anchor" data-target="s-04-bf1ca32cec16" id="s-41"></span><span class="legacy-anchor" data-target="s-04-bf1ca32cec16" id="p-177"></span><span class="legacy-anchor" data-target="s-04-bf1ca32cec16" id="u-04-a67ec4ce24ac"></span><span class="legacy-anchor" data-target="s-04-bf1ca32cec16" id="u-04-413be4b2f50d"></span><span class="legacy-anchor" data-target="s-04-bf1ca32cec16" id="u-04-d2db98a5003a"></span><span class="legacy-anchor" data-target="s-04-bf1ca32cec16" id="u-04-e841b647ff09"></span><span class="legacy-anchor" data-target="s-04-bf1ca32cec16" id="u-04-452117da2129"></span><span class="legacy-anchor" data-target="s-04-bf1ca32cec16" id="u-04-explain-06efca91f2"></span><span class="legacy-anchor" data-target="s-04-bf1ca32cec16" id="u-04-be440e48e5ba"></span><span class="legacy-anchor" data-target="s-04-bf1ca32cec16" id="u-04-168da7254014"></span>
<a id="s-04-bf1ca32cec16"></a>

#### 自学习功能

<div class="study-unit" id="u-04-rewrite-c808d5965e15">

收到帧后先把源 MAC 与入口端口关联，再查目的：已知且在其他口就定向转发，在同一入口段则过滤，未知单播与广播在同 VLAN 其他允许端口泛洪，旧表项按规则老化。

</div>

<div class="study-unit" id="u-04-rewrite-ad98838ab517">

例如 A→B 从端口 1 来，先学 A 在 1；B 回帧从 3 来，才学 B 在 3。**学习依据源地址，不是猜测目的位置。** 若同一源从新口出现要更新记录，泛洪也应遵守 VLAN、端口状态等范围限制。

</div>

<span class="legacy-anchor" data-target="s-04-9520056bb862" id="s-42"></span><span class="legacy-anchor" data-target="s-04-9520056bb862" id="p-178"></span><span class="legacy-anchor" data-target="s-04-9520056bb862" id="u-04-6c1bbac90d0e"></span><span class="legacy-anchor" data-target="s-04-9520056bb862" id="u-04-9d6a9f584e01"></span><span class="legacy-anchor" data-target="s-04-9520056bb862" id="u-04-3087f425da30"></span><span class="legacy-anchor" data-target="s-04-9520056bb862" id="u-04-a1bce2b33ab4"></span>
<a id="s-04-9520056bb862"></a>

#### 两种交换方式

<div class="study-unit" id="u-04-rewrite-2d5d37d103aa">

存储转发收齐完整帧、检查 FCS 后再发，能过滤检出误码并缓冲速率差异；直通在读到足够目的信息后开始输出，降低首次转发等待，但无法事先完成整帧检查。

</div>

<div class="study-unit" id="u-04-rewrite-f5dbe735f9f1">

**直通延迟从哪里计时要写清。** “读到 6 B 目的地址”若从整帧上线路开始算，还可能要计前导和定界；排队、出口速率和拥塞也会影响实际总延迟。

</div>

<span class="legacy-anchor" data-target="s-04-outline-df32dc20da" id="u-04-efac3d8f63f6"></span><span class="legacy-anchor" data-target="s-04-outline-df32dc20da" id="u-04-outline-b208092d1d"></span><span class="legacy-anchor" data-target="s-04-outline-df32dc20da" id="u-04-2d0c8d4c5288"></span><span class="legacy-anchor" data-target="s-04-outline-df32dc20da" id="u-04-c272f38b0fa7"></span><span class="legacy-anchor" data-target="s-04-outline-df32dc20da" id="u-04-82ecc0db1814"></span><span class="legacy-anchor" data-target="s-04-outline-df32dc20da" id="u-04-e29a8160fd9e"></span><span class="legacy-anchor" data-target="s-04-outline-df32dc20da" id="u-04-c7ab91bf1acc"></span><span class="legacy-anchor" data-target="s-04-outline-df32dc20da" id="u-04-fe8c7788b6c8"></span>
<a id="s-04-outline-df32dc20da"></a>

### 广域网与PPP协议

<div class="study-unit" id="u-04-rewrite-41246c4fab38">

PPP 用于点到点链路，双方无需与多站竞争介质。帧包含标志、地址控制、协议、信息与 FCS，协议字段说明载荷属于哪种网络协议或控制报文。

</div>

<div class="study-unit" id="u-04-rewrite-d807dc43bfb8">

LCP 协商链路参数，按需要认证，NCP 配置网络层，FCS 检错。**PPP 通常不提供逐帧序号与 ACK 重传的可靠机制**；广域网是覆盖范围概念，与一定采用哪种拓扑或交换方式不同。

</div>

<span class="legacy-anchor" data-target="s-04-08e8f29fe409" id="s-43"></span><span class="legacy-anchor" data-target="s-04-08e8f29fe409" id="u-04-aad00ad368ef"></span>
<a id="s-04-08e8f29fe409"></a>

## 第四章 网络层

<div class="study-unit" id="u-04-rewrite-2ddf40aa6d22">

网络层连接不同链路，给分组选择路径并逐跳转发。路由协议维护到目的网络的可达信息，路由器再对每个数据报执行查表和封装，IP 本身通常提供尽力而为交付。

</div>

<div class="study-unit" id="u-04-rewrite-5283102abd38">

本章围绕**IP 地址、下一跳、链路地址**的分工展开，再解释分片、自动配置、控制报文和动态路由。跨越一跳时哪些字段变化，必须按它们的作用判断。

</div>

<span class="legacy-anchor" data-target="s-04-7a403212e923" id="s-44"></span><span class="legacy-anchor" data-target="s-04-7a403212e923" id="p-196"></span><span class="legacy-anchor" data-target="s-04-7a403212e923" id="u-04-5495d24a5dbc"></span><span class="legacy-anchor" data-target="s-04-7a403212e923" id="u-04-d15d9dd8e49b"></span><span class="legacy-anchor" data-target="s-04-7a403212e923" id="u-04-f8d35a5fd121"></span><span class="legacy-anchor" data-target="s-04-7a403212e923" id="u-04-61432fe72b4c"></span><span class="legacy-anchor" data-target="s-04-7a403212e923" id="u-04-059ffb5acc5d"></span>
<a id="s-04-7a403212e923"></a>

### 网络层功能

<div class="study-unit" id="u-04-rewrite-5678a3a584ec">

路由选择在控制平面计算或更新路径，转发在数据平面按表逐包送往出口。普通 IP 不保证不丢、按序或端到端可靠，上层需根据服务要求补充机制。

</div>

<div class="study-unit" id="u-04-rewrite-a8e841212564">

**拥塞控制针对网络承载能力，流量控制针对接收方容量。** 丢包可能由拥塞、链路差错等引起，不一定是接收窗口太小；预先限制的开环策略与利用反馈调整的闭环策略也应区分。

</div>

<span class="legacy-anchor" data-target="s-04-70b5e7cf7a49" id="s-45"></span><span class="legacy-anchor" data-target="s-04-70b5e7cf7a49" id="p-197"></span><span class="legacy-anchor" data-target="s-04-70b5e7cf7a49" id="u-04-7d743bfb4ca5"></span><span class="legacy-anchor" data-target="s-04-70b5e7cf7a49" id="u-04-02b007f46bee"></span><span class="legacy-anchor" data-target="s-04-70b5e7cf7a49" id="u-04-2299ef965c38"></span><span class="legacy-anchor" data-target="s-04-70b5e7cf7a49" id="u-04-a2f8a81c5cb6"></span><span class="legacy-anchor" data-target="s-04-70b5e7cf7a49" id="u-04-54ea437c10f5"></span>
<a id="s-04-70b5e7cf7a49"></a>

#### 虚电路和数据报

<div class="study-unit" id="u-04-rewrite-090beba81170">

数据报服务让每包携带目的地址独立处理，无需先建网络连接，路径可能不同；虚电路先建立逻辑路径，结点保存状态，后续包用标识沿相应路径转发。

</div>

<div class="study-unit" id="u-04-rewrite-a68a57155902">

**虚电路共享链路，并非物理专用电路。** 通常按既定路径能保持顺序，但可靠性仍取决于具体协议；故障可能需要重建，不能仅凭面向连接就保证绝不丢失。

</div>

<span class="legacy-anchor" data-target="s-04-a8f64ec981ca" id="s-46"></span><span class="legacy-anchor" data-target="s-04-a8f64ec981ca" id="p-198"></span><span class="legacy-anchor" data-target="s-04-a8f64ec981ca" id="u-04-e9822a5d9db2"></span><span class="legacy-anchor" data-target="s-04-a8f64ec981ca" id="u-04-33b8c26e0ad2"></span><span class="legacy-anchor" data-target="s-04-a8f64ec981ca" id="u-04-f36878ad151a"></span><span class="legacy-anchor" data-target="s-04-a8f64ec981ca" id="u-04-b6ff751b9c27"></span><span class="legacy-anchor" data-target="s-04-a8f64ec981ca" id="u-04-bd0aa532b2f5"></span><span class="legacy-anchor" data-target="s-04-a8f64ec981ca" id="u-04-93ed10aebd67"></span><span class="legacy-anchor" data-target="s-04-a8f64ec981ca" id="u-04-9fe30830f430"></span>
<a id="s-04-a8f64ec981ca"></a>

#### 软件定义网络SDN

<div class="study-unit" id="u-04-rewrite-79a08e7b9465">

SDN 把控制逻辑与逐包转发分开，控制器依据策略生成规则，设备按“匹配字段→动作”流表处理数据。北向连接应用，南向连接设备，控制器之间还可协作。

</div>

<div class="study-unit" id="u-04-rewrite-fe56c9762593">

**逻辑集中不要求物理上只有一台控制器。** 流表也可同时匹配 MAC、IP、端口等字段，不能把它缩成普通目的 IP 路由表；已有规则在控制链路故障时如何工作，取决于系统设计。

</div>

<span class="legacy-anchor" data-target="s-04-59a21bd617d7" id="s-47"></span><span class="legacy-anchor" data-target="s-04-59a21bd617d7" id="p-217"></span><span class="legacy-anchor" data-target="s-04-59a21bd617d7" id="u-04-94def316114c"></span><span class="legacy-anchor" data-target="s-04-59a21bd617d7" id="u-04-c15880610089"></span><span class="legacy-anchor" data-target="s-04-59a21bd617d7" id="u-04-9dd9799d4052"></span><span class="legacy-anchor" data-target="s-04-59a21bd617d7" id="u-04-53fc4aa522ed"></span><span class="legacy-anchor" data-target="s-04-59a21bd617d7" id="u-04-f5ca38f748a1"></span><span class="legacy-anchor" data-target="s-04-59a21bd617d7" id="u-04-f52b0c0cc436"></span><span class="legacy-anchor" data-target="s-04-59a21bd617d7" id="u-04-179987f290ce"></span><span class="legacy-anchor" data-target="s-04-59a21bd617d7" id="u-04-9fbc08511a83"></span>
<a id="s-04-59a21bd617d7"></a>

### IPv4

<div class="study-unit" id="u-04-rewrite-c7fd10ac34dc">

IPv4 地址为 32 位，基本首部 20 B，可含选项至 60 B；IHL 以 4 B 为单位，总长度则以字节计且包含首部与数据。协议字段标明上层，如 TCP 为 6、UDP 为 17，与版本字段不是同一个东西。

</div>

<div class="study-unit" id="u-04-rewrite-e5575c17db08">

**TTL 逐跳递减，首部检验和只覆盖首部。** 普通转发通常保留端到端源目的 IP，却需更新 TTL 与首部校验；NAT 是地址变化的例外。MTU 限制所承载整个 IP 包的大小，不能把它全部当数据空间，下表列出分片相关字段。

</div>

<div class="study-unit" id="u-04-441a8821684f">

| 字段 | 常考用途 |
| --- | --- |
| 版本 | IPv4 为 4，区别于协议字段 |
| 标识、DF、MF、片偏移 | 标识重组对象；DF（不分片）$=1$ 禁止分片；MF（更多分片）$=1$ 后面还有；偏移单位 8B |
| TTL（Time To Live，生存时间） | 转发递减到 0 丢弃，限制环路寿命 |
| 协议 | 上层：ICMP 1、TCP 6、UDP 17、OSPF 89 等 |
| 首部检验和 | 只检首部，TTL 改变后需重新计算 |
| 源 / 目的 IP | 跨普通路由转发通常不变，NAT 例外 |

</div>

### IP分片

<div class="study-unit" id="u-04-rewrite-f8b18eb6b15e">

IPv4 分片切的是原数据部分，每片另加首部。除最后片外，数据长度需是 8 的倍数，故最大数据长度为 **$8\lfloor(MTU-H)/8\rfloor$**；片偏移则是该片数据相对原数据起点的字节数除 8，不包含各片新首部。

</div>

<div class="study-unit" id="u-04-rewrite-e81cea872abb">

总长 4000 B、首部 20 B、MTU 1500 B 时，3980 B 数据分成 1480、1480、1020，偏移 0、185、370，MF 为 1、1、0。通常由最终主机重组；再次分片的偏移仍针对原始数据，原 MF 为 1 的片即使拆到自身末尾，最后子片也仍须表示后面还有原报文数据。

</div>

<div class="study-unit" id="u-04-b790673333c9">

$$\text{片偏移}=\frac{\text{该片数据在原数据中的起点}}{8}$$。

</div>

### IP地址划分

<div class="study-unit" id="u-04-rewrite-7ef4a0b9bd73">

地址前缀标明网络部分，剩余位区分该块中的主机位置。传统分类固定默认前缀，子网划分借更多位作网络号，CIDR 则用显式前缀统一表示不同大小的块。

</div>

<div class="study-unit" id="u-04-rewrite-2186501dc7e4">

**判断同子网看 IP 与掩码按位与的结果，不看十进制前三段是否相同。** 分配地址要检查块边界、网络和广播保留以及接口占用，路由查找还要另做最长前缀匹配。

</div>

<span class="legacy-anchor" data-target="s-04-4c635029cef1" id="s-50"></span><span class="legacy-anchor" data-target="s-04-4c635029cef1" id="p-227"></span><span class="legacy-anchor" data-target="s-04-4c635029cef1" id="p-228"></span><span class="legacy-anchor" data-target="s-04-4c635029cef1" id="u-04-39d3bc6d84ad"></span><span class="legacy-anchor" data-target="s-04-4c635029cef1" id="u-04-3450e62b2108"></span><span class="legacy-anchor" data-target="s-04-4c635029cef1" id="u-04-785f3ec7eb32"></span><span class="legacy-anchor" data-target="s-04-4c635029cef1" id="u-04-2235dc3dae7a"></span><span class="legacy-anchor" data-target="s-04-4c635029cef1" id="u-04-cf628f87dff3"></span><span class="legacy-anchor" data-target="s-04-4c635029cef1" id="u-04-3c6f78671fe8"></span>
<a id="s-04-4c635029cef1"></a>

#### 早期分类

<div class="study-unit" id="u-04-rewrite-ef9c8d1db07e">

传统 A、B、C 类分别常用 /8、/16、/24 默认网络部分，D 类用于组播，E 类保留；现代路由主要按 CIDR 前缀处理，不能仅按第一字节推导一切。

</div>

<div class="study-unit" id="u-04-rewrite-e097ae3fa801">

#### 定长子网划分

<div class="study-unit" id="u-04-rewrite-036dc2a2bb11">

</div>

<div class="study-unit" id="u-04-rewrite-632d634192c8">

#### 变长子网划分 CIDR

<div class="study-unit" id="u-04-rewrite-727c738975fb">

CIDR 用 IP/p 明确前 $p$ 位为网络前缀，网络地址通过按位与掩码求得，块尾把主机位全置 1。VLSM 按需求从大到小选最小足够的 2 次幂块，并按块大小对齐，确保互不重叠。

</div>

<span class="legacy-anchor" data-target="u-04-rewrite-a39c7156aae6" id="p-255"></span>
<div class="study-unit" id="u-04-rewrite-a39c7156aae6">

例如普通网络需 50 主机，至少 52 地址，选 64 地址的 /26，边界在末字节 0、64、128、192。路由聚合找连续且对齐块的共同前缀，不能忽略额外覆盖；**转发从所有匹配项选最长前缀，默认 /0 仅在无更具体项时使用**，前缀越长块越小、匹配越具体。

</div>

#### 网络地址转换 NAT

<div class="study-unit" id="u-04-rewrite-58cab558bf2d">

NAT 在内部地址与外部地址间建立映射，NAPT 再利用端口区分多个连接，使它们共用公网地址。出站改源 IP/端口，返回时查映射改目的 IP/端口，并相应处理校验信息。

</div>

<div class="study-unit" id="u-04-rewrite-e15a732289fe">

例如内网 `192.168.1.10:5000` 映成公网 `203.0.113.5:40001`，服务器回给公网 40001，网关再交回内网 5000。**映射记录内部与转换后端点，不是把内部地址配给远端目的地址**；公网主动入站通常需已有或显式配置的映射。

</div>

### IP地址解析 ARP

<div class="study-unit" id="u-04-rewrite-70da51c28b4b">

ARP 在当前链路把下一跳 IPv4 地址解析为 MAC，缓存无记录时广播询问，目标通常单播回应。它只解决本跳交付地址，不跨路由器广播寻找远端主机的 MAC。

</div>

<div class="study-unit" id="u-04-rewrite-1d73d58b8128">

**同网查目的主机，异网查网关下一跳。** A 发给异网 B，IP 目的仍为 B，第一帧目的却是网关 MAC；路由器取出 IP 包后为下一跳重新封帧，所以每跳 MAC 可变，端到端 IP 通常不变。

</div>

<span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="s-55"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="p-290"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="p-291"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-8c795d73cf05"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-670671cd9740"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-c9d1b300aba5"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-7f076f3c9b93"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-9809a55c70cd"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-26c8ebc20b02"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-10b9d5a6e893"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-ad923642e824"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-8027517ba01d"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-3d7546995166"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-aacd1bd43407"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-d5d35de1843a"></span><span class="legacy-anchor" data-target="s-04-d3163bcf6ada" id="u-04-3c9b0f31f817"></span>

### IP地址分配 DHCP

<div class="study-unit" id="u-04-rewrite-ae5d79a7edba">

DHCP 为主机分配地址、掩码、网关和 DNS 等配置，IPv4 常用 UDP 服务端 67、客户端 68。初次获取按 Discover、Offer、Request、ACK 进行，未有地址时客户端可从 0.0.0.0 向本地广播发送。

</div>

<div class="study-unit" id="u-04-rewrite-644ad2ddfbe1">

**回复单播还是广播取决于客户端状态和标志。** 地址还有租期与续租、拒绝及释放流程，跨网可通过 DHCP 中继而非任意转发广播；IPv6 另有 SLAAC 和 DHCPv6，不能将所有 DHCP 机制都等同于 IPv4 四步报文。

</div>

### IP报文控制 ICMP

<div class="study-unit" id="u-04-rewrite-8a52f18f01ad">

ICMP 封装在 IP 中，用于报告转发问题及网络诊断。目的不可达、时间超过、参数问题和重定向分别表达不同原因，Echo 请求和回答是 Ping 常用基础，具体见下表；历史源抑制类型已废弃。

</div>

<div class="study-unit" id="u-04-rewrite-13483f1f949a">

**Traceroute 逐次提高 TTL，让越来越远的路由器因 TTL 耗尽返回时间超过。** 最终响应依探测方式而异，UDP 高端口可能得到端口不可达，ICMP Echo 可能得到 Echo 回答。为避免递归与反馈放大，通常不对另一 ICMP 差错、广播组播和非首片等再发差错；限制针对差错报告，不能扩大为所有 ICMP 都不能发。

</div>

<div class="study-unit" id="u-04-aab7bd4265a6">

| 报文 | 什么时候使用 |
| --- | --- |
| 目的不可达 | 无法把数据报送到目的网络、主机或端口等，具体原因由代码字段区分 |
| 时间超过 | 数据报的 TTL 在途中耗尽，或重组等待超时 |
| 参数问题 | IP 首部存在无法正常处理的字段错误 |
| 重定向 | 路由器告知同一链路上的主机有更合适的下一跳 |
| Echo 请求 / 回答 | 检查对方是否可达，是常见 Ping 的工作基础 |

</div>

### IPv6

<div class="study-unit" id="u-04-rewrite-b18ba037b260">

IPv6 使用 128 位地址，基本首部固定 40 B，没有基本首部检验和，选项等由扩展首部承担。无广播，支持单播、组播和任播；Hop Limit 承担类似 TTL 的限制作用，路由器不替源端分片。

</div>

<div class="study-unit" id="u-04-rewrite-e0b83888bf23">

**地址简写只能使用一次 `::`，否则无法确定零组分布。** 邻居发现通过 ICMPv6 替代 ARP，接口标识不必由 MAC 构造；自动配置可用 SLAAC 或 DHCPv6，过渡可用双栈、隧道，不能从任意 IPv6 地址直接还原硬件地址。

</div>

### 路由算法和路由协议

<div class="study-unit" id="u-04-rewrite-4c53895dc00b">

静态路由由人工配置，动态路由通过交换信息适应变化。自治系统 AS 在统一管理和策略下运行，内部常用 RIP、OSPF，跨 AS 的 BGP 则体现可达性与策略。

</div>

<div class="study-unit" id="u-04-rewrite-cf6d8c917ead">

**三类算法交换的信息不同。** 距离向量告诉邻居到各目的多远，链路状态传播本地链路以形成拓扑，路径向量携带经过的 AS 等属性；不要把三者都概括成交换一张同样的路由表。

</div>

#### 路由信息协议 RIP

<div class="study-unit" id="u-04-rewrite-beaff47a95aa">

RIP 是自治系统内部的距离向量协议，常用 UDP 520，路由器向邻居交换到目的网络的跳数。有效距离最多 15，16 表示不可达；周期更新之外也可触发更新，故障后过期信息互相传播可能形成计数到无穷。

</div>

<div class="study-unit" id="u-04-rewrite-249e4371158e">

更新先将邻居距离加 1：本地没有目的就加入，**原下一跳就是该邻居时，即使变差也要跟随更新**；来自其他下一跳时，通常更短才替换。例如 B 报 3，A 经 B 为 4，B 后改报 6，原来依赖 B 的 A 必须改成 7，否则保留的是过期距离。

</div>

<div class="study-unit" id="u-04-rewrite-228d212d7435">

水平分割、毒性逆转等缓解环路，等价路径是否保留多条取决于实现。RIPv1 不带掩码，不能表达 VLSM/CIDR 所需无分类信息，不等于完全不能子网划分；RIPv2 带掩码，能支持无分类路由。下表把参数、更新条件和版本分开，便于对应计算。

</div>

<div class="study-unit" id="u-04-f40f53f6b4c1">

| 项目 | RIP 的规定 |
| --- | --- |
| 使用范围 | 自治系统内部的路由选择，即内部网关协议（IGP） |
| 距离度量 | 跳数，经过一台路由器通常增加 1 |
| 可达范围 | 有效距离最多 15 跳，16 表示不可达 |
| 传输方式 | 常见 IPv4 RIP 使用 UDP，端口为 520 |
| 更新方式 | 周期性向邻居交换路由信息；发生变化时也可触发更新 |

</div>

<div class="study-unit" id="u-04-1b3463a85314">

| 本地路由表的情况 | 更新规则 | 为什么 |
| --- | --- | --- |
| 没有这个目的网络 | 加入该目的网络和经该邻居的路由 | 获得了新的可达信息 |
| 原来就是经这个邻居转发 | 采用该邻居的新距离，即使距离变大 | 旧路由依赖它，必须跟踪它报告的变化 |
| 原来经其他邻居转发 | 新路由更短时才替换 | 已有路由更好时无需改走新路径 |

</div>

<div class="study-unit" id="u-04-4b541cb39a10">

| 版本 | 是否在通告中携带子网掩码 | 对路由划分的影响 |
| --- | --- | --- |
| RIPv1 | 不携带 | 不能支持 VLSM/CIDR 所需的无分类路由信息，不能据此断言它完全不支持子网划分 |
| RIPv2 | 携带 | 能表达不同长度的网络前缀，支持无分类路由 |

</div>

#### 开放最短路径优先协议 OSPF

<div class="study-unit" id="u-04-rewrite-94e334d69270">

OSPF 是链路状态 IGP，直接封装于 IP、协议号 89。路由器先用 Hello 发现邻居，需要建立邻接者再交换数据库摘要、请求缺项、发送更新并确认，使同一区域逐步形成一致拓扑，然后各自运行 Dijkstra 求总链路代价最小路径。

</div>

<div class="study-unit" id="u-04-rewrite-284988b4ca3d">

**传播的 LSA 是链路状态信息，LSU 是承载更新的报文，LSAck 是确认报文。** 它不像 RIP 主要向邻居报告到每个目的的距离，几种英文缩写不能混作同一种对象，下表单独说明其关系。

</div>

<div class="study-unit" id="u-04-rewrite-12e3f6a9aeee">

区域划分限制拓扑规模，骨干区域号为 0.0.0.0；ABR 连接区域，ASBR 处理与外部路由的边界。广播网络用 DR/BDR 减少完整邻接数量，**没有完整邻接不代表不是邻居**，其他路由器仍可通过 Hello 彼此发现。

</div>

<div class="study-unit" id="u-04-9763d1e67554">

| 名称 | 含义 | 相互关系 |
| --- | --- | --- |
| LSA：链路状态通告 | 描述链路、网络等状态的信息单元 | 是被传播的具体拓扑信息，不是整张路由表 |
| LSU：链路状态更新报文 | 承载更新信息的 OSPF 报文 | 一个 LSU 可以携带 LSA |
| LSAck：链路状态确认报文 | 确认收到相应通告 | 用于可靠传播中的确认 |

</div>

#### 边界网关协议 BGP

<div class="study-unit" id="u-04-rewrite-98b4a7f0c831">

BGP 用 TCP 179 建立会话，通告或撤销可达前缀及路径属性，按策略选路，不只追求最少跳。AS_PATH 记录 AS 路径，看到包含自身 AS 的通告可拒绝，帮助避免 AS 级环路。

</div>

<div class="study-unit" id="u-04-rewrite-c96ed20ecd0b">

OPEN 建关系，UPDATE 更新路由，KEEPALIVE 保活，NOTIFICATION 报错；eBGP 在不同 AS 间，iBGP 在同 AS 内传播 BGP 信息。**BGP 会话与某一条物理链路不同**，一次丢包不必然导致整个会话消失。

</div>

### 层次路由

<div class="study-unit" id="u-04-rewrite-ba8c24bd98a1">

层次路由让区域内维护详细关系，边界向外提供较概括信息，从而减少每台路由器需要处理的规模。AS 之间和内部可以采用不同策略与协议，OSPF 区域又在内部进一步分层。

</div>

<div class="study-unit" id="u-04-rewrite-ffd0c5cf283c">

**划层改变信息组织，不是把 IP 首部直接改成区域编号。** OSPF 的区域与 BGP 的 AS 也不是同一层概念，分析传播范围应先指出是哪一种边界。

</div>

<span class="legacy-anchor" data-target="s-04-outline-multicast" id="u-04-d2ec6d98c008"></span><span class="legacy-anchor" data-target="s-04-outline-multicast" id="u-04-63161b74db1f"></span><span class="legacy-anchor" data-target="s-04-outline-multicast" id="u-04-ca7d1f655db3"></span><span class="legacy-anchor" data-target="s-04-outline-multicast" id="u-04-6fdf3d9901fb"></span><span class="legacy-anchor" data-target="s-04-outline-multicast" id="u-04-750283cae30a"></span>

### IP组播

<div class="study-unit" id="u-04-rewrite-96fac83e9187">

IP 组播以一个组地址表示一组接收者，让网络在必要分支复制数据。IPv4 使用 D 类目的地址，IGMP 管理主机与本地组播路由器的成员关系，跨网分发还需组播路由机制。

</div>

<div class="study-unit" id="u-04-rewrite-190f105458fb">

IPv4 组播 MAC 常把 IP 低 23 位映射到 `01-00-5E` 前缀，映射会丢失部分地址信息。**多个 IP 组可对应同一 MAC，主机仍需在网络层过滤**；组播目的也不能当普通源地址使用。

</div>

<span class="legacy-anchor" data-target="s-04-outline-mobile-ip" id="u-04-ef435b72abf4"></span><span class="legacy-anchor" data-target="s-04-outline-mobile-ip" id="u-04-2c0da5c9b2e8"></span><span class="legacy-anchor" data-target="s-04-outline-mobile-ip" id="u-04-54bf456606eb"></span><span class="legacy-anchor" data-target="s-04-outline-mobile-ip" id="u-04-62b6592e5106"></span><span class="legacy-anchor" data-target="s-04-outline-mobile-ip" id="u-04-e5913a9a1157"></span>
<a id="s-04-outline-mobile-ip"></a>

### 移动IP

<div class="study-unit" id="u-04-rewrite-e16cd597c09f">

典型移动 IPv4 保留归属地址，在外地取得并登记转交地址，归属代理将发往归属地址的原包封装到隧道，送至外地再解封装。这样对方仍可使用稳定的归属地址联系移动主机。

</div>

<div class="study-unit" id="u-04-rewrite-9b67b853636e">

**内层目的为归属地址，外层目的才是转交地址。** 封装增加一层送往当前位置的运输，不是简单把原地址永久替换；这类网络层移动性与同网内切换 Wi-Fi AP 并非同一个问题。

</div>

<span class="legacy-anchor" data-target="s-04-e4de13a289f5" id="s-62"></span>
<a id="s-04-e4de13a289f5"></a>

### 路由器

<div class="study-unit" id="u-04-rewrite-7f989d7e03f3">

路由器从入口链路收帧，解出 IP 包，检查并查转发表，再通过交换结构和出口队列送往下一跳，最后按出口链路重新封帧。控制部分负责建立或维护转发所需信息。

</div>

<div class="study-unit" id="u-04-rewrite-3758be718ee8">

**选下一跳与解析下一跳 MAC 是两个步骤。** 路由表给前缀和出口，ARP 等机制解决本地链路交付；普通转发改变链路首部和 TTL，源目的 IP 通常保持。

</div>

#### 冲突域和广播域

<div class="study-unit" id="u-04-rewrite-ba4faf0e3c13">

集线器把端口连成共享冲突域，普通交换机隔离各端口的经典冲突域但默认仍转发广播，路由器与 VLAN 则形成广播边界。全双工点到点链路不存在经典共享介质碰撞。

</div>

<div class="study-unit" id="u-04-rewrite-4dac0256c01e">

**数域先在图上按传播边界分区，不直接数设备。** VLAN 配置、三层接口和集线器连接方式都会改变结果；一个交换机可以承载多个广播域，一个广播域也可跨多个交换机。

</div>

<span class="legacy-anchor" data-target="s-04-84f36ccbe52d" id="s-64"></span><span class="legacy-anchor" data-target="s-04-84f36ccbe52d" id="p-341"></span><span class="legacy-anchor" data-target="s-04-84f36ccbe52d" id="u-04-942561849470"></span><span class="legacy-anchor" data-target="s-04-84f36ccbe52d" id="u-04-aab37b084292"></span><span class="legacy-anchor" data-target="s-04-84f36ccbe52d" id="u-04-de3c352a140e"></span><span class="legacy-anchor" data-target="s-04-84f36ccbe52d" id="u-04-090796a0bf0f"></span><span class="legacy-anchor" data-target="s-04-84f36ccbe52d" id="u-04-e0d62cf167f8"></span><span class="legacy-anchor" data-target="s-04-84f36ccbe52d" id="u-04-61a0ac62c1d3"></span><span class="legacy-anchor" data-target="s-04-84f36ccbe52d" id="u-04-53b9e7ef6ea6"></span>
<a id="s-04-84f36ccbe52d"></a>

#### 路由器的功能

<div class="study-unit" id="u-04-rewrite-9297de3dd6dc">

输入端完成链路接收和拆帧，检查 IP 与 TTL，再按目的地址做最长前缀匹配选择下一跳、出口，经队列和交换结构送出。出口链路类型不同，封装格式也可不同。

</div>

<div class="study-unit" id="u-04-rewrite-d4b9b58df9f9">

**路由表不等于 ARP 表。** 普通 IPv4 转发每跳递减 TTL 并更新首部检验和，MAC 首部重写，端到端 IP 通常不变；若启用 NAT 等功能则另按其转换规则处理，不能把例外当普通逐跳行为。

</div>

<span class="legacy-anchor" data-target="s-04-a5d9f5c5c5ca" id="s-65"></span><span class="legacy-anchor" data-target="s-04-a5d9f5c5c5ca" id="u-04-61795a91b1b2"></span><span class="legacy-anchor" data-target="s-04-a5d9f5c5c5ca" id="u-04-9b2dd5c96044"></span>
<a id="s-04-a5d9f5c5c5ca"></a>

## 第五章 传输层

<div class="study-unit" id="u-04-rewrite-1c043ef36bb9">

网络层把包送到主机，传输层进一步把数据分用到应用端点。UDP 保留报文边界并保持较少机制，TCP 提供连接和可靠字节流，两者使用各自的端口空间。

</div>

<div class="study-unit" id="u-04-rewrite-c7ad45ba7033">

**TCP 的序号、确认、流量控制和拥塞控制围绕不同问题**：字节是否连续收到、对方还能收多少、网络还能承载多少，不能把所有窗口或所有 ACK 都理解成同一状态。

</div>

<span class="legacy-anchor" data-target="s-04-outline-e63a4dac6a" id="u-04-669b1a45267f"></span><span class="legacy-anchor" data-target="s-04-outline-e63a4dac6a" id="u-04-outline-2c862e3035"></span><span class="legacy-anchor" data-target="s-04-outline-e63a4dac6a" id="u-04-60467dcd2a81"></span><span class="legacy-anchor" data-target="s-04-outline-e63a4dac6a" id="u-04-5c7701a9b306"></span>
<a id="s-04-outline-e63a4dac6a"></a>

### 传输层服务与端口寻址

<div class="study-unit" id="u-04-rewrite-d5d30fd8938c">

端口标识传输层服务端点，使多个应用可以共用网络地址。发送端将多个应用数据复用到下层，接收端按协议和端口等信息分用，TCP 与 UDP 的同号端口也可分别使用。

</div>

<div class="study-unit" id="u-04-rewrite-e79736279d34">

**TCP 连接通常由源 IP、源端口、目的 IP、目的端口四元组区分。** 单个服务端端口可同时对应多个客户连接，不能只凭目的端口就判定整个连接身份，UDP 则不要求先建立这种连接过程。

</div>

<span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="s-66"></span><span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="p-353"></span><span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="p-354"></span><span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="u-04-8c8e49eec642"></span><span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="u-04-0847c7a969a1"></span><span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="u-04-e29c9c180c62"></span><span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="u-04-08b5e77e1ff7"></span><span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="u-04-d521276c1c16"></span><span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="u-04-fa518eec8f27"></span><span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="u-04-2dc80abe24df"></span><span class="legacy-anchor" data-target="s-04-f3112ce9e404" id="u-04-fda18561caa9"></span>
<a id="s-04-f3112ce9e404"></a>

### UDP数据报

<div class="study-unit" id="u-04-rewrite-cb7db98ac720">

UDP 无连接、面向报文，应用一次提交的数据保持报文边界；首部固定 8 B，四个 2 B 字段依次为源端口、目的端口、长度和检验和，长度包含首部与数据。

</div>

<div class="study-unit" id="u-04-rewrite-f974a6a77c94">

**UDP 本身不内置可靠重传、流控和拥塞控制，应用可以自行补充。** 它可用于单播、组播或广播，不意味着这些方式都可由 TCP 一样支持；目的端口无人监听时可能返回 ICMP 端口不可达。

</div>

### UDP检验

<div class="study-unit" id="u-04-rewrite-065174951f43">

UDP 检验包括伪首部、UDP 首部及数据，IPv4 伪首部共 12 B，包含源、目的 IP、零字段、协议号 17 和 UDP 长度，用于防止交付对象等发生错误，不作为 UDP 的额外内容单独发送。发送时检验字段置零，按 16 位反码加法求和，进位回卷，最后逐位取反；接收连检验字段一起求和。

</div>

<div class="study-unit" id="u-04-rewrite-3c3001c741ed">

**奇数字节末尾临时补零只为计算，不计入 UDP 长度。** IPv4 中字段零可表示未使用，计算值为零时发全 1；接收全 1 只表示未检出错误。IPv6 通常要求 UDP 检验，不能将 IPv4 的可省规则普遍套用。

</div>

### TCP报文段

<div class="study-unit" id="u-04-rewrite-542bb05a15a6">

### TCP连接管理

<div class="study-unit" id="u-04-rewrite-ad82413049a9">

TCP 两端要确认彼此初始序号并建立状态，发送结束时又分别关闭两个方向，因此建连和关闭不能只按报文数量机械记忆。应同时追踪发送方向、序号消耗和两端当前状态。

</div>

<div class="study-unit" id="u-04-rewrite-9064de2d9681">

**一次 FIN 只说明本方向无后续数据，对方仍可能继续发送。** TIME-WAIT 等状态也服务于重传和旧报文处理，不是单纯多等一段固定时间。

</div>

<span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="s-70"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="p-371"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="p-372"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-9f14025af006"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-a30e0626700b"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-906eb9fb3804"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-76d6c87e6938"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-9287f701bdfc"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-91d2a6c81925"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-ca27224231ba"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-explain-cf7e0b36fa"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-891d3e0ce16d"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-d70f4bc7c584"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-steps-38ab4e1a21"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-61449807deb2"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-f7086be50398"></span><span class="legacy-anchor" data-target="s-04-8bc0d5eef13c" id="u-04-5928120bce58"></span>
<a id="s-04-8bc0d5eef13c"></a>

#### 三次握手

<div class="study-unit" id="u-04-rewrite-9afb51c2c798">

客户先发 SYN、初始序号 $x$；服务器回 SYN+ACK，给出 $y$ 并确认 $x+1$；客户再确认 $y+1$，服务器收到后进入建立状态。双方各自提出序号，又各自得到对方确认。

</div>

<div class="study-unit" id="u-04-rewrite-f5fa50fb1d6e">

**SYN 消耗一个序号，纯 ACK 不消耗。** 第三段若无数据，客户后续首数据仍可从 $x+1$ 开始；理想客户约一 RTT 后可带数据，服务器收到第三段才完成建立，计时要注明起点和是否计发送延迟。

</div>

<div class="study-unit" id="u-04-f70d27a49dc6">

| 次序 | 客户→服务器 / 返回 | 状态与序号 |
| --- | --- | --- |
| 1 | $SYN=1$，$\mathrm{seq}=x$ | 客户 SYN-SENT；服务器先 LISTEN |
| 2 | $SYN=1$，$ACK=1$，$\mathrm{seq}=y$，$\mathrm{ack}=x+1$ | 服务器 SYN-RCVD |
| 3 | $ACK=1$，$\mathrm{seq}=x+1$，$\mathrm{ack}=y+1$ | 客户先 ESTABLISHED，服务器收到后 ESTABLISHED |

</div>

<a id="s-04-7a7c58176dc3"></a>

#### 四次挥手

<div class="study-unit" id="u-04-rewrite-cbbbde083cb1">

主动方先 FIN 关闭自己的发送方向，对方 ACK 后仍可发剩余数据；对方发送完再 FIN，主动方 ACK 并进入 TIME-WAIT，对方收到确认后关闭。ACK 与 FIN 有时可合并，报文不必永远恰好四个。

</div>

<div class="study-unit" id="u-04-rewrite-ab0936c4ae24">

**FIN 消耗序号，最终确认号应为对方 FIN 序号加 1。** 主动方保留 TIME-WAIT，既能重答丢失 ACK 导致的 FIN 重传，也让旧段有时间消失；标准教材 2MSL 等待与传送时间分开，不能当作任何关闭过程的总时长上界。

</div>

<div class="study-unit" id="u-04-cb98c6176d7c">

| 次序 | 报文 | 发送 / 接收状态 |
| --- | --- | --- |
| 1 客户→服务器 | $FIN=1$，$\mathrm{seq}=x$ | 客户 FIN-WAIT-1，服务器收后 CLOSE-WAIT |
| 2 服务器→客户 | $ACK=1$，$\mathrm{seq}=y$，$\mathrm{ack}=x+1$ | 客户收后 FIN-WAIT-2 |
| 3 服务器→客户 | $FIN=1$，$ACK=1$，$\mathrm{seq}=z$，$\mathrm{ack}=x+1$ | 服务器 LAST-ACK，客户收后 TIME-WAIT |
| 4 客户→服务器 | $ACK=1$，$\mathrm{seq}=x+1$，$\mathrm{ack}=z+1$ | 服务器收后 CLOSED；客户等 2MSL（两倍最大报文段生存时间）后 CLOSED |

</div>

### TCP可靠传输

<div class="study-unit" id="u-04-rewrite-9e83a03b806a">

TCP 通过字节序号、累计确认、校验、缓存和重传保证按序、不重复交付。失序段可以先缓存，但累计 ack 仍停在最早缺口，例如 100～149 已收到后 ack 为 150，即使再收到 200～249 也不能跳过缺失的 150～199。

</div>

<div class="study-unit" id="u-04-rewrite-0438f62d46f3">

**超时重传与快重传是两种触发。** RTO 根据往返样本及波动估计，重传样本可能有歧义；三个重复 ACK 可不等超时就重发缺口，首次同号 ACK 不算重复次数。SACK 能报告不连续已收区间，却不改变累计 ack 的基本含义，零窗口探测和 TIME-WAIT 又各有不同职责。

</div>

<a id="s-04-4a43092ab21e"></a>

### TCP流量控制

<div class="study-unit" id="u-04-rewrite-be7bfd19d8a4">

接收者通过 rwnd 通告可接收能力，发送者还受网络拥塞窗口 cwnd 约束，允许在途上限取两者较小值。**本次还能新发＝允许在途上限－已发未确认量**，窗口上限不等于剩余发送额度。

</div>

<div class="study-unit" id="u-04-rewrite-de432fcac6a5">

例如 rwnd 6000 B、cwnd 4000 B，已有 2500 B 在途，只能再发 1500 B。零窗口暂停普通新数据并用持续计时器探测，避免恢复通知丢失后互等；零窗口说明接收约束，不等于网络一定拥塞，窗口滑动也要等有效确认推进。

</div>

<span class="legacy-anchor" data-target="s-04-e86d6af8fb2a" id="s-74"></span><span class="legacy-anchor" data-target="s-04-e86d6af8fb2a" id="u-04-f21b72003c57"></span>
<a id="s-04-e86d6af8fb2a"></a>

### TCP拥塞控制

<div class="study-unit" id="u-04-rewrite-d7a25bf38697">

拥塞控制根据网络反馈限制注入量，流量控制则服从接收方缓存。分析时同时检查 cwnd、rwnd、已在途量以及采用的算法版本，才能确定真正可发数据。

</div>

<div class="study-unit" id="u-04-rewrite-e0b412260ed6">

**先确认题目是教材简化模型还是具体算法细节。** 初始窗口、丢包后门限和快恢复临时窗口会因约定不同而变化，不能把不同曲线规则混在同一计算里。

</div>

<span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="s-75"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="p-412"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="p-413"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-25826a2b61af"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-f0ee4cd83a87"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-16fb8da81d21"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-ade61ab0ff07"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-0b918943df09"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-65cd9dfb1e50"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-43f8260890ad"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-7dad9c920edb"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-9410b0e194d3"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-301f0a792630"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-bfc11a8e7e66"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-explain-42df787ae1"></span><span class="legacy-anchor" data-target="s-04-16d66afdcd8d" id="u-04-b06f6691cdf1"></span>

#### 慢开始和拥塞避免

<div class="study-unit" id="u-04-rewrite-baa4f95291e6">

教材简化模型常令初始 cwnd 为 1 MSS，慢开始每收到确认新数据的 ACK 增加约 1 MSS，满窗口连续确认使每 RTT 约翻倍；达到 ssthresh 后转为每 RTT 约加 1 MSS 的拥塞避免。

</div>

<div class="study-unit" id="u-04-rewrite-530763aa5b68">

**翻倍发生在一轮多次新确认累积后，不是每个 ACK 都翻倍。** 超时通常降低门限并回到较小窗口；实际门限可依据在途 FlightSize、算法另有初始值。画曲线先看横轴按 RTT 还是逐 ACK、是否受 rwnd 限制，并按题设处理跨门限时的增长。

</div>

#### 快恢复算法

<div class="study-unit" id="u-04-rewrite-5d172a0f4a82">

三个重复 ACK 表明后续数据仍有到达迹象，发送方可先快重传最早缺口，再按算法缩小拥塞窗口，避免像超时那样完全重新慢开始；这不证明网络完全没有拥塞。

</div>

<div class="study-unit" id="u-04-rewrite-1aa508e97acc">

**教材简化与 Reno 临时阶段要分开。** 简化曲线常直接减半进入拥塞避免，Reno 会临时设为 ssthresh 加 3 MSS，后续重复 ACK 膨胀，推进确认到达后再收缩。判断某时刻窗口必须说明观察的是哪个阶段。

</div>

## 第六章 应用层

<div class="study-unit" id="u-04-rewrite-6d7fc65177c0">

应用层把下层通信能力组织成域名解析、文件传输、邮件和网页等具体服务。每种协议的消息、连接和角色不同，端口号只是定位入口的一部分。

</div>

<div class="study-unit" id="u-04-rewrite-1662fb93b6ec">

**时间计算从依赖顺序出发。** 先解析地址、再按需建连、取基本内容，随后才能知道或请求依赖对象；缓存和已有连接会省去某些步骤，但需题目明确条件。

</div>

<span class="legacy-anchor" data-target="s-04-2e70d683088f" id="s-78"></span><span class="legacy-anchor" data-target="s-04-2e70d683088f" id="p-437"></span><span class="legacy-anchor" data-target="s-04-2e70d683088f" id="u-04-3d914f9348c9"></span><span class="legacy-anchor" data-target="s-04-2e70d683088f" id="u-04-789999d6f2b0"></span><span class="legacy-anchor" data-target="s-04-2e70d683088f" id="u-04-1ddd7adceb3a"></span><span class="legacy-anchor" data-target="s-04-2e70d683088f" id="u-04-9bdc33972629"></span><span class="legacy-anchor" data-target="s-04-2e70d683088f" id="u-04-f02d1fd0586a"></span><span class="legacy-anchor" data-target="s-04-2e70d683088f" id="u-04-73b16b7bb8ea"></span><span class="legacy-anchor" data-target="s-04-2e70d683088f" id="u-04-35741ce71ad2"></span>

### 网络应用模型 CS P2P

<div class="study-unit" id="u-04-rewrite-9967c5eee9a1">

C/S 模型由服务器持续提供服务，客户发请求，集中管理方便但可能形成瓶颈；P2P 让节点既请求又提供资源，分担负载，同时增加节点动态和协调难度。

</div>

<div class="study-unit" id="u-04-rewrite-28fbc4c8d294">

**角色是某次交互中的职责，不由设备名称永久决定。** P2P 也可有中心目录或协调节点，C/S 客户也可参与其他连接，混合应用不能只凭有没有服务器一刀切分类。

</div>

### 域名系统 DNS

<div class="study-unit" id="u-04-rewrite-d0eb006dfcce">

DNS 按层次管理域名与记录，解析器代客户查询并缓存，权威服务器回答其负责区的信息，根通常给下级指引。A 对应 IPv4，AAAA 对应 IPv6，CNAME 表别名，MX 指向邮件交换服务。

</div>

<div class="study-unit" id="u-04-rewrite-452e00cbf733">

**域名与 IP 不一一对应。** 一个名字可有多个地址，多个名字也可同址；缓存受 TTL 约束。DNS 常用端口 53，既可用 UDP 也可用 TCP，根服务器并不保存所有主机的最终地址。

</div>

<span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="s-80"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="p-443"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-7744d5f0aeed"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-260ff729d956"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-9012c0f4b54f"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-dd0ccce44235"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-957097a88fc6"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-c1342fdefdf3"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-73475cb40a56"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-92b4172bb52f"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-8737a8576c53"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-1b5df77f02cf"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-explain-4347948f9b"></span><span class="legacy-anchor" data-target="s-04-0ccb698db0f9" id="u-04-bd792b725fa3"></span>

#### 递归查询和迭代查询

<div class="study-unit" id="u-04-rewrite-24e17391828e">

递归请求让被询问者替自己继续查出最终答案，迭代请求则接受答案或下一级指引，由原请求者再问。主机通常递归请求本地解析器，解析器再迭代联系根、顶级与权威。

</div>

<div class="study-unit" id="u-04-rewrite-f114a05eaba8">

**数查询先确定谁发、问谁、是否命中缓存。** 本地已命中时外部查询可为零，但主机到本地仍有一次；域名每个点也不代表单独一次委派。耗时按实际串行往返相加，普通 UDP 查询不默认另加 TCP 握手。

</div>

### 文件传输协议 FTP

<div class="study-unit" id="u-04-rewrite-d5225ee2903f">

FTP 用 TCP 控制连接传命令和回复，数据连接另传文件或目录，两类流量分离，属于带外控制。控制服务常在服务器 21 端口，数据连接可以在一次会话中多次建立。

</div>

<div class="study-unit" id="u-04-rewrite-1d46a5e3ba21">

**控制与数据两条连接各有独立端点和过程。** 文本、二进制传输模式影响内容处理，不意味着 FTP 只能传 ASCII；主动、被动主要改变谁发起数据连接，见下一节。

</div>

<span class="legacy-anchor" data-target="s-04-def3ce8a69b0" id="s-82"></span><span class="legacy-anchor" data-target="s-04-def3ce8a69b0" id="p-457"></span><span class="legacy-anchor" data-target="s-04-def3ce8a69b0" id="u-04-a3dbd8fd39a3"></span><span class="legacy-anchor" data-target="s-04-def3ce8a69b0" id="u-04-d26077b95729"></span><span class="legacy-anchor" data-target="s-04-def3ce8a69b0" id="u-04-44cb730c4204"></span><span class="legacy-anchor" data-target="s-04-def3ce8a69b0" id="u-04-e863fa1e27f3"></span><span class="legacy-anchor" data-target="s-04-def3ce8a69b0" id="u-04-6d0bfbac74ee"></span><span class="legacy-anchor" data-target="s-04-def3ce8a69b0" id="u-04-dd8f6f83bb8c"></span><span class="legacy-anchor" data-target="s-04-def3ce8a69b0" id="u-04-7d8ca7e666b2"></span>
<a id="s-04-def3ce8a69b0"></a>

#### 工作模式

<div class="study-unit" id="u-04-rewrite-07fb5e2ff1cb">

主动模式由客户告诉服务器接收端口，服务器通常从 20 主动连接客户；被动模式由服务器公布临时数据端口，客户主动连接过去。两者控制连接仍通常连服务器 21。

</div>

<div class="study-unit" id="u-04-rewrite-33596e71818a">

**被动数据端口不固定为 20。** 它有利于客户在 NAT 或防火墙后主动建立连接，但“被动”只描述建连方向，没有自动加密或更高保密性的含义。

</div>

### 电子邮件 SMTP POP3

<div class="study-unit" id="u-04-rewrite-40bd8881b5e6">

邮件系统把提交、服务器间转送、邮箱保存和用户读取分成环节。SMTP 负责发送和转送，POP3 提供从邮箱读取，网页邮箱在浏览器这一段又可以使用 HTTP(S)。

</div>

<div class="study-unit" id="u-04-rewrite-4cff4d3bc2d6">

**同一邮件服务器在不同连接中可分别当客户和服务器。** 发件服务器向收件服务器发起 SMTP 时是客户，不能把整条邮件路径只画成一个固定客户到一个固定服务器。

</div>

<span class="legacy-anchor" data-target="s-04-5845687e1ed5" id="s-84"></span><span class="legacy-anchor" data-target="s-04-5845687e1ed5" id="p-465"></span><span class="legacy-anchor" data-target="s-04-5845687e1ed5" id="u-04-df2281bc47a7"></span><span class="legacy-anchor" data-target="s-04-5845687e1ed5" id="u-04-623d4f5c7d59"></span><span class="legacy-anchor" data-target="s-04-5845687e1ed5" id="u-04-71ee45a3c0db"></span><span class="legacy-anchor" data-target="s-04-5845687e1ed5" id="u-04-ab2ccf2fa3f3"></span><span class="legacy-anchor" data-target="s-04-5845687e1ed5" id="u-04-9bcafb0c2ee9"></span><span class="legacy-anchor" data-target="s-04-5845687e1ed5" id="u-04-cd866b967c32"></span>
<a id="s-04-5845687e1ed5"></a>

#### 邮件发送和读取协议

<div class="study-unit" id="u-04-rewrite-b5af265597b0">

发送方用户代理先提交到发件服务，服务器间通常经 SMTP 转送到收件邮箱，收件人再用 POP3 等读取。传统教材常用 SMTP TCP 25、POP3 TCP 110，端口与实际部署附加机制需按场景区分。

</div>

<div class="study-unit" id="u-04-rewrite-5212c7d43b56">

**读取不等于再次向外发送。** POP3 可配置取后删除或保留，网页界面与网站之间是 HTTP(S)，不代表服务器间邮件转送也因此换成 HTTP；分析协议要按每一段连接判断。

</div>

#### 多用途因特网邮件扩展 MIME

<div class="study-unit" id="u-04-rewrite-85118b794a22">

MIME 扩展邮件内容描述，用内容类型、传输编码和多部分边界承载非 ASCII 文本及附件。它告诉接收方怎样解释和还原内容，与 SMTP 负责运送的作用不同。

</div>

<div class="study-unit" id="u-04-rewrite-ada19ddd6721">

**Base64 是编码，不是加密。** 编码通常增加数据量，也不提供密钥保密；MIME 不是另一条独立运输连接协议，不能把附件能传送归因于它替代了 TCP 或 SMTP。

</div>

<span class="legacy-anchor" data-target="s-04-outline-f4e19f6120" id="u-04-32c6e77b2082"></span><span class="legacy-anchor" data-target="s-04-outline-f4e19f6120" id="u-04-outline-38b738a9ae"></span><span class="legacy-anchor" data-target="s-04-outline-f4e19f6120" id="u-04-b4f827a44759"></span><span class="legacy-anchor" data-target="s-04-outline-f4e19f6120" id="u-04-5900bed0d475"></span>
<a id="s-04-outline-f4e19f6120"></a>

### 电子邮件格式

<div class="study-unit" id="u-04-rewrite-9d5f96b9c6b7">

邮件由首部、空行和正文组成，From、To、Subject 描述显示身份、收件信息与主题，正文可由 MIME 进一步组织为多个部分。空行是区分首部与正文的重要结构。

</div>

<div class="study-unit" id="u-04-rewrite-556ba4349d1d">

**邮件显示首部与 SMTP 投递信封不同。** 真正路由投递依会话中的信封信息，不能仅凭 To 字段断言全部投递对象；Content-Type 和编码字段则负责说明内容怎样解析。

</div>

<span class="legacy-anchor" data-target="s-04-f711ced31347" id="s-86"></span><span class="legacy-anchor" data-target="s-04-f711ced31347" id="p-480"></span><span class="legacy-anchor" data-target="s-04-f711ced31347" id="u-04-a10041deb812"></span><span class="legacy-anchor" data-target="s-04-f711ced31347" id="u-04-concise-85"></span><span class="legacy-anchor" data-target="s-04-f711ced31347" id="u-04-65006fbf4ab2"></span><span class="legacy-anchor" data-target="s-04-f711ced31347" id="u-04-f6dc58507538"></span><span class="legacy-anchor" data-target="s-04-f711ced31347" id="u-04-582f37bbea83"></span>
<a id="s-04-f711ced31347"></a>

### 万维网 WWW

<div class="study-unit" id="u-04-rewrite-eefc39c818cb">

WWW 用 URL 定位资源、用超链接组织资源，浏览器向服务器请求页面及引用对象。URL 可含方案、主机、端口、路径和查询，HTTP 规定应用层请求与响应。

</div>

<div class="study-unit" id="u-04-rewrite-53f0dd7c842b">

**先拿到 HTML 才通常能发现其中引用对象。** 即使后续图片可并行下载，也不能在总时间计算一开始就假设浏览器已知道所有地址，进一步脚本或样式依赖还可能增加阶段。

</div>

<span class="legacy-anchor" data-target="s-04-0c13b55a39c6" id="s-87"></span><span class="legacy-anchor" data-target="s-04-0c13b55a39c6" id="p-481"></span><span class="legacy-anchor" data-target="s-04-0c13b55a39c6" id="u-04-d9be82583e0a"></span><span class="legacy-anchor" data-target="s-04-0c13b55a39c6" id="u-04-1da651e31562"></span><span class="legacy-anchor" data-target="s-04-0c13b55a39c6" id="u-04-87f0da236299"></span><span class="legacy-anchor" data-target="s-04-0c13b55a39c6" id="u-04-b3494f4714d8"></span><span class="legacy-anchor" data-target="s-04-0c13b55a39c6" id="u-04-00f018e5dd77"></span><span class="legacy-anchor" data-target="s-04-0c13b55a39c6" id="u-04-6483283331a4"></span>
<a id="s-04-0c13b55a39c6"></a>

#### HTTP协议特点

<div class="study-unit" id="u-04-rewrite-1d322937ce2b">

HTTP 语义无状态，应用通过 Cookie 或会话等保存交互状态；教材中说“无连接”不表示底层没有运输连接。HTTP/1.x 常用 TCP，1.0 典型非持续，1.1 默认可持续复用，流水请求则需另外说明。

</div>

<div class="study-unit" id="u-04-rewrite-fd9aaa6b7943">

**持续连接省重复握手，不自动让所有请求同时返回。** 非流水逐个等待，流水可连续提交但存在响应与依赖限制；这里讨论 HTTP/1.x 计时模型，不能扩成所有 HTTP 版本的传输行为。缓存命中又可省去部分网络获取。

</div>

<span class="legacy-anchor" data-target="s-04-5d53f9d10e40" id="s-88"></span><span class="legacy-anchor" data-target="s-04-5d53f9d10e40" id="p-482"></span><span class="legacy-anchor" data-target="s-04-5d53f9d10e40" id="u-04-f646c85cd9bf"></span><span class="legacy-anchor" data-target="s-04-5d53f9d10e40" id="u-04-cf08dee12aa3"></span><span class="legacy-anchor" data-target="s-04-5d53f9d10e40" id="u-04-811786ad1ae7"></span><span class="legacy-anchor" data-target="s-04-5d53f9d10e40" id="u-04-307a55c62f73"></span><span class="legacy-anchor" data-target="s-04-5d53f9d10e40" id="u-04-27072dc27ff3"></span><span class="legacy-anchor" data-target="s-04-5d53f9d10e40" id="u-04-b3fa3217ed16"></span>
<a id="s-04-5d53f9d10e40"></a>

#### HTTP报文结构

<div class="study-unit" id="u-04-rewrite-9214e0b8f9e4">

HTTP/1.x 请求以方法、目标、版本构成请求行，再跟首部、空行和可选实体；响应以版本、状态码等构成状态行，再跟首部、空行与实体。报文结构要按请求和响应分别识别。

</div>

<div class="study-unit" id="u-04-rewrite-2e3bd615a3e8">

GET 获取资源，HEAD 获取对应首部而不返回响应实体，POST 提交处理内容；Host 指目标服务主机。**状态码首位标识结果类别**，2xx 成功、3xx 重定向、4xx 请求侧问题、5xx 服务端问题，不能把所有非 200 都看成同一种失败。

</div>

<a id="s-04-4ad516ffdf0c"></a>

#### HTTP请求时间分析

<div class="study-unit" id="u-04-rewrite-bd66994e3a8a">

先列 DNS、必要建连、请求往返、传输和处理，再按依赖决定哪些串行、哪些能并行。新 TCP 连接的教材简化模型常为建连 1 RTT、取得小对象再 1 RTT，大对象还受带宽和窗口限制。

</div>

<div class="study-unit" id="u-04-rewrite-d5e3fe9a806d">

**基本 HTML 是发现引用对象的前置步骤。** 忽略其他开销、基本页加 $N$ 个独立小对象时，串行非持续为 $2(N+1)$ RTT，持续非流水为 $(N+2)$ RTT，允许理想流水可约 3 RTT；已有连接、有限并行、对象依赖或不同服务器 RTT 都会改变结果。下表只对应其列明的理想条件，不能脱离假设背常数。

</div>

<span class="legacy-anchor" data-target="u-04-dee893c1282b" id="p-507"></span>
<div class="study-unit" id="u-04-dee893c1282b">

| 连接方式 | 从首次建连开始的 RTT 开销 |
| --- | --- |
| 非持续、串行 | $2(N+1)\mathrm{RTT}$，每对象一建连一请求 |
| 持续、非流水 | $(N+2)\mathrm{RTT}$，一次建连，所有对象各一次请求 |
| 持续、流水 | 约 3RTT：建连 1、基本页 1、无进一步依赖引用对象批量 1 |
| 非持续、引用对象可无限并行 | 约 4RTT：基本页 2、引用批次建连+请求 2 |

</div>
