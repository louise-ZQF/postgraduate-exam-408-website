### 操作系统的功能

<div class="study-unit" id="u-03-6b86b273ff34">

操作系统（OS，Operating System）管理 CPU（中央处理器）、内存、文件、设备，向用户提供命令 / 图形接口，向程序提供系统调用。核心特征：并发、共享、虚拟、异步。

</div>

<div class="study-unit" id="u-03-db8d62687573">

- 并发是一段时间交替推进，并行是同一时刻执行；
- 共享分互斥共享和同时访问；
- 虚拟把有限物理资源抽象成多个逻辑资源；
- 异步指进程推进速度不可预知。
- 并发与共享相互依存。

</div>

<div class="study-unit" id="u-03-explain-1724e514a6">

**例子**

</div>

<div class="study-unit" id="u-03-4b95e0d347d2">

例：单核 CPU 快速切换两个进程，让它们在一段时间内都向前推进，是并发；两个核同一时刻各运行一个进程，是并行。多个进程都想用打印机体现共享，但实际打印还要排队，不能同时占用这台独占设备。

</div>

### 操作系统的分类

<div class="study-unit" id="u-03-d4735e3a265e">

| 类型 | 怎么运行 | 优缺点 / 目标 |
| --- | --- | --- |
| 单道批处理 | 内存一次一个作业，自动批量处理 | 自动但 I/O 等待时 CPU 闲，资源利用率低 |
| 多道批处理 | 多作业驻留，某个等待 I/O 时运行另一个 | 利用率 / 吞吐高，但交互响应差 |
| 分时 | 按时间片轮流服务用户 | 交互、较及时、公平，不以硬截止时间为保证 |
| 实时 | 按任务时限安排执行 | 硬实时必须满足关键截止时间，软实时容许有限超时 |

</div>

<div class="study-unit" id="u-03-54dc6ca310d2">

网络系统侧重通信与资源共享，分布式系统强调多机协同与一定透明性；实时不等于“平均速度快”。

</div>

### CPU的运行模式

<div class="study-unit" id="u-03-3e32e68ebcf7">

用户态不能执行受保护的特权操作，内核态可执行；模式由硬件状态控制。I/O 指令、修改中断允许状态和保护寄存器等通常为特权指令。

</div>

<div class="study-unit" id="u-03-c4a8c6fabc78">

- 用户态经异常、系统调用陷入、外中断等受控进入内核；
- 返回指令恢复原模式。
- 访管 / trap 是请求服务的非特权入口，不等于在用户态执行内核操作。
- 进入内核与切换进程是不同事件。

</div>

<span class="legacy-anchor" data-target="s-03-6f62f9d414f4" id="s-6"></span><span class="legacy-anchor" data-target="s-03-6f62f9d414f4" id="p-5"></span><span class="legacy-anchor" data-target="s-03-6f62f9d414f4" id="u-03-4b227777d4dd"></span><span class="legacy-anchor" data-target="s-03-6f62f9d414f4" id="u-03-9c7581459471"></span>

### 中断和异常处理

<div class="study-unit" id="u-03-908504f27c47">

外中断异步来自外设 / 时钟，通常在指令结束边界响应；异常由当前指令触发。缺页等可恢复故障处理后重执行当前指令，自陷通常继续下一指令，严重终止类可能无法恢复。

</div>

<div class="study-unit" id="u-03-98a24c3e9c69">

- 硬件保存必要断点和状态、转入处理入口，软件保存其他现场并处理。
- 普通关中断屏蔽可屏蔽外中断，不统一禁止异常和 NMI（不可屏蔽中断）。

</div>

### 系统调用过程

<div class="study-unit" id="u-03-ef2d127de37b">

执行：

</div>

<div class="study-unit" id="u-03-2b177336a1c1">

1. 用户程序准备调用号 / 参数。
2. 执行陷入指令。
3. 硬件转内核并保存返回状态。
4. 内核验证参数、查服务入口并执行。
5. 返回结果和用户态。

</div>

<div class="study-unit" id="u-03-477b4122b3b4">

- 系统调用可管理进程、文件、设备、内存、通信。
- 库函数可纯用户态执行，也可调用一个或多个系统调用；
- 普通 CALL 不必切内核态。
- 参数不一定都入栈，也可放寄存器，依接口约定。

</div>

### 程序内存映像与地址空间

<div class="study-unit" id="u-03-outline-84dbd030f8">

一个运行程序的用户虚拟地址空间通常包含代码段、已初始化数据、未初始化数据（BSS，Block Started by Symbol）、堆、栈及映射区域。

</div>

<div class="study-unit" id="u-03-98513b1287d0">

代码存指令，数据区存全局／静态变量，堆供动态分配，栈保存调用现场、局部变量和返回信息。

</div>

<div class="study-unit" id="u-03-403f663149fa">

逻辑／虚拟地址是程序看到的地址，物理地址是主存位置，由地址转换机制关联。

</div>

<div class="study-unit" id="u-03-98d89b318928">

- 不同进程可有相同虚拟地址却对应不同物理页；
- 只有显式共享等情形才可映射到同一物理区域。

</div>

<div class="study-unit" id="u-03-dda694b37823">

内存映像的具体布局及堆栈增长方向按题设。

</div>

<span class="legacy-anchor" data-target="s-03-aeed745efb9e" id="s-8"></span><span class="legacy-anchor" data-target="s-03-aeed745efb9e" id="p-7"></span>
<a id="s-03-aeed745efb9e"></a>

### 系统分层结构

<div class="study-unit" id="u-03-49e5e728bf2c">

单体 / 宏内核：多项服务在内核，直接调用快，但故障影响范围与耦合较大。微内核：保留基本调度 / 通信 / 低级内存等，把服务移用户态，通过消息协作，隔离扩展好但通信成本高。

</div>

<div class="study-unit" id="u-03-98290286df74">

- 分层结构限制层间依赖，便于调试；
- 模块化可按接口组合 / 动态加载功能。
- 外核提供受保护的底层资源，让应用库决定抽象。
- 不要以某产品名字替代结构定义，实际系统可能混合设计。

</div>

### 操作系统引导

<div class="study-unit" id="u-03-7e9085aec187">

传统 BIOS（基本输入输出系统）/ MBR（主引导记录）模型：

</div>

<div class="study-unit" id="u-03-701795ed6a26">

1. 固件上电自检、选启动设备。
2. 读 MBR 并执行引导、选择活动分区。
3. 读分区引导记录 PBR（Partition Boot Record）。
4. 装入启动管理器 / 内核。
5. 初始化管理结构、驱动和服务。

</div>

<div class="study-unit" id="u-03-676b456b9910">

- 引导代码通常在 ROM（只读存储器） / 固件和磁盘引导区；
- OS 内核最终装入主存执行。

</div>

<div class="study-unit" id="u-03-b2716e992b50">

UEFI（统一可扩展固件接口）/ GPT（全局唯一标识符分区表）流程不同，四阶段例子不能当成所有机器固定启动顺序。

</div>

### 虚拟机

<div class="study-unit" id="u-03-8f6d673acce9">

第一类监控器直接管理裸机资源；第二类运行在宿主 OS 上，如普通宿主应用。客户 OS 与宿主 OS 不同；虚拟磁盘可用宿主文件实现。

</div>

<div class="study-unit" id="u-03-4f7c2c3b5e7a">

- 监控器隔离虚拟 CPU / 内存 / 设备并处理特权访问。
- 虚拟机不等于进程，性能也不能只凭第一 / 第二类名称确定。

## 第二章 进程线程

<span class="legacy-anchor" data-target="s-03-2e65ca613464" id="s-12"></span><span class="legacy-anchor" data-target="s-03-2e65ca613464" id="p-10"></span><span class="legacy-anchor" data-target="s-03-2e65ca613464" id="p-11"></span>
<a id="s-03-2e65ca613464"></a>

### 进程的基本概念

<div class="study-unit" id="u-03-293486897236">

进程是程序的一次执行及资源、状态的集合；进程映像含代码、数据、PCB（进程控制块，Process Control Block）。

</div>

<div class="study-unit" id="u-03-0b8d8af667b3">

- 程序是静态代码，可多次执行形成不同进程；
- PCB 是 OS 识别管理进程的依据。

</div>

<div class="study-unit" id="u-03-877c23489fd1">

PCB 存标识、状态 / 调度信息、资源清单、寄存器与内存管理信息。

</div>

<div class="study-unit" id="u-03-5372f8b0caf0">

现代系统通常以进程分配资源、以内核线程调度；

</div>

<div class="study-unit" id="u-03-e161ae9827be">

- 线程共享进程地址空间 / 文件等，各有 PC（程序计数器）、寄存器状态、栈和 TCB（线程控制块，Thread Control Block）。

</div>

<a id="s-03-outline-57d3bb1a73"></a>

### 进程与线程的组织和控制

<div class="study-unit" id="u-03-outline-40c8fb3554">

操作系统用 PCB／TCB 保存管理信息，把就绪者放就绪队列、等待事件者放相应阻塞队列。创建时申请并初始化控制块和资源，撤销时释放；阻塞与唤醒改变状态及队列位置，应以原子方式维护相关结构。

</div>

<div class="study-unit" id="u-03-afc7e169e68d">

- 线程创建、退出、等待另一线程完成等也需要线程控制信息。
- 线程共享进程资源，但运行现场分别保存；
- 一次线程切换必须恢复目标线程的寄存器与栈，不能只换线程编号。

</div>

<span class="legacy-anchor" data-target="s-03-d6d61dd74ec3" id="s-13"></span><span class="legacy-anchor" data-target="s-03-d6d61dd74ec3" id="p-12"></span><span class="legacy-anchor" data-target="s-03-d6d61dd74ec3" id="p-13"></span><span class="legacy-anchor" data-target="s-03-d6d61dd74ec3" id="u-03-59e9af136cbb"></span><span class="legacy-anchor" data-target="s-03-d6d61dd74ec3" id="u-03-33dba29b4de5"></span><span class="legacy-anchor" data-target="s-03-d6d61dd74ec3" id="u-03-58386363e5d5"></span><span class="legacy-anchor" data-target="s-03-d6d61dd74ec3" id="u-03-8fe3ee4b25d0"></span><span class="legacy-anchor" data-target="s-03-d6d61dd74ec3" id="u-03-aac3acae4d4b"></span><span class="legacy-anchor" data-target="s-03-d6d61dd74ec3" id="u-03-d0648b5e148f"></span>
<a id="s-03-d6d61dd74ec3"></a>

### 进程的状态切换

<div class="study-unit" id="u-03-2c624232cdd2">

| 转换 | 触发 |
| --- | --- |
| 就绪→运行 | 调度取得 CPU |
| 运行→就绪 | 时间片用完 / 被抢占 |
| 运行→阻塞 | 主动等待 I/O 或事件 |
| 阻塞→就绪 | 所等事件完成，唤醒 |

</div>

<div class="study-unit" id="u-03-7aea3cc0ee54">

三态中阻塞不能直接到运行，就绪不能无故转阻塞。

</div>

<div class="study-unit" id="u-03-8477e1587581">

- 创建时申请 PCB / 资源、初始化并入队；
- 终止时回收资源和 PCB；
- 阻塞入事件等待队列，唤醒移入就绪队列。

</div>

<div class="study-unit" id="u-03-f9f3d08feb9a">

挂起表示调出内存，可分就绪挂起、阻塞挂起，不等于“等待 CPU”。

</div>

<div class="study-unit" id="u-03-explain-390b455dab">

- 就绪表示“其他运行条件已具备，只等 CPU”，阻塞表示“缺的还不是 CPU，而是数据或某个事件”。
- 例如进程发起磁盘读后等待数据，进入阻塞；
- 数据到达时只变为就绪，还要等调度后才能运行。

</div>

<a id="s-03-bcd02019c5aa"></a>

### 用户级内核级线程

<div class="study-unit" id="u-03-5da353d14fc7">

| 实现 / 模型 | 谁管理调度 | 优点 | 限制 |
| --- | --- | --- | --- |
| 用户级 / 多对一 | 用户线程库，内核只见进程 | 切换便宜，不必转内核 | 阻塞系统调用可阻塞整个进程，单个内核实体不能用多核并行 |
| 内核级 / 一对一 | 内核调度各线程 | 一个阻塞不必阻塞其他，可多核并行 | 创建切换开销较大 |
| 多对多 | 多个用户线程映射若干内核线程 | 结合灵活性与并行 | 实现较复杂 |

</div>

<div class="study-unit" id="u-03-98a0d6022572">

“用户线程阻塞必全阻塞”是多对一常见模型的结论；用户线程能共享变量不代表不用同步。线程在内核态执行系统调用，也可在用户态执行普通代码。

</div>

<div class="study-unit" id="u-03-explain-a4901a12b1">

- 多对一模型中，内核只看到一个可调度实体；
- 它因阻塞调用睡眠时，用户线程库也没有机会再运行其他线程。
- 一对一模型把每个线程交给内核分别调度，内核才能在其中一个等待时继续运行另一个。

</div>

### 进程的通信方式

<div class="study-unit" id="u-03-20e6118d7eb0">

共享存储：双方映射同一物理区域，直接读写，需同步互斥，减少额外复制。消息传递：send / receive，直接给目标进程或经信箱间接通信。

</div>

- 管道：有限缓冲的字节流，典型单向 / 半双工，空读等待、满写等待；

- 匿名管道常用于有亲缘关系进程，命名管道可无亲缘；
- 多读者对同一流会分走数据，不能保证各自收到完整副本。

### 三级调度

<div class="study-unit" id="u-03-4a44dc153642">

高级 / 作业调度：后备作业→内存，决定接纳；中级 / 内存调度：挂起进程→恢复内存，控制驻留数量；低级 / 进程调度：就绪→CPU，最频繁且必需。

</div>

<div class="study-unit" id="u-03-f212d2c75ddd">

- 挂起与阻塞不同，阻塞进程也可能驻留内存。
- 中级调度不是从就绪队列挑下一运行者。

</div>

### 进程调度

<span class="legacy-anchor" data-target="s-03-8e7d2d8e7ed6" id="s-18"></span><span class="legacy-anchor" data-target="s-03-8e7d2d8e7ed6" id="p-22"></span><span class="legacy-anchor" data-target="s-03-8e7d2d8e7ed6" id="u-03-f768e1dea4dd"></span><span class="legacy-anchor" data-target="s-03-8e7d2d8e7ed6" id="u-03-60ca7488eb43"></span><span class="legacy-anchor" data-target="s-03-8e7d2d8e7ed6" id="u-03-b35f26f3280d"></span><span class="legacy-anchor" data-target="s-03-8e7d2d8e7ed6" id="u-03-d65206f3b22f"></span><span class="legacy-anchor" data-target="s-03-8e7d2d8e7ed6" id="u-03-6b51d431df5d"></span>

#### 进程上下文

<div class="study-unit" id="u-03-0678afb26796">

上下文含 PC、寄存器、栈指针、状态及地址空间等。切换执行：

</div>

<div class="study-unit" id="u-03-77a6c2c6f236">

1. 保存当前状态。
2. 更新 PCB / 队列。
3. 选择下一实体。
4. 恢复其状态与地址空间。
5. 继续。

</div>

<div class="study-unit" id="u-03-ab9d4556de0a">

- 模式切换只改特权级，不一定换进程；
- 进程切换通常还换地址空间，同进程线程切换通常不换地址空间，但仍需保存寄存器 / 栈。

</div>

#### 调度的方式

<div class="study-unit" id="u-03-4e7a11b5e1db">

非抢占：运行者直到结束、阻塞或主动放弃 CPU 才换。抢占：时间片或更高优先级任务到来时可夺取 CPU，交互响应更好但切换成本与同步要求较高。

</div>

<div class="study-unit" id="u-03-75e36022f87e">

- 算法名字与抢占版本要配套，如 SJF 常为非抢占，SRTF 为抢占；
- 优先级调度可有两版本。

</div>

<span class="legacy-anchor" data-target="s-03-7b4790c0e905" id="s-20"></span><span class="legacy-anchor" data-target="s-03-7b4790c0e905" id="p-24"></span><span class="legacy-anchor" data-target="s-03-7b4790c0e905" id="u-03-bcad0c358893"></span><span class="legacy-anchor" data-target="s-03-7b4790c0e905" id="u-03-54e2e7f553a1"></span><span class="legacy-anchor" data-target="s-03-7b4790c0e905" id="u-03-7fc1d0afdadf"></span>
<a id="s-03-7b4790c0e905"></a>

#### 调度和不可调度的时机

<div class="study-unit" id="u-03-363aa6604502">

通常在结束 / 阻塞、时间片结束、就绪变化等时机调度。执行中断处理、关中断原子段、关键内核临界区等教材情形不可任意切换。

</div>

<div class="study-unit" id="u-03-757a97477c54">

- 用户临界区不等于禁止调度：锁还在，别的进程可运行，但不能进入同一互斥区。
- 退出中断可能触发调度，不能把“中断过程不可调度”推广成“中断永远不会导致切换”。

</div>

<a id="s-03-outline-4001616c9c"></a>

### 调度器与闲逛进程

<div class="study-unit" id="u-03-outline-11cccd0772">

调度器按算法从可运行实体中选择下一个，分派和上下文切换负责把 CPU 交给它。内核级线程由内核调度，用户级线程由线程库在已获得的运行机会中选择。

</div>

<div class="study-unit" id="u-03-3dd9cf575f90">

- 没有普通就绪任务时运行闲逛进程（idle process），可执行等待中断等动作；
- 它不是阻塞进程的替代品，也不意味着有正在完成的用户任务。
- 新任务就绪后，按调度规则离开闲逛状态。

</div>

### 调度算法

<div class="study-unit" id="u-03-3fdba35f04dc">

<span class="legacy-anchor" data-target="s-03-3d7d43a1b041" id="s-22"></span><span class="legacy-anchor" data-target="s-03-3d7d43a1b041" id="p-25"></span><span class="legacy-anchor" data-target="s-03-3d7d43a1b041" id="p-26"></span>
<a id="s-03-3d7d43a1b041"></a>

#### 评价指标

<div class="study-unit" id="u-03-24e10ff8f36f">

$\text{周转时间}=\text{完成时刻}-\text{提交时刻}$；

</div>

<div class="study-unit" id="u-03-5565c89793eb">

- $\text{带权周转时间}=\frac{\text{周转时间}}{\text{服务时间}}$；
- 平均量分别求平均，不能用平均周转除平均服务替代平均带权周转。

</div>

<div class="study-unit" id="u-03-349ae0910ce7">

- 等待时间统计等待 CPU 的时间，不计 I/O 阻塞；
- $\text{响应时间}=\text{首次响应时刻}-\text{提交时刻}$，不是全部完成。

</div>

<div class="study-unit" id="u-03-359ba3075baf">

$\text{CPU利用率}=\frac{\text{忙碌时间}}{\text{总时间}}$，吞吐量＝单位时间完成作业数。

</div>

<div class="study-unit" id="u-03-4383e0fc41aa">

甘特图先按到达、阻塞和抢占规则排，再算指标。

</div>

<div class="study-unit" id="u-03-explain-1c86255acc">

**例子**

</div>

<div class="study-unit" id="u-03-6de93b84f50c">

例：某作业 0 时刻提交、3 时刻首次运行，累计 CPU 服务 4、I/O 阻塞 2，到 10 时刻完成：周转$=10$，带权周转$=\frac{10}{4}=2.5$，等待 CPU 的时间$=10-4-2=4$；若以首次获得 CPU 算响应，响应时间为 3。

</div>

<span class="legacy-anchor" data-target="s-03-01d32d99dfca" id="s-23"></span><span class="legacy-anchor" data-target="s-03-01d32d99dfca" id="p-27"></span><span class="legacy-anchor" data-target="s-03-01d32d99dfca" id="p-28"></span><span class="legacy-anchor" data-target="s-03-01d32d99dfca" id="p-29"></span><span class="legacy-anchor" data-target="s-03-01d32d99dfca" id="p-30"></span><span class="legacy-anchor" data-target="s-03-01d32d99dfca" id="p-31"></span><span class="legacy-anchor" data-target="s-03-01d32d99dfca" id="p-32"></span><span class="legacy-anchor" data-target="s-03-01d32d99dfca" id="p-33"></span><span class="legacy-anchor" data-target="s-03-01d32d99dfca" id="p-34"></span>
<a id="s-03-01d32d99dfca"></a>

#### 基础调度算法

<div class="study-unit" id="u-03-a2d1a4c74a6a">

| 算法 | 每次如何选择 | 优点 | 缺点 |
| --- | --- | --- | --- |
| FCFS（先来先服务） | 就绪队列按到达顺序，非抢占 | 简单、不会因不断新来短任务饥饿 | 长任务拖住短任务，护航效应 |
| SJF（短作业优先） | 选预计服务时间最短，常非抢占 | 同时到达等条件下平均等待较小 | 需估计时长，长任务可饥饿 |
| SRTF（最短剩余时间优先） | 选剩余时间最短，新来更短者抢占 | 改善短任务等待 | 长任务可饥饿，抢占开销 |
| HRRN（高响应比优先） | 每轮选 (等待+服务)/服务 最大者，非抢占 | 兼顾短任务与等待长者 | 需估计服务时间并反复计算比值 |
| RR（时间片轮转，Round Robin） | 队头运行一个时间片，未完成放队尾 | 公平、交互响应好 | 片太短切换多，太长趋 FCFS |
| 优先级 | 选最高优先级，可抢占或非抢占 | 体现重要性 | 低级任务可饥饿，老化可缓解 |

</div>

<div class="study-unit" id="u-03-ce9ff5b7f9c4">

每次选择只从已经到达且就绪的任务中选，不能把未到达短任务提前运行。HRRN 的响应比不是“响应时间”。

</div>

<div class="study-unit" id="u-03-explain-96d62a88dd">

HRRN 会随着等待增加而提高优先程度。

</div>

<div class="study-unit" id="u-03-97425431f10a">

**例子**

</div>

<div class="study-unit" id="u-03-38c6135fcd6e">

例如 A 等待 6、需服务 3，响应比为 $\frac{6+3}{3}=3$；B 等待 2、需服务 1，比值同为 3，平局按题设处理。

</div>

<div class="study-unit" id="u-03-2e68bf9e0b68">

RR 则给各任务轮流一个时间片，未完成者回队尾，已完成者直接离队。

</div>

<span class="legacy-anchor" data-target="s-03-6fa0d28efcd5" id="s-24"></span><span class="legacy-anchor" data-target="s-03-6fa0d28efcd5" id="p-35"></span><span class="legacy-anchor" data-target="s-03-6fa0d28efcd5" id="u-03-28f292ed69a3"></span><span class="legacy-anchor" data-target="s-03-6fa0d28efcd5" id="u-03-8527a891e224"></span>
<a id="s-03-6fa0d28efcd5"></a>

#### 多级队列调度算法

<div class="study-unit" id="u-03-3aa77076407d">

按类型把进程固定划入不同就绪队列，各队列可有不同算法；队列间用固定优先级或分配时间份额。

</div>

<div class="study-unit" id="u-03-b69b7c2786e5">

- 高优先级队列一直忙会使低队列饥饿；
- 固定分组中进程通常不因运行表现转队列，这是与反馈队列的重要区别。

</div>

#### 多级反馈队列调度算法

<div class="study-unit" id="u-03-b139f41bb9e4">

新任务进最高队列；高队列时间片短，低队列更长；每次先服务最高非空队列。一个片未完成则降级，较低队列运行时高队列来任务可抢占。

</div>

<div class="study-unit" id="u-03-4389e423d8c7">

- 短 / 交互任务响应好，长任务逐渐到低队列，兼顾多类负载；
- 持续高队列流量可使低队列饥饿，用老化 / 周期提升缓解。
- 画队列时“被高队列抢占”与“耗尽本片降级”分清，具体规则依题设。

</div>

<div class="study-unit" id="u-03-explain-64285e456a">

**例子**

</div>

<div class="study-unit" id="u-03-3822871e5679">

例：三个队列时间片为 1、2、4，新任务先在第一队列运行 1 个单位；若未结束且用完片，则进第二队列，再用完 2 个单位后降入第三队列。

</div>

<div class="study-unit" id="u-03-90628a6d7c2a">

高队列后来出现任务时可先服务它，但低队列被抢占后剩余片怎么处理，要按题目约定。

</div>

#### 多处理机调度

<div class="study-unit" id="u-03-350f6b783ef4">

多 CPU 可共用全局就绪队列，或每核独立队列。负载均衡在繁忙与空闲核间迁移任务；处理机亲和尽量在原核运行，保留 Cache（高速缓存） / TLB（快表）局部性。

</div>

<div class="study-unit" id="u-03-3777a734f989">

- 推迁移由忙核主动转出，拉迁移由空闲核取任务。
- 过度迁移有缓存失效成本，不能只看队列长度。

</div>

<span class="legacy-anchor" data-target="s-03-9775f73be7b1" id="s-27"></span><span class="legacy-anchor" data-target="s-03-9775f73be7b1" id="p-38"></span><span class="legacy-anchor" data-target="s-03-9775f73be7b1" id="u-03-66e3db6a30f2"></span><span class="legacy-anchor" data-target="s-03-9775f73be7b1" id="u-03-b17ef6d19c7a"></span>
<a id="s-03-9775f73be7b1"></a>

### 同步互斥的概念

<div class="study-unit" id="u-03-9092b24a4d09">

互斥：同一时刻至多一个执行者使用临界资源；同步：保证合作执行的先后关系。临界区是访问临界资源的代码，临界资源是共享对象，二者不同。

</div>

<div class="study-unit" id="u-03-6592ba7e1deb">

- 互斥实现通常要求空闲让进、忙则等待、有限等待；
- 让权等待是不满足进入条件时阻塞释放 CPU，不是自旋。

</div>

<div class="study-unit" id="u-03-explain-26e07aba86">

**例子**

</div>

<div class="study-unit" id="u-03-dbe2b8c4a6c1">

例：两个进程修改同一计数器，需要互斥，防止都读到旧值而丢一次更新；消费者必须等生产者放入产品后再取，需要同步。同一问题可能同时需要“不能一起做”和“必须按次序做”两种约束。

### 互斥的软件实现

<span class="legacy-anchor" data-target="s-03-446e48fb041e" id="s-29"></span><span class="legacy-anchor" data-target="s-03-446e48fb041e" id="p-40"></span><span class="legacy-anchor" data-target="s-03-446e48fb041e" id="u-03-e8454f808f9b"></span><span class="legacy-anchor" data-target="s-03-446e48fb041e" id="u-03-c33b73fac001"></span><span class="legacy-anchor" data-target="s-03-446e48fb041e" id="u-03-6203c84335bf"></span>

#### 单标志法

<div class="study-unit" id="u-03-4523540f1504">

单标志 turn 指定轮到谁；自己的回合才能进入，退出把 turn 交给对方。

</div>

<div class="study-unit" id="u-03-5b9a4bad46b2">

- 能互斥，但严格轮流：对方不想进入时自己也可能被挡住，违背空闲让进。
- 不能因为 turn 存在就说一定公平高效。

#### 皮特森算法

<div class="study-unit" id="u-03-f5ca38f748a1">

Peterson 两进程算法：先声明想进入，再让对方优先，等待条件必须是 **对方想进 AND 轮到对方**。

</div>

<div class="study-unit" id="u-03-4a58b0f22fce">

~~~c
flag[i] = true;
turn = j;
while (flag[j] && turn == j) { }  // 不能写成 OR
// 临界区
flag[i] = false;
~~~

</div>

<div class="study-unit" id="u-03-16697dddf8d9">

- 在原子读写及相应内存顺序假设下实现互斥、空闲让进、有限等待；
- 忙等待不满足让权等待。
- 现代弱内存机器直接照写需内存同步支持。

</div>

<div class="study-unit" id="u-03-explain-61d777e60e">

$flag[i]=true$ 是声明“我想进去”，$turn=j$ 是在竞争时让对方先。

</div>

<div class="study-unit" id="u-03-8776218638e7">

- 两者都想进时，turn 只能取一个值，因此只有一方持续满足等待条件；
- 如果对方根本不想进，$flag[j]=false$，自己就不会被 turn 单独挡住。

</div>

#### 总结

<div class="study-unit" id="u-03-1277a9dfcde3">

单标志被严格轮流限制；先检查双标志存在两者同时进入竞态；后检查双标志可能两者都等；Peterson 用 $flag+turn$ 协调进入次序。四种都是软件自旋方案，不因循环短就算让权等待。

### 互斥的硬件实现

<span class="legacy-anchor" data-target="s-03-c8fc3db1c471" id="s-35"></span><span class="legacy-anchor" data-target="s-03-c8fc3db1c471" id="p-46"></span><span class="legacy-anchor" data-target="s-03-c8fc3db1c471" id="u-03-1549c530cd0c"></span><span class="legacy-anchor" data-target="s-03-c8fc3db1c471" id="u-03-0992872ef410"></span><span class="legacy-anchor" data-target="s-03-c8fc3db1c471" id="u-03-4ff162168690"></span>
<a id="s-03-c8fc3db1c471"></a>

#### 中断屏蔽字

<div class="study-unit" id="u-03-f757daacc80c">

单 CPU 内核可在关键区屏蔽中断，避免本 CPU 被中断导致竞争；用户态通常无权这么做。多核上关本 CPU 中断不能阻止另一核同时访问，因此不能作为通用跨核互斥锁。

</div>

<span class="legacy-anchor" data-target="s-03-fc9d0b5f3f11" id="s-36"></span><span class="legacy-anchor" data-target="s-03-fc9d0b5f3f11" id="p-47"></span><span class="legacy-anchor" data-target="s-03-fc9d0b5f3f11" id="u-03-bfc88bcf73e8"></span><span class="legacy-anchor" data-target="s-03-fc9d0b5f3f11" id="u-03-9c1737776d14"></span><span class="legacy-anchor" data-target="s-03-fc9d0b5f3f11" id="u-03-140c261dd33c"></span><span class="legacy-anchor" data-target="s-03-fc9d0b5f3f11" id="u-03-8d9052805fea"></span>
<a id="s-03-fc9d0b5f3f11"></a>

#### TestAndSet指令

<div class="study-unit" id="u-03-6b36cb798fde">

TestAndSet 原子地“返回旧值并置 true”；若旧值 false，则取得锁，若 true 则自旋。

</div>

<div class="study-unit" id="u-03-dd8080bb7fc4">

~~~c
while (TestAndSet(&lock)) { }
// 临界区
lock = false;
~~~

</div>

<div class="study-unit" id="u-03-280d617fea97">

- 可保证互斥，但一般不保证有限等待，也不让权；
- 锁的释放须遵循内存同步要求，不能把普通读写两步当原子 TestAndSet。

</div>

<span class="legacy-anchor" data-target="s-03-ac73a6b1a2a8" id="s-37"></span><span class="legacy-anchor" data-target="s-03-ac73a6b1a2a8" id="p-48"></span><span class="legacy-anchor" data-target="s-03-ac73a6b1a2a8" id="u-03-cd553a5f6bb0"></span><span class="legacy-anchor" data-target="s-03-ac73a6b1a2a8" id="u-03-6f4b6612125f"></span><span class="legacy-anchor" data-target="s-03-ac73a6b1a2a8" id="u-03-d708ebcf76db"></span>
<a id="s-03-ac73a6b1a2a8"></a>

#### Swap指令

<div class="study-unit" id="u-03-57739a2a4d57">

Swap 原子交换共享 lock 与本地 key。$key=true$，反复交换；换出旧 $lock=false$ 时取得锁，退出置 $lock=false$。

</div>

<div class="study-unit" id="u-03-64198d809c62">

- 只要原子交换就可互斥，但仍可能忙等待、缺少公平性。
- 普通临时变量三次赋值不等于硬件原子 Swap。

</div>

### 互斥锁

<div class="study-unit" id="u-03-356886bfb456">

互斥锁 acquire 后进临界区，release 后退出；忙时自旋的叫自旋锁，忙时睡眠的会阻塞让出 CPU。

</div>

<div class="study-unit" id="u-03-0f2cd9323cb9">

- 锁保护的是所有遵守同一协议的访问，忘记释放、锁顺序相反都可能死锁。
- 临界区短且多核等待短时自旋可减少切换成本，长等待不宜一直占 CPU。

</div>

<span class="legacy-anchor" data-target="s-03-e3a38a5955eb" id="s-39"></span>
<a id="s-03-e3a38a5955eb"></a>

### 信号量

<div class="study-unit" id="u-03-concise-38">

信号量用原子 P / V 操作表示资源计数或先后约束。互斥量初值通常 1，资源量初值为资源数，先后同步量初值通常 0。P 请求 / 等待，V 释放 / 通知，不能用普通加减代替原子操作。

</div>

<span class="legacy-anchor" data-target="s-03-56f2f7610f89" id="s-40"></span><span class="legacy-anchor" data-target="s-03-56f2f7610f89" id="p-50"></span><span class="legacy-anchor" data-target="s-03-56f2f7610f89" id="u-03-453e673f8879"></span>
<a id="s-03-56f2f7610f89"></a>

#### 整型信号量

<div class="study-unit" id="u-03-613b1d3863b5">

整型信号量：P 反复检查 S>0，满足后原子减 1；V 原子加 1。可控制进入数量，但等待者自旋，不满足让权等待；检查与减 1 必须整体受保护。

</div>

<span class="legacy-anchor" data-target="s-03-0cac2dcd239e" id="s-41"></span><span class="legacy-anchor" data-target="s-03-0cac2dcd239e" id="p-51"></span><span class="legacy-anchor" data-target="s-03-0cac2dcd239e" id="u-03-22e31be9b2e0"></span><span class="legacy-anchor" data-target="s-03-0cac2dcd239e" id="u-03-369256d1ce6e"></span>
<a id="s-03-0cac2dcd239e"></a>

#### 记录型信号量

<div class="study-unit" id="u-03-94014b533a41">

记录型信号量含 value 和等待队列。P 先 value−−，若 value<0 则阻塞并入队；V 先 value++，若 $value\le 0$ 则唤醒一个等待者。

</div>

<div class="study-unit" id="u-03-d00b25712d29">

- value>0 是剩余资源，value<0 的绝对值是等待数量；
- 0 表示没有空闲且此时无计入的等待者。
- 信号量可负，V 不保证唤醒者马上取得 CPU。

</div>

<div class="study-unit" id="u-03-explain-e240b95c03">

**例子**

</div>

<div class="study-unit" id="u-03-f89f8826e248">

例：初值为 1，A 执行 P 后 $value=0$，拿到资源；B 再 P 后 $value=-1$，入队阻塞。

</div>

<div class="study-unit" id="u-03-1a5446029d22">

A 执行 V 后 $value=0$，并把资源机会交给被唤醒的 B，所以此时 0 不代表又多出一个空闲资源。

</div>

<span class="legacy-anchor" data-target="s-03-9e3c7f892dfe" id="s-42"></span><span class="legacy-anchor" data-target="s-03-9e3c7f892dfe" id="p-52"></span><span class="legacy-anchor" data-target="s-03-9e3c7f892dfe" id="u-03-c2e5e914d586"></span>
<a id="s-03-9e3c7f892dfe"></a>

#### 利用信号量实现互斥

<div class="study-unit" id="u-03-9cd35939911f">

过程：

</div>

<div class="study-unit" id="u-03-69c986055632">

- 互斥信号量初值为 `mutex=1`；
- 所有竞争者都按 **P(mutex) → 临界区 → V(mutex)** 执行。
- P 申请进入资格，V 在退出时释放；
- 未取得资格的进程等待。

</div>

<div class="study-unit" id="u-03-249c81dbedf8">

P 与 V 在同一控制路径配对，不能在临界区内忘记退出释放。

</div>

<div class="study-unit" id="u-03-2bb9b1b4eb30">

多个资源锁还要统一申请顺序，单个互斥量正确不代表全系统无死锁。

</div>

<span class="legacy-anchor" data-target="s-03-52cc3d7d8a3e" id="s-43"></span><span class="legacy-anchor" data-target="s-03-52cc3d7d8a3e" id="p-53"></span><span class="legacy-anchor" data-target="s-03-52cc3d7d8a3e" id="u-03-70fa950adb72"></span>
<a id="s-03-52cc3d7d8a3e"></a>

#### 利用信号量实现同步

<div class="study-unit" id="u-03-f4c92a418847">

保证 A 完成后 B 才能做：同步量 $s=0$；A 完成后 V(s)，B 开始前 P(s)。若 B 先到就阻塞；A 先到，计数保存通知，B 后到可通过。

</div>

<div class="study-unit" id="u-03-72a880e549c8">

“前 V 后 P”，而不是用互斥量初值 1 来保证固定先后关系。

</div>

<span class="legacy-anchor" data-target="s-03-45fe1bfaa294" id="s-44"></span><span class="legacy-anchor" data-target="s-03-45fe1bfaa294" id="p-54"></span><span class="legacy-anchor" data-target="s-03-45fe1bfaa294" id="u-03-9d9f03105820"></span><span class="legacy-anchor" data-target="s-03-45fe1bfaa294" id="u-03-6602453baf1e"></span>
<a id="s-03-45fe1bfaa294"></a>

#### 利用信号量实现前驱关系

<div class="study-unit" id="u-03-785f3ec7eb32">

每条前驱边设置初值 0 的同步量：前驱完成后 V，后继执行前 P。多个前驱必须全部完成，后继分别 P 各入边；一个前驱通知多个后继需分别 V，不让多个后继抢一个单份通知。

</div>

### 条件变量

<div class="study-unit" id="u-03-8ecb79eba6fb">

条件变量用于等待共享状态满足某个条件，通常与互斥锁配合。wait 在条件不满足时原子地释放锁并阻塞，signal 唤醒一个等待者。管程可作为把共享数据、互斥和条件等待封装在一起的实现背景。

</div>

<div class="study-unit" id="u-03-a64af333f942">

- 条件变量不是保存通知计数的信号量：没人等时 signal 通常不积累。
- 常用语义中唤醒后还要重新竞争并检查条件，因此用 while 检查，不只用 if。

</div>

<div class="study-unit" id="u-03-explain-57d89c44b6">

- 条件变量表达“现在还不能继续”，如队列为空时消费者 wait；
- wait 会放开管程锁，让生产者有机会进来填入数据。

</div>

<div class="study-unit" id="u-03-b726043c9b28">

唤醒后还要再检查队列，因为别的消费者可能已经取走产品，这也是常用语义下要用 while 的原因。

</div>

#### 生产者消费者问题

<span class="legacy-anchor" data-target="u-03-ddd287a6e592" id="p-58"></span>
<div class="study-unit" id="u-03-ddd287a6e592">

n 槽缓冲：$empty=n$，$full=0$，$mutex=1$。生产者先等空槽，再互斥写；消费者先等产品，再互斥读。

</div>

<div class="study-unit" id="u-03-7cb13705e977">

~~~c
// 生产者
produce();
P(empty); P(mutex);
put();
V(mutex); V(full);
// 消费者
P(full); P(mutex);
get();
V(mutex); V(empty);
consume();
~~~

</div>

<div class="study-unit" id="u-03-180c776b69d0">

P(empty/full) 要在 P(mutex) 前，否则持互斥锁等产品 / 空槽可死锁。

</div>

<div class="study-unit" id="u-03-0d33e03b5b1c">

互斥 P/V 在同一方，empty/full 的同步通知跨双方。

</div>

<div class="study-unit" id="u-03-55c5815ac596">

多个生产或消费条件需额外对应信号量。

</div>

<div class="study-unit" id="u-03-explain-8a42f32f1e">

empty 数的是空槽，full 数的是已有产品，mutex 只保护缓冲区的读写。

</div>

<div class="study-unit" id="u-03-6c7db60ed5b4">

**例子**

</div>

<div class="study-unit" id="u-03-4239a85e2df1">

若消费者先拿 mutex，再等 full，而缓冲区为空，它会持锁睡眠；

</div>

<div class="study-unit" id="u-03-067724ec97c5">

生产者又因拿不到 mutex 无法放产品，两者就互相卡住，所以要先等资源、后拿互斥锁。

</div>

#### 读者写者问题

<div class="study-unit" id="u-03-632743e58869">

读者可同时读，写者必须独占，读写之间互斥。

</div>

<div class="study-unit" id="u-03-8f405f464162">

- 读优先常用 $rw=1$、$mutex=1$、$count=0$：首读者 P(rw)，末读者 V(rw)，mutex 只保护 count 修改；
- 写者 P(rw)→写→V(rw)。

</div>

<div class="study-unit" id="u-03-dd1c181a34ac">

~~~c
// 读者入口
P(mutex);
if (count == 0) P(rw);
count++;
V(mutex);
// 读
P(mutex);
count--;
if (count == 0) V(rw);
V(mutex);
~~~

</div>

<div class="study-unit" id="u-03-ef1458c543ee">

- 读优先持续新读者可使写者饥饿。
- 公平版本增加入口闸门，等待写者关住后来的读者；
- “读可并发”不表示 count 可不互斥。

</div>

<div class="study-unit" id="u-03-explain-f3b970f8e6">

- count 表示当前正在读的读者数：从 0 变 1 的首读者替所有读者锁住 rw，从 1 变 0 的末读者释放它；
- 中间读者共用这次保护，因此能并发读。

</div>

<div class="study-unit" id="u-03-e50efbe93b50">

写者则独自拿 rw，读者群未退出时不能写。

</div>

### 死锁

<span class="legacy-anchor" data-target="s-03-901346eafcb7" id="s-50"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="p-73"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="p-74"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="p-75"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="p-76"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="p-77"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="p-78"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="p-79"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="u-03-fc3954f23bfc"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="u-03-9b6bbbf93475"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="u-03-c4c568fffec7"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="u-03-60d1c75d7b0c"></span><span class="legacy-anchor" data-target="s-03-901346eafcb7" id="u-03-5f9c4ab08cac"></span>
<a id="s-03-901346eafcb7"></a>

#### 死锁的概念

<div class="study-unit" id="u-03-799268f64029">

死锁是指一组进程各自占有部分资源，又等待其他进程占有的资源，结果这组进程谁都不能继续执行。

</div>

<div class="study-unit" id="u-03-f9c2007c8a77">

**为什么会互相卡住**：例如 P1 占有打印机、等待扫描仪，P2 占有扫描仪、等待打印机；两者都不释放已占有的设备，就会一直等下去。

</div>

<div class="study-unit" id="u-03-f7938a021c45">

**四个必要条件必须同时成立**

</div>

<div class="study-unit" id="u-03-883250dbb21a">

| 条件 | 含义 |
| --- | --- |
| 互斥 | 一个资源实例同时只能由一个进程使用 |
| 请求且保持 | 进程申请新资源时，仍占有已经得到的资源 |
| 不可剥夺 | 已占有的资源不能被强行拿走，需由占有者主动释放 |
| 循环等待 | 进程之间形成首尾相接的资源等待链 |

</div>

<div class="study-unit" id="u-03-9bea3a064cdb">

**与其他“卡住”现象的区别**

</div>

<div class="study-unit" id="u-03-9cf5ad828c9f">

| 现象 | 关键区别 |
| --- | --- |
| 死锁 | 一组进程互相等待对方占有的资源 |
| 饥饿 | 某个进程长期得不到服务，不一定存在等待环 |
| 死循环 | 程序因逻辑问题反复执行，不一定等待资源 |

</div>

<div class="study-unit" id="u-03-03d804adf92a">

**同类资源数量题**

</div>

<div class="study-unit" id="u-03-1190a7749edb">

有 n 个进程，每个进程最多同时需要 k 个同类资源时，常用的保证不死锁条件为：

</div>

<div class="study-unit" id="u-03-427409e9617c">

$$m\ge n(k-1)+1$$

</div>

<div class="study-unit" id="u-03-e63f7171c30d">

理由是：最坏情况下，每个进程都占有 k−1 个资源，只差 1 个；再提供 1 个，就至少能让一个进程完成并释放资源，其他进程便有机会依次完成。

</div>

<div class="study-unit" id="u-03-78ef58b671ce">

例如 3 个进程各最多需要 4 台同类设备，保证不因这种设备死锁，至少需要 3×(4−1)+1=10 台；9 台时可能每个进程各占 3 台而都无法继续。公式须结合题目对申请、完成和释放的约定。

</div>

#### 死锁的预防

<div class="study-unit" id="u-03-9e440b3e504c">

死锁预防是在资源使用规则上破坏至少一个必要条件，让等待环无法形成。

</div>

<div class="study-unit" id="u-03-2e2331c4546f">

| 要破坏的条件 | 具体做法 | 代价或限制 |
| --- | --- | --- |
| 互斥 | 对能共享的资源改为共享使用 | 不是所有资源都能共享 |
| 请求且保持 | 一次申请全部所需资源，或申请前不持有其他资源 | 资源可能提前占用而闲置 |
| 不可剥夺 | 请求失败时释放或剥夺其已占有资源，再重新申请 | 需要保存、恢复状态，只适合可恢复的资源 |
| 循环等待 | 给资源编号，只允许按统一顺序申请 | 限制申请次序，灵活性下降 |

</div>

<div class="study-unit" id="u-03-bbf6757e8a36">

**理解有序申请为何有效**：如果所有进程只申请比当前已持有资源编号更大的资源，等待链上的编号只能递增，就无法绕一圈回到原来的较小编号。

</div>

<div class="study-unit" id="u-03-6b848e71a3f8">

打印机这类正在产生外部结果的设备通常不能像 CPU 状态那样随意剥夺并恢复；SPOOLing 提供排队共享的使用方式，也不等于物理打印机能同时执行多个打印作业。

</div>

<span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="s-52"></span><span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="p-81"></span><span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="p-82"></span><span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="p-83"></span><span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="p-84"></span><span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="u-03-ab3e13f97c9c"></span><span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="u-03-7e7708c19d3a"></span><span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="u-03-f97147b4c712"></span><span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="u-03-3edc6ef7de54"></span><span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="u-03-670671cd9740"></span><span class="legacy-anchor" data-target="s-03-c195aed7a3e8" id="u-03-59e19706d51d"></span>

#### 死锁的避免（银行家算法）

<div class="study-unit" id="u-03-d95c54f23aa2">

银行家算法只在分配后仍安全时批准。

</div>

<div class="study-unit" id="u-03-f77b103fd23e">

- $\mathrm{Need}=\mathrm{Max}-\mathrm{Allocation}$，Available 为当前剩余；
- 安全序列是一种假设进程得到剩余需求、完成归还后，所有进程都可依次完成的次序。

</div>

<div class="study-unit" id="u-03-explain-aef642a129">

- Max 是最多可能需要的资源，Allocation 是已经持有的资源，Need 是还可能再要的资源；
- 各项比较都要对每一种资源分别成立。

</div>

<div class="study-unit" id="u-03-ba1256db58e9">

Work 是安全检查中的“假想可用量”，Finish 记录哪些进程已经被假设完成，不是在真实运行它们。

</div>

<div class="study-unit" id="u-03-f21fc6aae48e">

**安全性检查：模拟“完成一个进程 → 收回它原来持有的资源”。**

</div>

<div class="study-unit" id="u-03-f916de2fb1dc">

1. **初始化**：$\mathrm{Work}=\mathrm{Available}$，所有进程的 $\mathrm{Finish}=false$。
2. **找能完成者**：寻找尚未完成且 $\mathrm{Need}_i\le \mathrm{Work}$ 的进程，各类资源都必须满足比较。
3. **假设它完成**：令 $\mathrm{Work}=\mathrm{Work}+\mathrm{Allocation}_i$，置 $\mathrm{Finish}_i=true$，把它记入安全序列。
4. **回到第 2 步**：全部进程都能完成 → 安全；仍有未完成者但找不到可执行进程 → 不安全。

</div>

<div class="study-unit" id="u-03-39c84df2969f">

比较用剩余需求 $\mathrm{Need}$，归还加的是原已分配量 $\mathrm{Allocation}$。

</div>

<div class="study-unit" id="u-03-cd6962a3302b">

**处理一次资源请求。**

</div>

<div class="study-unit" id="u-03-ef86d7ad7922">

1. 检查 $\mathrm{Request}_i\le \mathrm{Need}_i$；不满足 → 超过声明的最大需求。
2. 检查 $\mathrm{Request}_i\le \mathrm{Available}$；不满足 → 当前资源不足，等待。
3. **试分配**：$\mathrm{Available}$ 减去请求量，$\mathrm{Allocation}_i$ 加上请求量，$\mathrm{Need}_i$ 减去请求量。
4. **运行安全性检查**：安全 → 确认分配；不安全 → 回滚试分配，进程等待。

</div>

<div class="study-unit" id="u-03-3fc7eafcf3bb">

- 不安全不等于已经死锁；
- 安全序列也不一定是实际调度顺序。

</div>

<div class="study-unit" id="u-03-explain-5c8b3e6d16">

**例子**

</div>

<div class="study-unit" id="u-03-775e564e1eb3">

例：仅一种资源，$\mathrm{Available}=1$；

</div>

<div class="study-unit" id="u-03-101f4488512b">

P1 已有 1、还需 1，P2 已有 1、还需 2。

</div>

<div class="study-unit" id="u-03-6838bd4e7b5c">

- 先假设给 P1 补足需求，它完成后会归还资源，Work 从 1 加上原已分配量 1 变成 2，补给 P1 的 1 个资源先扣后还，净增加的是它原来持有的 1 个；

</div>

<div class="study-unit" id="u-03-8e3a0459924e">

于是 P2 也能完成，安全序列为 P1→P2。

</div>

<div class="study-unit" id="u-03-0f6381519005">

这说明存在可完成的次序，不要求实际一定按此顺序调度。

</div>

### 内存的连续分配

<div class="study-unit" id="u-03-9f14025af006">

单一连续分配：一个用户作业，占一片区域；固定分区：预划分固定大小，一分区一作业，有内部碎片；动态分区：按需划连续区，主要有外部碎片。

</div>

<div class="study-unit" id="u-03-4db82ebb29ab">

- 内部碎片是已分配区域内用不到的空间；
- 外部碎片是分区之间的零散空闲。
- 动态重定位支持紧凑移动以合并外部碎片，搬动有成本。

</div>

**例子**

</div>

<div class="study-unit" id="u-03-5e47fd5edeb5">

#### 动态分区分配—顺序搜索算法

<div class="study-unit" id="u-03-7cb510447a10">

| 算法 | 怎么找 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 首次适应 FF | 空闲区按地址，从头找首个足够者 | 简单，保留后部大区 | 低地址易有小碎片 |
| 邻近适应 NF | 按地址，从上次位置循环找 | 分散查找开销 | 大区也可能较快被消耗 |
| 最佳适应 BF | 按大小升序，取最小足够区 | 本次剩余最小 | 易产生很多小外部碎片 |
| 最坏适应 WF | 按大小降序，取最大区 | 本次剩余通常较大 | 大区很快耗尽 |

</div>

<div class="study-unit" id="u-03-bff409408ea2">

分配后更新起址 / 长度并按所用规则维护表，不能沿用失效次序。BF 的问题是外部碎片，不能称“最容易产生内部碎片”。

</div>

<div class="study-unit" id="u-03-steps-fd59704f7c">

**分配与维护的顺序**

</div>

<div class="study-unit" id="u-03-d3485c2505f2">

1. 按 FF／NF／BF／WF 所要求的次序检索空闲区。
2. 找到足够大的区 → 分给请求进程；剩余部分继续登记为空闲。
3. 更新空闲区起址、长度和索引顺序；没有足够的连续区则等待或按题设处理。
4. 回收时先检查前后是否相邻 → 合并可合并的空闲区 → 再维护所用表的顺序。

</div>

<span class="legacy-anchor" data-target="s-03-bcc64f2b4082" id="s-61"></span><span class="legacy-anchor" data-target="s-03-bcc64f2b4082" id="p-94"></span><span class="legacy-anchor" data-target="s-03-bcc64f2b4082" id="u-03-7a61b53701be"></span>

#### 动态分区分配—内存回收

<div class="study-unit" id="u-03-5883ee83219a">

</div>

<div class="study-unit" id="u-03-24e2ad0a0f54">

- 两边都空闲合并成一块；
- 都不邻接则新建空闲记录。
- 邻接判据：$\text{前起址}+\text{前长度}=\text{回收起址}$，$\text{回收起址}+\text{长度}=\text{后起址}$。

</div>

<div class="study-unit" id="u-03-d7875eec320c">

- 合并后更新起址、长度和表次序。
- 按地址相邻与链表中当前相邻不必相同，最佳 / 最坏适应表可能按大小排序。

#### 地址变换机构

<div class="study-unit" id="u-03-3d914f9348c9">

页大小 P，逻辑地址 A：页号 $p=\lfloor \frac{A}{P}\rfloor$，偏移 $d=A \bmod  P$；

</div>

<div class="study-unit" id="u-03-f509758e320e">

- 查 p 是否越界，取页框 b，再算 $PA=bP+d$。
- $P=2^{k}$ 时低 k 位偏移不变。

</div>

<div class="study-unit" id="u-03-306c78916153">

- $\text{单级页表项地址}=\text{页表基址}+p\times\text{表项大小}$，不是基址+p×页面大小。
- 无 TLB 时通常一次查页表、一次访问数据；
- 权限 / 越界先检查。

</div>

<div class="study-unit" id="u-03-explain-d64b5c3625">

**例子**

</div>

#### 分页和分段的对比

<div class="study-unit" id="u-03-a169bd882b25">

| 比较 | 分页 | 分段 |
| --- | --- | --- |
| 划分依据 | 固定大小物理管理单位 | 逻辑功能单位，大小可变 |
| 用户可见 | 通常不可见 | 通常可见 |
| 碎片 | 内部碎片 | 外部碎片 |
| 共享 / 保护 | 按页，可实现 | 按逻辑段较自然 |
| 地址 | 页号+偏移，通常由连续地址自动划分 | 段号+段内偏移，逻辑上二维 |

</div>

<div class="study-unit" id="u-03-f808ff2e5737">

### 多级页表

<div class="study-unit" id="u-03-9b4127a3cbee">

多级页表把大页表分成页，外层作索引，只给使用区域分配下级表，减少不连续虚地址空间的大量空表项。顶级表通常驻留，部分低级页表可按需存在。

</div>

<div class="study-unit" id="u-03-1f257cb7c47b">

- 逻辑地址宽并不代表页表一定全部实际分配。

</div>

<div class="study-unit" id="u-03-explain-917cd2ac46">

**例子**

</div>

<div class="study-unit" id="u-03-dc6ccf380f29">

例如一个进程只使用地址空间开头和末尾的少数页，单级页表仍要为中间的大段地址预留表项。多级页表用外层表先指向下级页表；未使用的整片区域可以不分配下级表，节省的是这些空区域的表空间。

#### 二级页表地址变换

<div class="study-unit" id="u-03-031b4af5197e">

逻辑地址 p₁|p₂|d：

</div>

<div class="study-unit" id="u-03-fca2df76b990">

1. 顶级基址+p₁×项大小。
2. 读下级表基址；下级基址+p₂×项大小。
3. 读页框号；拼接 d 得数据地址。

</div>

<div class="study-unit" id="u-03-68e603bc3cfd">

**例子**

</div>

<div class="study-unit" id="u-03-37a5e2d7dcb1">

</div>

<div class="study-unit" id="u-03-explain-e48492e6e3">

- 上例的 12 位偏移是因为一页有 4096 个字节位置；
- 下级页表一页能放 1024 项，需 10 位选中一项；
- $32-12-10=10$ 位再作为顶级索引。

</div>

<div class="study-unit" id="u-03-602f9c9b00c6">

先用顶级索引找到“哪一张下级页表”，再用下级索引找到“哪一个页框”，最后拼接偏移。

### 请求分页

<span class="legacy-anchor" data-target="s-03-87df6a5e5cdc" id="s-73"></span><span class="legacy-anchor" data-target="s-03-87df6a5e5cdc" id="p-105"></span><span class="legacy-anchor" data-target="s-03-87df6a5e5cdc" id="u-03-63fd5709d471"></span>

#### 虚拟存储器

<div class="study-unit" id="u-03-6eee0f5e37c9">

虚存基于局部性，仅让当前所需部分驻留主存；访问未驻留页时调入，内存不足时置换。特征包括多次性、对换性、虚拟性，容量不等于物理内存。

</div>

<div class="study-unit" id="u-03-daf7e2c3d77c">

- Cache 提速与虚存扩容是不同机制。
- 请求分页＝分页＋请求调页＋页面置换；
- 需要硬件翻译 / 异常和 OS 调页配合。

</div>

<span class="legacy-anchor" data-target="s-03-79d6f954521f" id="s-74"></span><span class="legacy-anchor" data-target="s-03-79d6f954521f" id="p-106"></span><span class="legacy-anchor" data-target="s-03-79d6f954521f" id="u-03-19c3e39e9dd5"></span>

<div class="study-unit" id="u-03-41cfc0d1f2d1">

</div>

<div class="study-unit" id="u-03-b44c4bd445ee">

- 存在位 0 不一定是合法地址，还需看虚页是否映射；
- 非法 / 权限错误与合法但缺页分别处理。
- 页号常由表项下标隐含。

#### 缺页中断机构

<div class="study-unit" id="u-03-d410b07a14f6">

**缺页处理：地址合法，但目标页当前不在主存。**

</div>

<div class="study-unit" id="u-03-7246f5e46869">

1. 产生缺页故障 → 保存现场并进入内核。
2. 查找空闲页框；没有空框 → 按置换算法选牺牲页，脏页需先写回。
3. 从外存读入目标页 → 更新页表和相应 TLB 信息。
4. 返回用户程序 → **重新执行触发缺页的指令**。

</div>

<div class="study-unit" id="u-03-b29e27b7b8ba">

缺页在指令执行中触发，不等待它正常完成；一次指令可能跨多页而先后缺页。普通文件 read 等待磁盘 I/O 不必然叫缺页异常。

</div>

<div class="study-unit" id="u-03-explain-1636e32547">

- “脏页”是驻留后被修改、与外存副本不同的页，换出前通常要保存；
- 干净页仍有可用的外存副本，可直接丢弃再读回。
- 故障指令必须重试，是因为第一次访问没有真正取得所需页面、尚未完成原操作。

</div>

<span class="legacy-anchor" data-target="s-03-405ba4342caa" id="p-97"></span><span class="legacy-anchor" data-target="s-03-405ba4342caa" id="p-99"></span><span class="legacy-anchor" data-target="s-03-405ba4342caa" id="p-102"></span><span class="legacy-anchor" data-target="s-03-405ba4342caa" id="s-76"></span><span class="legacy-anchor" data-target="s-03-405ba4342caa" id="p-108"></span><span class="legacy-anchor" data-target="s-03-405ba4342caa" id="u-03-16a346782ee0"></span><span class="legacy-anchor" data-target="s-03-405ba4342caa" id="u-03-d9c0ddf29d6f"></span><span class="legacy-anchor" data-target="s-03-405ba4342caa" id="u-03-cc442f84da7f"></span><span class="legacy-anchor" data-target="s-03-405ba4342caa" id="u-03-2fca346db656"></span>

<div class="study-unit" id="u-03-2858dcd1057d">

</div>

<div class="study-unit" id="u-03-2c815277dad5">

- TLB 未命中$\ne$缺页。
- 时间计算区分串行 / 重叠查询，单级无 TLB 页表+数据常为两次；
- 多级和缺页要按题设逐项计，不能一律加固定两次。

### 页框分配

<div class="study-unit" id="u-03-02d20bbd7e39">

固定分配+局部置换：每进程页框数固定，只换本进程页；可变分配+全局置换：可从其他进程取得框；可变分配+局部置换：通常内部替换，也可按故障率调整份额。

</div>

<div class="study-unit" id="u-03-437dc1627fc1">

- 分配可等额、按大小比例、按优先级；
- 最小页框数受指令寻址、同时所需页面等硬件要求。
- 固定框数与任意全局夺框相矛盾。

</div>

### 页面置换

<div class="study-unit" id="u-03-c837649cce43">

| 置换 | 执行规则 | 优点 | 缺点 |
| --- | --- | --- | --- |
| OPT（最佳置换，Optimal） | 换出未来最晚再用 / 不再用的页 | 给定序列故障最少，比较基准 | 实际不知道未来 |
| FIFO（先进先出） | 换出最早调入的页，命中不改顺序 | 简单 | 不顾近期使用，可能 Belady 异常 |
| LRU（最近最少使用） | 换出过去最长时间未用页，命中也更新次序 | 利用时间局部性，不出现 Belady 异常 | 精确实现开销大 |
| CLOCK（时钟置换） | 循环查访问位，1 清 0 并跳过，0 则换出 | 近似近期使用，实现便宜 | 不精确等于 LRU |
| 改进 CLOCK | 同时用访问 A 和修改 M，优先 (0,0)，再 (0,1)，扫描时清访问位后再找 | 减少脏页写回 | 多轮扫描，具体清位时机按题设 |

</div>

<div class="study-unit" id="u-03-d6d3b7184e60">

模拟先记初始空框装入也算缺页，命中不需置换；

</div>

<div class="study-unit" id="u-03-30e828967f4f">

- $\text{缺页率}=\frac{\text{缺页次数}}{\text{访问次数}}$。
- 页框增加后 FIFO 故障反增叫 Belady；
- 不是任何算法都发生。

</div>

<div class="study-unit" id="u-03-0365a270052d">

- **驻留集**是实际分配给进程的页框集合；
- **工作集 W(t,Δ)** 是时刻 t 前最近 Δ 次访问（或给定时间窗）涉及的不同页面集合，重复页只计一次。

</div>

<div class="study-unit" id="u-03-2b7943897bcd">

- 抖动：频繁换页导致大部分时间做 I/O，通常工作集所需框超出实际份额；
- 降低多道程度、增加框 / 按工作集分配可缓解，不能靠“继续增加进程”解决。

</div>

<div class="study-unit" id="u-03-explain-fbb7e85482">

**例子**

</div>

<div class="study-unit" id="u-03-f67a67246cc2">

例：三个页框依次装入 1、2、3，再访问 1，最后请求 4：FIFO 淘汰最早进入的 1，LRU 淘汰最久没访问的 2。

</div>

<div class="study-unit" id="u-03-cef56fe2bd7b">

- CLOCK 则从指针处检查访问位，遇 1 清零并向前走，遇 0 才选中；
- 看的是位和指针位置，不直接比较访问时间。

</div>

<div class="study-unit" id="u-03-explain-16c68168d5">

工作集例：最近 5 次访问为 1、2、1、3、2，工作集是 {1,2,3}，大小为 3，而不是 5。

</div>

<div class="study-unit" id="u-03-eb2f03fe79c6">

**例子**

</div>

<div class="study-unit" id="u-03-3df6e6beaea4">

若驻留页框长期装不下当前常用页，刚换出的页又马上需要调回，进程就在读盘和换页之间反复等待，形成抖动。

</div>

<div class="study-unit" id="u-03-steps-5a465edff9">

**逐次访问页面，按同一模板模拟**

</div>

<div class="study-unit" id="u-03-c82d0568ae32">

1. 当前页已在页框 → 命中，只更新本算法需要的访问状态。
2. 当前页不在 → 记一次缺页；有空框就装入，没有空框才选牺牲页。
3. 选页规则：OPT 看未来最远使用；FIFO 看最早装入；LRU 看过去最久未访问。
4. Clock 从指针处检查访问位 → 为 1 则清 0 并前进，为 0 则选中替换；装入后按题设更新访问位与指针。
5. 处理下一次访问，最后用缺页次数除以总访问次数。命中不等于置换，初始装入也计缺页。

</div>

### 虚拟存储器性能与改进

<div class="study-unit" id="u-03-outline-fd7d434b47">

有效访问时间不仅含正常地址转换和访存，还含缺页后的磁盘调入、脏页写回、更新和指令重启。

</div>

<div class="study-unit" id="u-03-fddb3a06f4c8">

**例子**

</div>

<div class="study-unit" id="u-03-3fd3d8fcbc7d">

若正常访问时间为 t、缺页率为 p、一次缺页的总处理时间为 F，且 F 已含本次完成访问的时间，则平均为 $(1-p)t+pF$，不能再重复加 t。

</div>

<div class="study-unit" id="u-03-6b5d63ad59cb">

- 程序局部性、页面大小、页框数量、置换策略及页面缓冲都会影响性能。
- 改善访问次序、匹配工作集分配、预调页和批量写回可减少等待；
- 页面增大可能减少页表规模，但也会增加内部碎片与无用数据调入。

</div>

### 文件的基本概念与逻辑结构

### 目录的操作

<div class="study-unit" id="u-03-outline-c0bdc7e7b9">

创建目录是在父目录中增加入口并建立目录实体；查找按路径逐级解析名称；列目录返回目录项；重命名修改名称或所属入口。删除目录需满足系统对空目录、使用中目录和权限的要求。

- 绝对路径从根开始，相对路径从当前工作目录开始。
- 路径中每一层都可能需要目录访问权限，知道最终文件名不等于可以绕过中间目录。

</div>

### 文件的物理结构

<div class="study-unit" id="u-03-49d180ecf561">

逻辑结构描述用户看到的记录组织，物理结构描述数据块如何放到磁盘，不是同一分类。

</div>

<div class="study-unit" id="u-03-e0776f7f25a4">

| 分配 | 怎么定位 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 连续 | 起始块+逻辑块号 | 顺序 / 随机快，寻道少 | 外部碎片，增长 / 插删困难 |
| 隐式链接 | 每块保存下一块指针，沿链找到 | 离散增长方便，无外部碎片 | 不支持高效随机定位，指针损坏影响后续 |
| 显式链接 FAT（文件分配表，File Allocation Table） | 链指针集中到 FAT，目录给首块 | 可在内存沿链，减少找块读盘 | 找远处块仍需沿链，FAT 占空间 |
| 索引 | 目录给索引块，索引项给物理块号 | 支持直接定位，便于增长 | 小文件索引开销，多级间接增访盘 |

</div>

<div class="study-unit" id="u-03-b719731f3bb6">

- **索引容量**：块 B 字节、地址项 a 字节，每索引块可指 $q=\lfloor \frac{B}{a}\rfloor$ 块；

</div>

<div class="study-unit" id="u-03-71cae59f323f">

d 个直接地址、一级 / 二级 / 三级各一项时可寻址数据量$=(d+q+q^{2}+q^{3})B$。

</div>

<div class="study-unit" id="u-03-1dd3fde63b0f">

索引块本身不算用户数据块；

</div>

<div class="study-unit" id="u-03-a518c337bb46">

取某数据块的读盘次数看其间接层级和已缓存内容。

</div>

<div class="study-unit" id="u-03-1726974dff04">

- 无结构文件是字节流；
- 记录文件可顺序、索引、索引顺序或散列组织。
- 逻辑“顺序文件”不必物理连续。

</div>

<div class="study-unit" id="u-03-explain-eb1aa03fb6">

链接分配找“逻辑第 k 块”要从首块沿链走，索引分配则按块号直接查索引项。

</div>

<div class="study-unit" id="u-03-7af592c441d4">

**例子**

</div>

<div class="study-unit" id="u-03-5aa05fac2306">

例：块大小 4KB、地址项 4B，每索引块有 1024 项，一级间接项可覆盖 4MB 数据，二级间接项可覆盖 4GB；访问二级间接数据还要先经过两层索引。

</div>

### 文件的操作

<div class="study-unit" id="u-03-a9fa67d549e8">

创建：检查目录 / 权限，分配 inode / 控制信息并添加名称；打开：按路径定位实体、检查权限、建立打开表项并返回 fd；读写：按 fd、偏移定位块并传数据；关闭：释放打开引用及相关状态。

</div>

<div class="study-unit" id="u-03-17e81aba40d4">

fd 是本进程打开表的整数索引，不是文件数据缓冲地址。

</div>

<div class="study-unit" id="u-03-b6f211cea006">

- read(fd,buf,n) 的 buf 是目标内存地址；
- 文件偏移由打开状态维护。

</div>

<div class="study-unit" id="u-03-05e2f09f4db3">

多个打开实例可有不同偏移，dup / fork 等共享同一打开实例时偏移可共享。

</div>

<div class="study-unit" id="u-03-82897a9f98eb">

- 删除通常先去掉目录链接；
- 硬链接数为 0 且无打开 / 映射等引用时才最终回收。
- 关闭文件不等于删除文件，也不保证所有缓存脏数据已持久化，需同步操作语义。

</div>

<div class="study-unit" id="u-03-explain-ca70d7f8f6">

- 打开文件相当于建立一次访问状态，fd 用来找到这份状态。
- 两次独立 open 同一文件，通常各自维护读写位置；
- dup 复制的是对同一打开状态的引用，两个 fd 可能共同推进同一偏移。

</div>

### 文件的共享

<div class="study-unit" id="u-03-eb624dbe56eb">

硬链接：多个目录项指向同一 inode，增加链接计数，共享同一文件实体；通常不能跨文件系统，目录硬链接受限制。

</div>

<div class="study-unit" id="u-03-b67fcad5159e">

- 软链接：独立的链接文件保存目标路径，可跨文件系统 / 指向目录；
- 目标删除后可成为悬空链接。
- 删软链接不删目标，软链接不增加目标的硬链接计数。

</div>

<div class="study-unit" id="u-03-9ff14411dd8e">

访问权限由目标和路径等共同决定，共享不等于任意用户都有读写权。

</div>

<div class="study-unit" id="u-03-explain-24c5b6ec08">

**例子**

</div>

<div class="study-unit" id="u-03-3e8cea72c6b5">

例：a、b 是同一文件的两个硬链接，删除 a 后，b 仍能读到原数据；若 b 是指向 a 路径的软链接，删除 a 后，b 保存的路径找不到目标，就成为悬空链接。

</div>

<div class="study-unit" id="u-03-093c6d642c43">

区别在于链接保存的是“同一实体的入口”还是“另一个名称的路径”。

</div>

<div class="study-unit" id="u-03-98a3ab7c340e">

### 外存空闲空间管理

<div class="study-unit" id="u-03-48449a14a4ff">

| 管理 | 执行 | 特点 |
| --- | --- | --- |
| 空闲表 | 记录每片连续空闲区起始块和长度，分配 / 回收并合并 | 适合连续分配 |
| 空闲链 | 空闲块或盘区串成链，取链头分配、回收接入 | 管理简单，找大连续区较慢 |
| 位示图 | 一位对应一块，扫描空位分配，回收改位 | 紧凑，便于找连续块；0/1 含义依题设 |
| 成组链接 | 一组空闲块号保存在栈，栈底块指向下一组 | 减少逐块链的 I/O，UNIX 教材常见 |

</div>

<div class="study-unit" id="u-03-3c452b10ad0a">

位图每字 w 位，块号 b 从 0 起：字号$=\lfloor \frac{b}{w}\rfloor$，位号$=b \bmod  w$；起始编号从 1 时先减 1。

</div>

<div class="study-unit" id="u-03-ee3c8d857389">

- 成组分配弹栈；
- 只剩存下一组索引的块时，先读下一组填栈再分配该块。
- 回收栈满时把当前栈写入回收块，再将该块作为新组链接压入。

</div>

<div class="study-unit" id="u-03-explain-60f3960abc">

- 位示图例：每个字有 8 位、块号从 0 起，块号 19 对应字号 $19\div 8$ 的整数部分 2、位号 3。
- 分配时把该位从“空闲”改为“占用”，回收反向改回；
- 0 / 1 谁表示空闲应以题设为准。

</div>

### IO设备

<div class="study-unit" id="u-03-78164b1af4f4">

块设备按块传输，可定位指定块，如磁盘；字符设备按字符流传输，通常不提供任意位置寻址，如键盘。共享设备可由多个请求分时使用，独占设备需分配后独占，虚拟设备用软件把独占使用抽象成共享。

</div>

<div class="study-unit" id="u-03-042996856b44">

- 磁带虽然按块记录，但访问是顺序的；
- 不能把所有“块形式数据”都当作随机访问设备。

</div>

<a id="s-03-outline-1dc631a492"></a>

### I/O控制方式

<div class="study-unit" id="u-03-outline-ce98b2489f">

轮询：CPU 反复或定时读设备状态，设备就绪后由 CPU 搬数据；

</div>

<div class="study-unit" id="u-03-ec32ad0eebb7">

- 中断：设备就绪通知 CPU，由服务程序完成传送；
- DMA：CPU 设置地址和计数后，由控制器在设备和主存间批量传送，完成再通知 CPU。

</div>

<div class="study-unit" id="u-03-9b2a8497c30d">

- 中断方式省掉准备期的忙等，DMA 进一步省掉逐字程序搬运。
- 接口／控制器是硬件，驱动是软件；
- 端口是接口中用于数据、状态或命令交互的可访问寄存器。

</div>

### IO软件

<div class="study-unit" id="u-03-633c53bdd2d7">

I/O（输入 / 输出，Input / Output）软件从上到下：

</div>

<div class="study-unit" id="u-03-7318513909da">

2. 设备独立性软件。
3. 设备驱动。
4. 中断处理。
5. 硬件控制器 / 设备。

</div>

<div class="study-unit" id="u-03-e213ed85c81a">

- 设备独立层做共性管理，驱动把抽象请求变成设备命令，中断程序处理完成通知。
- 驱动是软件、控制器是硬件；
- 中断处理不必发生进程切换。

### 用户层IO软件

<div class="study-unit" id="u-03-concise-96">

用户层提供库函数、格式化输入输出和调用接口，通过系统调用请求内核服务；如格式化打印不等于每个字符立即执行一次写系统调用。

#### SPOOLing技术

<div class="study-unit" id="u-03-8f606a5933c3">

SPOOLing（假脱机，Simultaneous Peripheral Operations On-Line，外部设备联机并行操作）用磁盘输入 / 输出井和内存缓冲，把独占设备模拟为可共享服务。

</div>

<div class="study-unit" id="u-03-cea30fefc989">

- 打印执行：

</div>

<div class="study-unit" id="u-03-d65c470884aa">

1. 用户请求写入输出井 / 队列。
2. 返回或继续工作。
3. 后台输出进程按序取任务。
4. 独占实际打印机输出。

</div>

<div class="study-unit" id="u-03-45c22b3b7b6b">

- 多个用户可同时提交，不表示打印机同一时刻打印多个任务；
- 交换的是设备使用权与排队方式，不是硬件变成并行。
- 需外存空间及多道并发支持。

</div>

#### 应用程序IO接口

<div class="study-unit" id="u-03-94c4df5c9b9d">

阻塞 I/O：没有所需结果时调用者等待，完成后才返回。非阻塞 I/O：不能立即完成时返回状态，调用者可稍后再试；不必一直忙轮询。

</div>

<div class="study-unit" id="u-03-897ee7c5a016">

- 块设备常提供读写 / 映射，字符流提供顺序读写，网络常用 socket；
- 套接字不只是“某块网卡编号”。

</div>

### 设备独立性软件

<div class="study-unit" id="u-03-concise-99">

设备独立层提供统一接口，处理逻辑→物理映射、设备保护、分配回收、缓冲、共性差错处理等。LUT（逻辑设备表，Logical Unit Table）记录逻辑设备名与物理设备 / 驱动对应。

</div>

<div class="study-unit" id="u-03-1e333cfc2012">

- 同一逻辑名可映射不同物理设备，用户程序不必写具体硬件端口。
- 设备专属寄存器格式和命令序列由驱动负责。

</div>

<span class="legacy-anchor" data-target="s-03-1ba0f96b9dd3" id="s-101"></span><span class="legacy-anchor" data-target="s-03-1ba0f96b9dd3" id="p-137"></span><span class="legacy-anchor" data-target="s-03-1ba0f96b9dd3" id="u-03-434c9b5ae514"></span><span class="legacy-anchor" data-target="s-03-1ba0f96b9dd3" id="u-03-3cbad1caa0ad"></span><span class="legacy-anchor" data-target="s-03-1ba0f96b9dd3" id="u-03-a22d4e520043"></span>
<a id="s-03-1ba0f96b9dd3"></a>

#### 缓冲管理

<div class="study-unit" id="u-03-00efd8aa62ff">

缓冲调和速度差异、传送单位差异，减少中断 / I/O 次数并让阶段重叠。单缓冲交换时设备 / CPU 仍会互等；双缓冲可交替填充与处理；循环缓冲和缓冲池服务更多并发请求。

</div>

<div class="study-unit" id="u-03-0b07d5281f39">

设 T 为设备读入一块时间、M 为缓冲→用户区传送时间、C 为 CPU 分析时间。

</div>

<div class="study-unit" id="u-03-ceaf478dbd39">

连续稳态、教材约定下：单缓冲每块约 max(T,C)+M，双缓冲约 $\max (T,M+C)$。

</div>

<div class="study-unit" id="u-03-889d718e868e">

有限块总时长还需计启动 / 收尾，不能直接 n 倍平均公式。

</div>

<div class="study-unit" id="u-03-explain-a3dad6e0f6">

- 单缓冲中，输入下一块 T 可与 CPU 分析上一块 C 重叠，但缓冲向用户区搬运 M 要单独占用，因此出现 max(T,C)+M。

</div>

<div class="study-unit" id="u-03-444992a0c4d1">

双缓冲让设备填这一块时，CPU 在另一块上完成搬运和分析，于是比较的是 T 与 $M+C$ 中较慢的一方。

</div>

#### 设备分配和回收

<div class="study-unit" id="u-03-5170b92e4606">

分配先由 LUT 找物理设备，经 SDT / DCT 查状态，再申请对应控制器 COCT 和通道 CHCT；分配过程要考虑独占、共享、安全分配与等待。

</div>

<div class="study-unit" id="u-03-d24c755ba4e8">

- DCT（设备控制表）一设备一表，COCT（控制器控制表）一控制器一表，CHCT（通道控制表）一通道一表，SDT（系统设备表）记录系统设备目录。

</div>

<div class="study-unit" id="u-03-575fefde4899">

共享控制器 / 通道意味着设备空闲也可能暂不能使用。

</div>

<div class="study-unit" id="u-03-7f3a133f0c0f">

回收释放相应占用，唤醒等待请求。

</div>

<div class="study-unit" id="u-03-explain-8d5ffa752c">

LUT 先把程序使用的逻辑名称转换成物理设备，SDT 找到该设备的 DCT，DCT 再关联它所属控制器和通道。

</div>

<div class="study-unit" id="u-03-e8b44204392f">

- 申请设备成功却拿不到同一路径上的控制器 / 通道，仍不能开始 I/O；
- 因此需要逐层检查、登记占用，结束后再释放。

</div>

### 设备驱动程序接口

<div class="study-unit" id="u-03-outline-45ab60557f">

#### 磁盘调度算法

<div class="study-unit" id="u-03-303b7b34a633">

磁盘调度决定**请求服务顺序**，目标是减少寻道并兼顾等待公平性。先确定初始磁头、请求、方向与柱面范围。

</div>

<div class="study-unit" id="u-03-398544766b86">

| 算法 | 执行过程 | 优点 | 缺点 |
| --- | --- | --- | --- |
| FCFS 先来先服务 | 按请求到达先后依次服务 | 简单、按到达公平、不会因后来请求而饥饿 | 磁头来回移动，平均寻道可能大 |
| SSTF 最短寻道优先 | 每次从未完成请求中选离当前磁头最近者 | 通常比 FCFS 移动少 | 远处请求可能饥饿；局部最短不保证全局总距离最短 |
| SCAN 扫描 / 电梯 | 沿当前方向依次服务，走到物理端点才折返 | 限制单纯就近造成的远端饥饿 | 刚扫过区域需等较久，端部与中部等待不均 |
| C-SCAN 循环扫描 | 只沿一个方向服务，到物理末端回到另一端，返回不服务 | 各位置等待时间较均匀 | 回跳增加移动距离 |
| LOOK（扫描到最后请求即折返） | 同 SCAN，但到当前方向最后一个请求即折返，不走无请求端部 | 少走空路 | 仍有双向扫描等待差异 |
| C-LOOK（循环 LOOK） | 单向服务到该方向最后一个请求，回跳到另一侧最远请求，再同向服务 | 省去端部空路，等待较均匀 | 回跳仍有移动开销 |

</div>

<div class="study-unit" id="u-03-explain-63fbc877cd">

SSTF 的“最近”是比较 |请求磁道−当前磁道|，每服务一个请求后重新比较。

</div>

<div class="study-unit" id="u-03-7d67e1fc914d">

SCAN / LOOK 则先确定移动方向，把该方向的请求按磁道顺序依次处理，不在每一步改去全盘最近请求；

</div>

<div class="study-unit" id="u-03-f5ae0b8f2b14">

C-SCAN / C-LOOK 的回跳只移动，不顺路服务。

</div>

<div class="study-unit" id="u-03-c1fcc02cd649">

- **计算**：写出完整磁头路径，$$D=\sum_{i=1}^{m}|x_i-x_{i-1}|,\qquad\overline D=\frac{D}{n}$$

</div>

<div class="study-unit" id="u-03-116994087a16">

- 其中 $x_0$ 是初始磁头位置，$x_1,\ldots,x_m$ 记录移动路径中的服务位置和转折点；
- $n$ 是实际请求数，端点和回跳不能额外算成服务请求。
- 。

</div>

<div class="study-unit" id="u-03-54035ac7587b">

SCAN / C-SCAN 计物理端点；

</div>

<div class="study-unit" id="u-03-b631d0c84293">

LOOK / C-LOOK 只到请求边界；

</div>

<div class="study-unit" id="u-03-185533139cce">

循环回跳通常计距离但不服务途中请求，题目若明确忽略回跳再按约定。

</div>

<div class="study-unit" id="u-03-d50bd0766a74">

**例子**

</div>

<div class="study-unit" id="u-03-f3638c42ba04">

例：柱面范围 0～199，起点 50，初始向增大方向，待处理请求按到达顺序为 10、90、30。以下路径从起点写起，也包含必要的无请求端点；总移动是每段距离相加。

</div>

<div class="study-unit" id="u-03-1eff509f0326">

| 算法 | 完整磁头路径 | 总移动（磁道数） |
| --- | --- | ---: |
| FCFS | 50→10→90→30 | 180 |
| SSTF | 50→30→10→90 | 120 |
| SCAN | 50→90→199→30→10 | 338 |
| LOOK | 50→90→30→10 | 120 |
| C-SCAN | 50→90→199→0→10→30 | 378 |
| C-LOOK | 50→90→10→30 | 140 |

</div>

<div class="study-unit" id="u-03-a31154565a1f">

**例子**

</div>

<div class="study-unit" id="u-03-e2b727f699bd">

例如 SCAN 的四段距离为 40、109、169、20，加起来是 338；199 是折返点，并不是新增的一次服务请求。

</div>

<div class="study-unit" id="u-03-0f26824f44da">

求平均移动仍除以 3 个请求。

</div>

<div class="study-unit" id="u-03-fecb12e8da66">

各算法在最后一个请求完成时停止，不再额外走一次端点。

</div>

<div class="study-unit" id="u-03-c3365807acf4">

**例子**

</div>

<div class="study-unit" id="u-03-7bae79442752">

若新请求不断聚集当前区域，扫描仍可能出现“磁臂粘着”；按批次冻结队列可限制插队，这与静态序列算总距离不同。

</div>

<div class="study-unit" id="u-03-steps-f237b19302">

**先排路径，再算距离**

</div>

<div class="study-unit" id="u-03-11caad9d98c5">

1. 写出初始磁头位置、请求序列、磁道范围及初始方向。
2. FCFS 按到达顺序；SSTF 每次从未完成请求中重新选最近者；SCAN／LOOK 按当前方向逐个服务。
3. SCAN 到物理端点才折返，LOOK 到该方向最后请求即折返；C-SCAN／C-LOOK 回跳时不服务沿途请求。
4. 将服务点、必要端点和回跳按顺序用箭头串起来 → 相邻位置差取绝对值 → 全部相加。
5. 需要平均距离时，除以实际请求数；全部请求完成后停止，不再额外走端点。

</div>

#### 提升效率的方式

<div class="study-unit" id="u-03-cf945bcf443b">

调度减少寻道；交错扇区编号 / 跨盘面错位减少因处理间隔错过下一扇区而多转一圈；缓存、预读利用局部性，延迟写把多次修改合并。

</div>

<div class="study-unit" id="u-03-2c1fb0697a01">

- 优化目录与文件布局减少定位 / 寻道次数；
- 缓存收益不等于所有请求都省磁盘时间，延迟写也有未落盘数据丢失风险。

### 固态硬盘

<div class="study-unit" id="u-03-8f7ff3b6ae42">

SSD（固态硬盘）无机械寻道 / 旋转，不能直接套磁盘电梯算法的寻道收益。Flash 按页读写、按块擦除，控制器做逻辑地址映射、垃圾回收和磨损均衡。

</div>

<div class="study-unit" id="u-03-d1680110fbd7">

- 擦写寿命有限，更新和回收可能引起写放大。
- 块、页、逻辑扇区各自粒度不同，计算容量 / 开销看题设。

</div>
