### 冯诺依曼机的特点

<div class="study-unit" id="u-02-ad5006cb372e">

**基本概念**

</div>

<div class="study-unit" id="u-02-db1a33a76630">

冯·诺依曼机采用**存储程序**：指令和数据以二进制存入存储器，按指令控制依次取指执行，遇转移改变顺序。

</div>

<div class="study-unit" id="u-02-cc308165cee4">

**规则与说明**

</div>

<div class="study-unit" id="u-02-9c42909b7e1c">

</div>

<div class="study-unit" id="u-02-75ca2e73c36d">

</div>

<div class="study-unit" id="u-02-3d225e990c1d">

ISA（指令集体系结构，Instruction Set Architecture）是软硬件界面，规定可执行指令及程序员可见状态。

### 计算机系统层次与软硬件关系

<div class="study-unit" id="u-02-5cdc3a41cbdd">

**基本概念**

</div>

<div class="study-unit" id="u-02-outline-5a75234f8d">

硬件提供机器指令能执行的基本操作，操作系统管理硬件并提供服务，汇编器／编译器等把较高层语言转换为机器可执行形式。

</div>

<div class="study-unit" id="u-02-bf929a76f6d6">

**规则与说明**

</div>

<div class="study-unit" id="u-02-37accde1c953">

- ISA（指令集体系结构）是软硬件约定的接口；
- 同一 ISA 可由不同内部结构实现。

</div>

<div class="study-unit" id="u-02-c1152df91669">

- 高级语言表达式最终要落实为取数、运算、写回等指令。
- 取指由 PC 提供地址，译码确定操作，再由数据通路完成执行；
- 软件选择怎样的指令序列，硬件决定这些指令需要多少周期，两者共同影响程序性能。

</div>

### 三种常见字长

<div class="study-unit" id="u-02-84283e05ed0c">

**基本概念**

</div>

<div class="study-unit" id="u-02-df6fa7e9bde9">

机器字长是 CPU（中央处理器）一次整数运算通常处理的位数，常与通用寄存器 / ALU（算术逻辑单元）宽度一致；指令字长是一条指令编码的总位数，可定长或变长；存储字长是一个存储字的位数。

</div>

<div class="study-unit" id="u-02-c055cfa51ae2">

**规则与说明**

</div>

<div class="study-unit" id="u-02-04a263f22d7c">

- 三者不必相等。
- 数据通路带宽是一次传送的数据宽度，要看内部通路 / 外部总线具体对象，不能都叫机器字长。

</div>

### 计算机性能指标

<div class="study-unit" id="u-02-e26cf6eeda50">

**对照与计算**

</div>

<div class="study-unit" id="u-02-2a73abafd4ae">

| 指标 | 公式 / 含义 |
| --- | --- |
| 时钟周期 T、主频 f | $T=\frac{1}{f}$ |
| 平均 CPI（每条指令的平均时钟周期数） | 总时钟周期 / 总指令数；按指令比例加权 |
| CPU 执行时间 | 指令数×平均 CPI/f |
| IPS（每秒指令数） / MIPS（每秒百万条指令数） | f/平均 CPI；$\mathrm{MIPS}=\frac{\mathrm{IPS}}{10^{6}}$ |
| FLOPS（每秒浮点运算次数） | 每秒浮点运算次数，不等同每秒指令数 |
| 吞吐量 / 响应时间 | 单位时间完成任务数 / 从请求到完成的总时间 |

</div>

<div class="study-unit" id="u-02-32319dfef071">

性能比较同时看指令数、CPI、主频，不能只比主频或跨 ISA 直接比 MIPS。

</div>

<div class="study-unit" id="u-02-282679ec6528">

总响应时间还含 I/O、等待等。

</div>

<div class="study-unit" id="u-02-d728524c99fc">

速度 k/M/G 为 $10^{3}/10^{6}/10^{9}$，计组容量题常按 K/M 为 $2^{10}/2^{20}$；

</div>

<div class="study-unit" id="u-02-b7aa09c1baa9">

$1B=8bit$，$1s=10^{3}ms=10^{6}\mu s=10^{9}ns$。

</div>

<div class="study-unit" id="u-02-explain-cd451ff791">

**例子**

</div>

<div class="study-unit" id="u-02-2b5413755d4c">

例：程序执行 $10^{6}$ 条指令，平均 $\mathrm{CPI}=2$，主频 1GHz，则需 $2\times 10^{6}$ 个时钟周期，CPU 执行时间为 2ms。

</div>

<div class="study-unit" id="u-02-4c1a9da8f626">

主频提高能缩短一个周期，但如果同时增加了指令数或 CPI，程序不一定更快。

</div>

<div class="study-unit" id="u-02-3712699e12e0">

**规则与说明**

</div>

<div class="study-unit" id="u-02-outline-flops-scale">

- 浮点运算率的 MFLOPS、GFLOPS、TFLOPS、PFLOPS、EFLOPS、ZFLOPS 分别表示每秒 $10^{6}$、$10^{9}$、$10^{12}$、$10^{15}$、$10^{18}$、$10^{21}$ 次浮点运算。

</div>

<div class="study-unit" id="u-02-0aa1761ec18e">

前缀每升一级乘 1000，比较时先统一数量级，再看测量任务与条件。

</div>

### 定点数的机器数转换

<div class="study-unit" id="u-02-015f61eab483">

**进制转换，先分整数和小数。**

</div>

<div class="study-unit" id="u-02-70a9f27dad58">

1. **整数部分**：反复除以目标进制的基数 → 记录每次余数 → 将余数**倒序**写出。
2. **小数部分**：反复乘以目标进制的基数 → 记录每次整数部分 → 将整数部分**顺序**写出。

</div>

<div class="study-unit" id="u-02-849efa4bf36f">

**例子**

</div>

<div class="study-unit" id="u-02-13004561c298">

例如：$13_{10}=1101_2$，$0.625_{10}=0.101_2$。十进制有限小数不一定能用有限二进制精确表示。

</div>

<div class="study-unit" id="u-02-ba36c68e3325">

**约定：总共 $w$ 位，其中最高位为符号位。**

</div>

<div class="study-unit" id="u-02-9aede1177d3b">

| 对象 | 原码 | 反码 | 补码 |
| --- | --- | --- | --- |
| 正数 | 符号位为 0，写出数值 | 与原码相同 | 与原码相同 |
| 负数 | 符号位为 1，数值位写绝对值 | 符号位不变，数值位逐位取反 | 反码加 1，保留 $w$ 位 |

</div>

<div class="study-unit" id="u-02-fcb873bb7b6d">

**负数转换顺序**：写原码 → 数值位取反得到反码 → 加 1 得到补码。

</div>

<div class="study-unit" id="u-02-86f3cc836dda">

也可直接计算负数补码对应的无符号值：

</div>

<div class="study-unit" id="u-02-a176190fad56">

**计算公式**

</div>

<div class="study-unit" id="u-02-4c8d4375fb98">

$$U=2^w-|x|\qquad(x<0)$$

</div>

<div class="study-unit" id="u-02-96fc4c472ecc">

**规则与说明**

</div>

<div class="study-unit" id="u-02-1562e8d8eaff">

- 算出 $U$ 后，再写成 $w$ 位二进制；
- 这个式子不是正数补码的计算规则。

</div>

<div class="study-unit" id="u-02-e7deef82cb7e">

**补码求真值，先看最高位。**

</div>

<div class="study-unit" id="u-02-6189df7bc1ab">

1. 最高位为 0 → 直接按普通二进制求值。
2. 最高位为 1 → 先把整个位串按无符号数读成 $U$ → 再减去 $2^w$。

</div>

<div class="study-unit" id="u-02-c9518040ec4b">

**计算公式**

</div>

<div class="study-unit" id="u-02-efe15ad9fd62">

$$x=\begin{cases}U,&\text{最高位为 0}\\U-2^w,&\text{最高位为 1}\end{cases}$$

</div>

<div class="study-unit" id="u-02-208ccebf5da5">

**例子**

</div>

<div class="study-unit" id="u-02-1fc55f018fe8">

例如，8 位补码 $11010110_2$：$U=214$ → $x=214-256=-42$。

</div>

<div class="study-unit" id="u-02-68bcf0f6098f">

**规则与说明**

</div>

<div class="study-unit" id="u-02-87a73f16a0c3">

- 等价理解：符号位的位权为 $-2^{w-1}$，其余位的位权为正。
- 最小负数没有同位数原码绝对值表示。

</div>

<div class="study-unit" id="u-02-6cdae7725c9a">

**移码：真值加上偏置。**

</div>

<div class="study-unit" id="u-02-7d408bf1f8b2">

$$\text{移码对应的无符号值}=x+\text{偏置}$$

</div>

<div class="study-unit" id="u-02-be8e6ed0939f">

偏置为 $2^{w-1}$ 时：补码 → **翻转符号位，其余位不变** → 移码。

</div>

<div class="study-unit" id="u-02-23f3d073156f">

IEEE 754 的阶码偏置为 127／1023，不能直接套用这个翻位规则。

</div>

<div class="study-unit" id="u-02-explain-ec44d8f5ec">

**例子**

</div>

<div class="study-unit" id="u-02-ff5f76666d3f">

例：8 位的 −5，原码为 10000101，反码为 11111010，补码为 11111011；把补码位串按无符号读成 251，再减 256，也能得到 −5。

</div>

<div class="study-unit" id="u-02-6460a2a6cdd2">

编码题先看总位数和有无符号，再做取反、加 1 或求真值。

</div>

### 定点数的表示范围

<div class="study-unit" id="u-02-a1ff86362502">

**对照与计算**

</div>

<div class="study-unit" id="u-02-2942f70decdb">

| w 位表示 | 整数范围 | 小数点在符号位后时的范围 |
| --- | --- | --- |
| 无符号 | $0\sim 2^{w}-1$ | $0\sim 1-2^{-w}$ |
| 原码 / 反码 | $-(2^{w-1}-1)\sim 2^{w-1}-1$ | $-(1-2^{-(w-1)})\sim 1-2^{-(w-1)}$ |
| 补码 | $-2^{w-1}\sim 2^{w-1}-1$ | $-1\sim 1-2^{-(w-1)}$ |

</div>

<div class="study-unit" id="u-02-c2c90388036a">

原 / 反码有正零、负零，补码只有一个零。补码全 1 的整数是 −1，小数是 $-2^{-(w-1)}$，先看小数点约定。

</div>

<span class="legacy-anchor" data-target="s-02-5a3d23143d3f" id="s-10"></span><span class="legacy-anchor" data-target="s-02-5a3d23143d3f" id="p-16"></span><span class="legacy-anchor" data-target="s-02-5a3d23143d3f" id="p-17"></span><span class="legacy-anchor" data-target="s-02-5a3d23143d3f" id="u-02-68f37b8fab67"></span>

### 定点数的格式转换

<div class="study-unit" id="u-02-137a138631a4">

**基本概念**

</div>

<div class="study-unit" id="u-02-e7f6c011776e">

同宽有符号 / 无符号转换在常用补码机器模型中保留位串、改变解释。宽→窄截高位，可能丢失信息；窄→宽：有符号补码做符号扩展，无符号补 0。

</div>

<div class="study-unit" id="u-02-ea926438633f">

int→float 可能因有效位不足丢精度；

</div>

<div class="study-unit" id="u-02-3a988fa56562">

32 位 float 有 24 位二进制有效精度。

</div>

<div class="study-unit" id="u-02-9573ba6517df">

float→double 可精确表示原 float 值，double→float 可能舍入或溢出。

</div>

<div class="study-unit" id="u-02-83fed1dcbac2">

浮点→整数通常截去小数向 0 取整；

</div>

<div class="study-unit" id="u-02-4e0631ef6788">

超范围结果不能当成普通截位规则。

</div>

<div class="study-unit" id="u-02-explain-63c5cea74a">

**例子**

</div>

<div class="study-unit" id="u-02-901d9680f514">

例：8 位补码 11111011 表示 −5，扩为 16 位时高位补 1，得到 11111111 11111011，仍为 −5；若高位补 0，则被解释为 +251。

</div>

<div class="study-unit" id="u-02-b85b0bb7e463">

符号扩展保存的是有符号真值，零扩展保存的是无符号值。

</div>

<div class="study-unit" id="u-02-c870dd52221e">

### 加法器与算术逻辑部件

<div class="study-unit" id="u-02-6103ad7eeec8">

**基本概念**

</div>

<div class="study-unit" id="u-02-outline-19f48dd61b">

一位全加器输入 Aᵢ、Bᵢ 和低位进位 Cᵢ，输出和位 Sᵢ 与高位进位 Cᵢ₊₁。

</div>

<div class="study-unit" id="u-02-86f8da9550d7">

**规则与说明**

</div>

<div class="study-unit" id="u-02-c8bf7eafbb90">

- 设 $P_{i}=A_{i} XOR B_{i}$、$G_{i}=A_{i} AND B_{i}$，则 $S_{i}=P_{i} XOR C_{i}$，Cᵢ₊$_{1}=G_{i} OR (P_{i} AND C_{i})$。

</div>

<div class="study-unit" id="u-02-2ccbce85e971">

- 多位串行进位加法器把各位全加器连接，进位逐级传播；
- 先行进位根据输入提前形成进位，减少等待但增加电路。

</div>

<div class="study-unit" id="u-02-446cc31ca13c">

ALU（Arithmetic Logic Unit，算术逻辑部件）通过控制信号选择加、减、与、或等操作，并产生相应结果和标志。

### 定点数的加减法

<div class="study-unit" id="u-02-f26d22eedb5e">

**基本概念**

</div>

<div class="study-unit" id="u-02-7902699be42c">

补码加法符号位一起加，超出 w 位的进位丢弃；减法 $X-Y=X+NOT(Y)+1$。$Sub=0$ 选 Y、$Cin=0$；$Sub=1$ 选 NOT Y、$Cin=1$。

</div>

<div class="study-unit" id="u-02-explain-c69a78e35f">

Sub 是加 / 减选择信号，Cin 是加法器最低位进位输入，Cout 是最高位进位输出。

</div>

<div class="study-unit" id="u-02-9ddb17d0da86">

**规则与说明**

</div>

<div class="study-unit" id="u-02-c5bad061d645">

- 做减法时给 Y 逐位取反，再令 $Cin=1$，就把“取反加 1”并入一次加法；
- 表中的 XOR 表示异或，两个输入不同才为 1。

</div>

<div class="study-unit" id="u-02-166c79cfa14d">

**对照与计算**

</div>

<div class="study-unit" id="u-02-bba77b03c714">

| 标志 | 判定 | 用途 |
| --- | --- | --- |
| ZF（零标志，Zero Flag） | 结果全 0 | 有 / 无符号均适用 |
| SF（符号标志，Sign Flag） | 结果最高位 | 有符号结果符号 |
| OF（溢出标志，Overflow Flag） | 进入和离开符号位的进位异或 | 有符号溢出 |
| CF（进位 / 借位标志，Carry Flag） | 本电路 Sub XOR Cout | 无符号加法进位 / 减法借位 |

</div>

<div class="study-unit" id="u-02-d13d31ee53a7">

**规则与说明**

</div>

<div class="study-unit" id="u-02-027db89700af">

- 例 4 位 $X=0101$、$Y=1110$：有符号为 5、−2，$X-Y=0111=7$，$OF=0$；
- 同位串按无符号为 $5-14$，发生借位 $CF=1$。
- OF 与 CF 不能混用。

</div>

<div class="study-unit" id="u-02-steps-b64c33b650">

**用一个补码加法器完成加／减**

</div>

<div class="study-unit" id="u-02-86e9f0a3b6e5">

1. 确认位数与有／无符号解释，准备两个操作数。
2. 加法 → 第二操作数不变、最低进位为 0；减法 → 第二操作数逐位取反、最低进位为 1。
3. 符号位和数值位一起相加 → 保留约定字长的结果。
4. 有符号看 OF，无符号看 CF；它们对应不同解释，不能只看最终符号判定所有溢出。

</div>

### 定点数的溢出判断

<div class="study-unit" id="u-02-8892f821bb10">

**基本概念**

</div>

<div class="study-unit" id="u-02-4864db524adc">

有符号加法只有同号相加才可能溢出：正+正变负、负+负变正；减法只有异号相减才可能溢出，结果符号与被减数不一致时溢出。

</div>

<div class="study-unit" id="u-02-f2aa91e7dced">

**规则与说明**

</div>

<div class="study-unit" id="u-02-7a4568c35a57">

- 进位判定 $OF=C_{n} XOR C_{n}$₋₁。
- 结果数值截位后还能算出来，不代表没有溢出；
- 无符号范围错误用 CF 判。

</div>

<div class="study-unit" id="u-02-explain-140b01f285">

**例子**

</div>

<div class="study-unit" id="u-02-e62070f83cf4">

例：4 位补码范围为 −8～7，$0111+0001$ 得 1000，按补码变成 −8，说明 $7+1$ 超过正数上限，$OF=1$。

</div>

<div class="study-unit" id="u-02-26e8486cdd28">

**规则与说明**

</div>

<div class="study-unit" id="u-02-1c9efc2752b4">

- 相同位串按无符号做 $7+1=8$ 却没有超出 0～15，所以 $CF=0$；
- 两个标志判断的是不同范围。

</div>

### 定点数的移位乘除法

<div class="study-unit" id="u-02-ad20b3828276">

**基本概念**

</div>

<div class="study-unit" id="u-02-ee457e4fb9ec">

逻辑左移低位补 0、右移高位补 0；补码算术右移高位补符号，左移低位补 0。左移 k 位在不溢出时乘 $2^{k}$，右移会丢低位；补码负数算术右移通常向负无穷取整，不等于向 0 截断的除法。

</div>

<div class="study-unit" id="u-02-a7876fa46d33">

**规则与说明**

</div>

<div class="study-unit" id="u-02-95b4e598cbd2">

- 原码移位保留符号并移动数值位；
- 反码负数移出 / 补入规则与补码不同，题目给什么编码就按什么规则。
- 循环移位把移出的位转入另一端，若含进位位则 CF 也参加循环。

</div>

<div class="study-unit" id="u-02-db6c7fc77848">

**乘法**：无符号 / 原码数值部分用“逐位判断乘数→为 1 则加被乘数→移位”重复 n 次；

</div>

<div class="study-unit" id="u-02-6b3b28d27ede">

原码积符号为两符号异或。

</div>

<div class="study-unit" id="u-02-3739f4dbb19b">

补码 Booth 法由乘数低位与附加位决定 +X、−X 或不加，再做算术右移；

</div>

<div class="study-unit" id="u-02-b9d49508486e">

常用 $(Q_0,Q_{-1})=01$ 加 X、10 减 X、00/11 不加，重复 n 轮。

</div>

<div class="study-unit" id="u-02-e9d3f2114cc2">

**除法**：逐位试减并形成商。

</div>

<div class="study-unit" id="u-02-b478b9594ea1">

**规则与说明**

</div>

<div class="study-unit" id="u-02-5ead5e8def68">

- 恢复余数法试减为负则商 0 并恢复；
- 不恢复余数法按余数正负选择下一步减 / 加除数，最终若余数负则恢复。

</div>

<div class="study-unit" id="u-02-141d2a14484b">

- 商和余数的符号、移位次数、双倍字长按题设；
- 除数为 0、商超范围必须检测。

</div>

<div class="study-unit" id="u-02-steps-7807905791">

- **原码数值部分乘法**：检查当前乘数位 → 为 1 则把被乘数加到部分积，为 0 则不加 → 按算法整体移位 → 重复规定轮数 → 单独确定积的符号。

</div>

<div class="study-unit" id="u-02-c54afe7bdf0a">

**恢复余数法除法**

</div>

<div class="study-unit" id="u-02-9620898168df">

1. 将当前余数按算法移位，引入下一待处理位。
2. 试减除数 → 非负则保留余数、商上 1。
3. 试减为负 → 商上 0，并加回除数以恢复余数。
4. 重复到规定商位数，最后按题设处理商与余数符号、零除和商溢出。

</div>

### 乘除运算电路的基本结构

<div class="study-unit" id="u-02-b3f186ebcdeb">

**基本概念**

</div>

<div class="study-unit" id="u-02-outline-2f97a48099">

移位加法乘法电路通常包含被乘数寄存器 M、乘数寄存器 Q、部分积寄存器 A、加法器和计数控制。每轮检查乘数位，按规则加／不加，再把部分积和乘数整体移位；双倍字长保存乘积。

</div>

<div class="study-unit" id="u-02-7db4cf46eb80">

**规则与说明**

</div>

<div class="study-unit" id="u-02-1cebd159e96a">

- 除法电路用除数寄存器、余数／商寄存器、加减器、移位和控制部件反复试减，依据余数符号形成一位商；
- 恢复余数法失败时把除数加回。
- 符号处理、商溢出及零除检测按有／无符号模型分别进行。

</div>

### 一般浮点数

<div class="study-unit" id="u-02-1dfa987a1d60">

**基本概念**

</div>

<div class="study-unit" id="u-02-a983c1a97285">

浮点数真值 $N=(-1)^{s}\times M\times R^{E}$，阶码 E 决定数量级，尾数 M 决定有效精度，基数 R 由题设给出。

</div>

<div class="study-unit" id="u-02-c99dbd20e0ea">

**规则与说明**

</div>

<div class="study-unit" id="u-02-explain-83d21812a2">

- s 是符号位，M 是尾数，E 是实际指数。
- 可类比十进制的 $1.25\times 10^{3}$：尾数提供有效数字，指数把小数点移到合适位置；
- 规格化就是统一尾数的写法，方便比较、存储和运算。

</div>

<div class="study-unit" id="u-02-fbd52b3f5fbf">

规格化把有效尾数放入约定范围，不改变真值。

</div>

<div class="study-unit" id="u-02-e27e6cc541fa">

**规则与说明**

</div>

<div class="study-unit" id="u-02-a9908f5eccf4">

- 二进制原码小数尾数绝对值通常为 [0.5,1)，补码尾数要求符号位与最高数值位不同；
- IEEE 隐含 1 的形式是 [1,2)，不能把两种小数点位置混用。

</div>

### IEEE754浮点数

<div class="study-unit" id="u-02-f52b0c0cc436">

### 浮点数的精度问题

<div class="study-unit" id="u-02-841a992f6c86">

**基本概念**

</div>

<div class="study-unit" id="u-02-2667133e5c4b">

浮点运算会舍入，满足交换性的情况也不保证结合律，例如大数与小数相加，小数可能在对阶时全部丢失。

</div>

<div class="study-unit" id="u-02-056bafe61cd3">

**规则与说明**

</div>

<div class="study-unit" id="u-02-83e994ddce5d">

- float 能精确表示所有 |整数|$\le 2^{24}$ 的整数，double 对应 $2^{53}$；
- 超过阈值不表示每个整数都失真，取决于低位是否正好为 0。
- 精度损失与数值溢出是不同问题。

</div>

### 浮点数的加减法

<div class="study-unit" id="u-02-49256ebfbbe2">

**基本概念**

</div>

<div class="study-unit" id="u-02-d634f5a604a5">

执行

</div>

<div class="study-unit" id="u-02-26c8ebc20b02">

**操作步骤**

</div>

<div class="study-unit" id="u-02-5d40647875d4">

1. 对阶，小阶尾数右移到大阶。
2. 尾数加减。
3. 规格化，左规尾数左移、阶码减，右规尾数右移、阶码加。
4. 对移出低位舍入。
5. 检查阶码溢出。舍入进位可能再次右规。

</div>

<div class="study-unit" id="u-02-61b26f196a15">

**规则与说明**

</div>

<div class="study-unit" id="u-02-7698353525fd">

- 左右规格化保持真值，改变的是阶码与尾数的组合。
- 对阶向大阶看齐，不能把大阶降到小阶而强行保留低位。

</div>

<div class="study-unit" id="u-02-explain-fd7f3d1367">

- 以二进制 $1.1\times 2^{2} + 1.0\times 2^{0}$ 为例，先把后者对齐为 $0.01\times 2^{2}$，再加得 $1.11\times 2^{2}$。

</div>

<div class="study-unit" id="u-02-92186da33a1a">

- 对阶需要右移小阶尾数；
- 有限尾数位可能装不下移出的低位，因此要舍入，精度损失主要在这些步骤发生。

</div>

### 边界对齐

<div class="study-unit" id="u-02-ec3dfcb716ba">

**基本概念**

</div>

<div class="study-unit" id="u-02-32640ec2afff">

边界对齐要求起始地址是对齐值整数倍。例如按 4B 对齐，地址低两位为 0，跨边界访问可能多次取数。

</div>

<div class="study-unit" id="u-02-cf14e8c5d91e">

**规则与说明**

</div>

<div class="study-unit" id="u-02-39bef5e605f2">

</div>

<div class="study-unit" id="u-02-explain-388dc9265e">

- 按常见 char 对齐 1B、int 对齐 4B 的题设，结构体先放一个 char，再放 int：char 占偏移 0，补 3B 后 int 占偏移 4～7，总大小 8B。

<div class="study-unit" id="u-02-d87c585369e7">

<div class="study-unit" id="u-02-cc8047b8cdb4">

</div>

#### 动态随机存储器 DRAM

<div class="study-unit" id="u-02-88a0f05a99c4">

**基本概念**

</div>

<div class="study-unit" id="u-02-a7e4266199fa">

DRAM（Dynamic RAM，动态随机存取存储器）用电容电荷保存位，需要按行刷新，读出具有破坏性并需再生。容量密度高、成本低，常用作主存。

</div>

<div class="study-unit" id="u-02-3dddcbf343f7">

**规则与说明**

</div>

<div class="study-unit" id="u-02-1bdddf7f488c">

- 行列地址分时复用减少地址引脚，不减少逻辑地址位数。
- $4M\times 4b$ 共 $2^{22}$ 个单元，地址需 22 位；
- 行列各 11 位时仅 11 根地址引脚、4 根数据线。

</div>

<div class="study-unit" id="u-02-6b8d291d865a">

- 集中刷新产生死区；
- 分散刷新把刷新分配到各存取周期；
- 异步刷新均匀安排各行。
- 刷新次数由行数决定。
- $\text{行缓冲容量}=\text{列数}\times\text{位平面数}\ \mathrm{bit}$，不是“列地址位数×位平面数”。

</div>

<div class="study-unit" id="u-02-14a072ac2dad">

SDRAM（Synchronous DRAM，同步动态随机存取存储器）与时钟同步，可突发传送，仍需刷新。

</div>

<div class="study-unit" id="u-02-715c0f437a17">

**规则与说明**

</div>

<div class="study-unit" id="u-02-explain-0f6dc3e3fb">

- 行列复用相当于同一组引脚先送“第几行”、再送“第几列”；
- 逻辑地址仍完整，只是分两次输入。
- 刷新则读取并重新写回一整行的电荷，所以一轮刷新要覆盖全部行，而不是给每个存储单元逐个单独发地址。

</div>

#### SRAM和DRAM对比

<div class="study-unit" id="u-02-76d6c87e6938">

**对照与计算**

</div>

<div class="study-unit" id="u-02-2bb08317b200">

| 比较 | SRAM | DRAM |
| --- | --- | --- |
| 保存位 | 双稳态电路 | 电容 |
| 刷新 / 读出 | 无需刷新 / 非破坏性 | 周期刷新 / 破坏性后再生 |
| 典型用途 | Cache | 主存 |
| 速度 / 成本 / 密度 | 快 / 高 / 低 | 较慢 / 低 / 高 |
| 易失 | 是 | 是 |

### DRAM芯片、内存条与CPU连接

<div class="study-unit" id="u-02-a78f3824720a">

**基本概念**

</div>

<div class="study-unit" id="u-02-outline-e4c87da441">

内存条把多片 DRAM 和连接电路装在一块模块上，用并行芯片凑足数据位宽，再用组选择扩展容量。

</div>

<div class="study-unit" id="u-02-30671c3e7835">

**例子**

</div>

<div class="study-unit" id="u-02-4f285083f5dd">

</div>

<div class="study-unit" id="u-02-c85bc19e3abe">

连接 CPU 时，地址线用于选择存储位置，数据线搬运数据，读写／片选等控制线决定哪组芯片响应。

</div>

<div class="study-unit" id="u-02-9302fb2e756b">

**规则与说明**

</div>

<div class="study-unit" id="u-02-321a318b9b15">

- DRAM 的行列地址通常由内存控制器分时送入；
- 芯片的地址引脚数、逻辑地址位数和 CPU 地址总线宽度要分别判断，不能视为相同。

</div>

### 多模块存储器

<div class="study-unit" id="u-02-7f28c4ea4525">

**基本概念**

</div>

<div class="study-unit" id="u-02-040bcd6b9488">

多体存储各体独立控制，可并行或交叉启动。高位交叉：体号在高位，连续地址集中同体，主要扩容；低位交叉：体号在低位，连续地址分散各体，可流水式连续访问。

</div>

<div class="study-unit" id="u-02-83f624388f44">

**规则与说明**

</div>

<div class="study-unit" id="u-02-0b8f121333df">

- 低位交叉，地址 A、m 体：体号$=A \bmod  m$，体内地址$=\lfloor \frac{A}{m}\rfloor$。
- 高位交叉，每体 L 单元：体号$=\lfloor \frac{A}{L}\rfloor$，体内地址$=A \bmod  L$。

</div>

<div class="study-unit" id="u-02-5f8efb15b749">

存取周期 T、启动间隔 r，连续轮流访问要求 $m\ge \lceil \frac{T}{r}\rceil$；

</div>

<div class="study-unit" id="u-02-2cc6771161d0">

取 n 个连续字理想耗时 $T+(n-1)r$。

</div>

<div class="study-unit" id="u-02-07c129513612">

步长 s 的访问会按 $(A+ks) \bmod  m$ 落体，可能冲突，不能见多体就套连续吞吐量。

</div>

<div class="study-unit" id="u-02-77a56a914fbf">

单体多字 / 同时启动需相应宽数据通路。

</div>

<div class="study-unit" id="u-02-explain-22dbbbd91f">

**例子**

</div>

<div class="study-unit" id="u-02-ed3a09ae072b">

例：4 体低位交叉，地址 0、1、2、3 分别落在体 0、1、2、3，地址 4 再回体 0；不同体可以错开启动。

</div>

<div class="study-unit" id="u-02-3e77cacaff6a">

**例子**

</div>

<div class="study-unit" id="u-02-10a1020b20d2">

若周期 $T=40ns$、间隔 $r=10ns$，4 体足够轮转，取 4 个连续字约需 $40+3\times 10=70ns$。

</div>

#### 性能指标

<div class="study-unit" id="u-02-413be4b2f50d">

**基本概念**

</div>

<div class="study-unit" id="u-02-80d56c178386">

$\text{访问时间}=\text{寻道时间}+\text{旋转延迟}+\text{数据传输时间}$（题设需要时加控制器开销）。

</div>

<div class="study-unit" id="u-02-e841b647ff09">

**规则与说明**

</div>

<div class="study-unit" id="u-02-e298acd8c4f7">

- 转速 r 转/秒，转一周 $\frac{1}{r}$，平均旋转延迟 $\frac{1}{2r}$；
- rpm 先除以 60。

</div>

<div class="study-unit" id="u-02-3b48645ad422">

- 传 b 字节、每道 N 字节，传输时间$=\frac{b}{rN}$，或直接用 b/传输速率。
- 寻道距离由请求顺序决定；
- 平均延迟不能直接当成每次指定扇区的实际延迟。

</div>

<div class="study-unit" id="u-02-explain-ecfaf50148">

**例子**

</div>

<div class="study-unit" id="u-02-8314865dc8a2">

</div>

<div class="study-unit" id="u-02-3087f425da30">

**规则与说明**

</div>

<div class="study-unit" id="u-02-ecf4b72902b6">

- 寻道是磁头沿半径移动到目标磁道，旋转等待是目标扇区转到磁头下，传输才是读写字节；
- 三者是先后发生的不同开销。

</div>

### 高速缓存 Cache

<span class="legacy-anchor" data-target="s-02-002fc081bbcc" id="s-46"></span><span class="legacy-anchor" data-target="s-02-002fc081bbcc" id="p-56"></span><span class="legacy-anchor" data-target="s-02-002fc081bbcc" id="p-57"></span>
<a id="s-02-002fc081bbcc"></a>

#### Cache的基本原理

<div class="study-unit" id="u-02-d15d9dd8e49b">

**基本概念**

</div>

<div class="study-unit" id="u-02-c8e89e128984">

Cache 利用时间局部性（近期访问很可能再访问）和空间局部性（相邻地址可能被访问），把主存块缓存到更快的行中。

</div>

<div class="study-unit" id="u-02-61432fe72b4c">

**规则与说明**

</div>

<div class="study-unit" id="u-02-41da61d4374b">

- 命中直接取数；
- 未命中从主存调块，必要时替换；
- CPU—Cache 所求字与主存—Cache 调块单位不同。

</div>

<div class="study-unit" id="u-02-3fe93f6dfc93">

命中率 $H=$命中次数/总访问次数。

</div>

<div class="study-unit" id="u-02-a2f8a81c5cb6">

**规则与说明**

</div>

<div class="study-unit" id="u-02-0942fdbc4c78">

- 串行查询且未命中追加开销为 Tm 时，平均时间 $Tc+(1-H)Tm$；
- 若未命中总时间已含 Tc，则用 $H\cdot Tc+(1-H)\cdot Tmiss$。

</div>

<div class="study-unit" id="u-02-ebb20882567a">

访存模型不同不能重复加时间。

</div>

<div class="study-unit" id="u-02-explain-afae3fe55b">

Tc 是查 Cache 并取得命中结果的时间，Tm 是未命中后追加的主存开销。

</div>

<div class="study-unit" id="u-02-224f5af42eb2">

**例子**

</div>

<div class="study-unit" id="u-02-aed1519e92cc">

例：$Tc=2ns$、$Tm=40ns$、命中率 95%，串行模型平均时间为 $2+0.05\times 40=4ns$；其含义是每次先花 2ns，只有 5% 的访问再花 40ns。

</div>

<span class="legacy-anchor" data-target="s-02-de22e9bb48e3" id="s-47"></span><span class="legacy-anchor" data-target="s-02-de22e9bb48e3" id="p-58"></span><span class="legacy-anchor" data-target="s-02-de22e9bb48e3" id="p-59"></span><span class="legacy-anchor" data-target="s-02-de22e9bb48e3" id="u-02-382a4e9ac7a1"></span><span class="legacy-anchor" data-target="s-02-de22e9bb48e3" id="u-02-6e322d93affa"></span>
<a id="s-02-de22e9bb48e3"></a>

#### Cache的映射方式

<div class="study-unit" id="u-02-44d908053441">

**对照与计算**

</div>

<div class="study-unit" id="u-02-d4d6d50955a9">

| 映射 | 主存块放哪里 | 地址字段 |
| --- | --- | --- |
| 直接 | $\text{行号}=\text{主存块号}\bmod\text{行数}$ | Tag + 行号 + 块内偏移 |
| 全相联 | 任意行 | Tag + 块内偏移 |
| r 路组相联 | $\text{组号}=\text{主存块号}\bmod\text{组数}$，组内任选 r 行 | Tag + 组号 + 块内偏移 |

</div>

<div class="study-unit" id="u-02-10f8dba830f1">

流程：

</div>

<div class="study-unit" id="u-02-54bf456606eb">

**操作步骤**

</div>

<div class="study-unit" id="u-02-f7e5c7cc7251">

1. 地址分字段。
2. 选行 / 组。
3. 检查有效位且 Tag 匹配。
4. 按偏移取数。

</div>

<div class="study-unit" id="u-02-93ed10aebd67">

**规则与说明**

</div>

<div class="study-unit" id="u-02-d3167deb54a8">

- 直接映射实现简单但冲突多，全相联冲突少但比较硬件多，组相联折中；
- r 路表示每组 r 行，不是总共 r 组。

</div>

<div class="study-unit" id="u-02-c76b5a88d22d">

- 字节编址、块 B 字节：偏移 log₂B 位；
- Cache 数据容量 C 字节：行数$=\frac{C}{B}$，组数$=\frac{C}{Br}$。
- $Tag=$主存地址位数−组 / 行号位数−偏移位数。

</div>

<div class="study-unit" id="u-02-explain-0c66694924">

- 块内偏移决定“取这一块里的哪个字节”，行 / 组号决定“去 Cache 的哪里找”，Tag（标记）再区分“此处放的是哪个主存块”。

</div>

<div class="study-unit" id="u-02-03a28d9643c2">

**例子**

</div>

<div class="study-unit" id="u-02-1485179fde3e">

例：直接映射 Cache 有 4 行，主存块 1、5 都只能放第 1 行，因此两块交替访问会冲突。

</div>

#### Cache块的替换算法

<div class="study-unit" id="u-02-f36878ad151a">

**基本概念**

</div>

<div class="study-unit" id="u-02-78245db4d051">

直接映射行已固定，无需从多个候选行中选替换对象；全相联或组内满时才按替换算法选择。

</div>

<div class="study-unit" id="u-02-f48abef893da">

FIFO（先进先出）淘汰最早装入者，命中不改装入先后；

</div>

<div class="study-unit" id="u-02-988e4cb36277">

LRU（最近最少使用，Least Recently Used）淘汰最长时间未访问者，命中也更新近期顺序；

</div>

<div class="study-unit" id="u-02-f10df027f719">

RAND（随机替换）随机；

</div>

<div class="study-unit" id="u-02-a1d5ce981a58">

LFU（最不经常使用，Least Frequently Used）淘汰累计访问少者。

</div>

<div class="study-unit" id="u-02-202228cc5b1d">

组相联只在当前组内替换，不在全部行里挑 LRU。

</div>

<div class="study-unit" id="u-02-179987f290ce">

**规则与说明**

</div>

<div class="study-unit" id="u-02-e0e8a0268202">

- 精确 LRU 的控制位数依实现；
- 逐行年龄计数常需 $\lceil \log_{2}r\rceil$ 位 / 行，但不能当作所有 LRU 硬件的唯一容量公式。

</div>

<div class="study-unit" id="u-02-explain-fc18fd3457">

**例子**

</div>

<div class="study-unit" id="u-02-1b3ecd9dab83">

假设两行先后装入 A、B，然后命中 A，再调入 C：FIFO 淘汰先装入的 A；LRU 淘汰更久没访问的 B。

</div>

<div class="study-unit" id="u-02-c94ed5731b07">

区别在于 FIFO 记“进入时间”，LRU 记“最近使用时间”，命中只会改变后者的次序。

</div>

<div class="study-unit" id="u-02-steps-713e1ae4b9">

**做替换题的统一顺序**

</div>

<div class="study-unit" id="u-02-81b1b32ebc52">

1. 按地址映射确定 Cache 的行或组，先检查有效位和标记。
2. 命中 → 按策略更新“最近使用”等信息，不把命中当作重新装入。
3. 未命中 → 优先使用空行；没有空行，再在当前组内按 FIFO／LRU 等选牺牲块。
4. 牺牲块若为脏且采用回写 → 先写回；调入新块，更新标记、有效位及替换状态。

</div>

<span class="legacy-anchor" data-target="s-02-f83426575850" id="s-50"></span><span class="legacy-anchor" data-target="s-02-f83426575850" id="p-63"></span><span class="legacy-anchor" data-target="s-02-f83426575850" id="p-64"></span><span class="legacy-anchor" data-target="s-02-f83426575850" id="u-02-040fa77b0781"></span><span class="legacy-anchor" data-target="s-02-f83426575850" id="u-02-5f9c4ab08cac"></span>
<a id="s-02-f83426575850"></a>

#### Cache的写策略

<div class="study-unit" id="u-02-38c2f399f963">

**对照与计算**

</div>

<div class="study-unit" id="u-02-8662416f9d5e">

| 情形 | 策略 | 操作 |
| --- | --- | --- |
| 写命中 | 全写 / 直写 | 同时更新 Cache 和主存，可用写缓冲减少等待 |
| 写命中 | 回写 | 只改 Cache 并置脏位，替换脏块时写回 |
| 写未命中 | 写分配 | 先调入对应块，再在 Cache 写 |
| 写未命中 | 非写分配 | 直接写主存，不调入块 |

</div>

<div class="study-unit" id="u-02-b847b97df435">

全写常配非写分配，回写常配写分配，但这是常见组合，不是定义上的强制绑定。统计主存读写次数时，还要计调块、脏块写回、写缓冲等题设开销。

</div>

<div class="study-unit" id="u-02-8bffa7eafca3">

**规则与说明**

</div>

<div class="study-unit" id="u-02-explain-5767e0abd5">

- 脏位表示 Cache 中的数据已被修改、尚未同步回主存。
- 回写时只在淘汰脏块等需要同步的时机写主存；
- 写分配则回答另一个问题：写入目标不在 Cache 时，要不要先把整个块调进来。

</div>

#### Cache的容量

<div class="study-unit" id="u-02-53fc4aa522ed">

**基本概念**

</div>

<div class="study-unit" id="u-02-708c8dae69b9">

Cache **数据容量**：$\text{行数}\times\text{每行数据字节}$；**总容量**还加 Tag、有效位、脏位和题设替换控制位。按 bit 算完最后除以 8 转 B。

</div>

<div class="study-unit" id="u-02-b50bb1f37faa">

**规则与说明**

</div>

<div class="study-unit" id="u-02-327c851f784b">

- 例 32 位字节地址、64KB 数据区、64B 块：1024 行，偏移 6 位；
- 直接映射行号 10 位、Tag 16 位；
- 8 路组相联为 128 组，组号 7 位、Tag 19 位。

</div>

<div class="study-unit" id="u-02-f0d4800c6ccd">

每行数据为 $64\times 8=512bit$，不是 6bit。

</div>

<span class="legacy-anchor" data-target="s-02-87df6a5e5cdc" id="s-52"></span><span class="legacy-anchor" data-target="s-02-87df6a5e5cdc" id="p-66"></span><span class="legacy-anchor" data-target="s-02-87df6a5e5cdc" id="u-02-ee62513370bd"></span><span class="legacy-anchor" data-target="s-02-87df6a5e5cdc" id="u-02-247e2cfea023"></span><span class="legacy-anchor" data-target="s-02-87df6a5e5cdc" id="u-02-fa01ecdaf6b8"></span><span class="legacy-anchor" data-target="s-02-87df6a5e5cdc" id="u-02-5b8fef0f1e24"></span>

### 虚拟存储器

<div class="study-unit" id="u-02-e73fb6561c32">

**基本概念**

</div>

<div class="study-unit" id="u-02-b0f3b3af71a7">

虚拟存储器给每个进程虚拟地址空间，将暂不需要页面留在辅存，靠请求调页与置换提供超过实际主存的使用能力。

</div>

<div class="study-unit" id="u-02-8e5a259fe073">

地址翻译由 MMU（内存管理单元，Memory Management Unit）、页表 / TLB 配合，缺页由 OS 处理。

</div>

<div class="study-unit" id="u-02-2235dc3dae7a">

**规则与说明**

</div>

<div class="study-unit" id="u-02-1814e114cc8b">

- 虚拟容量受地址位数和外存支持等限制，不等于实际物理内存。
- Cache 主要解决速度，虚存主要解决容量 / 地址空间隔离；
- 命中缺失和管理者不能混为一谈。

</div>

<span class="legacy-anchor" data-target="s-02-574aa32d8893" id="s-53"></span><span class="legacy-anchor" data-target="s-02-574aa32d8893" id="p-67"></span><span class="legacy-anchor" data-target="s-02-574aa32d8893" id="u-02-670671cd9740"></span>
<a id="s-02-574aa32d8893"></a>

#### CPU访存全过程

<div class="study-unit" id="u-02-3b2a8ba919d9">

**一次正常访存，先翻译地址，再查数据。**

</div>

<div class="study-unit" id="u-02-a7be0cb991a5">

1. 将虚拟地址拆为 VPN（虚页号，Virtual Page Number）与页内偏移。
2. **查 TLB**：命中 → 取得页框号；未命中 → 查页表。
3. **检查页面是否驻留**：驻留 → 形成物理地址，并按需要更新 TLB；不驻留 → 转缺页处理。
4. **查 Cache**：命中 → 取数据；未命中 → 访问主存、调入数据块。

</div>

<div class="study-unit" id="u-02-7faf8149ba53">

**主线**：虚拟地址 → TLB／页表 → 物理地址 → Cache／主存 → 数据。

</div>

<div class="study-unit" id="u-02-86f2260b5ac6">

页面不驻留：

</div>

<div class="study-unit" id="u-02-a06eb51cc098">

**操作步骤**

</div>

<div class="study-unit" id="u-02-1345959c52a7">

1. 缺页异常。
2. OS 选空闲框或置换，必要时写回脏页。
3. 从辅存调页。
4. 更新页表 / TLB。
5. 重新执行故障指令。

</div>

<div class="study-unit" id="u-02-32e017959a9e">

**规则与说明**

</div>

<div class="study-unit" id="u-02-b7bab85f7750">

- TLB 未命中不等于缺页；
- Cache 未命中也不一定产生异常。

</div>

<div class="study-unit" id="u-02-explain-835ac6c8d8">

这是两种查找：TLB / 页表先回答“这个虚拟地址对应哪个物理地址”，Cache 再回答“这个物理位置的数据是否已有高速副本”。

</div>

<div class="study-unit" id="u-02-a1e405ea4c78">

**规则与说明**

</div>

<div class="study-unit" id="u-02-2750f72f37bf">

- 因此 TLB 未命中后查到页面已驻留，可以继续访存；
- 只有合法页面确实不驻留时，才需缺页调入。

</div>

<div class="study-unit" id="u-02-3fff0abefc6f">

</div>

- 存在位 0 表示当前不驻留，不是页号越界。
- 多级页表按多段页号逐级索引，顶级基址为物理地址。

#### 操作码扩展

<div class="study-unit" id="u-02-c7a915742c28">

**基本概念**

</div>

<div class="study-unit" id="u-02-9344a7450e6a">

扩展操作码：在短操作码中保留部分前缀，用原地址字段继续扩展为长操作码。短编码一旦代表独立指令，不能同时作为长编码前缀。

</div>

<div class="study-unit" id="u-02-7541bcfbcd25">

16 位指令、地址字段各 6 位，二 / 一 / 零地址操作码分别 4 / 10 / 16 位。

</div>

<div class="study-unit" id="u-02-69d3e6232c08">

**例子**

</div>

<div class="study-unit" id="u-02-d479e4f457e2">

若还需一 / 零地址，二地址至多 15 种；

</div>

<div class="study-unit" id="u-02-a0af5dad3a0a">

二地址 P 种、零地址 Q 种时，一地址最多 $64(16-P)-\lceil \frac{Q}{64}\rceil$ 种。

</div>

<div class="study-unit" id="u-02-dba7496f1c76">

向上取整因为零地址需占完整的 6 位扩展子树；

</div>

<div class="study-unit" id="u-02-ee23d7a9eba5">

Q 整除 64 时可省取整。

</div>

<div class="study-unit" id="u-02-3cbfb8be86f4">

**规则与说明**

</div>

<div class="study-unit" id="u-02-explain-8bc9755fa9">

- 可以把操作码看成一棵编码树：某个短前缀已经代表一条指令，就不能再沿该前缀编码更长指令；
- 保留的前缀才可继续扩展。

</div>

<div class="study-unit" id="u-02-e79b56819c3d">

- 上例中，一个一地址编码槽再借 6 位可编码 64 条零地址指令，所以 Q 条零地址指令至少占 $\lceil \frac{Q}{64}\rceil$ 个槽。

</div>

### 数据的寻址方式

<div class="study-unit" id="u-02-a75d99f6a805">

**基本概念**

</div>

<div class="study-unit" id="u-02-abbe59001a25">

形式地址 A 是指令字段，有效地址 EA（Effective Address）是真正操作数位置；(X) 表示取 X 所指位置内容。

</div>

<div class="study-unit" id="u-02-78338ec5c861">

**对照与计算**

</div>

<div class="study-unit" id="u-02-a0b5add7f8fe">

| 方式 | 规则 | 用途 / 取操作数访存 |
| --- | --- | --- |
| 隐含 | 指令约定位置，如 ACC | 无须显式给地址 |
| 立即 | $D=A$ | 不额外访存 |
| 直接 | $EA=A$，$D=M[A]$ | 通常 1 次 |
| 间接 | $EA=M[A]$，$D=M[EA]$ | 一级间接通常 2 次 |
| 寄存器 | $D=(R_{i})$ | 不访主存取操作数 |
| 寄存器间接 | $EA=(R_{i})$，$D=M[EA]$ | 通常 1 次 |
| 相对 | $EA=$更新后的 PC+有符号位移 A | 转移；PC 基准按题设 |
| 基址 | $EA=(BR)+A$，BR 为基址寄存器 | 程序重定位，基址通常由系统设置 |
| 变址 | $EA=A+(IX)$，IX 为变址寄存器 | 数组等，IX 随操作改变 |
| 堆栈 | 栈顶 SP（栈指针，Stack Pointer）隐含或指定 | 进出栈，栈增长方向按题设 |

</div>

<div class="study-unit" id="u-02-ca7d1f655db3">

**规则与说明**

</div>

<div class="study-unit" id="u-02-5f7bfc6af6a0">

- 表中访存不计取指，且假定数据在主存、无 Cache。
- 基址与变址式子相同，变化对象与用途不同。

</div>

<div class="study-unit" id="u-02-explain-adec4624c3">

**例子**

</div>

<div class="study-unit" id="u-02-fcb9fd1d3652">

例：地址字段 $A=100$，$M[100]=500$，$M[500]=7$：直接寻址取 M[100]，操作数为 500；

</div>

<div class="study-unit" id="u-02-90abfd573a44">

主存间接先取出地址 500，再取 M[500]，操作数为 7。

</div>

<div class="study-unit" id="u-02-6472256ab98c">

这里 M[x] 表示地址 x 处的内容，EA 是最终要去访问的地址。

</div>

### 复杂精简指令集 CISC/RISC

<div class="study-unit" id="u-02-5169f238de1e">

**对照与计算**

</div>

<div class="study-unit" id="u-02-3d9f1eea5bc9">

| 特征 | CISC（复杂指令集，Complex Instruction Set Computer） | RISC（精简指令集，Reduced Instruction Set Computer） |
| --- | --- | --- |
| 指令功能 / 格式 | 复杂、格式多、常变长 | 功能较简单、格式规整、常定长 |
| 访存 | 多种指令可含存储操作数 | 典型仅 Load / Store |
| 寄存器 / 控制 | 通常较少 / 常微程序 | 通常较多 / 常硬布线 |
| 流水实现 | 复杂指令增加设计难度 | 较易流水和编译优化 |

</div>

<div class="study-unit" id="u-02-008449767032">

这是典型教材对比，不是硬性数量界限；RISC 也可有压缩 / 变长扩展，不能说所有 RISC 指令都严格等长或只能一个周期。

### 程序的机器级表示

<span class="legacy-anchor" data-target="s-02-a688d9bdac10" id="s-66"></span><span class="legacy-anchor" data-target="s-02-a688d9bdac10" id="p-88"></span><span class="legacy-anchor" data-target="s-02-a688d9bdac10" id="p-89"></span><span class="legacy-anchor" data-target="s-02-a688d9bdac10" id="u-02-72d1366d2cec"></span><span class="legacy-anchor" data-target="s-02-a688d9bdac10" id="u-02-aea92132c4cb"></span><span class="legacy-anchor" data-target="s-02-a688d9bdac10" id="u-02-a6f0089ab675"></span>

#### 常用汇编指令

<div class="study-unit" id="u-02-7ee35330c6d4">

**对照与计算**

</div>

<div class="study-unit" id="u-02-7a61b53701be">

| 指令 | 执行含义 |
| --- | --- |
| MOV | 复制源到目的，通常不改算术标志 |
| ADD / SUB | 加 / 减，通常更新结果标志 |
| INC / DEC | 加 / 减 1；x86 中通常不改 CF |
| NEG | 0−操作数，不是逐位取反 |
| AND / OR / XOR / NOT | 位运算；NOT 与 NEG 不同 |
| CMP / TEST | 分别作减法 / 按位与来设置标志，不保存计算结果 |
| MUL / IMUL | 无符号 / 有符号乘法；操作数形式、结果寄存器按 ISA |
| PUSH / POP | 压栈 / 出栈并更新 SP |
| CALL / RET | 保存返回地址并转移 / 取回地址并返回 |

</div>

#### CPU的组成

<div class="study-unit" id="u-02-5ab85f3a8940">

**基本概念**

</div>

<div class="study-unit" id="u-02-3d914f9348c9">

$CPU=$运算器+控制器。运算器负责数据加工（ALU、工作寄存器、标志等）；控制器负责取指、译码、时序与控制信号、中断响应等。

</div>

<div class="study-unit" id="u-02-08b5e77e1ff7">

**规则与说明**

</div>

<div class="study-unit" id="u-02-d79814f252e2">

- PC（程序计数器）存下一取指位置，IR（指令寄存器）存当前指令，MAR（存储器地址寄存器）存访存地址，MDR（存储器数据寄存器）缓冲访存数据；

</div>

<div class="study-unit" id="u-02-a0f10795f017">

GPR（通用寄存器）保存操作数 / 结果，PSW（程序状态字）保存状态。

</div>

<div class="study-unit" id="u-02-25232953bef0">

PC 是地址、IR 是指令，MAR 是地址、MDR 是数据，不能互换。

</div>

#### 取指周期

<div class="study-unit" id="u-02-de3c352a140e">

**基本概念**

</div>

<div class="study-unit" id="u-02-2f6facab58f7">

取指：

</div>

<div class="study-unit" id="u-02-1eda6b062ec5">

**操作步骤**

</div>

<div class="study-unit" id="u-02-7a7868878afb">

1. **给地址**：PC → MAR，确定指令所在存储单元。
2. **读指令**：发出读控制，M[MAR] → MDR。
3. **保存并译码**：MDR → IR，IR 中的操作码交给译码部件。

</div>

<div class="study-unit" id="u-02-821d8a9048fc">

**规则与说明**

</div>

<div class="study-unit" id="u-02-31e0503b1010">

- 顺序取指还需 PC ← PC + 本条指令长度；
- 它安排在哪一拍、能否与读存储器并行，取决于题设的数据通路。

</div>

<div class="study-unit" id="u-02-eb67f976eff9">

操作码从 IR 送译码器，不是从 PC 直接取指令内容。

</div>

<div class="study-unit" id="u-02-097353b92b1f">

**规则与说明**

</div>

<div class="study-unit" id="u-02-823fc937b3ad">

- 一次能否取完整指令由存储字 / 通路宽度决定；
- 指令跨块、跨单元时可能需多次取数。

</div>

<div class="study-unit" id="u-02-explain-2073a63fb7">

- PC 先给出“指令在哪里”，MAR 接收该地址；
- 主存把指令内容送入 MDR，再交给 IR 保存并译码。
- PC 随后指向顺序执行的下一条；
- 若本条是转移指令，执行阶段会再把 PC 改成转移目标。

</div>

#### 数据通路的定义

<div class="study-unit" id="u-02-f8125630e3aa">

**基本概念**

</div>

<div class="study-unit" id="u-02-348d4c6b6ef3">

<div class="study-unit" id="u-02-a6e66519e3bf">

- 数据线承载操作数，控制线承载控制信号；
- “数据通路”不等于只有一条数据总线。

</div>

<div class="study-unit" id="u-02-f7086be50398">

</div>

<div class="study-unit" id="u-02-e82f585b61d2">

- 高电平有效三态门的 EN（使能信号）$=1$ 导通，$EN=0$ 高阻；
- 低电平有效相反。
- 多个驱动共享总线时，同一时刻只能允许一个有效驱动，多个接收部件可同时接收。

#### 单总线结构

<div class="study-unit" id="u-02-34c94e1edc3a">

**基本概念**

</div>

<div class="study-unit" id="u-02-1a6562590ef1">

CPU 内部单总线把部件接到一条共享通路：一次通常只允许一个源输出。为完成二元运算，先把一操作数存暂存器，再从总线送另一操作数到 ALU；结果通常先存 Z，再输出总线。

</div>

<div class="study-unit" id="u-02-e068b280274c">

**规则与说明**

</div>

<div class="study-unit" id="u-02-8b361ac255fd">

- 优点连接简单、成本低；
- 缺点传送受共享限制，需要更多节拍。
- 可并行的微操作不能争用同一总线源 / 同一部件。

</div>

<div class="study-unit" id="u-02-explain-3c9302da6a">

**例子**

</div>

<div class="study-unit" id="u-02-86fd6547d7f8">

例如 $R1+R2$→R3，单总线不能同时让 R1、R2 两个源都驱动总线。

</div>

<div class="study-unit" id="u-02-961dd4fef425">

**规则与说明**

</div>

<div class="study-unit" id="u-02-cfd89a51630f">

- 可先 R1→暂存器 Y，再让 R2 经总线与 Y 相加、结果存 Z，最后 Z→R3；
- 所需节拍来自“共享通路一次只能送一个源”。

</div>

#### 单周期和多周期CPU

<div class="study-unit" id="u-02-4f40ebbaad85">

#### 微程序控制的概念

<div class="study-unit" id="u-02-1061fb144137">

**基本概念**

</div>

<div class="study-unit" id="u-02-0497baaf08e6">

</div>

<div class="study-unit" id="u-02-a7c27f506bbd">

- 机器指令→对应微程序→各微指令→微命令 / 微操作。

<div class="study-unit" id="u-02-95526355feb1">

#### 微指令的格式和编码方式

<div class="study-unit" id="u-02-623d4f5c7d59">

**基本概念**

</div>

<div class="study-unit" id="u-02-7688b6ef5255">

微指令含操作控制字段和顺序控制字段。水平型可并行控制多个相容微操作，微指令较长、微程序较短；垂直型像机器指令，编码较紧、通常并行度较低。

</div>

<div class="study-unit" id="u-02-12209f6013f2">

**对照与计算**

</div>

<div class="study-unit" id="u-02-4f8a671744a3">

| 编码 | 执行 / 优缺点 |
| --- | --- |
| 直接编码 | 一位一个微命令，无需译码，快、并行强，但字长长 |
| 字段直接编码 | 互斥命令同字段、相容命令不同字段，需译码，缩短字长 |
| 字段间接编码 | 某字段依赖另一字段解释，进一步压缩，译码更复杂 |

</div>

<div class="study-unit" id="u-02-695861424678">

**规则与说明**

</div>

<div class="study-unit" id="u-02-c667a3a811d2">

- 一个字段容纳 k 个互斥命令且留一个“不操作”码，需 $\lceil \log_{2}(k+1)\rceil$ 位；
- 各字段位数相加，另加顺序控制字段。

</div>

<div class="study-unit" id="u-02-explain-f74b4e6779">

- 相容微操作能同拍执行，例如一个源经总线写入两个目的寄存器；
- 互斥微命令会争同一资源，例如两个源同时输出同一总线。
- 若一个字段有 3 个互斥命令，加上“不操作”共 4 种状态，只需 2 位编码。

</div>

#### 异常和中断的概念

<div class="study-unit" id="u-02-a7c2cd3ff4e7">

**基本概念**

</div>

<div class="study-unit" id="u-02-3e1e967e9b79">

异常与当前指令有关，执行中检测；外中断来自外设 / 定时器等，与当前指令无直接关系，通常在指令结束边界响应。

</div>

<div class="study-unit" id="u-02-4f3948ecfedb">

**规则与说明**

</div>

<div class="study-unit" id="u-02-0d20e628e03f">

- 故障：如缺页，修复后重执行当前指令；
- 自陷：如系统调用 / 调试陷入，通常返回下一指令或定义的继续位置；
- 终止：严重错误，通常不能恢复原程序。

</div>

<div class="study-unit" id="u-02-063a00cac05c">

中断返回位置与实际处理策略 / ISA 有关，不能把“异常都重执行”当统一规则。

<div class="study-unit" id="u-02-cf08dee12aa3">

**基本概念**

</div>

<div class="study-unit" id="u-02-5f9a7b3b7d23">

**规则与说明**

</div>

<div class="study-unit" id="u-02-ddac00de8602">

- 同时请求 A,C,D、响应 A>B>C>D：先 A，再 C；
- C 开中断后 D 可打断 C；
- 回 C 完成；
- C 期间来的 B 只能延后。

五段流水：

**操作步骤**

#### 流水线的指令要求

</div>

<span class="legacy-anchor" data-target="s-02-d36c608de335" id="s-106"></span><span class="legacy-anchor" data-target="s-02-d36c608de335" id="p-125"></span>

#### 流水线的性能指标

<div class="study-unit" id="u-02-5031ded2d923">

**基本概念**

</div>

<div class="study-unit" id="u-02-d99e75d632c4">

k 段等时、时钟 Δt、n 条、无停顿时 $T=(k+n-1)\Delta t$；第一条 kΔt，后续每条增加 Δt。

</div>

<div class="study-unit" id="u-02-b3494f4714d8">

**规则与说明**

</div>

<div class="study-unit" id="u-02-524d6a69aaa1">

- 吞吐率 TP（Throughput）$=\frac{n}{T}$，n 很大时$\approx 1/\Delta t$；
- 相对逐条 k 阶段串行执行，加速比 $S=\frac{kn}{k+n-1}$，极限 k；
- 效率可按 S/k。

</div>

<div class="study-unit" id="u-02-89da9b19f4ac">

**例子**

</div>

<div class="study-unit" id="u-02-402e6af13f46">

若有 s 个停顿周期，$T=(k+n-1+s)\Delta t$，冲刷和访存延迟依题设另计。

</div>

<div class="study-unit" id="u-02-96622530d7d2">

阶段不等时先取最长段加寄存器开销作为时钟，不能直接用阶段平均时间。

</div>

<span class="legacy-anchor" data-target="s-02-6d4d390173bf" id="s-107"></span><span class="legacy-anchor" data-target="s-02-6d4d390173bf" id="p-126"></span><span class="legacy-anchor" data-target="s-02-6d4d390173bf" id="p-127"></span><span class="legacy-anchor" data-target="s-02-6d4d390173bf" id="u-02-dc2cdea9dcd7"></span><span class="legacy-anchor" data-target="s-02-6d4d390173bf" id="u-02-a21855da08cb"></span><span class="legacy-anchor" data-target="s-02-6d4d390173bf" id="u-02-43bd2fb95ee7"></span><span class="legacy-anchor" data-target="s-02-6d4d390173bf" id="u-02-7d1c3c6ca435"></span><span class="legacy-anchor" data-target="s-02-6d4d390173bf" id="u-02-b93538f02558"></span><span class="legacy-anchor" data-target="s-02-6d4d390173bf" id="u-02-40b2d197fdbe"></span>
<a id="s-02-6d4d390173bf"></a>

### 流水线冒险和处理

<div class="study-unit" id="u-02-b9c5de4c3fb6">

**对照与计算**

</div>

<div class="study-unit" id="u-02-49d180ecf561">

| 冒险 | 怎么发生 | 处理 |
| --- | --- | --- |
| 结构 | 多条指令同周期争同一硬件，如取指 / 数据共用存储器 | 增加独立部件或停顿 |
| 数据 RAW（写后读相关，Read After Write） | 后指令先读前指令尚未写回的结果 | 旁路、停顿、编译调序 |
| WAR（读后写相关） / WAW（写后写相关） | 先读后写 / 先写后写顺序被打乱 | 乱序体系可用寄存器重命名等；基础顺序五段通常不发生 |
| 控制 | 分支结果未确定就取了后续指令 | 停顿、预测、延迟分支；预测错冲刷 |

</div>

<div class="study-unit" id="u-02-e64b785283ee">

**load-use**：典型带旁路五段流水中，Load 在 MEM 后才有数据，紧邻使用者仍通常停一周期，再旁路到 EX。

</div>

<div class="study-unit" id="u-02-307a55c62f73">

**规则与说明**

</div>

<div class="study-unit" id="u-02-441017d0c11b">

- 检测后冻结 PC、IF/ID，在 ID/EX 注入空操作；
- 不是冻结所有阶段。

</div>

<div class="study-unit" id="u-02-e2270e8b64bb">

画时空图按“数据何时产生、何时需要”决定停顿，不背所有分支必停三周期。

</div>

<div class="study-unit" id="u-02-explain-fa123ba84a">

**例子**

</div>

<div class="study-unit" id="u-02-b990eb420b78">

例：Load R1 后紧接 Add 使用 R1，Add 的 EX 阶段需要值时，Load 的访存才将完成，普通 EX 旁路来不及提供它。

</div>

<div class="study-unit" id="u-02-360faf4e8e34">

停一拍后，Load 继续向前，Add 延后再取旁路值；

</div>

<div class="study-unit" id="u-02-0109144ad447">

这就是 load-use 停顿，而不是两条指令不能进入流水线。

</div>

<div class="study-unit" id="u-02-a81ab06d07db">

### 高级流水线

<div class="study-unit" id="u-02-33c4bcf23352">

**基本概念**

</div>

<div class="study-unit" id="u-02-a9e947ceb8c6">

超标量（Superscalar）在同一周期发射多条指令，配备多个功能部件；依赖和资源允许时可并行执行，理想平均 CPI 可小于 1。多发射提高的是吞吐量，不代表每条指令只需一个周期。

</div>

<div class="study-unit" id="u-02-5357d3323451">

**规则与说明**

</div>

<div class="study-unit" id="u-02-a419a47382fe">

- 动态流水线可在同一时间让不同功能段按不同组合处理不同类型的操作；
- 静态流水线在同一时间只能按一种功能连接方式工作。

</div>

<div class="study-unit" id="u-02-63473b738f3b">

- 指令流水线中的动态调度则根据操作数和资源是否就绪安排执行，让独立的后续指令越过等待者；
- 它与“动态流水线”的功能分类应区分。

</div>

<div class="study-unit" id="u-02-92e45dbe8765">

- 发射宽度、主频、单条延迟是不同指标。
- 动态调度不表示所有指令都能随意交换执行顺序；
- 乱序执行通常仍要求按序提交以维护精确异常。

</div>

#### 多处理器的概念

#### 硬件多线程

<div class="study-unit" id="u-02-247bacb191ad">

**基本概念**

</div>

<div class="study-unit" id="u-02-189ed0185b37">

硬件多线程在一个核保存多套线程状态并共享执行资源，以切换 / 混合线程隐藏停顿。

</div>

<div class="study-unit" id="u-02-d8cf290bb883">

**规则与说明**

</div>

<div class="study-unit" id="u-02-32b9ecd9be5f">

- 细粒度每周期切线程，粗粒度遇长停顿切线程，SMT（同时多线程，Simultaneous Multithreading）同周期可发射多个线程指令。

</div>

<div class="study-unit" id="u-02-2a98460f2152">

- 软件多线程是程序组织方式，不一定有硬件 SMT。
- 一个核支持两个线程也不等于两个完整物理核。

</div>

### 向量处理器与共享内存多处理器

<div class="study-unit" id="u-02-1da8c9eea761">

**基本概念**

</div>

<div class="study-unit" id="u-02-outline-616dfe248b">

向量处理器的一条向量指令对一组元素执行相同操作，如两个数组逐元素相加，属于数据级并行；启动流水后可以连续处理后续元素。多核处理器是在一个芯片中集成多个处理核心。

</div>

<div class="study-unit" id="u-02-026da0e475e7">

**规则与说明**

</div>

<div class="study-unit" id="u-02-605beaf062f2">

- 共享内存多处理器 SMP（Shared Memory Multiprocessor）让多个处理器访问共享地址空间并通过内存交换数据，需要同步和 Cache 一致性支持；

</div>

<div class="study-unit" id="u-02-0c2712369059">

多个核同时写同一变量仍需互斥。

</div>

<div class="study-unit" id="u-02-7e8c72301a09">

共享存储不等于所有访问代价都相同，是否统一访问由具体结构决定。

</div>

### 总线的性能指标

<div class="study-unit" id="u-02-4e5a55e95322">

**基本概念**

</div>

<div class="study-unit" id="u-02-1637cf6dae21">

总线宽度是一次并行传送数据位数；时钟频率 $f=\frac{1}{Tclk}$；一次有效传送占 n 个时钟且每次一份数据时，工作频率$=\frac{f}{n}$。

</div>

<div class="study-unit" id="u-02-089930703d0b">

$\text{带宽}=\text{数据宽度}\times\text{每秒有效传送次数}$，bit/s 转 B/s 除 8。

</div>

<div class="study-unit" id="u-02-2636c471fd6a">

32bit、10MHz、每两周期传一次：$4B\times 5MHz=20MB/s$；

</div>

<div class="study-unit" id="u-02-a67d2641b56c">

DDR（双倍数据速率，Double Data Rate）每周期两次需乘 2。

</div>

<div class="study-unit" id="u-02-3d98f3344d57">

峰值忽略仲裁 / 地址等开销，实际事务平均速率要用有效数据量/总时间。

</div>

<div class="study-unit" id="u-02-explain-49b4d26ded">

计算时先问“一秒有多少次有效数据传送”，再乘“一次多少字节”。

</div>

<div class="study-unit" id="u-02-72f1a076cbbe">

**规则与说明**

</div>

<div class="study-unit" id="u-02-7e0d2a738310">

- 总线宽 32bit 就是 4B；
- 10MHz 若每两周期才传一次，只有 $5\times 10^{6}$ 次/秒，所以是 20MB/s，而不是直接按 40MB/s 计算。

</div>

<span class="legacy-anchor" data-target="s-02-58b26bfafc3e" id="s-117"></span><span class="legacy-anchor" data-target="s-02-58b26bfafc3e" id="p-135"></span><span class="legacy-anchor" data-target="s-02-58b26bfafc3e" id="u-02-47794bd43aad"></span><span class="legacy-anchor" data-target="s-02-58b26bfafc3e" id="u-02-8c27de48c8d3"></span><span class="legacy-anchor" data-target="s-02-58b26bfafc3e" id="u-02-a88a7902cb4e"></span><span class="legacy-anchor" data-target="s-02-58b26bfafc3e" id="u-02-a79a9b0e7ff6"></span><span class="legacy-anchor" data-target="s-02-58b26bfafc3e" id="u-02-5ad85280804b"></span>

### 总线事务

<div class="study-unit" id="u-02-39ae4f014f55">

**基本概念**

</div>

- 突发给首地址后连续传多份，摊薄控制开销。
- 事务耗时不一定等于一个时钟周期；
- 计算带宽要看每事务能传多少份数据。

### 总线定时

<div class="study-unit" id="u-02-afbeeddea565">

**对照与计算**

</div>

<div class="study-unit" id="u-02-349c41201b62">

| 定时 | 怎么执行 | 优缺点 |
| --- | --- | --- |
| 同步 | 统一时钟规定阶段 | 简单，适合速度接近；慢设备可能拖慢整体 |
| 异步 | 请求 / 应答握手，无统一强制节拍 | 适应速度差异，握手逻辑复杂 |
| 半同步 | 统一时钟采样 WAIT，未就绪则延长 | 兼顾规整和等待慢设备 |
| 分离式 | 请求发完释放总线，准备好后另申请应答事务 | 提高利用率，需跟踪事务，控制较复杂 |

</div>

<div class="study-unit" id="u-02-b6674d4eee3c">

#### 程序查询方式

<div class="study-unit" id="u-02-f92280e7844a">

**基本概念**

</div>

<div class="study-unit" id="u-02-44c8031cb036">

程序查询：

</div>

<div class="study-unit" id="u-02-206bc46d6ad8">

**操作步骤**

</div>

<div class="study-unit" id="u-02-3652f28f6f86">

1. CPU 发启动命令。
2. 反复或定时读状态。
3. 设备就绪后由 CPU 读写数据。
4. 继续查询。

<div class="study-unit" id="u-02-2c3dd1f8488b">

**规则与说明**

</div>

<div class="study-unit" id="u-02-733a3181e907">

- 每次查询 c 条指令、CPI、主频 f，查询 CPU 占比$\approx (\frac{R}{B})\times c\times \frac{\mathrm{CPI}}{f}$。

</div>

<div class="study-unit" id="u-02-bbecd7026e8f">

例 2MB/s、4B 缓冲、10 条、$\mathrm{CPI}=4$、500MHz：间隔 2μs、占比 4%。

#### DMA方式

<div class="study-unit" id="u-02-58c5bb3436a5">

**基本概念**

</div>

<div class="study-unit" id="u-02-cc6d625154dd">

DMA（Direct Memory Access，直接存储器访问）直接在设备与主存间传批量数据：

</div>

<div class="study-unit" id="u-02-b58131693bf0">

**操作步骤**

</div>

<div class="study-unit" id="u-02-db9466f0d4f9">

1. CPU 预置主存地址、方向、计数等并启动。
2. DMA 请求并取得总线。
3. 硬件传数据且更新地址 / 计数。
4. 完成发中断。
5. CPU 后处理。

</div>

<div class="study-unit" id="u-02-75564b9ef01b">

**规则与说明**

</div>

<div class="study-unit" id="u-02-0b9544b808d5">

- 停止 CPU 访存：DMA 一段时间独占；
- 周期挪用：每次借一个存储周期；
- 交替访存：CPU / DMA 按时段交替。

</div>

<div class="study-unit" id="u-02-b0624d75343f">

- DMA 可在总线周期边界取得控制，不必统一等整指令结束；
- 争用优先级依系统，教材常让 DMA 优先。

</div>

<div class="study-unit" id="u-02-89eede005ee1">

- DMA 不等于“全程不用 CPU”；
- CPU 做预 / 后处理，只是数据搬运不逐字由程序执行。

</div>

<div class="study-unit" id="u-02-explain-6c415c3339">

- CPU 先告诉 DMA“从哪到哪、传多少”，DMA 再逐项推进地址和计数。
- 设备准备、数据搬运、完成通知是三个阶段；
- DMA 省掉的是 CPU 逐字搬运，不是取消 CPU 的启动和收尾工作。

</div>

#### IO方式的比较

<div class="study-unit" id="u-02-42172183db28">

**对照与计算**

</div>

<span class="legacy-anchor" data-target="u-02-7d24b7c97e82" id="p-149"></span>
<div class="study-unit" id="u-02-7d24b7c97e82">

| 方式 | 数据由谁搬 | CPU / 设备关系 | 适用 |
| --- | --- | --- | --- |
| 查询 | CPU 程序 | 忙等待时准备期也占 CPU | 简单、小量 / 低速 |
| 中断 | CPU 服务程序 | 准备期可并行，传送期需 CPU | 低中速、事件驱动 |
| DMA | DMA 硬件 | CPU 只预 / 后处理，搬运仅争用总线 | 高速、批量 |

</div>

<div class="study-unit" id="u-02-e99eeabeb93a">

中断通常在指令结束响应，DMA 在适当总线 / 存储周期边界获准。比较占用率需区分设备准备时间、每次服务开销与批量长度。

</div>

### DMA控制器的组成

<div class="study-unit" id="u-02-91b26f64a91b">

**基本概念**

</div>

<div class="study-unit" id="u-02-outline-5005d1b005">

DMA 控制器通常包含主存地址寄存器、传送计数器、设备地址／数据缓冲、命令／状态寄存器以及请求、仲裁和传送控制逻辑。

</div>

<div class="study-unit" id="u-02-874e576cab36">

**规则与说明**

</div>

<div class="study-unit" id="u-02-6abfe44081b3">

- CPU 初始化地址、方向和数量；
- 每完成一次传送，控制器更新地址、减少计数，计数完成后报告结束并请求中断。

</div>

<div class="study-unit" id="u-02-912c7db43883">

设备就绪请求与总线请求是不同环节：设备能给数据，还需 DMA 获得所需总线／存储访问权，才能真正搬运。

</div>
