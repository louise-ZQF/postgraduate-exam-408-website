## 第一章 绪论

<div class="study-unit" id="u-01-rewrite-600ea17e06c4">

数据结构要解决三件事：数据之间是什么关系，数据在计算机中怎样存放，以及怎样对它们进行操作。**逻辑结构**包括集合、线性、树形和图状结构；**存储结构**包括顺序、链式、索引和散列。同一逻辑结构可以有不同实现，例如线性表既可以用数组，也可以用链表。数据元素是讨论关系的基本单位，数据项是一个元素内部的组成部分；抽象数据类型 ADT 则只约定数据及其操作，不指定存储细节。

</div>

<div class="study-unit" id="u-01-rewrite-4efc4648734e">

**复杂度计算的对象是操作次数和辅助空间。** 顺序执行的工作量相加，嵌套执行先算内层每次做多少，再对外层求和。例如每轮翻倍的循环只有约 $\log_2 n$ 轮，而内层次数依次为 1、2、4…的总和为 $O(n)$。i 每次加 1、条件为 $i^2<n$ 时约循环 $\sqrt n$ 次；内层依次执行 $0,1,\ldots,n-1$ 次时，总数为 $n(n-1)/2$，属 $O(n^2)$。朴素斐波那契的重复递归会产生指数级调用，不能只按递归深度估计时间。递归还要计入调用栈：深度为 $n$ 时通常占 $O(n)$ 空间，先后结束的调用可以复用空间，不能用总调用次数代替最大栈深度。

</div>

<span class="legacy-anchor" data-target="s-01-outline-f06554d616" id="u-01-631ed2aea2aa"></span><span class="legacy-anchor" data-target="s-01-outline-f06554d616" id="u-01-outline-56b515e583"></span><span class="legacy-anchor" data-target="s-01-outline-f06554d616" id="u-01-7eab07dbd027"></span><span class="legacy-anchor" data-target="s-01-outline-f06554d616" id="u-01-ab8ce72555f3"></span><span class="legacy-anchor" data-target="s-01-outline-f06554d616" id="u-01-486300506aa0"></span>

### 算法的基本概念

<div class="study-unit" id="u-01-rewrite-ad01cbe8ed51">

算法是一组能在有限步骤内解决问题的明确操作。它有五个基本特征：**输入、输出、有穷性、确定性、可行性**，其中输入允许为零个，输出至少有一个。有穷性要求能够结束，确定性要求每一步含义明确，可行性要求每一步能实际完成。

</div>

<div class="study-unit" id="u-01-rewrite-0a274f8a93c2">

判断一个方案是不是算法，要检查上述特征；评价算法设计得好不好，再考虑正确性、可读性、健壮性和时间、空间效率。例如无限循环可能是某个程序的运行方式，却不满足算法的有穷性。

</div>

<span class="legacy-anchor" data-target="s-01-b0f3777d88e5" id="s-3"></span><span class="legacy-anchor" data-target="s-01-b0f3777d88e5" id="p-16"></span><span class="legacy-anchor" data-target="s-01-b0f3777d88e5" id="u-01-5cdc3a41cbdd"></span><span class="legacy-anchor" data-target="s-01-b0f3777d88e5" id="u-01-concise-2"></span>

## 第二章 线性表

<div class="study-unit" id="u-01-rewrite-53e97ec31df6">

线性表把同类型元素排成一个有限序列，除首元素没有前驱、尾元素没有后继外，每个元素各有一个直接前驱和直接后继。这里描述的是**一对一的逻辑关系**，不要求物理地址连续。

</div>

<div class="study-unit" id="u-01-rewrite-0c31ba42a2c5">

做位置题先统一编号：第 $i$ 个元素的“位序”通常从 1 开始，数组下标通常从 0 开始，因此第 $i$ 个元素常存于 `a[i-1]`。后面的顺序表、链表都是这套逻辑关系的不同存储实现。

</div>

<span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="s-4"></span><span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="p-17"></span><span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="p-18"></span><span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="u-01-0b4c527afd16"></span><span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="u-01-5e7e5e0612a3"></span><span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="u-01-84283e05ed0c"></span><span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="u-01-df072b35a3f8"></span><span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="u-01-3e2b65c2ad9b"></span><span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="u-01-79cd52b7856e"></span><span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="u-01-explain-dfb1b6c508"></span><span class="legacy-anchor" data-target="s-01-c12986cc5db7" id="u-01-d071fce46e96"></span>
<a id="s-01-c12986cc5db7"></a>

### 顺序表

<div class="study-unit" id="u-01-rewrite-6800053a14c8">

顺序表用一段连续空间按逻辑次序存放元素，因此知道下标就能直接算地址，**按位访问为 $O(1)$**；没有额外索引时，按值查找仍需逐个比较，最坏为 $O(n)$。当前长度是已经存了多少个元素，容量是最多能装多少个，两者不能混为一谈。

</div>

<div class="study-unit" id="u-01-rewrite-97c27ee80129">

**插入先腾位置，删除后补空位。** 在第 $i$ 位插入时，将第 $i$ 至第 $n$ 个元素从后往前移动；删除第 $i$ 个元素时，将后续元素从前往前补齐。比如在 `[3,5,8]` 的第 2 位插入 4，先移 8、再移 5，最后写 4，才能避免覆盖。动态扩容可能搬移全部元素；“顺序表”说明存储连续，“有序表”才说明关键字已排序。

</div>

<div class="study-unit" id="u-01-f9ae965fe5ef">

| 操作 | 执行过程（位序从 1 开始） | 移动次数 / 复杂度 |
| --- | --- | --- |
| 在位置 i 插入 | 从后往前，把 i～n 位各后移一位，再写新元素 | $n-i+1$；等概率平均 n/2；$O(n)$ |
| 删除位置 i | 取出元素，把 $i+1\sim n$ 位各前移一位 | $n-i$；等概率平均 $\frac{n-1}{2}$；$O(n)$ |

</div>

### 链表

<div class="study-unit" id="u-01-rewrite-f392c8c7bebf">

链表把元素放在结点中，用链接表示先后关系，结点地址可以不连续，因此定位第 $i$ 个元素通常必须沿链行走。**头指针是一个指针变量，头结点是可选的辅助结点，首元结点是第一个存数据的结点。** 有头结点时，头指针指向头结点；没有头结点时，它直接指向首元。

</div>

<div class="study-unit" id="u-01-rewrite-7c62a8591f2d">

**单链表的插删分成“找位置”和“改链接”两步。** 已知前驱后，插入或删除后继只改常数条链接，为 $O(1)$；寻找前驱可能需要 $O(n)$。头插会逆转输入次序，维护尾指针的尾插可在线性时间内建表；单链表即使有尾指针，删除尾结点仍通常需要找前驱。双链表多一个 `prior` 指针，已知目标时可直接找到前驱，但按值查找仍为 $O(n)$。

</div>

<div class="study-unit" id="u-01-rewrite-fd2c34a62268">

**循环链表以回到起点作为结束条件。** 带头结点 `h` 的循环单链表为空时满足 **`h->next==h`**，维护尾指针时始终有 **`r->next==h`**，空表还应有 `r==h`。不带头结点且约定 `h==NULL` 表示空时，`h->next==h` 反而表示只有一个数据结点。循环双链表的空头结点满足 `h->next==h && h->prior==h`，首、尾分别是 `h->next`、`h->prior`。删除最后一个数据结点后必须恢复相应空表关系。

</div>

<div class="study-unit" id="u-01-rewrite-77b4e4f745a5">

静态链表用数组下标代替指针保存链接，逻辑次序仍由游标决定，不能因为使用数组就按顺序表处理。下面的代码展示单链表插删时为什么必须先保留旧后继。

</div>

<div class="study-unit" id="u-01-76279a64c3e7">

~~~c
// 在 p 后插入 s：先保存原后继，不能颠倒顺序
s->next = p->next;
p->next = s;
// 删除 p 的后继：先检查 q 非空
q = p->next;
if (q != NULL) {
    p->next = q->next;
    free(q);
}
~~~

</div>

### 线性表的应用

<div class="study-unit" id="u-01-rewrite-eb12cc0aef04">

选择结构时先看主要操作：频繁按位访问适合顺序表；已知位置附近频繁插删时，链表可以避免移动后续数据。**有序表合并**用两个指针分别指向当前元素，每次取较小者并只移动该指针，某表用完后接上另一表余项，总时间为 $O(m+n)$。链表可以复用原结点，顺序表通常需要结果空间。

</div>

<div class="study-unit" id="u-01-rewrite-421f7ae777e1">

**单链表逆置**每轮依次执行“保存旧后继、当前结点改指前驱、前驱前进、当前结点前进”，最后更新头部链接，时间为 $O(n)$、辅助空间为 $O(1)$。若先反转再找后继，原链就会丢失。有序表去重可比较相邻元素，无序表必须另行查重或先排序。

</div>

## 第三章 栈、队列和矩阵

<div class="study-unit" id="u-01-rewrite-80d730540edc">

本章的共同难点是“位置怎样解释”：栈限制在一端操作，队列规定两端的进出次序，矩阵则把多维坐标换成一维地址。**先写下标范围、指针含义和存储规则，再推表达式**，比直接记公式可靠；同名 `top` 或 `rear` 在不同实现中可能指向不同位置。

</div>

<span class="legacy-anchor" data-target="s-01-5cfaad7421e0" id="s-7"></span><span class="legacy-anchor" data-target="s-01-5cfaad7421e0" id="p-35"></span><span class="legacy-anchor" data-target="s-01-5cfaad7421e0" id="u-01-6480090999e5"></span><span class="legacy-anchor" data-target="s-01-5cfaad7421e0" id="u-01-f26d22eedb5e"></span><span class="legacy-anchor" data-target="s-01-5cfaad7421e0" id="u-01-6636c1440ac1"></span><span class="legacy-anchor" data-target="s-01-5cfaad7421e0" id="u-01-explain-2373d1bfd2"></span><span class="legacy-anchor" data-target="s-01-5cfaad7421e0" id="u-01-d53741a7abd0"></span>
<a id="s-01-5cfaad7421e0"></a>

### 卡特兰数

<div class="study-unit" id="u-01-rewrite-1116c6aa3a8e">

固定 $n$ 个不同元素的入栈先后次序，允许入栈、出栈交替进行时，合法出栈序列数为 **$C_n=\binom{2n}{n}/(n+1)$**。它也等于含 $n$ 个结点的不同二叉树形态数，前几项为 $1,1,2,5,14$。

</div>

<div class="study-unit" id="u-01-rewrite-95b90d84bfdc">

例如输入 1、2、3，合法输出只有 123、132、213、231、321。312 无法实现：要先输出 3，必须先把三个元素都压入栈，此后 2 压在 1 上方，不能先弹 1。因此答案不是所有排列数 $n!$；若输入次序可变或容量受限，需重新分析条件。

</div>

<span class="legacy-anchor" data-target="s-01-41aa2da47ebc" id="s-8"></span><span class="legacy-anchor" data-target="s-01-41aa2da47ebc" id="p-36"></span><span class="legacy-anchor" data-target="s-01-41aa2da47ebc" id="p-37"></span><span class="legacy-anchor" data-target="s-01-41aa2da47ebc" id="u-01-8bdec8ed0f78"></span><span class="legacy-anchor" data-target="s-01-41aa2da47ebc" id="u-01-8892f821bb10"></span><span class="legacy-anchor" data-target="s-01-41aa2da47ebc" id="u-01-c1ded955f426"></span>
<a id="s-01-41aa2da47ebc"></a>

### 栈

<div class="study-unit" id="u-01-rewrite-cd6597122eaa">

栈只在栈顶进行插入和删除，最后压入的元素最先弹出，即后进先出。**入栈前检查是否还有空间，出栈前检查是否有元素**，一次基本入栈或出栈为 $O(1)$。

</div>

<div class="study-unit" id="u-01-rewrite-a4ffbbe8b7c3">

顺序栈用数组保存数据，边界取决于 `top` 的定义；链栈通常以单链表表头为栈顶，不受固定数组容量约束，但分配结点仍可能失败。下面两种顺序栈约定分别讲解，表达式不能互换。

</div>

<span class="legacy-anchor" data-target="s-01-d3b6a48b0a5e" id="u-01-074dbfd025fa"></span><span class="legacy-anchor" data-target="s-01-d3b6a48b0a5e" id="u-01-49b5ecc6c574"></span><span class="legacy-anchor" data-target="s-01-d3b6a48b0a5e" id="u-01-d8939acab723"></span>

#### 顺序栈：top 指向当前栈顶

<div class="study-unit" id="u-01-rewrite-b1e85fc19f4f">

约定数组容量为 $n$、下标为 `0～n-1`，`top` 指向已经存有元素的栈顶。**判空：`top==-1`；判满：`top==n-1`；元素数：`top+1`。** 空栈的栈顶退到数组左侧一格，满栈的栈顶停在最后一个有效下标。

</div>

<div class="study-unit" id="u-01-rewrite-4533e8a953fd">

入栈先将 `top` 加 1，再存数据，即 `a[++top]=x`；出栈先读取当前元素，再将 `top` 减 1，即 `x=a[top--]`。例如容量 4，已有三个元素时 `top=2`，再入一个后 `top=3` 才满；`top=4` 已越界。

</div>

<div class="study-unit" id="u-01-f45470593db5">

| 要看什么 | 表达式 / 操作 |
| --- | --- |
| 初值 | `top = -1` |
| 元素个数 | `top+1` |
| 入栈（先判满） | `a[++top] = x`，先把 top 移到新位置，再写入 |
| 出栈（先判空） | `x = a[top--]`，先读取当前栈顶，再后退 |

</div>

<span class="legacy-anchor" data-target="s-01-77e66fe2a111" id="u-01-dfa812993dfb"></span><span class="legacy-anchor" data-target="s-01-77e66fe2a111" id="u-01-ac578ad974e2"></span>
<a id="s-01-77e66fe2a111"></a>

#### 顺序栈：top 指向下一空位

<div class="study-unit" id="u-01-rewrite-465fecd1aa7c">

仍使用下标 `0～n-1`，但现在 `top` 指向下一次要写入的位置。**判空：`top==0`；判满：`top==n`；元素数：`top`。** 满时 `top` 可以等于 $n$，因为它描述边界位置，此时不能访问 `a[top]`。

</div>

<div class="study-unit" id="u-01-rewrite-3860a52a7f32">

入栈先写空位再前进，即 `a[top++]=x`；出栈先退回已有元素再读取，即 `x=a[--top]`。例如容量 4，存满四个元素后 `top=4`，真正栈顶在 `a[3]`，不是 `a[4]`。

</div>

<div class="study-unit" id="u-01-91db1b589c69">

| 要看什么 | 表达式 / 操作 |
| --- | --- |
| 初值 | `top = 0` |
| 元素个数 | `top` |
| 入栈（先判满） | `a[top++] = x`，先写当前空格，再让 top 后移 |
| 出栈（先判空） | `x = a[--top]`，先退回已有元素，再读取 |

</div>

<span class="legacy-anchor" data-target="s-01-71aaa4827251" id="u-01-113783e23d65"></span><span class="legacy-anchor" data-target="s-01-71aaa4827251" id="u-01-1dae2b962eeb"></span><span class="legacy-anchor" data-target="s-01-71aaa4827251" id="u-01-7b3845ada061"></span><span class="legacy-anchor" data-target="s-01-71aaa4827251" id="u-01-35588ee3f245"></span><span class="legacy-anchor" data-target="s-01-71aaa4827251" id="u-01-a540cf777a10"></span><span class="legacy-anchor" data-target="s-01-71aaa4827251" id="u-01-86f8da9550d7"></span><span class="legacy-anchor" data-target="s-01-71aaa4827251" id="u-01-1b4d43aa8519"></span><span class="legacy-anchor" data-target="s-01-71aaa4827251" id="u-01-4f3d24eb97b7"></span>

#### 共享栈：两端向中间生长

<div class="study-unit" id="u-01-rewrite-29b6a4220dc8">

两个栈共享容量为 $n$ 的数组，栈 1 从左向右长，栈 2 从右向左长，两指针都指当前栈顶，初值为 `top1=-1`、`top2=n`。**左栈空：`top1==-1`；右栈空：`top2==n`；整体满：`top2-top1==1`。** 判断某个栈能否出栈，只检查它自己的空条件。

</div>

<div class="study-unit" id="u-01-rewrite-4103d27b0909">

两个栈顶之间的空格数是 **`top2-top1-1`**，所以相邻时就已经满了。例如 $n=6$，左栈占 0、1、2，右栈占 3、4、5，此时两个栈顶是 2 和 3；若等到两指针重合，早已覆盖数据。左栈入栈用 `++top1`，右栈入栈用 `--top2`，空间动态共享，不必各分一半；共享也不能阻止对空栈出栈造成的下溢。

</div>

<div class="study-unit" id="u-01-71af0e9c57d2">

| 要看什么 | 表达式 / 操作 |
| --- | --- |
| 两栈都空 | `top1 == -1 && top2 == n` |
| 中间剩余空位 | `top2-top1-1` |
| 已存元素总数 | `(top1+1)+(n-top2)` |
| 左栈入 / 出 | `a[++top1]=x` / `x=a[top1--]` |
| 右栈入 / 出 | `a[--top2]=x` / `x=a[top2++]` |

</div>

<span class="legacy-anchor" data-target="s-01-c70e3f07d1a3" id="u-01-e26cf6eeda50"></span><span class="legacy-anchor" data-target="s-01-c70e3f07d1a3" id="u-01-96ab74181905"></span><span class="legacy-anchor" data-target="s-01-c70e3f07d1a3" id="u-01-0b37d912940e"></span>

#### 栈的典型应用

<div class="study-unit" id="u-01-rewrite-5d948cb708ef">

栈适合保存“稍后要按逆序处理”的状态。括号匹配时，左括号入栈，右括号必须与当前栈顶配对；遇到空栈、类型不匹配或扫描结束后仍有左括号，都说明不合法。递归调用同样要保存尚未完成的返回位置与局部变量。

</div>

<div class="study-unit" id="u-01-rewrite-47f58ae4119b">

中缀转后缀时，操作数直接输出，运算符暂存在栈中，按优先级和结合性决定何时弹出；括号只控制次序，不出现在后缀结果里。**后缀求值先弹右操作数，再弹左操作数**，例如 `8 2 /` 计算 $8/2$，不能反成 $2/8$。下表把三种应用的完整扫描规则分开列出。

</div>

<div class="study-unit" id="u-01-e528d571b553">

| 应用 | 执行过程 | 易错处 |
| --- | --- | --- |
| 括号匹配 | 1. 左括号入栈<br>2. 右括号与栈顶匹配并弹栈<br>3. 结束时检查空栈 | 右括号遇空栈、类型不匹配或最后非空均失败 |
| 中缀转后缀 | 1. 操作数直接输出<br>2. 左括号入栈<br>3. 运算符弹出栈顶更高优先级者后入栈<br>4. 右括号弹至左括号<br>5. 最后清栈 | 左结合遇同优先级也先弹；括号不输出 |
| 后缀求值 | 1. 操作数入栈<br>2. 遇运算符先弹右操作数，再弹左操作数，计算结果入栈 | 减、除的操作数顺序不能反 |

</div>

### 队列

<div class="study-unit" id="u-01-rewrite-8cf1f208a4a5">

队列从队尾插入、队头删除，最先进入的元素最先离开。普通顺序队列的尾指针走到数组末端后，前面已释放的空格可能无法直接复用；循环队列通过取模把最后一格的后继接回第 0 格。

</div>

<div class="study-unit" id="u-01-rewrite-9dd668393e6c">

约定容量为 $M$，`front` 指队头、`rear` 指下一入队位置，并**牺牲一个单元**：**空为 `front==rear`，满为 `(rear+1)%M==front`，数量为 `(rear-front+M)%M`，最多存 $M-1$ 个。** 入队先写 `a[rear]` 再推进尾指针，出队先读 `a[front]` 再推进头指针。例如 $M=5$、`front=3`、`rear=1`，有效位置是 3、4、0，共三个，不能直接用 `rear-front`。

</div>

<div class="study-unit" id="u-01-rewrite-aeebb935958e">

若增加 `size` 记录元素数，则空为 `size==0`、满为 `size==M`，可用满全部空间，原来的判满式便不再适用。链队列维护首尾指针可在 $O(1)$ 时间入出队，删除最后一个数据结点必须同时重置尾指针。双端队列允许两端操作，输入受限、输出受限分别限制入队端和出队端。

</div>

<div class="study-unit" id="u-01-5fbbccad472a">

| 操作 / 状态 | 规则 |
| --- | --- |
| 空 | $\mathrm{front} == \mathrm{rear}$ |
| 满 | $(\mathrm{rear}+1)\%M == \mathrm{front}$ |
| 入队 | 先写 A[rear]，再令 $\mathrm{rear}=(\mathrm{rear}+1)\%M$ |
| 出队 | 先取 A[front]，再令 $\mathrm{front}=(\mathrm{front}+1)\%M$ |
| 元素个数 | $(\mathrm{rear}-\mathrm{front}+M)\%M$；最多 $M-1$ |

</div>

### 矩阵

<div class="study-unit" id="u-01-rewrite-4717ff64951a">

数组地址计算的本质是：**先数目标元素前面有多少个元素，再乘每个元素的字节数，最后加首地址。** 对 $n$ 行 $m$ 列、下标从 0 起的二维数组，行优先偏移是 $im+j$，列优先偏移是 $jn+i$；下标从 1 起时先减 1，多维数组则让变化最快的下标放在最内层。

</div>

<div class="study-unit" id="u-01-rewrite-b9f7a3e4e4ca">

压缩矩阵先判断实际保存哪部分。对称矩阵可只存一个三角区，目标在另一半时交换行列；三角矩阵还需为另一半共同常数留一个位置；三对角矩阵只保存主对角线及两侧，共 $3n-2$ 个位置。比如按行保存下三角、行列从 1 起，$A[3,2]$ 前有 $1+2+1=4$ 个元素，压缩下标为 4。**三元组按行、列、值保存非零元，原矩阵坐标不再直接等于数组下标**；十字链表则同时组织行链和列链。

</div>

<div class="study-unit" id="u-01-f8eddfd77e76">

| 矩阵压缩（i,j 从 1 起，压缩下标 k 从 0 起） | 规则 / 数量 |
| --- | --- |
| 对称矩阵，按行存下三角 | $i\ge j$：$k=i(i-1)/2+j-1$；i<j 交换 i,j；$n(n+1)/2$ 个 |
| 三角矩阵 | 有效三角照存，另一半公共常数另占一个位置；$n(n+1)/2+1$ 个 |
| 三对角矩阵，按行 | 有效位置满足 $abs(i-j)\le 1$，$k=2i+j-3$；$3n-2$ 个 |
| 稀疏矩阵 | 三元组记录行、列、值，通常按行、同一行按列排序；十字链表同时链接同行和同列非零元 |

</div>

## 第四章 串

<div class="study-unit" id="u-01-rewrite-3253a1d3c24b">

串是字符的有限序列，子串必须连续，子序列可以跳过字符；空串长度为 0，空格也是字符，因此空格串通常不是空串。模式匹配是在主串中寻找与模式串完全相同的连续片段。

</div>

<div class="study-unit" id="u-01-rewrite-80bc3a5685b9">

朴素匹配从一个候选起点开始逐字符比较，失配便把候选起点后移一位，最坏为 $O(nm)$。**KMP 在失配时只调整模式指针，主串指针不回退**：已经匹配过的字符中，若末尾与模式开头相同，就可以直接复用这段结果，总时间为 $O(n+m)$。

</div>

<div class="study-unit" id="u-01-rewrite-a6a69e64927c">

本节采用模式下标从 1 起、`next[1]=0` 的约定：`next[j]` 等于 `P[1..j-1]` 最长相等真前后缀长度加 1；`j=0` 时两指针一起前进。模式 `ababaa` 的 next 为 `0,1,1,2,3,4`，第 5 位失配时跳到第 3 位，复用前面的 `ab`。**next 是模式的新比较位置，不是主串的新起点。** nextval 进一步跳过必然再次失败的同字符比较，该例为 `0,1,0,1,0,4`；题目换用从 0 起或 −1 哨兵时，必须按新约定重算。

</div>

## 第五章 树

<div class="study-unit" id="u-01-rewrite-f4e7b8901b94">

树用层次关系组织数据：除根外，每个结点恰有一个双亲，可以有多个孩子。学习本章时先区分一般树、二叉树、完全二叉树的约束，再讨论遍历、存储和应用；**二叉树的左右次序、完全二叉树的连续编号都属于额外条件**，不能推广给所有树。

</div>

### 树和二叉树

<div class="study-unit" id="u-01-rewrite-3dac7dc9269e">

结点的度是孩子数，树的度是所有结点度数的最大值。非空树的每个非根结点恰好贡献一条到双亲的边，因此 **$n-1=\sum_i i n_i$**；结合 $n=\sum_i n_i$，非空二叉树可推出 **$n_0=n_2+1$**。二叉树区分左、右子树，允许只有右孩子，也允许空树，不能简单等同于度不超过 2 的普通树。

</div>

<div class="study-unit" id="u-01-rewrite-e76bafd9cc17">

完全二叉树必须从上到下、从左到右没有编号空缺。从 1 编号时，双亲是 $\lfloor i/2\rfloor$，孩子候选为 $2i$、$2i+1$，只有不超过 $n$ 才存在；它至多有一个度为 1 的结点且只有左孩子。一般二叉树用数组可能留下大量空位，完全二叉树则适合顺序存储。n 个结点的二叉链表共有 2n 个孩子指针，真实边占 n−1 个，因而空指针有 n+1 个。

</div>

<div class="study-unit" id="u-01-rewrite-1e3c08e37d9f">

**遍历名称决定何时访问根：先序根左右，中序左根右，后序左右根；层序用队列逐层访问。** 递归遍历时间为 $O(n)$、栈空间为 $O(h)$，层序队列最坏占 $O(n)$。结点值互异时，先序加中序或后序加中序可以唯一还原；仅先序加后序一般不行。三种深度遍历中叶结点的相对次序一致，层序不受此结论约束。

</div>

<div class="study-unit" id="u-01-fcc5b5bcb426">

| 二叉树性质（根在第 1 层） | 结论 |
| --- | --- |
| 第 i 层最多结点数 | $2^{i-1}$ |
| 高 h 最多结点数 | $2^{h}-1$ |
| 度 0、1、2 的结点数 | $n_{0}=n_{2}+1$ |
| 完全二叉树 | 从上到下、从左到右无缺口；n₁为 0 或 1，n 偶数时为 1 |
| 完全二叉树高 | $\lfloor \log_{2}n\rfloor +1=\lceil \log_{2}(n+1)\rceil$ |
| 完全二叉树顺序编号 | i 的孩子 2i、$2i+1$，双亲 $\lfloor \frac{i}{2}\rfloor$（编号存在时） |

</div>

### 树和森林

<div class="study-unit" id="u-01-rewrite-f90515f6e6fd">

孩子兄弟表示法让每个结点只保留两个链接：**左链接指第一个孩子，右链接指下一个兄弟**。右链接表示同一层的兄弟关系，因此转换所得二叉树中的右孩子，未必是原树中的孩子。

</div>

<div class="study-unit" id="u-01-rewrite-83c63265ed69">

转换树时，保留每个结点到第一个孩子的链接，再把各兄弟依次向右串起来；转换森林时，再把各树的根当作兄弟串起来。反向读取也按“左边找孩子、右边找兄弟”恢复。保留原孩子次序时，树的先根遍历对应二叉树先序，后根对应中序；森林的先序、中序也分别对应转换后二叉树的先序、中序。

</div>

### 线索二叉树

<div class="study-unit" id="u-01-rewrite-9e3e587fa705">

普通二叉链表有许多空孩子指针，线索化把这些空指针改为指向某种遍历次序下的前驱或后继。**先看 tag，再解释指针：tag 为 0 时是真实孩子，为 1 时是线索。** 指针非空并不代表有孩子，线索化也不能覆盖原有孩子链接。

</div>

<div class="study-unit" id="u-01-rewrite-88e3a35b19fe">

中序求后继时，若 `rtag==1`，右指针直接给出答案；若 `rtag==0`，进入右子树，再沿真实左孩子走到最左结点。中序求前驱对称处理。线索化时用 `pre` 记录刚访问的结点：当前无左孩子就指向 `pre`，`pre` 无右孩子就指向当前结点，然后更新 `pre`；最后按有无头结点处理末端。

</div>

<div class="study-unit" id="u-01-rewrite-3dff87c74ba2">

**线索必须与遍历次序配套。** 中序线索可支持不使用递归栈的中序遍历，但先序线索不一定能直接求任意前驱，后序线索也不一定能直接求任意后继，因为这些位置可能需要向双亲回退。

</div>

### 哈夫曼树

<div class="study-unit" id="u-01-rewrite-85a6824c6532">

哈夫曼树的目标是让频率高的符号尽量少走边，使 **带权路径长度 $WPL=\sum_i w_i l_i$ 最小**，其中 $l_i$ 是根到叶的边数。构造时每次选根权最小的两棵树合并，父权为两者之和，再放回候选集合，直到只剩一棵。

</div>

<div class="study-unit" id="u-01-rewrite-4a67d8314d5c">

例如权值 1、2、4，先合成 3，再合成 7，$WPL=3+7=10$，也等于 $1\times2+2\times2+4\times1$。$n$ 个叶结点的二叉哈夫曼树有 $n-1$ 个内部结点，共 $2n-1$ 个；左右分支标 0、1 就得到前缀编码。**同权选择及左右安排可使编码不唯一，但最优 WPL 相同；平均码长为 $WPL/\sum_i w_i$**，不能直接写成 WPL。

</div>

### 堆及其应用

<div class="study-unit" id="u-01-rewrite-402b2a38f7d9">

堆是满足父子大小约束的完全二叉树：大根堆的父关键字不小于孩子，小根堆反之。**它只保证堆顶是极值，不保证左右子树的关键字范围分开**，因此不能像二叉搜索树那样查找任意值。

</div>

<div class="study-unit" id="u-01-rewrite-43e37aa3dcac">

插入时把新元素放到数组末尾，再与父结点比较并上浮；删除堆顶时把末元素移到根，再与较大孩子（大根堆）比较并下沉，两者均为 $O(\log n)$。从最后一个非叶结点开始向前逐个下沉，可在 $O(n)$ 时间建堆，因为多数结点靠近叶层、移动距离很短；逐个插入建堆则通常为 $O(n\log n)$。堆适合优先队列、反复取极值和堆排序。

</div>

### 并查集及其应用

<div class="study-unit" id="u-01-rewrite-f5b173878c17">

并查集用一组双亲树表示互不相交的集合，**根是集合代表，Find 找根，Union 连接不同的根**。根数组项可以用负数保存集合大小，但 Find 返回的是根的位置或代表元，不是那个负数。

</div>

<div class="study-unit" id="u-01-rewrite-3279d5346051">

合并前分别查找两元素的根，相同则不操作，不同才把一棵树接到另一根并更新大小。按规模或秩合并避免小树被拉成长链，路径压缩让沿途结点直接指向根。Kruskal 选边时，若两端同根，说明已有路径相连，再加边就成环；不同根才能选边并合并。

</div>

## 第六章 图

<div class="study-unit" id="u-01-rewrite-1350a761112a">

图用于描述多对多关系，顶点表示对象，边表示关系，方向与权值表达额外约束。本章先学习路径、连通性及两种主要存储，再用遍历实现可达性和分层搜索，最后区分**连通全部点的最小生成树、两点间的最短路径、任务先后次序与工程工期**这几类目标。

</div>

<span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="s-18"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="p-131"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="p-132"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="u-01-555aa578667d"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="u-01-b520f43c6d5d"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="u-01-e67f97304956"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="u-01-789cdb7f2d16"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="u-01-ec3dfcb716ba"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="u-01-8a5da0f176fb"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="u-01-0a30bb0d7c4c"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="u-01-95e4ddbce716"></span><span class="legacy-anchor" data-target="s-01-a8f1e3390852" id="u-01-d23a7fde90fe"></span>

### 图的概念

<div class="study-unit" id="u-01-rewrite-9b7d28777bd0">

图 $G=(V,E)$ 的顶点集非空，边集可以为空；无向边没有方向，有向弧从弧尾指向弧头。通常路径长度数边，带权长度求边权之和，简单路径不重复顶点，回路的起终点相同。**有路径表示可达，有直接边才叫邻接**。

</div>

<div class="study-unit" id="u-01-rewrite-087dd9f21b0f">

无向图每条边给两端各贡献 1 度，故度数和为 $2e$；有向图每条弧各贡献一次入度与出度，两者总和分别为 $e$。无向图的极大连通子图是连通分量，有向图要求任意两点双向可达才构成强连通分量；“极大”指不能再扩展。连通无环的无向图是树，生成树保留全部顶点和 $n-1$ 条边。下表中的边数界限以简单图为前提。

</div>

<div class="study-unit" id="u-01-b6242ea4bca0">

| 性质 | 结论 |
| --- | --- |
| 无向度数和 | 2e |
| 有向入度和 / 出度和 | 各为 e |
| 简单无向完全图边数 | $n\frac{n-1}{2}$ |
| 简单有向完全图弧数 | $n(n-1)$ |
| n 点无向连通图 | 至少 $n-1$ 条边；边数 $> (n-1)(n-2)/2$ 时一定连通 |
| 子图 | V′⊆V、E′⊆E，且边端点必须在 V′ 中 |

</div>

<span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="s-19"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="p-149"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="p-150"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="p-151"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="p-152"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="p-153"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="p-154"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="u-01-e7f6c011776e"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="u-01-556cd9933530"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="u-01-1bc37d8d9254"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="u-01-7902699be42c"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="u-01-e49dd93baf40"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="u-01-76d6c87e6938"></span><span class="legacy-anchor" data-target="s-01-ce6ac417ead5" id="u-01-f9b09b56a985"></span>

### 存储结构

<div class="study-unit" id="u-01-rewrite-ca88d93213a0">

邻接矩阵为每对顶点预留一个位置，判断一条边是否存在只需查一次；邻接表只保存实际邻接关系，稀疏图可以节省空间。**矩阵的行对应出边、列对应入边；有向邻接表的一条顶点链通常只列出边**，求入度可能要扫描全表。

</div>

<div class="study-unit" id="u-01-rewrite-85cfd80a4a26">

无向图的邻接表通常把每条边记录两次，邻接多重表则用一个边结点同时挂入两端；有向图的十字链表让同一弧结点同时加入出边链与入边链。顶点次序确定后矩阵固定，但邻接表链内顺序仍可不同，进而影响遍历输出次序。

</div>

<div class="study-unit" id="u-01-71286e3669a0">

| 存储 | 怎么存 / 场景 | 代价 |
| --- | --- | --- |
| 邻接矩阵 | $n\times n$ 数组记录边；无向矩阵对称，适合稠密图 | $O(n^{2})$ 空间，$O(1)$ 判边；出度看行、入度看列 |
| 邻接表 | 每顶点接邻接链，适合稀疏图 | $O(n+e)$ 空间，无向边存两份、有向边存一份 |
| 十字链表 | 有向弧结点同时挂在弧尾出边链、弧头入边链 | 便于查入出边、删弧 |
| 邻接多重表 | 无向边只设一个结点，分别挂在两端点边链 | 便于删边，避免边的双份存储 |

</div>

### 图的基本操作

<div class="study-unit" id="u-01-rewrite-4112d4b2f718">

判断邻接是在问两点间有没有直接边；枚举邻居则要找出全部直接相邻的顶点，两者开销取决于存储方式。邻接矩阵判断单条边为 $O(1)$，枚举某点邻居要扫描一行；邻接表枚举邻居只需沿对应链走。

</div>

<div class="study-unit" id="u-01-rewrite-90b0ac51091f">

**无向边必须同时维护两个端点的记录。** 例如加入 $(u,v)$，矩阵需改两个对称单元，普通邻接表需各加一项；有向弧只按指定方向登记。删除顶点还要清除全部关联边，否则会留下指向不存在顶点的记录。

</div>

<span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="s-20"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="p-161"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="p-162"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-af2265f07f09"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-e4aa7da95219"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-33e5f592d1cd"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-cf14e8c5d91e"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-9460721ccefe"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-3e7698d57b67"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-c9ac15c36a68"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-1754084da588"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-b1e6f0dc43d3"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-e201a8f56b12"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-steps-37ff7d241c"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-710f39f72fc0"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-f3db35e23d08"></span><span class="legacy-anchor" data-target="s-01-02ad10a1f27f" id="u-01-9d37671d80cc"></span>

### 图的遍历

<div class="study-unit" id="u-01-rewrite-ee838d9f9245">

DFS 从起点沿一个未访问邻接点不断深入，走不动才回退，因此用递归栈或显式栈保存回退位置。BFS 则把起点标记后入队，每次弹出队首，再把尚未访问的邻接点标记并入队，**以到起点的最少边数逐层扩展**。标记应在入队时完成，避免同一点被多次加入。

</div>

<div class="study-unit" id="u-01-rewrite-b00b8be6d4a0">

非连通图必须从剩余未访问点继续启动，得到遍历森林。两者用邻接表均为 $O(n+e)$，邻接矩阵均为 $O(n^2)$，辅助空间最坏为 $O(n)$。判环另需条件：有向 DFS 要识别“仍在当前递归路径中”的点，无向图则要排除返回双亲的边，不能只凭已访问就下结论。

</div>

<span class="legacy-anchor" data-target="s-01-6f6745dcebfc" id="s-21"></span><span class="legacy-anchor" data-target="s-01-6f6745dcebfc" id="u-01-49b9d295de17"></span><span class="legacy-anchor" data-target="s-01-6f6745dcebfc" id="u-01-4fc82b26aecb"></span><span class="legacy-anchor" data-target="s-01-6f6745dcebfc" id="u-01-8cb6d927fa6d"></span><span class="legacy-anchor" data-target="s-01-6f6745dcebfc" id="s-01-a1abef19fd89"></span><span class="legacy-anchor" data-target="s-01-6f6745dcebfc" id="u-01-a3d09b5c5f46"></span><span class="legacy-anchor" data-target="s-01-6f6745dcebfc" id="u-01-959bda0e579c"></span><span class="legacy-anchor" data-target="s-01-6f6745dcebfc" id="u-01-e70910d084a0"></span>

### 图的应用

<div class="study-unit" id="u-01-rewrite-111b2b359362">

图算法的选择由目标决定：要求用最小总权连通所有点，使用最小生成树；要求从起点到终点代价最低，使用最短路径；要求满足全部前驱约束，使用拓扑排序；要求求工程最短完成时间，使用关键路径。

</div>

<div class="study-unit" id="u-01-rewrite-fcde470f37de">

**先读清方向、边权和是否有环，再选算法。** 同一个网络的最小生成树未必包含某个起点的最短路径，工期问题中的关键路径反而取源到汇的最长耗时，不能见到“最小”或“路径”就套同一个算法。

</div>

<span class="legacy-anchor" data-target="s-01-f625d100ccca" id="s-22"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="p-169"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="p-170"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="u-01-3eed04ade846"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="u-01-1a72bd800758"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="u-01-2c624232cdd2"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="u-01-92f508c20f8c"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="u-01-a230a97fcc07"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="u-01-abbe069e508e"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="u-01-44d908053441"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="u-01-9f969a4e055f"></span><span class="legacy-anchor" data-target="s-01-f625d100ccca" id="u-01-75cfac59893e"></span>

#### 最小生成树

<div class="study-unit" id="u-01-rewrite-054645bb1263">

最小生成树针对带权无向连通图，要选出 $n-1$ 条边，在没有环的同时连通全部顶点，并让总边权最小。非连通图只能分别求最小生成森林。

</div>

<div class="study-unit" id="u-01-rewrite-d70d8608296b">

**Prim 从已有树向外接点，Kruskal 从全局按权选边。** Prim 每轮在树内外之间找最小接入边；Kruskal 将边排序，只接受两端尚不连通的边，并用并查集更新连通关系。前者朴素实现适合稠密图，后者常适合稀疏图。边权全不相同可保证结果唯一；出现相同权值只说明可能不唯一，仍要检查可替换关系。

</div>

<div class="study-unit" id="u-01-29035c6700a2">

| 算法 | 执行过程 | 特点 |
| --- | --- | --- |
| Prim | 1. 任取一点建立集合 S<br>2. 选连接 S 与外部的最小权边，加入新点并更新候选边<br>3. 重复到选完所有点 | 每次加一个点，朴素 $O(n^{2})$，适合稠密图 |
| Kruskal | 1. 边按权递增排序<br>2. 逐条取边，若两端分属不同集合则加入并合并，否则丢弃<br>3. 选够 $n-1$ 边结束 | 每次加一条不成环边；$O(e \log  e)$，适合稀疏图 |

</div>

#### 最短路径

<div class="study-unit" id="u-01-rewrite-5dc070b6808c">

用 `dist[v]` 保存当前已知的源点到 $v$ 的最好距离，若经 $u$ 走到 $v$ 更短，就更新它，这一步叫松弛。例如 A→B 权 2、A→C 权 7、B→C 权 1，经 B 可把到 C 的距离改为 3。

</div>

<div class="study-unit" id="u-01-rewrite-ebfa2a293808">

**无权或等权非负图用 BFS；非负权单源最短路可用 Dijkstra；任意两点间可用 Floyd。** Dijkstra 每轮确定尚未确定点中 dist 最小者，再更新其邻居，比较的是从源点累计的距离，不能只选局部最小出边；负权边会破坏其确定性。Floyd 逐轮允许一个新中间点 $k$，因此循环必须让 $k$ 在最外层，初始对角线为 0、直接边填权、无边填无穷，用下方递推更新所有起终点；可有负边，但涉及负环时不一定存在有限最短路。

</div>

<div class="study-unit" id="u-01-2e4749daa15d">

| 算法 | 求什么 | 条件 / 复杂度 |
| --- | --- | --- |
| BFS | 从一个源点到其余点的最少边数 | 无权或等权图，邻接表 $O(n+e)$ |
| Dijkstra | 从一个源点到其余点的最短距离 | 非负权，朴素 $O(n^{2})$；负权边不能直接用 |
| Floyd | 任意两点间的最短距离 | $O(n^{3})$；可有负权边，有限最短路不能经过负权环 |

</div>

<div class="study-unit" id="u-01-03e3ddf61d3a">

$$
d[i][j]=\min\{d[i][j],\ d[i][k]+d[k][j]\}
$$

#### 拓扑排序

<div class="study-unit" id="u-01-rewrite-3f03d4bb5be2">

拓扑序要求每条弧 $u\to v$ 的 $u$ 都排在 $v$ 前，表示前驱任务必须先完成。**存在拓扑序当且仅当有向图无环**；同时有多个零入度点时，可选择不同顺序，因此答案可能不唯一。

</div>

<div class="study-unit" id="u-01-rewrite-799c32597d19">

操作时先统计入度，把零入度点放入队列；取出并输出一个点后，删除它的所有出边，即将对应邻居入度减 1，新变为 0 的点再入队。最终输出全部 $n$ 点才成功，输出不足说明剩余部分存在环。邻接表实现为 $O(n+e)$，拓扑序中的先后位置不等于两点之间必有直接弧。

</div>

#### 关键路径

<div class="study-unit" id="u-01-rewrite-e3c3d3f1194f">

AOE 网以顶点表示事件、有向带权边表示活动，事件只有在全部前驱活动完成后才能发生。**源到汇的最长耗时决定最短工期**，因为各项必要活动都必须完成；达到这个时长的路径可能不止一条。

</div>

<div class="study-unit" id="u-01-rewrite-0c4c1bb4ae13">

先拓扑排序，再正向求事件最早时间 $ve$：把各前驱最早时间加活动时长后取最大。工期 $T$ 确定后，逆向求最迟时间 $vl$：把各后继最迟时间减活动时长后取最小。对活动 $u\to v$，**最早开始是 $ve(u)$，最迟开始是 $vl(v)-w(u,v)$**，两者相等才是关键活动。

</div>

<div class="study-unit" id="u-01-rewrite-5aaf574e4075">

下方例子中，A→B→D 耗时 5，A→C→D 耗时 6，所以工期为 6，关键路径为 A→C→D。延长关键活动会延长工期；缩短某条关键路径却可能仍受另一条同长路径限制，改变时长后应重新核对全部关键路径。

</div>

<div class="study-unit" id="u-01-c239085d9e1e">

$$ve(v)=\max_{u\to v}\{ve(u)+w(u,v)\}$$

</div>

<div class="study-unit" id="u-01-6dafc349f811">

$$vl(u)=\min_{u\to v}\{vl(v)-w(u,v)\}$$

</div>

<div class="study-unit" id="u-01-9be8c77b460b">

$$e(u,v)=ve(u),\qquad l(u,v)=vl(v)-w(u,v)$$

</div>

<div class="study-unit" id="u-01-068e9106525c">

| 顺序 | A | B | C | D |
| --- | --- | --- | --- | --- |
| 正推 $ve$ | 0 | 2 | 4 | $\max(2+3,4+2)=6$ |
| 逆推 $vl$ | $\min(3-2,4-4)=0$ | 3 | 4 | 6 |

</div>

## 第七章 查找

<div class="study-unit" id="u-01-rewrite-9acbbd9f13e4">

查找是在数据集合中定位目标，方法取决于是否有序、是否能随机访问，以及是否频繁插删。线性查找、树形查找和散列查找利用的条件不同；**平均查找长度 ASL 必须分别统计成功与失败，并按题设概率加权**，不能只凭最坏复杂度判断一次具体查找的比较次数。

</div>

<span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="s-28"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="p-199"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="p-200"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-7b597ac736e3"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-1cc9666eba4d"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-8527a891e224"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-018db2ec16e1"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-05de7dffca32"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-83f624388f44"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-0fce5a51ca09"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-78338ec5c861"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-246732b59e00"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-32efc773f40f"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-explain-3096b8b291"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-5d48de0d3b8a"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-58f51030cd92"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-6f48c153ea39"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-steps-3149d10151"></span><span class="legacy-anchor" data-target="s-01-2dd94635b6d1" id="u-01-b8bb54da7154"></span>

### 线性查找

<div class="study-unit" id="u-01-rewrite-63be25fd1a3b">

顺序查找逐项比较，不要求数据有序；折半查找每次排除一半区间，要求**按关键字有序且能按逻辑次序随机访问**；分块查找先根据块索引定位，再进入块内查找，通常块间有序、块内可无序。

</div>

<div class="study-unit" id="u-01-rewrite-6f200f9e2376">

折半查找维护闭区间 `[low,high]`，与中点比较后令 `high=mid-1` 或 `low=mid+1`，直到命中或 `low>high`。查找判定树中，成功次数等于目标层数；失败落入某个空区间，按实际经过的比较结点计数。比如 `[10,20,30]` 首比 20，三个成功查找次数为 2、1、2，等概率 ASL 为 $5/3$；失败有四个区间，应另行平均。

</div>

<div class="study-unit" id="u-01-a98be6531d19">

| 算法 | 执行过程 | 条件 / 结果 |
| --- | --- | --- |
| 顺序查找 | 逐个比较，哨兵可省越界判断 | 无需有序；等概率成功 $\mathrm{ASL}=\frac{n+1}{2}$；失败 n 或 $n+1$ 次，是否计哨兵看题设 |
| 折半查找 | 有序表取 mid，比较后保留可能的一半，直到命中或区间空 | 需有序和随机存取；$O(\log  n)$，链表一般不适合 |
| 分块查找 | 索引记录各块最大值和起点，先定位块再块内顺序查 | 块间有序、块内可无序；等长块、两层顺序查时 $\mathrm{ASL}=\frac{b+1}{2}+\frac{s+1}{2}$，$b\cdot s=n$，$s\approx \sqrt{n}$ 最优 |

</div>

### 树形查找

<div class="study-unit" id="u-01-rewrite-4b5fc32dab82">

搜索树把关键字范围分给不同子树，每次比较即可排除一部分候选。普通 BST 只维护次序，形状可能退化；AVL 和红黑树通过不同平衡约束控制高度；B 树、B+ 树让一个结点容纳多个关键字，以减少外存访问层数。

</div>

<div class="study-unit" id="u-01-rewrite-42abdfd7223d">

**查找代价既取决于树高，也取决于一个结点内怎样比较。** 对磁盘索引尤其关注访盘次数，不能把树的每个关键字比较都当作一次磁盘读取。后面各节分别给出结构约束和更新方式。

</div>

<span class="legacy-anchor" data-target="s-01-d1a32948b17f" id="s-30"></span><span class="legacy-anchor" data-target="s-01-d1a32948b17f" id="p-208"></span><span class="legacy-anchor" data-target="s-01-d1a32948b17f" id="p-209"></span><span class="legacy-anchor" data-target="s-01-d1a32948b17f" id="u-01-a8b8bf7af058"></span><span class="legacy-anchor" data-target="s-01-d1a32948b17f" id="u-01-dc122c3f9ff5"></span><span class="legacy-anchor" data-target="s-01-d1a32948b17f" id="u-01-a78f3824720a"></span><span class="legacy-anchor" data-target="s-01-d1a32948b17f" id="u-01-222b203af27b"></span><span class="legacy-anchor" data-target="s-01-d1a32948b17f" id="u-01-368c19e9e4af"></span><span class="legacy-anchor" data-target="s-01-d1a32948b17f" id="u-01-fcef4cbbf835"></span><span class="legacy-anchor" data-target="s-01-d1a32948b17f" id="u-01-837cf9881897"></span>
<a id="s-01-d1a32948b17f"></a>

#### 二叉搜索树

<div class="study-unit" id="u-01-rewrite-db0fee48659f">

二叉搜索树要求左子树所有关键字小于根、右子树所有关键字大于根，各子树递归满足同一规则，所以中序遍历递增；重复关键字的处理以题设为准。查找时小走左、大走右，到空链接则失败；插入就在这条查找路径的空位置建立叶结点。

</div>

<div class="study-unit" id="u-01-rewrite-a5fc1a933808">

删除时分三种：叶结点直接去掉，只有一个孩子则由孩子接替，有两个孩子则先用中序前驱或后继替换关键字，再删除对应的原结点。**操作为 $O(h)$，普通 BST 不保证 $h=O(\log n)$**；递增插入可能形成链，最坏达到 $O(n)$。

</div>

<span class="legacy-anchor" data-target="s-01-659f23556a6c" id="s-31"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="p-214"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="p-215"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="p-216"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="p-217"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="p-218"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="p-219"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="p-220"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-42f563b4c80f"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-0268a12fde0e"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-4c08838d5a32"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-7f28c4ea4525"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-8c04631fe99d"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-5169f238de1e"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-e841b647ff09"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-db99f9bb8cc9"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-explain-4b3c2c19ac"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-aaba1e4dd080"></span><span class="legacy-anchor" data-target="s-01-659f23556a6c" id="u-01-7d9566a80f62"></span>
<a id="s-01-659f23556a6c"></a>

#### 平衡二叉树

<div class="study-unit" id="u-01-rewrite-c2ee7462d8b9">

AVL 是每个结点左右子树高度差绝对值不超过 1 的二叉搜索树，常用平衡因子“左高减右高”。插入后从新叶向上找最低失衡祖先，根据该祖先及其较高孩子的方向，选择 LL、RR、LR、RL 调整，旋转时必须保持中序次序。

</div>

<div class="study-unit" id="u-01-rewrite-73b5770fb790">

例如依次插入 3、2、1，3 的左侧及左孩子的左侧过高，属于 LL，对 3 右旋，得到 2 为根、1 和 3 为左右孩子。插入通常修好最低失衡处即可，**删除可能使更高祖先继续失衡**。最少结点递推 $N(h)=N(h-1)+N(h-2)+1$ 用于求高度边界，不代表每棵 AVL 都取最少结点。

</div>

<div class="study-unit" id="u-01-833b33d09c10">

| 类型 | 最小失衡子树的调整 |
| --- | --- |
| LL（左—左型） | 失衡根右旋 |
| RR（右—右型） | 失衡根左旋 |
| LR（左—右型） | 先左旋左孩子，再右旋失衡根 |
| RL（右—左型） | 先右旋右孩子，再左旋失衡根 |

</div>

#### 红黑树

<div class="study-unit" id="u-01-rewrite-2eb1ff3baab9">

红黑树用颜色约束控制 BST 的高度：根和 NIL 空叶为黑，红结点不能有红孩子，每个结点通向各后代 NIL 的路径具有相同黑结点数。**它保证高度为 $O(\log n)$，但不要求左右子树高度差至多 1。** NIL 是辅助空叶，不是实际数据记录。

</div>

<div class="study-unit" id="u-01-rewrite-60eb3b57eda8">

新结点按 BST 插入并染红。父黑时结束；父红、叔红时，将父叔染黑、祖父染红并向上检查；父红、叔黑时，通过旋转和变色消除连续红，折线形先转为直线形，最后保证根黑。空叔按黑色处理。删除黑结点可能破坏黑高，必须继续调整，不能只做普通 BST 删除。

</div>

#### B树

<div class="study-unit" id="u-01-rewrite-a74331ab5f72">

$m$ 阶 B 树让一个非空结点保存有序关键字，$k$ 个孩子对应 $k-1$ 个关键字，各孩子分别负责关键字划出的范围。**最多 $m$ 个孩子、$m-1$ 个关键字；非根内部结点至少 $q=\lceil m/2\rceil$ 个孩子、$q-1$ 个关键字，非叶根至少两个孩子。** 全部外部失败叶同层，讨论高度时要说明是否只计含关键字层。

</div>

<div class="study-unit" id="u-01-rewrite-dc7326a1b2fe">

插入先定位到底层非空结点，溢出时将中央关键字上移，左右分裂，必要时向上继续；根分裂会增高。删除若低于下限，优先向有余量兄弟借，但必须经过双亲交换分隔关键字；兄弟也不足时，把两结点与双亲分隔关键字合并。以 3 阶为例，临时出现 `[10,20,30]` 时把 20 上移，留下 `[10]` 和 `[30]`。若 $m\ge3$，高 h 只计含关键字层，n 个关键字满足 **$2q^{h-1}-1\le n\le m^h-1$**；由最稀疏界求最大高度，由最满界求最小高度。

</div>

#### B+树

<div class="study-unit" id="u-01-rewrite-3a762bce871a">

B+ 树把实际记录集中在叶层，内部结点只负责导航，叶结点通常按关键字顺序链接。**单点查找必须到叶层，范围查找先定位起点叶，再沿叶链顺序扫描**；即使内部索引已出现相同关键字，也不能据此结束记录查找。

</div>

<div class="study-unit" id="u-01-rewrite-bd06d24c9d8f">

按本节采用的 408 常见阶数约定，$m$ 阶结点最多有 $m$ 个关键字，除根外关键字通常至少 $\lceil m/2\rceil$ 个，非叶根至少两个孩子；内部结点的关键字数与孩子数相同，索引常取各子树最大关键字；B 树则是孩子数比关键字数多 1。比如查询 `[20,50]`，先找到 20 所在叶，再连续读到大于 50 为止。若题目对阶数或分隔关键字另有定义，以题设为准。

</div>

### 散列查找

<div class="study-unit" id="u-01-rewrite-70aa25b86fe5">

散列函数把关键字映射为初始地址，不同关键字落在同一地址称冲突。开放定址按探测序列寻找其他槽位，拉链法把同地址记录挂在一条链上；装填因子 $\alpha$ 越大通常冲突越多，但具体代价仍与函数和处理方式有关。

</div>

<div class="study-unit" id="u-01-rewrite-f03d7193a973">

**开放定址遇“从未使用的空槽”才能判失败，遇“已删除”槽必须继续。** 表长 7，10、17 都从槽 3 开始，线性探测使 17 落在槽 4；删掉 10 若直接把槽 3 变成真空，就会截断 17 的查找路径。成功 ASL 从每个实际关键字模拟到命中，失败 ASL 从每个可能初始地址探测到真空，计入检查空槽的一次；平均分母取初始地址可能值的数量，不一定等于表长。

</div>

<div class="study-unit" id="u-01-d2f7ecf66f4c">

| 处理 | 执行 / 考点 |
| --- | --- |
| 线性探测 | H、$H+1$、$H+2$…取模，可能聚集；直到命中或从未用过的空槽 |
| 平方探测 / 双散列 | 按题设增量探测；是否覆盖全表依参数，不能假定必访每槽 |
| 拉链 | 同散列地址记录放同一链表，插删方便，需额外指针 |

</div>

## 第八章 排序

<div class="study-unit" id="u-01-rewrite-945cbd1a0103">

排序按关键字重新排列记录，比较方法时要同时看时间、辅助空间、稳定性和每趟产生的确定结果。**稳定性只讨论相等关键字记录能否保留原相对顺序**；“局部已有序”也不等于这些元素已经到达最终位置。数据能否全部放入内存，又把问题分为内部排序和外部排序。

</div>

<span class="legacy-anchor" data-target="s-01-e2d3b81989aa" id="s-37"></span><span class="legacy-anchor" data-target="s-01-e2d3b81989aa" id="p-244"></span><span class="legacy-anchor" ### 内部排序

<div class="study-unit" id="u-01-rewrite-08996ab303e1">

直接插入维护有序前缀，将下一元素插到合适位置；折半插入只加快找位置，后续移动仍可能为 $O(n^2)$；希尔按增量分组插入，最后增量必须为 1。冒泡通过相邻交换逐趟固定端点极值，选择排序每轮从未排序区找最小值，二者的交换方式使稳定性不同。

</div>

<div class="study-unit" id="u-01-rewrite-597f801f924a">

**快排一趟固定枢轴，堆排序一趟取出堆顶，归并一趟扩大有序段。** 快排平均为 $O(n\log n)$，极不均衡划分时退化为 $O(n^2)$；升序堆排序用大根堆，不表示堆内所有元素有序。归并用双指针合并有序段，需要结果空间；最低位优先基数排序逐位稳定分配、收集，不属于比较排序，因而不受比较排序 $\Omega(n\log n)$ 下界的直接限制。

</div>

<div class="study-unit" id="u-01-rewrite-fdf78d438867">

例如记录 `2甲、1、2乙` 排完若仍是 `1、2甲、2乙`，就保留了这两个相等记录的先后。模拟每一趟时，应同时标出有序前缀、归位元素或归并段，不能只写一个看似更有序的结果。下表汇总各算法性能，后表给出稳定插入的完整过程。

</div>

<div class="study-unit" id="u-01-25b480c8fe30">

| 算法 | 一趟怎么执行 | 时间：最好 / 平均 / 最坏 | 辅助空间 | 稳定 |
| --- | --- | --- | --- | --- |
| 直接插入 | 下一元素插入有序前缀，比它大者后移 | $n / n^{2} / n^{2}$ | $O(1)$ | 是 |
| 折半插入 | 折半找插入点，再移动元素；相等插在已有相等者后 | 比较 $O(n \log  n)$，移动最坏 $O(n^{2})$ | $O(1)$ | 是 |
| 希尔 | 按增量分组插排，逐步减小增量至 1 | 依增量序列，不固定为 $n^{1.3}$ | $O(1)$ | 否 |
| 冒泡 | 邻接逆序交换，一趟极值归位，无交换提前结束 | $n / n^{2} / n^{2}$ | $O(1)$ | 是 |
| 快排 | 枢轴划分两侧，递归子区间 | $n \log  n / n \log  n / n^{2}$ | 栈平均 $O(\log  n)$、最坏 $O(n)$ | 否 |
| 选择 | 未排序区选最小，与该区首位交换 | $n^{2} / n^{2} / n^{2}$ | $O(1)$ | 否 |
| 堆 | 升序大根堆，堆顶与末项换，缩小堆、向下调整 | n log n / n log n / n log n | $O(1)$ | 否 |
| 二路归并 | 两有序段用双指针取较小者，合并为新段 | n log n / n log n / n log n | $O(n)$ | 是 |
| 基数 LSD（最低位优先，Least Significant Digit） | 从低位到高位，按桶稳定分配、收集 | $O(d(n+r))$，d 位数、r 基数 | 链式桶常 $O(r)$，数组可 $O(n+r)$ | 是 |

</div>

### 外部排序

<div class="study-unit" id="u-01-rewrite-acd6901aa5df">

当全部记录放不进内存时，先分批读入并排序，形成若干初始有序段，再进行多路归并。主要成本是磁盘读写，因此 **$r$ 个初始段做 $k$ 路归并约需 $\lceil\log_k r\rceil$ 趟**，每趟通常读取并写出全部数据；增加路数可减趟数，但需要更多输入缓冲区。

</div>

<div class="study-unit" id="u-01-rewrite-d5c5f4d2c7df">

三个工具各解决一个问题：置换选择通过冻结小于刚输出值的新记录，延长初始段；败者树在各段头中快速选最小者，每输出一条后用 $O(\log k)$ 调整；最佳归并树按段长安排合并次序，减少加权读写量。构造 $k$ 叉最佳归并树时，必要时补零权虚段以满足叶数条件。比如 8 段二路归并需 3 趟，四路只需 2 趟；初始段生成是否计“趟”，必须看题目问法。

</div>
