### 冯诺依曼机的特点

| 冯诺依曼机的特点                                             |
| ------------------------------------------------------------ |
| ① 采用“<emp>存储程序</emp>”的工作方式。                      |
| ② 计算机由运算器、存储器、控制器、输入输出设备五大部件组成，<emp>以运算器为核心</emp>。（现代计算机改以<emp>存储器</emp>为核心） |
| ③ 指令和数据以<emp>同等地位</emp>存储在存储器中。            |
| ④ 指令和数据均以二进制形式表示。                             |
| ⑤ 指令由操作码和地址码组成，操作码指出操作的类型，地址码指出操作数的地址。 |
| ⑥ 程序和功能都是通过中央处理器执行指令实现的。（“<emp>程序控制</emp>”思想） |

<img src="./02-计算机组成原理.assets/计算机结构.png" style="zoom: 25%;" />

::: info 计算机的功能部件
1. 存储器是指主存和辅存。
2. 一个编址的对应一个存储单元，存储单元中存储的叫存储字，每一个bit叫存储元件。
3. 运算器的核心是ALU算术逻辑单元。

> 其常见寄存器有：累加器ACC、乘商寄存器MQ、操作数寄存器X、变址寄存器IX、基址寄存器BR。

4. 控制器由程序计数器PC、指令寄存器IR和控制单元CU组成。
5. 存储器地址寄存器MAR、存储器数据寄存器MDR。

一个功能既可以由硬件实现、也可以由软件实现，这一等价性称为<emp>软硬件逻辑功能等价性</emp>。
:::

| 汇编程序（汇编器） | 将汇编语言汇编成机器语言。                      |

### 定点数的机器数转换

无符号数没有原反补移，原反补移只针对有符号数。

<img src="./02-计算机组成原理.assets/移码表示.png" style="zoom: 30%;" />

| 机器数转换 | 规则                                                         |
| ---------- | ------------------------------------------------------------ |
| 移码转真值 | <emp>移码（解读成无符号真值）= 实际真值 + 偏置值</emp>。偏置值一般为<em>2<sup>n-1</sup></em>。 |
| 补码转移码 | 补码符号位取反得移码。                                       |
| 补码转真值 | 符号位赋负位权<emp><em>-2<sup>i</sup></em></emp>，数值位赋正位权，参与运算。 |

### 定点数的表示范围

|         定点数         | 定点整数                            | 定点小数                                      | 二进制表示              |
| :--------------------: | ----------------------------------- | --------------------------------------------- | ----------------------- |
| （$\small n$位）无符号 | $\small 0 \sim 2^n-1$               | $\small 0 \sim 1-2^{-n}$                      | $\small 0000 \sim 1111$ |
| （$\small n+1$位）原码 | $\small -(2^n-1) \sim 2^n-1$        | <emp>$\small -(1-2^{-n}) \sim 1-2^{-n}$</emp> | $\small 1111 \sim 0111$ |
| （$\small n+1$位）补码 | <emp>$\small -2^n \sim 2^n-1$</emp> | $\small -1 \sim 1-2^{-n}$                     | $\small 1000 \sim 0111$ |

| 补码规则                                                     |
| ------------------------------------------------------------ |
| 补码全0为0，全1为-1。                                        |
| 补码符号位为0，数值位全1，表示最大整数<em>2<sup>n</sup>-1</em>。 |
| 补码符号位为1，数值位全0，表示最小整数<em>-2<sup>n</sup></em>。 |
| 补码的符号扩展：高位用符号位填充。                           |

::: info 补码最大最小值
- 负值补码最小，符号位为1，数值位有1往后放。$\small 1|0000011$
- 负值补码最大，符号位为1，数值位有1往前放。$\small 1|1100000$
- 正值补码最小，符号位为0，数值位有1往后放。$\small 0|0000011$
- 正值补码最大，符号位为0，数值位有1往前放。$\small 0|1100000$

> 补码符号位取反就是移码，上述规则只要取反符号位就适用于移码。
:::

::: info 补码比较大小
1. 首先看符号位，正数一定比负数大。
2. 其次看数值位，数值位大的就大，数值位小的就小。FFFDH > FFDFH
:::

|                  加法器标志 |                                                              |

### 浮点数的精度问题

| 什么样的小数能用浮点数表示？                                 |
| ------------------------------------------------------------ |
| 𝟏. 只有能写成 $\pm\frac{A}{2^n}$ 形式的十进制小数才能转成二进制小数，因此浮点数只能表示这样的小数。<br/>𝟐. 浮点数尾数精度有限，尾数不得多于规定位数。 |
| <thd>浮点数完整表示整数的精度范围？</thd>                    |
| 浮点数可以表示整数，减小阶码，将尾数小数点后移至末尾，所得就是整数。但若超出尾数范围，再减小阶码就无法完整表示，只是乘2。<hr style="margin: 4px 0px;" />• 单精度浮点数完整表示整数的精度范围：$\small \pm1.\underbrace{1\ldots1}_{23位} \times 2^{23}=\pm\underbrace{11\ldots1}_{24位}=\pm(2^{24}-1)$。<br/>• 单精度浮点数能表示的最大整数：$\small \pm1.\underbrace{1\ldots1}_{23位} \times 2^{127}=\pm\underbrace{11\ldots1}_{24位}\underbrace{00\ldots0}_{104位}$。 |
| <thd>阶数差距过大，“大数吃小数”现象</thd>                    |
| 对单精度浮点数而言，两数阶码之差大于等于25时，小数的尾数在对阶时会直接变0，导致小数对运算无影响，二者加减结果等于大数。 |

### 浮点数的加减法

| 步骤         | 内容                                     | 示例                                    |
| ------------ | ---------------------------------------- | --------------------------------------- |
| 对阶         | 小阶向大阶对齐，小阶增大，尾数右移       | 1.2×10<sup>3</sup>=0.012×10<sup>5</sup> |
| 尾数运算     | 阶码相同，尾数可直接加减                 |                                         |
| 尾数规格化   | 尾数写成1.Y的形式，阶码顺势调整          | 0.012×10<sup>5</sup>=1.2×10<sup>3</sup> |
| 尾数舍入处理 | 多余位>0.5进位，<0.5舍去，=0.5向偶数舍入 | 1.10\|101≈1.11 (101=0.625)              |
| 溢出判断     | 规格化尾数，检查阶码是否超出范围         |                                         |

::: info 尾数舍入处理

如下四个例子，假设后三位待舍入，将多余位赋小数位权。

- $\small 1.10|101≈1.11$：因为 $\small 101=0.625>0.5$，所以 $\small 101$ 舍入并进位。
- $\small 1.10|011≈1.10$：因为 $\small 011=0.375<0.5$，所以 $\small 011$ 舍去不进位。
- $\small 1.10|100≈1.10$：因为 $\small 100=0.5$，所以 $\small 100$ 向偶数舍入，若保留位为偶数 (末位为0)，则舍去。
- $\small 1.01|100≈1.10$：因为 $\small 100=0.5$，所以 $\small 100$ 向偶数舍入，若保留位为奇数 (末位为1)，则进位。
:::

| ① 需要刷新，且按行刷新 | • 刷新时不可读写，称为死时间。<br/>• 刷新一行，耗时一个存储周期。所有行都刷新一次，耗时一个刷新周期。 |
| ② 行列地址复用         | • 同一组地址引脚，先传行地址，再传列地址。<br/>• 地址引脚数取行列数的最大值，一般行列地址线数相等。 |
| ③ 行缓冲区             | 行缓冲区大小为一行数据大小。                                 |
| 同步动态存储器 SDRAM   | DRAM升级版，继承DRAM的特点，支持突发传输、流水线，连续读写快。 |

<img src="./02-计算机组成原理.assets/DRAM行缓冲区.png" style="zoom: 60%;" />

| 刷新方式 | 策略                                             | 优缺点                 |
| -------- | ------------------------------------------------ | ---------------------- |
| 分散刷新 | 存取周期之后进行一次刷新，刷新时间囊括进存取周期 | 无死时间，存取周期翻倍 |
| 集中刷新 | 刷新周期的后期集中刷新所有行                     | 死时间长               |
| 异步刷新 | 刷新周期分成行数段，每一段最后进行一次刷新       | 死时间短               |

### 高速缓存 Cache

#### Cache的基本原理

| 局部性原理                                                   |
| ------------------------------------------------------------ |
| • 时间局部性：现在用的信息，未来还要用。<br/>• 空间局部性：未来用的信息，在现在所用信息的附近。 |
| <thd>CPU访问数据逻辑</thd>                                   |
| 𝟏. 首先去Cache中取数据，若命中，则算一次Cache存取。<br/>𝟐. 若未命中，则将数据从主存调入Cache，再从Cache访问数据，算一次Cache存取+一次主存存取。 |
| <thd>性能指标</thd>                                          |
| • Cache的命中率 $h = \frac{N_c}{N_c+N_m}$ .<br/>• 平均访问时间 = 命中率 × 访问Cache时间 + ( 1 - 命中率 ) × ( 访问Cache时间 + 访问主存时间 )<br/>&emsp;&emsp;&emsp;&emsp;&emsp;&emsp;&nbsp;&nbsp;&nbsp; = 访问Cache时间 + ( 1 - 命中率 ) × 访问主存时间 |

#### Cache的映射方式

|  映射方式  | 内容                                                         |
| :--------: | ------------------------------------------------------------ |
|  直接映射  | 直接映射，主存块只能放到固定位置。<br/>• 主存地址 = <span style="color:#de6c36">主存块号</span> + <span style="color:#b83c68">块内地址</span> = <span style="color:#de6c36">Tag + Cache块号</span> + <span style="color:#b83c68">块内地址</span><br/>计算步骤：<br/>• 主存块号 = 主存地址 / 块大小<br/>• Cache块号 = 主存块号 % Cache块数<blockquote style="margin: 5px 0px; padding-left: 10px;">块内地址位数取决于块大小，Cache块号位数取决于Cache块数，主存地址位数取决于主存大小。</blockquote> |
| 全相联映射 | 全相联映射，主存块可以放到任意位置。<br/>• 主存地址 = <span style="color:#de6c36">主存块号</span> + <span style="color:#b83c68">块内地址</span> = <span style="color:#de6c36">Tag</span> + <span style="color:#b83c68">块内地址</span> |
| 组相联映射 | 组相联映射，主存块只能放在固定组中，但组内可以放到任意位置。<em>n</em>路组相联表示一个组内有<em>n</em>个Cache块。<br/>• 主存地址 = <span style="color:#de6c36">主存块号</span> + <span style="color:#b83c68">块内地址</span> = <span style="color:#de6c36">Tag + Cache组号</span> + <span style="color:#b83c68">块内地址</span><br/>计算步骤：<br/>• Cache组数 = Cache块数 / Cache路数<br/>• Cache组号 = 主存块号 % Cache组数 |

#### Cache的比较器

从Cache中获取数据，需要先找到对应位置，再比较保存的Tag信息与自身地址中的Tag是否相等，相等则命中。

|        映射方式         | 比较器个数                                                   |
| :---------------------: | ------------------------------------------------------------ |
|       全相联映射        | 因为每块都能映射到所有的Cache行，因此只需设置<em>n</em>个比较器。 |
|        直接映射         | 因为每块只能映射到唯一的Cache行，因此只需设置<em>1</em>个比较器。 |
| <em>r</em> 路组相联映射 | 因为每块只能映射到唯一的Cache组，需与<em>r</em>个Cache行比较，需设置<em>r</em>个比较器。 |

- 每次获取仅消耗一次比较的时间，因为有多个比较器并行工作。
- 比较器仅需对比Tag位，比较器位数就是Tag位数。

#### Cache块的替换算法

替换算法的目标是找到代价最小的块。只有全相联和组相联需考虑替换算法，直接映射替换位置唯一，无需替换算法。

| 替换算法             | 策略                                    | 替换位                    |
| -------------------- | --------------------------------------- | ------------------------- |
| RAND 随机替换        | 随机找一个位置替换                      | <em>0</em>                |
| FIFO 先进先出        | 谁先进来替换谁                          | <em>log<sub>2</sub>n</em> |
| LRU 最近最久未使用 ★ | 设置计数器，没使用就加1，替换计数最大者 | <em>log<sub>2</sub>n</em> |
| LFU 最不经常使用     | 设置计数器，被使用就加1，替换计数最小者 | 长度无限，无需考虑        |

> FIFO、LRU替换位中的n指候选块总数，故组相联时<em>n</em>指路数，全相联时<em>n</em>指总块数。

::: info LRU手算方法
向前找第<em>n</em>个最近最久未使用的，重复的不算。假设有4个Cache块，访问主存块的序列为

<pre style="margin: 8px 0px">
 1  2  3  2  4  1  2  5
  <---√4--1--3--2--1--↑
</pre>
:::

#### Cache的写策略

| 情况     | 名称       | 策略                            | 优缺点                   |
| -------- | ---------- | ------------------------------- | ------------------------ |
| 写命中   | 全写法     | 又写Cache，又写存               | 数据一致性，增加访存次数 |
| 写命中   | 回写法     | 只写Cache，不写存，换出时再写存 | 数据不一致，减少访存次数 |
| 写不命中 | 写分配法   | 调入Cache，只写Cache            | 数据不一致               |
| 写不命中 | 非写分配法 | 不调Cache，只写存               | 数据一致性               |

| 全写法、回写法特点                                           |
| ------------------------------------------------------------ |
| • 全写法（直写法）可提供写缓冲队列，CPU同时写入Cache和缓冲区，缓冲区自行写入主存。<br/>• 回写法需为每个Cache块设置修改位（脏位）。 |
| <thd>各策略搭配情况</thd>                                    |
| • 写分配法只能搭配回写法，非写分配法只能搭配全写法。<br/>• 当题设说明采用回写法，就意味着写不命中时采用写分配法。 |

### 虚拟存储器

::: info 基本概念
> 常规存储器的缺点：
>
> 1. 一次性：必须全部加载才能运行作业，当作业很大或有大量作业无法全部装入。
> 2. 驻留性：作业执行完毕前，必须全部驻留内存。

虚拟存储器解决主存容量不够用的问题，存在于主存-辅存层，所以虚拟地址与物理地址的转换由操作系统负责。

内外存的数据交换以页为单位。虚拟存储器中称页，主存中称页框，页与页框的大小相同。

- “基本分页”：基于常规存储器，将程序的所有页导入内存。
- “请求分页”：基于虚拟存储器，只将访问的页导入内存。

一个进程拥有一个虚拟地址空间和一个页表，主存唯一存在。
:::

#### CPU访存全过程

| 通过虚拟地址获取物理地址                                     |
| ------------------------------------------------------------ |
| 𝟏. CPU给出虚拟地址，<br/>𝟐. 先查快表，若命中，直接转换为物理地址。若未命中，<br/>𝟑. 再查页表，若命中，更新快表并转换为物理地址。若未命中，触发缺页中断后更新页表和快表。 |
| <thd>使用物理地址获取数据</thd>                              |

### 指令的寻址方式

::: info 取指周期
1. 将PC中下条指令地址放到MAR中，(PC)→MAR
2. 根据MAR中的指令地址访存获得指令放到MDR中，M(MAR)→MDR
3. 将MDR中的指令放到IR中，(MDR)→IR
4. PC指针自增形成下条指令地址，(PC)+1→PC

<img src="./02-计算机组成原理.assets/取指周期数据流_transparent.png" style="zoom: 50%;" />
:::

| 顺序寻址                                                     |
| ------------------------------------------------------------ |
| 程序计数器PC + “指令所占存储单元数”，自动形成下条指令的地址。<br/>取指周期末，PC自动自增以指向下条指令，相当于<emp>PC时刻保存当前所执行指令的下条指令地址</emp>。 |
| <thd>跳跃寻址</thd>                                          |
| 跳跃寻址有两种地址给出方式：<br/>𝟏. 绝对地址：直接就是转移目标地址，A→PC（A无符号数）<br/>𝟐. 相对地址：指出当前PC值到转移目标地址的偏移量，(PC)+A→PC（<emp>A可正可负，补码表示</emp>）<br/><hr style="margin: 4px 0px;" />转移指令在指令执行阶段才进行跳跃寻址，此时PC早已在取指周期自增“1”，执行周期再将“PC+A”，故偏移量本质是相对下条指令地址的偏移量。 |

### 数据的寻址方式

| 寻址方式       | 具体内容                                                     |
| -------------- | ------------------------------------------------------------ |
| 隐含寻址       | 操作数地址无需直接指出，隐含在ACC或栈帧中，具体据指令类型而定。 |
| 立即寻址       | 操作数即**数据本身**，无需访存时间最短，但立即数的范围被限制。 |
| 直接寻址       | 操作数即数据的**有效地址EA**，需访存一次。                   |
| 间接寻址       | 操作数是数据的**间接地址**，需访存两次。n次间接寻址需访存n+1次。 |
| 寄存器寻址     | 操作数是**寄存器编号**，寄存器中存储数据**本身**。无需访存，地址码短，寄存器有限。 |
| 寄存器间接寻址 | 操作数是**寄存器编号**，寄存器中存储数据的**有效地址**。     |
| 相对(偏移)寻址 | 指令的跳跃寻址，算作一种数据寻址方式，EA=(PC)+A。适用于转移指令。<br/>三种偏移寻址的<emp>偏移量A均可正可负、使用补码表示</emp>。 |
| 基址(偏移)寻址 | 用基址寄存器BR或通用寄存器保存基址，指令的形式地址保存偏移量。<br/>基址固定、偏移量可变，二者结合为有效地址，EA=(BR)+A。适用于多道程序设计。 |
| 变址(偏移)寻址 | 用变址寄存器IX或通用寄存器保存变址，指令的形式地址保存偏移量。<br/>变址可变、偏移量固定，二者结合为有效地址，EA=(IX)+A。用户可更改，适用于循环、数组遍历。 |
| 堆栈寻址       | 用寄存器或内存的一块区域模拟堆栈，寄存器堆栈称硬堆栈，内存堆栈称软堆栈。堆栈读写位置由堆栈指针SP指出，故一般堆栈寻址的指令隐含操作数。 |

### 复杂精简指令集 CISC/RISC

| 复杂指令系统CISC                                             |
| ------------------------------------------------------------ |
| 1. 指令系统<u>复杂</u>，指令数目200条以上。<br/>2. 指令<u>长度不固定，格式多，寻址方式多</u>。<u>指令访存性不受限制</u>。指令间使用频度差距大。<br/>3. 各种指令<u>执行时间相差很大</u>，大多数指令需多个时钟周期才能完成。<br/>4. 控制器采用<u>微程序</u>控制，难以通过优化编译生成高效的目标代码程序。 |

|  通用寄存器数量  |          较少          |            较多            |

|     编译优化     |     不利于编译优化     |       有利于编译优化       |

```asm
        mov [ebp-8], 80             # M[R[ebp]-8]←80，即temp2=80
        mov eax, dword ptr [ebp-8]  # R[eax]←M[R[ebp]-8], 即R[eax]=temp2
        mov [esp+4],eax             # M[R[esp]+4]←R[eax]，即temp2入栈
        mov eax, dword ptr [ebp-12] # R[eax]←M[R[ebp]-12]，即R[eax]=temp1
        mov [esp], eax              # M[R[esp]]←R[eax]，即temp1入栈
        call add                    # 调用add，将返回值保存在eax中
        mov [ebp-4], eax            # M[R[ebp]-4]←R[eax]，即add返回值送sum
        mov eax, dword ptr [ebp-4]  # R[eax]←M[R[ebp]-4]，即sum作为返回值
        leave
        ret
```

### 指令周期的数据流向

| 概念     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 指令周期 | CPU取出并执行指令的全部过程。<blockquote style="margin: 5px 0px;">指令周期是灵活的，有的指令只有取指周期，有的只有取指周期和执行周期，不同指令的执行周期不一定相等。</blockquote> |
| 机器周期 | 指令周期的每个阶段称为一个机器周期。（区别于CPU时钟周期）    |

<img src="./02-计算机组成原理.assets/多种指令周期.png" style="zoom: 60%;" />
<img src="./02-计算机组成原理.assets/指令周期.png" style="zoom: 50%;" />

#### 取指周期

根据PC中的指令地址，从主存中取出指令代码存放在IR中。

1. 取指操作无需操作码，由控制器自动进行。
2. 当指令定长时，所有指令的取指都相同。
3. 取指周期必定访问存储器。

<img src="./02-计算机组成原理.assets/取指周期数据流.png" style="zoom: 60%;" />

| 数据流向                                                     | 机器指令    | 描述                               |
| ------------------------------------------------------------ | ----------- | ---------------------------------- |
| PC $\small \xrightarrow{1}$ MAR $\small \xrightarrow{2}$ 地址总线 $\small \xrightarrow{3}$ 主存 | PC→MAR      | 将PC中的指令地址放入MAR            |
| CU发出读命令 $\small \xrightarrow{4}$ 控制总线 $\small \xrightarrow{5}$ 主存 | M(MAR)→MDR  | 拿MAR指令地址访存，将指令放到MDR中 |
| 主存 $\small \xrightarrow{6}$ 数据总线 $\small \xrightarrow{7}$ MDR $\small \xrightarrow{8}$ IR | (MDR)→IR    | 将MDR中的指令放到IR中              |
| CU发出控制信号 $\small \xrightarrow{9}$ PC加1                | (PC)+“1”→PC | PC自动指向下一条指令的地址         |

#### 间址周期

访存取出操作数的有效地址EA，而非操作数本身。

<img src="./02-计算机组成原理.assets/间址周期数据流.png" style="zoom: 60%;" />

| 数据流向                                                     | 机器指令   | 描述                             |
| ------------------------------------------------------------ | ---------- | -------------------------------- |
| Op(IR) $\small \xrightarrow{0}$ CU                           | Op(IR)→CU  | 将操作码提供给CU，以进行译码     |
| Ad(IR) $\small \xrightarrow{1}$ MAR $\small \xrightarrow{2}$ 地址总线 $\small \xrightarrow{3}$ 主存 | Ad(IR)→MAR | 取出指令中的形式地址A，放入MAR中 |
| CU发出读命令 $\small \xrightarrow{4}$ 控制总线 $\small \xrightarrow{5}$ 主存 |            | 读出主存中的有效地址EA           |
| 主存 $\small \xrightarrow{6}$ 数据总线 $\small \xrightarrow{7}$ MDR | M(MAR)→MDR | 将有效地址EA放入MDR中            |

#### 执行周期

| 执行周期                                                     |
| ------------------------------------------------------------ |
| 通过有效地址EA取出操作数，并根据指令的操作码，进行运算并产生结果。 |
| <thd>执行周期的特点</thd>                                    |
| 𝟏. 取操作数未必需要访存，取决于数据的寻址方式<br/>𝟐. 不同指令的执行不同，因此没有统一的数据流向 |

#### 各周期访存对比

| 周期     | 是否访存   | 访存工作                 |
| -------- | ---------- | ------------------------ |
| 取指周期 | 一定访存   | 访存取指令               |
| 间址周期 | 一定访存   | 访存取操作数的有效地址EA |
| 执行周期 | 不一定访存 | 取决于数据寻址方式       |

### 数据通路的概念

#### 数据通路的定义

| 数据通路的定义                                               |
| ------------------------------------------------------------ |
| 数据在功能部件之间传送的路径，包括功能部件本身，统称为数据通路。 |
| • 数据流经的部件包括ALU、通用寄存器、状态寄存器、异常和中断处理逻辑。<br/>• CPU由数据通路和控制部件两部分组成。控制部件会根据指令生成对数据通路的控制信号。<blockquote style="margin: 5px 0px; padding-left: 10px;">数据通路描述了信息从什么地方开始，中间经过哪个寄存器或多路开关，最后传送到哪个寄存器，这些都由控制信号决定。</blockquote> |

#### 数据通路的组成

<img src="./02-计算机组成原理.assets/数据通路的组成.png" style="zoom: 25%;" />

数据通路由组合逻辑元件（操作元件）和时序逻辑元件（状态元件）组成。

| 数据通路组成             | 内容                                              | 特点       |
| ------------------------ | ------------------------------------------------- | ---------- |
| 组合逻辑元件（操作元件） | 算术逻辑单元、译码器、多路选择器、三态门          | 数据存不住 |
| 时序逻辑元件（状态元件） | 通用寄存器、程序计数器、状态/暂存/移位/锁存寄存器 | 数据存的住 |

::: info 三态门、多路选择器的作用
- 多路选择器(MUX)通过控制信号Select来确定哪个输入被输出。
- 三态门视为一种控制开关，由控制信号EN决定信号线的通断，也就是所连寄存器与总线通断。
:::

<img src="./02-计算机组成原理.assets/组合逻辑元件.png" style="zoom: 60%;" />

### 数据通路的结构

<img src="./02-计算机组成原理.assets/数据通路的分类.png" style="zoom: 25%;" />

|   总线方式   | 含义                                       | 特点                             |
| :----------: | ------------------------------------------ | -------------------------------- |
|  单总线方式  | 所有寄存器的输入输出端都接在一条公共通路上 | 结构简单、**容易冲突**、性能较低 |
|  多总线方式  | 所有寄存器的输入输出端都接到多条公共通路上 | 效率较高                         |
| 专用数据通路 | 根据指令执行过程中的数据流向安排连接线路   | 避免共享，性能更高，硬件量大     |

#### 单总线结构

<img src="./02-计算机组成原理.assets/单总线横图.png" style="zoom: 60%;" />

::: info 单总线框图描述
- 虚线表示控制信号，实线表示数据流向。
- 三态门 <img src="./02-计算机组成原理.assets/三态门符号_transparent.png" width="20" height="20" style="margin: 0 !important; display: inline; vertical-align: middle;"/> 表示通过信号控制连接和断开，<img src="./02-计算机组成原理.assets/并行传输符号_transparent.png" width="20" height="20" style="margin: 0 !important; display: inline; vertical-align: middle;"/> 表示并行传输4位二进制数据。

- 单总线结构同时仅能有一个部件发数据，但可有多个部件接收数据。

#### 单周期和多周期CPU

| CPU分类   | CPI         | 内容                                                         |
| --------- | ----------- | ------------------------------------------------------------ |
| 单周期CPU | 平均CPI = 1 | 每条指令都在一个时钟周期内完成，时钟周期由耗时最长的指令决定。单周期CPU使用单周期数据通路。 |
| 多周期CPU | 平均CPI > 1 | 不同指令所分配时钟周期数不同，时钟周期由最复杂的指令阶段决定。多周期CPU使用多周期数据通路。 |

::: info 时钟周期的概念
时钟周期是计算机内最小时间单位，
- 控制器以时钟周期为单位产生控制信号。即一个时钟周期内，控制信号不变。
- 而发出一次控制信号，只会控制对应部件运行一次。即一个时钟周期内，每个部件最多使用一次。
:::

| 单周期数据通路的特点                                         |
| ------------------------------------------------------------ |
| • 对于单周期CPU而言，一次指令执行过程中，控制信号不会发生改变，每个部件只会使用一次。<br/>• 对于多周期CPU而言，一次指令执行过程中，控制信号多次发生改变，每个部件可以使用多次。 |
| 单周期数据通路，程序计数器PC无须写使能控制信号。<blockquote style="margin: 5px 0px; padding-left: 10px;">单周期CPU每个时钟周期自动取指，故无需额外PC控制信号。</blockquote> |
| 单周期数据通路，一个时钟周期内无法发生状态元件到状态元件的数据转移。因此无需设置寄存器IR。 |
| 单周期数据通路，指令和数据需分离存储，一个存储器在一个时钟周期内，只能响应一个地址请求。 |

### 微程序控制器

#### 微程序控制的概念

- 微程序设计思想是将机器指令编写成一个微程序，微程序由微指令组成。
- 微指令存储在控制存储器CM中，微指令的寻址方式和机器指令类似。x86平台多采用微程序技术。

> 控制存储器CM是一块ROM芯片，能按地址进行随机存取。

<table>
  <thead><tr><th>概念</th><th>含义</th><th>对应关系</th></tr></thead>
  <tbody>
    <tr><td>微命令</td><td>控制器发出的控制信号，如(PC)→MAR</td><td>一条微指令 ⇔ 多个微命令</td></tr>
    <tr><td>微操作</td><td>执行部件收到微命令所做的操作，如PC<sub>out</sub> MAR<sub>in</sub></td><td>一个微操作 ⇔ 一套微命令</td></tr>
    <tr><td colspan="3">一条机器指令 ⇔ 一个微程序 ⇔ 若干微指令 ⇔ 若干多个微指令</td></tr>
  </tbody>
</table>

::: info 控制存储器和主存的区别
- 主存储器用于存放程序和数据，在CPU外部，用ROM和RAM实现。
- 控制存储器用于存放微程序，在CPU内部，用ROM实现。
+ 存放指令的主存储器单元的地址称为地址。
+ 存放微指令的控制存储器单元的地址称为微地址。
- 程序是指令的集合，以实现特定功能。
- 微程序是微指令的集合，以实现机器指令。
:::

#### 微程序控制器的组成

<div style="display: flex; gap: 5px; align-items: center; justify-content: center;">
  <img src="./02-计算机组成原理.assets/增量法.png" style="zoom: 30%;" title="增量法" />
  <img src="./02-计算机组成原理.assets/下地址断定法.png" style="zoom: 60%;" title="下地址断定法" />
</div>

|      组成部件       | 介绍                                                         |
| :-----------------: | ------------------------------------------------------------ |
|   微地址形成部件    | 根据指令操作码生成对应微程序的入口地址，依据当前微指令的顺序控制字段及状态条件，产生后续微地址。 |
| 微指令地址寄存器μPC | 接收微地址形成部件提供的微地址，作为CM的读地址。             |
|   控制存储器CS/CM   | 微程序控制器的核心部件，用于存放所有机器指令对应的微程序。   |
|   微指令寄存器μIR   | 暂存从CM中读出的微指令，并将其操作控制字段和顺序控制字段分别送至执行单元和微地址形成部件。 |

#### 微程序控制器的工作过程

| ① 执行取指令公共操作                                         |
| ------------------------------------------------------------ |
| 将取指微程序的入口地址（通常为0号地址）送入μPC，再从CM中读取首条取指微指令并送入μIR。完成取指微程序后，从主存中取出的机器指令即被存入指令寄存器IR中。 |
| <thd>② 生成当前指令的微程序入口地址</thd>                    |
| 根据IR中机器指令的操作码，通过微地址形成部件产生对应微程序的起始微地址，并送入μPC。 |
| <thd>③ 顺序执行微程序</thd>                                  |
| 在CM中逐条读取微指令，送入μIR并执行，直至该微程序执行完毕。  |
| <thd>④ 循环重新取指</thd>                                    |
| 当前指令的微程序执行结束后，控制器自动转移到取指微程序的入口，重新开始处理下一条机器指令。 |

#### 微指令地址的生成方式

| 地址             | 生成方式                                                     |
| ---------------- | ------------------------------------------------------------ |
| 微程序入口地址   | 一条机器指令从主存取出并送入IR后，微地址形成部件通过其操作码，生成对应微程序的首条微指令地址，并送入μPC。 |
| 顺序执行         | 增量方式：由μPC+1自动生成下条微地址。<br/>断定方式：微指令的下地址字段中指出下一条微指令地址。 |
| 条件分支（转移） | 增量方式：修改μPC。<br/>断定方式：微指令的下地址字段指定的转移目标地址。 |

##### 微指令的编码方式

|   编码方式   | 内容                                                         |
| :----------: | ------------------------------------------------------------ |
|   直接编码   | 微命令字段相当于位图，每一位代表一个微命令。<br/>无需译码，简单直观，速度快，并行性好，但字长过长。 |
| 字段直接编码 | 微命令字段分成若干小字段，每个字段独立编码。互斥性微命令编进同一字段，相容性微命令编进不同字段。<br/>缩短字长，但削弱并行性。 |
| 字段间接编码 | 一个字段的某些微命令需由另一个字段中的某些微命令来解释，又称隐式编码。<br/>进一步缩短字长，进一步削弱并行性。 |

<img src="./02-计算机组成原理.assets/水平型微指令.png" style="zoom: 60%;" />

::: info 字段直接编码的具体编码方法
直接编码方式本质就是位图，该位置1表示有效，置0表示无效。

字段直接编码方式用字段编码，比如三位划作一个字段，该字段可表示2<sup>3</sup>-1个微命令，<emp>留出一种以表示空</emp>。

- 互斥性微命令：同一个时钟周期内，不能同时出现的微命令，需划分到一个字段
- 相容性微命令：同一个时钟周期内，可以同时出现的微命令，需划分到不同字段
:::

### 异常和中断机制

#### 异常和中断的概念

<img src="./02-计算机组成原理.assets/异常和中断.png" style="zoom: 25%;" />

| 概念           | 内容                                                         |
| -------------- | ------------------------------------------------------------ |
| 异常（内中断） | <emp>指令执行过程中</emp>，检测到CPU内部的，和正在执行的指令有关的事件。 |
| 中断（外中断） | <emp>指令执行结束后</emp>，检测到外设触发的，与当前执行的指令无关的事件。 |

| 异常 | 内容                                                         |
| ---- | ------------------------------------------------------------ |
| 故障 | 指令执行过程中被检测到的，处理完毕后，<emp>返回原指令位置重新执行</emp>，若无法处理，直接终止。 |
| 自陷 | 指令执行完毕后主动触发的，处理完毕后，<emp>返回原指令的下条指令继续执行</emp>。又叫陷阱或陷入。 |
| 终止 | 指令执行过程中发生严重的硬件故障，导致程序无法运行，因此终止。 |

### 指令流水线

#### 指令流水线的概念

将一个指令分成五个阶段，每个阶段使用不同部件，这样同一时刻可执行多个指令的不同阶段，这就是流水线技术。

| 流水段             | 内容                                           |
| ------------------ | ---------------------------------------------- |
| 取指 (IF)          | 从指令存储器或Cache中取指令。                  |
| 译码/读寄存器 (ID) | 控制器对指令进行译码，同时从寄存器中取操作数。 |
| 执行/计算地址 (EX) | 执行运算操作或计算地址。                       |
| 访存 (MEM)         | 对存储器进行读写操作。                         |
| 写回 (WB)          | 将指令执行结果写回寄存器。                     |

<div style="display: flex; gap: 5px; align-items: center; justify-content: center;">
    <img src="./02-计算机组成原理.assets/指令流水线.png" style="zoom: 60%;" />
    <img src="./02-计算机组成原理.assets/流水线时空图.png" style="zoom: 60%;" />
</div>

::: info 指令流水段的时长
- 一个时段T就是一个CPU时钟周期，因此时钟周期必须为五个阶段的最长耗时。
- 从5T开始，每隔一个时钟周期就有一条指令流出流水线，做到平均CPI为1。
:::

#### 流水线的逻辑结构

<img src="./02-计算机组成原理.assets/流水线结构.png" style="zoom: 60%;" />

- 因各阶段耗时不同，故需设置寄存器暂存本段的**结果和控制信号**，以便在下个周期提供给下个流水段。
- 统一的CLK时钟信号即作用在功能部件上，也作用在流水段寄存器上。
- 单周期和流水线CPU的取指和译码阶段自动完成，不需要控制信号的参与，但多周期CPU需要。

<img src="./02-计算机组成原理.assets/流水线硬件.png" style="zoom: 50%;" />

#### 流水线的指令要求

1. 长度一致：指令长度尽量一致，利于简化取指和译码操作。
2. 格式规整：指令格式尽量规整。
3. 访存受限：仅Load/Store指令可访存。
4. 内存对齐：数据在存储器中对齐存放。

#### 流水线的性能指标

| 任务耗时                                                     |
| ------------------------------------------------------------ |
| • 5段指令采用流水线执行n条指令的耗时：<em>5T+(n-1)T</em><br/>• 5段指令不用流水线执行n条指令的耗时：<em>5nT</em><br/>• k段指令采用流水线执行n条指令的耗时：<em>kT+(n-1)T</em><br/>• k段指令不用流水线执行n条指令的耗时：<em>knT</em><blockquote style="margin: 5px 0px; padding-left: 10px;">k段指令采用流水线，前kT只能完成一条指令，后面每个T都能完成一条指令，故总耗时是 <em>(k + n- 1)T</em>。</blockquote> |
| <thd>吞吐率</thd>                                            |
| 单位时间内流水线所完成的任务量，即任务量 / 所耗时间。<br/><div style="text-align: center; margin: 8px;">$\large {\small TP}=\frac{n}{T_k}=\frac{n}{(k+n-1)\Delta t}$</div>n是任务数量，k是流水段数，Δt是时钟周期。n充分大时，TP<sub>max</sub>=1/Δt 。 |
| <thd>加速比</thd>                                            |
| 相同任务量下，不用流水线和使用流水线的耗时之比。<br/><div style="text-align: center; margin: 8px;">$\large {\small S}=\frac{T_0}{T_k}=\frac{kn\Delta t}{(k+n-1)\Delta t}=\frac{kn}{k+n-1}$</div>n充分大时，S<sub>max</sub>=k 。 |

#### 多处理器的概念

多指令流多数据流 MIMD 又可分为多核处理器、多处理器系统、多计算机系统。

| MIMD         | 含义                                                         |
| ------------ | ------------------------------------------------------------ |
| 多核处理器   | 一个CPU中有多个处理器核心                                    |
| 多处理器系统 | 一个计算机中有多个处理器，多个CPU共享一个内存 (SMP)<br/>统一内存访问 (UMA)：所有处理器共享唯一的集中式内存<br/>非统一内存访问 (NUMA)：主存划分成多个区域分配给不同CPU并以总线互连 |
| 多计算机系统 | 一个系统中有多个计算机                                       |

  <img src="./02-计算机组成原理.assets/UMA.png" style="zoom: 10%;" />
  <img src="./02-计算机组成原理.assets/NUMA.png" style="zoom: 25%;" />

#### 硬件多线程

硬件多线程必须为线程提供单独的通用寄存器组、程序计数器等，线程切换只需激活寄存器不必访存，大大减少了线程切换的开销。

| 实现方式      | 含义                                                         |
| ------------- | ------------------------------------------------------------ |
| 细粒度多线程  | 多个线程之间轮流交叉执行指令                                 |
| 粗粒度多线程  | 连续若干时钟周期执行同一线程的指令，阻塞时切换线程且需清空流水线 |
| 同时多线程SMT | 单个时钟周期内同时执行多个线程的多条指令，实现了指令级并行和线程级并行，如超线程技术在一个核心中维护两套线程状态部件，但共享执行资源。 |

### 总线的性能指标

| 性能指标     | 含义                                                         |
| :----------: | ------------------------------------------------------------ |
| 总线宽度     | 总线中数据线的条数，即并行传输的数据位数。                   |
| 总线复用     | 没有单独地址线，地址通过数据线传送，即地址/数据线复用。      |
| 总线寻址能力 | 地址线位数决定寻址空间量，16根地址线可寻址2<sup>16</sup>个单元。 |
| 总线工作频率 | 时钟周期：总线有自己的时钟周期，时钟频率：总线时钟周期的倒数。<br/>总线周期：完成一次总线事务的时间，总线工作频率：每秒完成总线事务的次数。<blockquote style="margin: 5px 0px;">总线的工作频率 = 总线周期 / 时钟周期 × 时钟频率</blockquote> |
| 总线带宽<br/>数据传输速率     | 最大数据传输速率，总线带宽 = 总线宽度 × 总线工作频率<br/>平均数据传输速率，数据传输速率 = 数据传输量 / 时钟周期数<blockquote style="margin: 5px 0px;">总线带宽是最大值，只看总线宽度和工作频率，其他不管。数据传输速率是平均值，需考虑具体传输情况。</blockquote>         |

### 总线事务

<img src="./02-计算机组成原理.assets/总线事务.png" style="zoom: 25%;" />

主从设备之间的一次完整信息交换，称为一个总线事务。包含三个阶段：

| 事务阶段                   | 内容                                                      |
| -------------------------- | --------------------------------------------------------- |
| 地址传送阶段               | 主设备将目标地址和操作类型（读/写）通过总线传送给从设备。 |
| 从设备响应 (数据准备) 阶段 | 从设备根据地址准备数据。（该阶段耗时若未提及可忽略）      |
| 数据传送阶段               | 完成实际数据在总线上的传输。                              |

<img src="./02-计算机组成原理.assets/总线传输.png" style="zoom: 25%;" />

| 传送方式   | 内容                                                   |
| ---------- | ------------------------------------------------------ |
| 非突发传送 | 主从设备之间一般只能传输一个总线宽度的数据。           |
| 突发传送   | 寻址阶段发的是首地址，传输阶段传送多个连续单元的数据。 |

| 传送方式 | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 串行传输 | 同步串行：双方时钟严格一致，效率高，但复杂成本高。仅添加首尾定界标记。<br/>异步串行：双方使用独立时钟，无须严格同步。格式：起始位+数据位+校验位+停止位。 |
| 并行传输 | 多条线同时传输，短距离延迟低吞吐高。信号串扰和时序偏移，限制工作频率的提升。 |

### 总线定时

<img src="./02-计算机组成原理.assets/总线定时.png" style="zoom: 25%;" />

| 总线定时方式 | 内容                                                       |
| ------------ | ---------------------------------------------------------- |
| 独占式       | 从发起请求到传送结束，总线全程被该事务占用。               |
| 分离式       | 将总线事务分解为请求和应答两个子过程，避免准备时段的占用。 |

| 独占式 | 内容                                                         |
| ------ | ------------------------------------------------------------ |
| 同步   | 采用统一的时钟来协调双方的定时。一个总线周期可以进行一次数据传送。<br/>速度快、逻辑简单，不能及时校验，适用于总线长度短、<emp>设备速度接近</emp>的系统。 |
| 异步   | 无统一时钟，无固定间隔，依靠握手信号实现定时。<br/>总线周期和长度可变、能及时校验更可靠，稍复杂且速度慢，适合<emp>速度差距大</emp>的系统。 |
| 半同步 | 增设一条Wait响应信号线，Wait信号有效则存在数据。<br/>控制简单、可靠性高，时钟频率不能太高、速度不快，适合速度不高的简单系统。 |

异步定时又分以下三类：

<img src="./02-计算机组成原理.assets/异步定时.png" style="zoom: 60%;" />

| 异步定时 | 内容                                                         |
| :------: | ------------------------------------------------------------ |
|  不互锁  | 请求信号自动撤销。                                           |
|  半互锁  | 请求信号必须等收到回答信号才可撤销，回答信号自动撤销。       |
|  全互锁  | 请求信号必须等收到回答信号才可撤销，回答信号必须等请求信号撤销之后撤销。 |

### IO接口

| IO接口（控制器）                                                |
| ------------------------------------------------------------ |
| IO接口是主机和外设的交界面，包含程序和硬件，以实现信息交换。具体功能有：信号转换、数据暂存、地址译码、控制设备、暂存设备状态等。<blockquote style="margin: 5px 0px; padding-left: 10px;">常见的IO接口有打印机适配器、网络控制器、可编程中断控制器等。</blockquote> |
| <thd>IO端口</thd>                                            |
| IO端口是接口电路中设置的若干寄存器，用来缓冲数据、设定控制状态等，这些寄存器可被CPU直接访问。|

<img src="./02-计算机组成原理.assets/IO接口通用结构.png" style="zoom: 60%;" />

#### IO接口和系统总线的连接

| IO接口如何连接主机？                                         |
| ------------------------------------------------------------ |
| 早期单总线将CPU、主存、外设接在一起，CPU可直接与外设交换信息。所以，IO接口在主机侧通过系统总线与CPU相连，系统总线中分有数据线、地址线和控制线。 |
| <thd>数据线有何作用？</thd>                                  |
| • 发命令：发送命令字到控制寄存器。<br>• 读状态：从状态寄存器中读取状态字。<br>• 传数据：从数据缓冲寄存器中交换数据。 |
| <thd>与数据线相连的IO端口是哪些？有何作用？</thd>            |
| • 数据缓冲器：用来传数据，暂存与CPU之间传送的数据。<br>• 状态寄存器：用来读状态，记录接口或设备的状态信息。<br>• 控制寄存器：用来发信号，保存CPU对外设的控制命令。<blockquote style="margin: 5px 0px; padding-left: 10px;">状态和控制寄存器在方向上相反，时间上错开，因此可合二为一。</blockquote> |
| <thd>三条总线的传输内容</thd>                                |
| • 数据线：数据、状态信息/状态字、控制信息/控制字、命令/命令字、中断类型号。<br>• 地址线：IO端口地址。<br>• 控制线：读写控制信号、中断请求信号、中断响应信号、仲裁信号、握手信号。<blockquote style="margin: 5px 0px; padding-left: 10px;">看到字就在数据线，看到信号就在控制线。</blockquote> |

<img src="./02-计算机组成原理.assets/IO接口所连接的系统总线.png" style="zoom: 25%;" />

#### IO端口的编址

IO端口须进行编址以被CPU访问，有两种编址方式，独立编址和统一编址。

| 编址方式 | 含义                                                         |
| -------- | ------------------------------------------------------------ |
| 独立编址 | IO端口的地址空间与主存地址空间是两个独立的地址空间。<br/>优点：IO端口数少，只需少量地址线，译码简单，寻址速度快<br/>缺点：需专用IO指令，增加了指令系统的复杂性。 |
| 统一编址 | 主存地址空间分出一部分给IO端口进行编址，IO端口和主存单元在同一地址空间。<br/>优点：CPU访IO端口和访存一致，无需专门IO指令，简化指令系统设计。<br/>缺点：IO端口占用了一部分地址空间，导致减少了内存地址的可用范围。 |

<img src="./02-计算机组成原理.assets/IO端口编址.png" style="zoom: 60%;" />

#### 程序查询方式

<div style="display: flex; gap: 20px; align-items: center; justify-content: center;">
  <img src="./02-计算机组成原理.assets/程序查询方式.png" style="zoom: 50%;" />

| 流程     | 内容                                       |
| -------- | ------------------------------------------ |
| 发命令   | CPU发送传输命令到控制寄存器   |
| 读状态   | CPU从状态寄存器读取设备状态 |
| 传数据 | 外设准备好一个字的数据，CPU从数据缓冲寄存器读取该字，IO程序修改地址和计数值，以便传输下一个字，直至数据全部传输完毕。<blockquote style="margin: 5px 0px;">所有IO方式都是按字传输多次，以传输整个数据。</blockquote>   |

| 查询方式 | 内容                                           |

#### 程序中断方式

| 程序中断方式                                                 |
| ------------------------------------------------------------ |
| CPU发出命令外设准备数据，此时CPU可调度其他进程，IO就绪后通过中断程序传输数据，每准备好一个字就进行一次中断，直至整个数据块传输完毕。 |

| 中断的工作流程 | 内容                                                         |
| -------------- | ------------------------------------------------------------ |
| 中断请求       | 外部设备向CPU发起中断请求                                    |
| 中断响应判优   | 通过中断判优逻辑（一般由硬件实现）决定响应哪个中断请求       |
| 中断响应       | 中断响应被称为中断隐指令：关中断、保存断点PC和PSW、送中断向量 |
| 中断处理       | 执行中断服务程序叫中断处理                                   |

<img src="./02-计算机组成原理.assets/程序中断方式.png" style="zoom: 60%;" />

##### 异常和中断的响应流程

| 中断的响应流程    | 含义                                                         |
| ----------------- | ------------------------------------------------------------ |
| 𝟏. 中断判优       | 若存在多个中断请求，通过中断判优逻辑响应一个中断源。<blockquote style="margin: 5px 0px; padding-left: 10px;"><emp>中断判优仅用于外中断</emp>，外中断比异常多一个中断判优。</blockquote> |
| 𝟐. 中断响应的条件 | • 有中断请求<br/>• CPU允许中断（异常和不可屏蔽中断不受关中断限制）<br/>• 指令执行完毕（异常立即响应无需等到指令执行结束） |
| 𝟑. 中断隐指令     | • 关中断<br/>• 保存断点PC和程序状态PSW<br/>• 送中断向量<blockquote style="margin: 5px 0px; padding-left: 10px;">这三步由硬件完成且不可打断。关中断本质是将中断允许标志位IF置零0。</blockquote> |

##### 异常和中断的处理流程

中断响应和执行中断服务程序统称为中断处理，流程如下：

<img src="./02-计算机组成原理.assets/中断处理过程.png" style="zoom: 60%;" />

| 流程          | 处理步骤                                                     | 解释                                                         |         硬软件执行          |
| ------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | :-------------------------: |
| 中断<br/>响应 | 1. <emp>关中断</emp><br/>2. 保存断点<br/>3. 中断服务程序寻址 | 中断响应必须先关中断<br/>保存PC和PSW以能够返回<br/>根据中断类型号找中断向量，执行服务程序<br/> |  中断隐指令<br/>(硬件)完成  |
| 中断<br/>处理 | 4. <emp>保存现场和屏蔽字</emp><br/>5. 开中断<br/>6. 执行中断服务程序<br/>7. <emp>关中断</emp><br/>8. <emp>恢复现场和屏蔽字</emp><br/>9. 开中断、中断返回 | 发生进程切换，需要保存进程上下文<br/>多重中断，执行中断服务程序前，需要开中断<br/>-<br/>恢复进程上下文前需要关中断<br/>恢复进程上下文<br/>通过中断返回指令返回，恢复上下文和特权级<br/> | 中断服务程序<br/>(软件)完成 |

##### 中断向量和中断向量表

| 中断向量和中断向量表                                         |
| ------------------------------------------------------------ |
| 中断服务程序的首地址称中断向量，中断向量存放在中断向量表中，每个中断向量对应一个中断类型号。<blockquote style="margin: 5px 0px;">中断向量在中断向量表的下标即中断类型号，中断向量的所在内存地址即中断向量地址。</blockquote><img src="./02-计算机组成原理.assets/中断向量表.png" style="zoom: 60%;" />• 中断向量是中断服务程序的首地址<br/>• 中断向量地址是中断服务程序的首地址的地址 |

##### 多重中断和中断屏蔽

在执行中断服务程序的过程中，转去处理优先级更高的中断请求，称为多重中断/中断嵌套。

<img src="./02-计算机组成原理.assets/多重中断.png" style="zoom: 60%;" />

| 中断处理优先级                                               |
| ------------------------------------------------------------ |
| 每个中断源都有自己的中断屏蔽字，代表其中断处理优先级，执行其中断服务程序时，会将它放入屏蔽字寄存器中。<br/>中断程序执行中，屏蔽字才生效，主程序执行时，不屏蔽任何中断。处理优先级决定了其他中断是否被屏蔽。 |
| <thd>中断响应优先级</thd>                                    |
| 中断响应优先级由硬件排队电路（或查询程序）决定，不可动态改变。响应优先级决定了多个未屏蔽中断优先响应谁。 |

新中断请求，会先经处理优先级过滤，再按响应优先级进行判优。

<img src="./02-计算机组成原理.assets/中断屏蔽实现.png" style="zoom: 60%;" />

#### DMA方式

DMA让外设可以不经CPU与内存直接交换数据。

| DMA控制器                                                    |
| ------------------------------------------------------------ |
| 所有使用DMA传输的设备，都接在DMA控制器上，DMA控制器负责数据交换的全过程。<img src="./02-计算机组成原理.assets/DMA控制器.png" style="zoom: 60%;" /><div style="display: inline-grid; grid-template-columns: max-content max-content;"><span>• AR主存地址寄存器</span><span>：存放读写的主存地址</span><span>• WC传送长度计数器</span><span>：记录已写入字的个数</span><span>• BR数据缓冲寄存器</span><span>：存放将读写的数据字</span></div> |
| <thd>DMA整体流程</thd>                                       |
| 𝟏. 预处理：CPU完成准备工作。<br/>𝟐. 传数据：DMA控制器完成数据传输，CPU不参与该过程。DMA的数据传输是将一个数据块换到主存，具体要将块以字为单位分批传输。<br/>𝟑. 后处理：DMA控制器发出中断请求，CPU执行中断做后处理。<img src="./02-计算机组成原理.assets/DMA流程图.png" style="zoom: 60%;" /> |
| <thd>DMA传输过程</thd>                                       |
| <div style="display: inline-grid; grid-template-columns: max-content max-content;"><span>𝟏. 预处理</span><span>：CPU预处理，设置AR/WC/BR初始值。</span><span>𝟐. 请求DMA</span><span>：设备字就绪时，向DMA控制器发起DMA请求，DMA控制器设置AR/WC/BR内容。</span><span>𝟑. 请求总线</span><span>：DMA控制器向CPU发起总线请求，CPU响应此请求，DMA控制器将字传输到主存。</span><span>𝟒. 计数自增</span><span>：AR自增，WC自增。</span><span>𝟓. 后处理</span><span>：WC溢出时，发送"溢出信号"到中断机构，中断机构发起中断，请求CPU进行后处理。</span></div><blockquote style="margin: 5px 0px;">CPU每隔一个总线周期，对DMA请求检测和响应一次。</blockquote> |

<img src="./02-计算机组成原理.assets/DMA数据交换.gif" style="zoom: 25%;" />

##### DMA访问主存

DMA可能与CPU发生访存冲突，有如下三种策略：

| 策略             | 解释                                                         |
| ---------------- | ------------------------------------------------------------ |
| 停止CPU访存      | DMA要访存时向CPU发送停止信号，CPU放弃系统总线的使用权，整批数据传输完毕后，将总线控制器交给CPU。 |
| DMA与CPU交替访存 | 若CPU工作周期比主存存取周期长很多，采用交替访存。              |
| 周期挪用         | a. CPU不在访存，挪用若干个主存存取周期给IO设备<br/>b. CPU正在访存，等待CPU机器周期结束，CPU将总线占有权让出<br/>c. 二者同时访存，CPU暂时放弃总线占有权，因IO访存优先于CPU访存<br/>此时DMA使用分离式总线定时，传送一个字后立即释放总线。 |

#### IO方式的比较

| IO方式       | CPU和外设的工作情况           |
| ------------ | ----------------------------- |
| 程序查询方式 | CPU和外设完全串行工作         |
| 程序中断方式 | CPU和外设并行，程序和传输串行 |
| DMA方式      | CPU和外设并行，程序和传输并行 |
