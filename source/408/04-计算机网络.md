# 计算机网络

<!-- unit-id:s-04-47ea07d405a4 -->
## 第一章 计算机网络基础

<!-- unit-id:s-04-64a5b5fb2867 -->
### 三种交换方式

<!-- unit-id:u-04-e4c8f26359dc -->
| 交换 | 执行过程 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 电路 | 建立专用通路→连续传数据→释放 | 建立后时延较稳定、无存储转发 | 建立需时间，空闲仍占资源 |
| 报文 | 整个报文到结点后保存，再向下一跳发送 | 不预占专用电路 | 大报文占缓存、转发等待长 |
| 分组 | 报文切成分组，各跳按分组存储转发 | 可流水、线路利用率高 | 分组首部开销，可能排队 / 乱序 / 丢失 |

<!-- unit-id:u-04-566b717a55ae -->
总长 D、n 个等长分组 L、h 条等速率 R 链路、每链路传播 d，忽略排队 / 处理时：分组总时间=(n+h−1)L/R+hd；报文为 hD/R+hd。电路另加建立时间，数据只需一次 D/R 发送时间。各链路速率不同应按首包传播和瓶颈流水计算。

### 网络性能指标

<!-- unit-id:u-04-f10ce4f4f39f -->
| 指标 | 含义 / 公式 |
| --- | --- |
| 速率 | 每秒传的 bit，b/s；k/M/G 通常十进制 |
| 带宽 | 最高可达传输速率，b/s；物理信道频带宽则用 Hz |
| 吞吐量 | 实际单位时间通过的数据量，受路径瓶颈等限制 |
| 发送 / 传输时延 | 分组 bit 数 L / 发送速率 R |
| 传播时延 | 距离 d / 信号传播速度 v |
| 总时延 | 发送+传播+处理+排队 |
| 时延带宽积 | 传播时延×带宽，表示链路容纳的 bit |
| RTT（Round-Trip Time，往返时间） | 往返时间，具体是否含其他开销看题设 |
| 利用率 / 丢包率 | 有效占用时间占比 / 丢失分组占比 |

<!-- unit-id:u-04-1bd3e3210b50 -->
1B=8bit。提高速率只直接缩短发送时延，不使同介质同距离传播更快；不能把 MHz 的频宽和 Mb/s 的带宽直接混用。

<!-- unit-id:s-04-421527e00b01 -->
### 网络协议模型

<!-- unit-id:u-04-56efe0923129 -->
协议规定对等层如何通信，含语法、语义、时序；服务是下层通过接口向上层提供的功能。PDU（协议数据单元）=PCI（协议控制信息）+SDU（服务数据单元），上层 PDU 成为下层 SDU。

<!-- unit-id:u-04-7597677a6b90 -->
OSI（开放系统互连参考模型，Open Systems Interconnection）自上而下：应用、表示（格式 / 压缩 / 加密）、会话（会话管理）、传输（进程到进程、端口）、网络（主机 / 路由、IP）、数据链路（相邻结点、帧 / MAC）、物理（比特）。

<!-- unit-id:u-04-d552f108dd3f -->
TCP/IP 四层：应用、传输、网际、网络接口；教学五层把网络接口拆成数据链路与物理。协议举例：HTTP/DNS/SMTP→应用，TCP（传输控制协议）/UDP（用户数据报协议）→传输，IP（网际协议）/ICMP（网际控制报文协议）→网际。封装只加对应层首部，不把全部层都叫“数据报”。

## 第二章 物理层

<!-- unit-id:s-04-db7e507a44e1 -->
### 物理层接口特性

<!-- unit-id:u-04-cddf10432784 -->
物理层接口四特性：机械（接头形状 / 引脚）、电气（电压 / 速率）、功能（某引脚做什么）、过程（信号出现次序）。提供比特传输，不按 MAC / IP 寻址转发。

<!-- unit-id:u-04-e87ada8eb86e -->
双绞线、同轴电缆、光纤属导向介质，无线属非导向；光纤不受电磁干扰。单工单向、半双工交替双向、全双工同时双向，区别于串 / 并行。

<!-- unit-id:s-04-cc554f4c2103 -->
### 通信指标计算

<!-- unit-id:s-04-57c584df91f8 -->
#### 码元

<!-- unit-id:u-04-417efdc56dcb -->
码元是一个信号状态的基本传输单元；V 种可区分状态，每码元最多携带 log₂V bit。2 状态 1bit、4 状态 2bit、16 状态 4bit。

<!-- unit-id:u-04-d87dcbd08d40 -->
码元与比特不必一一对应，也不能直接用“波形跳了几次”当码元数；编码方式和一个码元持续多久要先明确。

<!-- unit-id:s-04-dc1a2d759146 -->
#### 传输速率

<!-- unit-id:u-04-127e7e0574ce -->
波特率 B 为每秒码元数，单位 Baud；比特率 R=B·log₂V，单位 b/s。给定波特率时直接乘每码元 bit 数，不再自动乘 2。

<!-- unit-id:u-04-48b79ba16ca5 -->
频率上限 f₂、下限 f₁，频带宽 W=f₂−f₁（Hz）；带宽若已给 b/s 就是数据速率上界，不能再把它当 W 代入奈氏。

<!-- unit-id:s-04-66bcb34e257e -->
#### 奈氏准则

<!-- unit-id:u-04-97bfc25e46d9 -->
理想无噪声低通信道：最高码元速率 2W Baud，数据率上界 C=2W log₂V bit/s，W 用 Hz，V 为状态数。

<!-- unit-id:u-04-f85895ad1114 -->
W 固定时增加状态可提高该理想公式的数据率，但噪声限制可区分状态；同时给奈氏与香农条件时分别计算、取较小上界。

<!-- unit-id:s-04-414c7fcc9a1f -->
#### 香农定理

<!-- unit-id:u-04-dddf546f1176 -->
有噪声信道容量 C=W log₂(1+S/N)，W 用 Hz，S/N 用功率比例。给 dB 时先还原 S/N=10^(dB/10)，如 30dB→1000。

<!-- unit-id:u-04-63f31d0cf38a -->
不能把 30 直接代入 1+S/N；香农给理论上界，不表示实际协议一定达到该速率。

<!-- unit-id:s-04-3f88a2cd5201 -->
### 编码与调制

<!-- unit-id:s-04-a868e8aa8bc3 -->
#### 编码

<!-- unit-id:u-04-4b227777d4dd -->
| 编码 | 每 bit 怎么形成波形 | 识别重点 |
| --- | --- | --- |
| NRZ（不归零编码） | 整个 bit 期间保持相应电平 | 连续相同位无跳变，自同步较难 |
| RZ（归零编码） | bit 内先给数据电平，再回零 | 有回零时序，需较高符号速率 |
| NRZI（反向不归零编码） | 本稿约定边界跳变为 0、不跳为 1 | 初始电平需题设，跳变方向无关 |
| 曼彻斯特 | 每位中间必跳，方向表示 0 / 1 | 经典约定向下 1、向上 0，题设可反；每 bit 两个半位电平 |
| 差分曼彻斯特 | 中间必跳同步，起始边界跳变为 0、不跳为 1 | 看边界，不看中间跳变方向判断数据 |

<!-- unit-id:u-04-d6a14a8f99bf -->
经典 10Mb/s 以太网采用曼彻斯特；不能推为所有高速以太网都相同。4B/5B 用 5 个编码 bit 表示 4 个数据 bit，效率 80%；线路速率与有效数据速率区分。

#### 调制

<!-- unit-id:u-04-ef2d127de37b -->
ASK（幅移键控）改振幅，FSK（频移键控）改频率，PSK（相移键控）改相位；QAM（正交幅度调制）联合振幅与相位形成状态。V 状态每码元 log₂V bit：16-QAM 为 4bit，64-QAM 为 6bit。

<!-- unit-id:u-04-452ed72ace5d -->
调制把基带数据映射到载波，不等于数据链路层封装。基带直接传基带信号，频带传输先调制；选择介质、状态与速率要结合频宽 / 噪声条件。

<!-- unit-id:s-04-d68e580ec58b -->
### 物理层设备

<!-- unit-id:s-04-ce2e0877e677 -->
#### 中继器

<!-- unit-id:u-04-d91ab2d19af1 -->
中继器对数字信号再生整形，延长物理传输范围；放大器只放大模拟信号，也可能放大噪声。中继器不识别帧、不学习 MAC、不隔离冲突域或广播域。

<!-- unit-id:s-04-d6837580079a -->
#### 集线器

<!-- unit-id:u-04-3d17c3a21878 -->
集线器是多端口中继器，收到信号复制到其他端口，物理星形、逻辑共享总线。全部端口共享带宽、同一冲突域 / 广播域，经典情形半双工使用 CSMA/CD。

<!-- unit-id:u-04-c4e82828113a -->
交换机按 MAC 决定出口，集线器不按地址选择，也不能把每端口速率相加当作各主机独占吞吐。

<!-- unit-id:s-04-1c232baa7769 -->
## 第三章 数据链路层

<!-- unit-id:s-04-3a49414625e6 -->
### 封装成帧

<!-- unit-id:u-04-81d294649eda -->
封装成帧给比特流标出边界，透明传输使任意数据不会被误认成边界。

<!-- unit-id:u-04-3cbcbcab625e -->
字符计数用长度判界，计数字段错会失步；字节填充在控制字符前加转义 ESC；零比特填充在数据中每连续 5 个 1 后加 0，接收方删除，旗标 01111110 不参与填充；违规编码用合法数据不使用的信号模式标界。

<!-- unit-id:u-04-237826c6b005 -->
PPP（点对点协议）用 LCP（链路控制协议）建立 / 配置链路，NCP（网络控制协议）配置网络层协议，FCS（帧检验序列）检错；典型不靠帧序号 / ACK 保证可靠交付。点到点链路不需多站竞争的 CSMA/CD。

### 差错控制

<!-- unit-id:u-04-concise-20 -->
检错通过冗余发现部分位错误，纠错用冗余定位并修正；可靠传输还需处理丢失、重复、失序等。ARQ（自动重传请求）=检错+重传，FEC（前向纠错）。

<!-- unit-id:u-04-27d6cb8f8f35 -->
最小码距 d：最多检测 d−1 位错误，最多纠正 ⌊(d−1)/2⌋ 位。检错通过不等于绝对无差错，不能把 CRC 无余数当作必然原数据完全正确。

<!-- unit-id:s-04-d4c688a518fa -->
#### 奇偶校验码

<!-- unit-id:u-04-7902699be42c -->
给数据加一个校验位，使总 1 数为奇 / 偶。能发现奇数个位翻转，偶数个位翻转可能漏检；不能定位错误，普通奇偶校验不能纠错。

#### 循环冗余校验码 CRC

<!-- unit-id:u-04-2c624232cdd2 -->
生成多项式 G(x) 阶数 r，对应 r+1 位。发送：数据后补 r 个 0→模 2 除法（异或、不借位）→取 r 位余数 FCS→替换补零作为尾部。

<!-- unit-id:u-04-d72d2355bb63 -->
接收对整个码字除以同一生成串，余数非 0 则检出错，余数 0 仅说明未检出。位串前导余数 0 要补齐 r 位。常规帧 CRC 主要用于检错，不因“冗余多”就称有自动纠错。

<!-- unit-id:s-04-30e7635b455d -->
#### 海明校验码

<!-- unit-id:u-04-ced9d33af31c -->
n 个数据位、k 个海明校验位，单错纠正需 2^k≥n+k+1。校验位放 1、2、4、8…位置，各位的二进制编号决定参与哪些校验组。

<!-- unit-id:u-04-7ec5236aaaa6 -->
接收重新校验组成 syndrome：0 未检出，非 0 在单错假设下给出错位，可翻转修正。普通单错海明码不能同时可靠区分全部双错；增加总奇偶位可形成 SECDED（单错纠正、双错检测）。

<!-- unit-id:s-04-f1e636dd15f9 -->
### 流量控制和可靠传输

<!-- unit-id:s-04-71e6710a0f2d -->
#### 停止等待协议 SW

<!-- unit-id:u-04-0cc7c2e6da52 -->
停等发送窗口 / 接收窗口均为 1：发一帧→保存副本并启动计时→正确 ACK（确认，Acknowledgment）后发下一帧→超时重发。用交替序号区分“新帧”与“确认丢失引发的重复帧”。

<!-- unit-id:u-04-30a579e1c76e -->
接收重复正确帧不重复交付，但重新 ACK；数据 / ACK 丢失或损坏可致超时。ACK 编号表示已收帧还是期望帧依协议 / 题设。

<!-- unit-id:s-04-43b04ff3121c -->
#### 后退N帧协议 GBN

<!-- unit-id:u-04-a70305d58ae4 -->
GBN（Go-Back-N，后退 N 帧协议）发送窗口 Wt>1、接收 Wr=1。可连续发多个帧，接收只收按序下一个，失序丢弃并重复确认最后按序帧；ACK 累计确认。

<!-- unit-id:u-04-265dcdfc226c -->
最早未确认帧超时后，重传它和其后已发送未确认帧。n 位序号要求 Wt≤2^n−1；n=3 最多 7。序号循环时窗口过大会把旧帧误认新帧。

<!-- unit-id:s-04-28abb34768bc -->
#### 选择重传协议 SR

<!-- unit-id:u-04-94963f73d03d -->
SR（Selective Repeat，选择重传协议）发送和接收窗口都可>1，窗口内正确失序帧缓存、逐帧 ACK；超时通常只重传该帧。补齐窗口下沿后按序交付并滑窗，后面已 ACK 不代表下沿可跨缺帧前移。

<!-- unit-id:u-04-e630c78f0968 -->
n 位序号、典型滑窗模型：Wt+Wr≤2^n；两窗相等时≤2^(n−1)。Wr 已给时 Wt≤2^n−Wr，不一律套半空间。缓存开销比 GBN 大，但错误时少重传正确帧。

<!-- unit-id:s-04-1e52974d53c0 -->
### 信道利用率

<!-- unit-id:u-04-a47eb6fff6c0 -->
数据发送 TD=L/R，确认发送 TA，RTT 仅指往返传播时，停等 U=TD/(TD+RTT+TA)。无差错连续可发 W 帧，滑窗 U=min(1,W·TD/(TD+RTT+TA))。

<!-- unit-id:u-04-42a3bd01e810 -->
题目 RTT 若已含发送 / 处理开销不能重复加。平均有效速率≈U×R；若帧含首部，求有效数据率还要乘数据字段占比。要 100% 利用率，W·TD 至少覆盖该等待周期。

### 介质访问控制

<!-- unit-id:s-04-96105a5954e8 -->
#### 信道划分

<!-- unit-id:u-04-64941db9cc0a -->
FDM（频分复用）把频带分开，TDM（时分复用）把时间分隙，WDM（波分复用）在光纤分不同波长，CDM（码分复用）用正交码片区分发送者。固定 TDM 每站固定时隙，统计 TDM 按需求分配。

<!-- unit-id:u-04-972c11ab0e28 -->
CDM：发 1 用本站码片 S，发 0 用 −S，不发用 0；各站叠加成 R，接收用归一化内积 (R·S)/m 判别：+1 为 1、−1 为 0、0 未发（理想正交同步模型）。如 S=(1,1,1,1)、R=(2,0,2,0)，结果 1。

<!-- unit-id:u-04-ba8e4309719a -->
纯 ALOHA 随时发，碰撞随机等再发；时隙 ALOHA 只在时隙起点发，缩小冲突窗口。CSMA（载波监听多路访问）先监听：1-坚持空闲即发，非坚持忙则随机后再听，p-坚持空闲时以 p 发、以 1−p 等下一隙。

<!-- unit-id:s-04-6bb533104c46 -->
#### 随机访问 CSMA/CD

<!-- unit-id:u-04-83c627b583ef -->
CSMA/CD（带碰撞检测的载波监听多路访问）用于经典共享介质半双工以太网：先听后发、边发边检测；碰撞停止有效发送、发干扰信号，再随机退避重传。交换式全双工不使用碰撞检测退避。

<!-- unit-id:u-04-3d61c5ce8485 -->
最大单程传播 τ，争用期 2τ，最小帧 bit 数≥2τR，以保证碰撞能在发完前返回。10Mb/s、51.2μs 对应 512bit=64B；64B 是 MAC 帧，不是数据字段。

<!-- unit-id:u-04-ccb1284bf880 -->
第 j 次重传 k=min(j,10)，随机整数 r∈[0,2^k−1]，等待 r·2τ，超规定次数放弃。最小帧间间隔 96bit 时间，10Mb/s 为 9.6μs；速率变时不能固定套该微秒数。

<!-- unit-id:s-04-e8f59f58d6ca -->
#### 随机访问 CSMA/CA

<!-- unit-id:u-04-486428f682ba -->
CSMA/CA（带碰撞避免的载波监听多路访问）用监听、随机退避、可选预约与 ACK 降低碰撞，不承诺绝无碰撞。无线发送时难以像有线那样同时可靠检出冲突。

<!-- unit-id:u-04-99414a2d6bbb -->
DCF（分布式协调功能）：空闲 DIFS（分布式协调帧间间隔）后按规则退避，空闲减计数、忙则冻结，恢复空闲再等 DIFS 继续；到 0 发送并等待 ACK，超时重传。SIFS（短帧间间隔）<PIFS（点协调帧间间隔）<DIFS，CTS / ACK 等短响应优先。

<!-- unit-id:u-04-d6e30868b456 -->
RTS（请求发送）/CTS（允许发送）过程：DIFS→RTS→SIFS→CTS→SIFS→DATA→SIFS→ACK，可缓解隐蔽站。其他站依据 Duration 更新 NAV（网络分配向量），属于虚拟载波监听。

<!-- unit-id:u-04-07e5f8b65564 -->
忽略传播：RTS Duration=3SIFS+TCTS+TDATA+TACK；CTS=2SIFS+TDATA+TACK；DATA=SIFS+TACK。Duration 是剩余预约时间，不是该帧自身长度。

### 局域网

#### 802.3 以太网

<!-- unit-id:u-04-b17ef6d19c7a -->

### 以太网交换机

<!-- unit-id:s-04-920e03c58648 -->
#### 独占带宽特点

<!-- unit-id:u-04-0d55daa8f0f4 -->
交换机端口分别隔离冲突域，点到点全双工链路各方向独立传输，可同时多个端口对交换；集线器各站共享带宽。

<!-- unit-id:u-04-e1d721991295 -->
单端口标称 R 不因全双工变成“单方向 2R”，双向合计可为 2R。算交换容量先确定按所有端口入+出合计还是只计单方向，以及是否双计同一转发流。

<!-- unit-id:s-04-bf1ca32cec16 -->
#### 自学习功能

<!-- unit-id:u-04-d2db98a5003a -->
交换机收到帧先用**源 MAC+入口**学习 / 更新表项，再查目的：已知且出口不同则转发；目的在入口同一段则过滤；未知单播 / 广播在同 VLAN 其他允许口泛洪。

<!-- unit-id:u-04-452117da2129 -->
表项老化删除陈旧映射；学习用源不是目的。交换表不是 IP 路由表，二层交换默认不隔离广播域，VLAN 可隔离。

<!-- unit-id:s-04-9520056bb862 -->
#### 两种交换方式

<!-- unit-id:u-04-9d6a9f584e01 -->
存储转发先收完整帧、检验 FCS 后转发，延迟较大但能过滤误码、适应不同速率。直通读到足够目的地址信息即开始转发，延迟小但不能事先完成整帧 CRC 检查。

<!-- unit-id:u-04-a1bce2b33ab4 -->
“直通只需等 6B”要看从哪位置开始计：若从整帧上线路开始，还需按题设计前导 / 定界符等。不能仅凭两名字断言所有流量下某方式必更快。

<!-- unit-id:s-04-08e8f29fe409 -->
## 第四章 网络层

<!-- unit-id:s-04-7a403212e923 -->
### 网络层功能

<!-- unit-id:u-04-f8d35a5fd121 -->
网络层负责路由选择（计算可用路径、控制平面）和分组转发（按转发表逐包处理、数据平面），将不同链路互连。端到端应用可靠性不由普通 IP 保证。

<!-- unit-id:u-04-059ffb5acc5d -->
拥塞是网络承载不足，流量控制是接收方处理不足；开环拥塞控制预先限制，闭环依据反馈调整。TCP 可据丢包 / RTT 等作反馈，不能把丢包都认作接收窗口太小。

<!-- unit-id:s-04-70b5e7cf7a49 -->
#### 虚电路和数据报

<!-- unit-id:u-04-2299ef965c38 -->
数据报不先建立网络连接，每包带目的地址、独立选路，可能乱序 / 丢失。虚电路先建立逻辑路径，后续包用虚电路号沿既定路径转发，结点保存连接状态，通常按序。

<!-- unit-id:u-04-54ea437c10f5 -->
虚电路不等于物理专用电路，不独占整条线路；“有连接”不自动保证无差错，可靠性取决于协议。路径故障可能需重建虚电路，数据报可重新选路。

<!-- unit-id:s-04-a8f64ec981ca -->
#### 软件定义网络SDN

<!-- unit-id:u-04-b6ff751b9c27 -->
SDN（Software-Defined Networking，软件定义网络）将控制逻辑与转发分离：控制器计算策略，下发“匹配字段→动作”流表，交换设备按流表转发。北向接口对应用，南向接口对设备，控制器之间可有东西向接口。

<!-- unit-id:u-04-9fe30830f430 -->
逻辑集中控制不表示只能一台物理控制器。流表可匹配 IP、MAC、端口等，不只按目的 IP；控制器缺失时已有流表行为依设计。

<!-- unit-id:s-04-59a21bd617d7 -->
### IPv4

<!-- unit-id:u-04-f5ca38f748a1 -->
IPv4 地址 32bit；基本首部 20B，可扩到 60B，首部长度 IHL（Internet Header Length）单位 4B；总长度单位 1B，包含首部与数据。

<!-- unit-id:u-04-441a8821684f -->
| 字段 | 常考用途 |
| --- | --- |
| 版本 | IPv4 为 4，区别于协议字段 |
| 标识、DF、MF、片偏移 | 标识重组对象；DF（不分片）=1 禁止分片；MF（更多分片）=1 后面还有；偏移单位 8B |
| TTL（Time To Live，生存时间） | 转发递减到 0 丢弃，限制环路寿命 |
| 协议 | 上层：ICMP 1、TCP 6、UDP 17、OSPF 89 等 |
| 首部检验和 | 只检首部，TTL 改变后需重新计算 |
| 源 / 目的 IP | 跨普通路由转发通常不变，NAT 例外 |

<!-- unit-id:u-04-9fbc08511a83 -->
IP 总长最大 65535B；MTU（Maximum Transmission Unit，最大传输单元）通常限制某链路承载的整个 IP 包，不是仅限制其数据字段。

### IP分片

<!-- unit-id:u-04-ad8fbec74554 -->
分片对**原 IP 数据部分**切分，每片另有首部；除最后片外，片数据长度为 8 的倍数。最大片数据=8⌊(MTU−首部长度)/8⌋，片偏移=该片数据在原数据中的起点/8。

<!-- unit-id:u-04-9590c7ab7e02 -->

#### 早期分类

#### 变长子网划分 CIDR

<!-- unit-id:u-04-89b31068a9bd -->

#### 网络地址转换 NAT

<!-- unit-id:u-04-ca88e5c8dac7 -->

### IP地址解析 ARP

<!-- unit-id:u-04-0d68fbd41923 -->
ARP（Address Resolution Protocol，地址解析协议）在本地链路解析下一跳 IP→MAC。缓存无对应项时广播“谁有目标 IP”，目的 MAC FF-FF-FF-FF-FF-FF；目标通常单播回答，双方缓存对应关系。

<!-- unit-id:u-04-74fe6d117830 -->
同网直接解析目的主机；跨网先解析路由器下一跳接口，不跨路由器广播查询远端 MAC。IP 目的通常仍为远端主机，帧目的是当前下一跳，别把两地址互换。

<!-- unit-id:s-04-d3163bcf6ada -->
### IP地址分配 DHCP

<!-- unit-id:u-04-7f076f3c9b93 -->
DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）为应用层，IPv4 常 UDP 服务器 67、客户端 68，给 IP、掩码、默认网关、DNS 等配置。

<!-- unit-id:u-04-9809a55c70cd -->
初次分配：Discover 发现→Offer 提供→Request 选定并请求→ACK 确认。无 IP 客户常以 0.0.0.0 为源、255.255.255.255 为目的广播；服务器回复可依广播标志 / 客户状态单播或广播，不能一律断言网络广播但 MAC 必单播。

<!-- unit-id:u-04-3d7546995166 -->
地址有租期，客户续租、服务器确认 / 拒绝，客户端可主动 Release；检测地址占用可 Decline 再申请。服务器跨网可用 DHCP 中继，路由器不直接泛洪所有广播。IPv6 可用 SLAAC（无状态地址自动配置） / DHCPv6，不能说 DHCP 全部只适用 IPv4。

### IP报文控制 ICMP

<!-- unit-id:u-04-aab21e8e0f66 -->
ICMP 用 IP 封装，报告转发差错或进行网络询问。常见差错：目的不可达、时间超过、参数问题、重定向；Echo 请求 / 回答用于 Ping。源抑制是历史类型，已废弃。

<!-- unit-id:u-04-059cb1719753 -->
TTL 耗尽触发时间超过，Traceroute 逐次增加 TTL 发现路径；最终响应依探测用 UDP / ICMP 等而不同。ICMP 差错通常不再针对另一 ICMP 差错、广播 / 组播或非首片等生成，避免放大反馈；具体例外按协议题设。

<!-- unit-id:s-04-9c598b9daeb5 -->
### IPv6

<!-- unit-id:u-04-a6f83dbd900a -->
IPv6 地址 128bit，基本首部固定 40B，无基本首部检验和，扩展首部在有效载荷中。无广播，有单播、组播、任播；任播交给组内一个适合的接收者。

<!-- unit-id:u-04-0c5597ec3be5 -->
路由器不做 IPv6 分片，源端可用分片扩展首部。Hop Limit 类似 TTL，ICMPv6 邻居发现替代 ARP，不能从所有 IPv6 地址直接推出 MAC。

<!-- unit-id:u-04-55605ca0acea -->
十六进制冒号记法，每组可省前导 0，连续全 0 组可用 ::，同址只能一次。支持 SLAAC，也可 DHCPv6；双栈 / 隧道帮助 IPv4 过渡。接口标识符不必由硬件 MAC 构造。

### 路由算法和路由协议

<!-- unit-id:u-04-22b3059efe4d -->
静态路由手工设定，简单稳定但不自动适应变化；动态路由交换信息并调整。AS（Autonomous System，自治系统）是受统一管理 / 路由策略的自治系统；内部协议 IGP（Interior Gateway Protocol，内部网关协议）如 RIP、OSPF，外部 BGP 体现跨 AS 策略。

<!-- unit-id:u-04-3ee4ca7df789 -->
**距离向量**向邻居交换“到各目的的距离”；**链路状态**传播本地链路信息、建立区域拓扑再算最短路；**路径向量**传播所经 AS 路径等。

<!-- unit-id:u-04-63161b74db1f -->
**IP 组播**：IPv4 D 类地址作组目的，不作普通源地址；IGMP（Internet Group Management Protocol，网际组管理协议）管理主机与本地组播路由器的成员关系，跨网还需组播路由。IPv4 组播地址低 23 位映射到 01-00-5E 开头 MAC，多个 IP 可映到同一 MAC，网络层仍需过滤。

<!-- unit-id:u-04-2c0da5c9b2e8 -->
**移动 IPv4 典型过程**：移动主机保留归属地址→在外地取得转交地址并登记→归属代理把发往归属地址的包封装进隧道转交→外地端解封装交给主机；回归后注销。原包目的仍是归属地址，外层隧道目的才是转交地址，不等于普通 Wi-Fi 换 AP。

<!-- unit-id:s-04-3e603502ddd6 -->
#### 路由信息协议 RIP

<!-- unit-id:u-04-bcf4483210b8 -->
RIP 用跳数作为度量，最多 15 跳、16 不可达，基于距离向量，通常 UDP 520。向邻居周期性交换路由，变化可触发更新，坏消息传播慢、可能计数到无穷。

<!-- unit-id:u-04-18d49f5ecc6a -->
收到邻居条目先距离+1：新目的加入；原下一跳就是该邻居时采用新信息（即使变差）；不同下一跳只有更优时替换，等价路径按实现可多条。水平分割、毒性逆转等缓解环路。

<!-- unit-id:u-04-b749ca9e09da -->
RIPv1 不传掩码，不能支持 VLSM/CIDR，但不能说“所有子网划分都不支持”；RIPv2 传掩码、支持无分类路由。

#### 开放最短路径优先协议 OSPF

<!-- unit-id:u-04-12e113b4ae39 -->
OSPF 为链路状态 IGP，直接封装 IP、协议号 89。Hello 发现邻居，交换数据库摘要 / 请求 / 更新 / 确认，让同一区域形成链路状态数据库，再用 Dijkstra 求总代价最小路径。

### 路由器

<!-- unit-id:s-04-0448ea52e776 -->
#### 冲突域和广播域

<!-- unit-id:u-04-c8f7de2b2a76 -->
集线器所有口同一冲突 / 广播域；普通二层交换机每口隔离冲突域、默认不隔离广播域；路由器按三层网络隔离广播域；VLAN 可在二层划多个广播域。

<!-- unit-id:u-04-5ec54bf17aca -->

<!-- unit-id:s-04-84f36ccbe52d -->
#### 路由器的功能

<!-- unit-id:u-04-090796a0bf0f -->
路由器包括控制 / 路由选择与数据转发部分。输入收帧、检链路、取 IP→检查 IP / TTL→最长前缀匹配确定下一跳和出口→队列 / 交换结构→以出口链路重新封帧。

<!-- unit-id:u-04-61a0ac62c1d3 -->
每跳 MAC 首部可变，普通转发源 / 目的 IP 不变，TTL 递减、IPv4 首部校验更新；NAT 等特殊功能例外。路由表 / 转发表不是 ARP 表，选出下一跳 IP 后还可能需要解析其 MAC。

## 第五章 传输层

<!-- unit-id:s-04-f3112ce9e404 -->
### UDP数据报

<!-- unit-id:u-04-e29c9c180c62 -->
UDP（User Datagram Protocol，用户数据报协议）无连接、面向报文，保留应用交付的报文边界，首部固定 8B；不提供协议内置可靠重传 / 流量 / 拥塞控制，开销小，应用可自己实现。

<!-- unit-id:u-04-fa518eec8f27 -->
首部源端口、目的端口、长度、检验和各 2B；长度含首部与数据。端口 16bit，TCP 和 UDP 的端口空间分别独立；熟知 0～1023、注册 1024～49151、动态 / 私有 49152～65535。

<!-- unit-id:u-04-fda18561caa9 -->
复用把多应用数据向下送，分用按目的端口交给对应接收端；找不到 UDP 端口可能返回 ICMP 端口不可达。UDP 可支持单播、组播、广播，TCP 连接通常一对一。

### UDP检验

<!-- unit-id:u-04-c6f3ac57944a -->
UDP 检验和覆盖伪首部+UDP 首部+数据。IPv4 伪首部 12B：源 IP、目的 IP、0、协议 17、UDP 长度，只用于计算，不随 UDP 单独发送。

<!-- unit-id:u-04-e9f4b47c9460 -->
发送先把校验字段置 0，奇数字节末尾临时补 0→按 16bit 反码求和（溢出回卷加到低位）→取反放字段。接收含校验字段一起求和，全 1 表示未检出错。

<!-- unit-id:u-04-8094d95d84f5 -->
补零不计 UDP 长度。IPv4 校验字段 0 可表示未使用；计算结果恰 0 时应以全 1 发送；IPv6 通常要求 UDP 校验，例外看协议。IPv4 首部检验和只检 IP 首部，与 UDP 范围不同。

### TCP报文段

<!-- unit-id:u-04-86e501496586 -->
TCP（Transmission Control Protocol，传输控制协议）面向连接、可靠、全双工、字节流，不保留应用报文边界。两端套接字（IP+端口）确定连接；每个字节编号，报文段序号是该段第一个数据字节号。

<!-- unit-id:u-04-8fa793d8ebba -->
**ack=N 表示 N 之前的字节已按序收到，下一期待 N**；ACK（确认）控制位=1 表示该确认号有效，不能与 ack 数值混用。窗口字段通告本端还能接收的数量，不是直接写发送方 cwnd。

<!-- unit-id:u-04-92ea8033228c -->
基本首部 20B，含选项可到 60B，数据偏移单位 4B；MSS（Maximum Segment Size，最大报文段长度）仅指最大 TCP 数据字段，不含 TCP/IP 首部。SYN（同步标志）用于建连同步、FIN（终止标志）关闭发送方向、RST（复位标志）重置连接、PSH（推送标志）请求及时交付、URG（紧急标志）配合紧急指针；检验和覆盖伪首部+整段。

### TCP连接管理

<!-- unit-id:s-04-8bc0d5eef13c -->
#### 三次握手

<!-- unit-id:u-04-f70d27a49dc6 -->
| 次序 | 客户→服务器 / 返回 | 状态与序号 |
| --- | --- | --- |
| 1 | SYN=1，seq=x | 客户 SYN-SENT；服务器先 LISTEN |
| 2 | SYN=1，ACK=1，seq=y，ack=x+1 | 服务器 SYN-RCVD |
| 3 | ACK=1，seq=x+1，ack=y+1 | 客户先 ESTABLISHED，服务器收到后 ESTABLISHED |

<!-- unit-id:u-04-9287f701bdfc -->
SYN 占一个序号；教材建连前两段不带数据，第三段可带，纯 ACK 不额外占序号。作用是确认双方发送 / 接收能力并同步初始序号，防旧请求被误当新连接。

<!-- unit-id:u-04-ca27224231ba -->
忽略发送时延、两向各 RTT/2 时，客户约 1RTT 后可发数据，服务器约 1.5RTT 后完成建立；计算起点必须明确。

<!-- unit-id:s-04-7a7c58176dc3 -->
#### 四次挥手

<!-- unit-id:u-04-e60f9b12f5a4 -->
典型客户主动关闭，x / y 为当时两端下一个发送序号，服务器等待期间可能继续发数据使 y→z。

<!-- unit-id:u-04-cb98c6176d7c -->
| 次序 | 报文 | 发送 / 接收状态 |
| --- | --- | --- |
| 1 客户→服务器 | FIN=1，seq=x | 客户 FIN-WAIT-1，服务器收后 CLOSE-WAIT |
| 2 服务器→客户 | ACK=1，seq=y，ack=x+1 | 客户收后 FIN-WAIT-2 |
| 3 服务器→客户 | FIN=1，ACK=1，seq=z，ack=x+1 | 服务器 LAST-ACK，客户收后 TIME-WAIT |
| 4 客户→服务器 | ACK=1，seq=x+1，ack=z+1 | 服务器收后 CLOSED；客户等 2MSL（两倍最大报文段生存时间）后 CLOSED |

<!-- unit-id:u-04-22bbb4b65613 -->
FIN 占序号，纯 ACK 不占。一次 FIN 只关闭一方发送，另一方还可发，因此确认与自身 FIN 可分开；也可合并，不能说所有关闭必有四个独立报文。

<!-- unit-id:u-04-7347f4cdb456 -->
TIME-WAIT（时间等待）保留以便重答可能重传的 FIN，并使旧段消失。双方立即响应、无剩余数据和重传时，自首 FIN 起客户约 RTT+2MSL，服务器约 1.5RTT；不是任意情况下的最长时间。

### TCP可靠传输

<!-- unit-id:u-04-d90c153e328f -->
TCP 用字节序号、累计确认、检验和、重传与接收缓存实现可靠字节流。收到失序可缓存，但 ack 仍指最早缺字节；重复数据不能重复交应用。

<!-- unit-id:u-04-deceb59164c0 -->
超时重传由 RTO（重传超时时间）触发；收到三个重复 ACK 可快重传最早未确认段，不等超时。三个“重复”通常另有一个首次 ACK，不把总共三个同号 ACK 误认成三次重复。

<!-- unit-id:u-04-695057d7c5af -->
RTT 估计平滑更新：SRTT（平滑往返时间）=(1−α)旧SRTT+α样本，RTO 还考虑 RTT 变化；重传段样本可能归属不明，通常不直接用来更新。SACK（选择确认）可告知已收到的不连续区间以少重传，但不改变基本累计 ack 含义。

<!-- unit-id:u-04-31b0cc3cf35b -->
重传计时器、零窗口持续计时器、TIME-WAIT、可选保活作用不同，不能互相替代。

### TCP流量控制

<!-- unit-id:u-04-077e28fba4a5 -->
接收方通告 rwnd（接收窗口）限制未确认数据，防缓存被淹没；发送同时受 cwnd（拥塞窗口）限制，可在途上限=min(rwnd,cwnd)，还能新发的量需减去已在途未确认数据。

<!-- unit-id:u-04-98205ea9a290 -->
rwnd=0 时停止普通新数据，启动持续计时 / 窗口探测，防窗口恢复通知丢失导致双方一直等。零窗口不是“网络已经拥塞”，正常 ACK 等控制通信仍需处理。

<!-- unit-id:u-04-e680f523aec8 -->
序号、ACK、窗口字节数画在同一字节轴上，窗口滑动由确认推进，不能把发送了数据就当作已经滑过。

<!-- unit-id:s-04-e86d6af8fb2a -->
### TCP拥塞控制

<!-- unit-id:s-04-16d66afdcd8d -->
#### 慢开始和拥塞避免

<!-- unit-id:u-04-0b918943df09 -->
慢开始和拥塞避免根据 cwnd 与门限 ssthresh（慢开始门限）控制网络注入量，MSS 是数据字节单位，不自动等于 1KB。

<!-- unit-id:u-04-43f8260890ad -->
**教材模型**：初始 cwnd=1MSS；慢开始每个确认新数据的 ACK 增 1MSS，连续满窗口且逐段确认时每 RTT 约翻倍；到门限改为拥塞避免，每 RTT 约+1MSS。重复 ACK 不是“新数据确认”。

<!-- unit-id:u-04-301f0a792630 -->
超时后 cwnd 回 1MSS、门限通常按原窗口一半算，再慢开始。画曲线先查题设是按 RTT 还是逐 ACK、是否跨门限取整、接收窗口是否更小，不能把“每收到一 ACK 翻倍”写成规则。

<!-- unit-id:u-04-bfc11a8e7e66 -->
标准细节门限依据在途 FlightSize 而不总是 cwnd，通常上界 max(FlightSize/2,2MSS)；实际初始窗口等依算法 / 实现。考题用明确教材模型时按题设计算。

<!-- unit-id:u-04-d59eced1ded0 -->

### 网络应用模型 CS P2P

<!-- unit-id:u-04-1ddd7adceb3a -->
C/S（Client / Server，客户—服务器模型）：持续提供服务的服务器，客户发请求；服务集中便于管理，但可能成为瓶颈 / 单点。P2P（Peer-to-Peer，对等模型）：节点既请求又提供资源，负载可分散，但节点动态、管理与信任复杂。

### 域名系统 DNS

<!-- unit-id:u-04-bacb71ab3838 -->
DNS 把域名映射为地址等记录，应用层，常用端口 53，UDP 和 TCP 都可使用。域名层次自右向左：根、顶级、下级；权威服务器给其管理区记录，递归解析器为客户代查并缓存。

<!-- unit-id:u-04-5d6de7cd9f7f -->
A（地址记录）对应 IPv4，AAAA（IPv6 地址记录）对应 IPv6，CNAME（规范名称记录）为别名，MX（邮件交换记录）指定邮件服务器。域名与 IP 不一一对应；可多个域名同 IP，一个域名多 IP；没有域名的主机也可用 IP 访问。

<!-- unit-id:u-04-a3a004a6187f -->
缓存受 TTL 限制，根服务器通常给下级权威指引，不保存所有主机最终 IP。

<!-- unit-id:s-04-0ccb698db0f9 -->
#### 递归查询和迭代查询

<!-- unit-id:u-04-73475cb40a56 -->
递归：被询问者继续代查并给最终结果，客户通常向本地解析器这样请求。迭代：服务器给答案或下级服务器地址，请求者再去问下一站；本地解析器常依次问根、顶级、权威。

<!-- unit-id:u-04-8737a8576c53 -->
查询次数先确定“谁发的、是否有缓存、是否逐层委派”。本地命中时外部查询 0 次，但主机向本地仍有 1 次；www.a.b.c.d.com 不必每一标签都另设权威，不能只数点固定次数。

<!-- unit-id:u-04-1b5df77f02cf -->
时间按实际串行查询 RTT 相加，缓存命中可省；常用 UDP 查询不另加 TCP 建连 RTT，截断后回退 TCP 等需题设说明。

<!-- unit-id:s-04-1bf87d6fa026 -->
### 文件传输协议 FTP

<!-- unit-id:u-04-6f6402b20b01 -->
FTP 用 TCP，控制与数据两条独立连接。控制连接连服务器 21，用命令 / 回复管理会话；数据连接传目录或文件，可多次建立。

<!-- unit-id:u-04-c14c4e1c45e9 -->
控制信息在独立连接属于带外控制；不等于文件数据一定也是 ASCII，FTP 有文本与二进制传输模式。TFTP（Trivial File Transfer Protocol，简单文件传输协议）是简化文件传输，使用 UDP / 69，与 FTP 不同。

<!-- unit-id:s-04-def3ce8a69b0 -->
#### 工作模式

<!-- unit-id:u-04-6d0bfbac74ee -->
主动 PORT：客户经控制连接告诉接收端口，服务器通常从 20 主动连客户临时端口。被动 PASV：服务器告诉临时数据端口，客户主动连服务器该端口。

<!-- unit-id:u-04-7d8ca7e666b2 -->
两模式控制端口都 21；被动数据端口不固定 20，更便于客户在 NAT / 防火墙后发起连接，但“被动”不自带加密或更强数据安全。

### 电子邮件 SMTP POP3

<!-- unit-id:s-04-5845687e1ed5 -->
#### 邮件发送和读取协议

<!-- unit-id:u-04-71ee45a3c0db -->
发送方用户代理→发件服务器→收件服务器通常用 SMTP（简单邮件传送协议）；接收方用 POP3（邮局协议第 3 版） / IMAP（因特网报文存取协议）从邮箱读取。传统 SMTP TCP/25，POP3 TCP/110，IMAP TCP/143，安全提交 / 加密另有端口与机制。

<!-- unit-id:u-04-9bcafb0c2ee9 -->
POP3 偏下载，可配置删除或保留；IMAP 管理服务器邮箱、可取部分内容和同步状态。浏览器使用网页邮箱时浏览器—网站用 HTTP(S)，邮件服务器间仍可 SMTP。

<!-- unit-id:u-04-cd866b967c32 -->
SMTP 的客户 / 服务器角色随连接而定，发件邮件服务器也会作为下一段的 SMTP 客户。

#### 多用途因特网邮件扩展 MIME

<!-- unit-id:u-04-a4c22b7bf7dd -->
MIME（Multipurpose Internet Mail Extensions，多用途因特网邮件扩展）扩展邮件内容类型、编码和多部分结构，让非 ASCII 文本及二进制附件可通过邮件传输；它是内容格式约定，不是另一条独立运输协议。

<!-- unit-id:u-04-aac742cc6c77 -->
Base64 等编码增加数据量，不是加密；不能因邮件被 MIME 编码就说密码或内容受到保密保护。

<!-- unit-id:s-04-f711ced31347 -->
### 万维网 WWW

<!-- unit-id:u-04-concise-85 -->
WWW（World Wide Web，万维网）用 URL（Uniform Resource Locator，统一资源定位符）标识资源，超文本链接组织资源，由浏览器请求服务器。URL 常含方案、主机、端口、路径、查询等，HTTP（Hypertext Transfer Protocol，超文本传输协议）为应用层请求 / 响应协议。

<!-- unit-id:u-04-582f37bbea83 -->
浏览器先取得基本 HTML（超文本标记语言文档）才能发现其中引用对象，计算并行下载时间也要计这一依赖，不能一开始就已知道全部图片地址。

<!-- unit-id:s-04-0c13b55a39c6 -->
#### HTTP协议特点

<!-- unit-id:u-04-87f0da236299 -->
HTTP 以请求 / 响应交换资源，语义上无状态；Cookie / 会话等可维持应用状态。教材“HTTP 无连接”不是底层没有 TCP，HTTP/1.x 通常建可靠运输连接。

<!-- unit-id:u-04-00f018e5dd77 -->
HTTP/1.0 常非持续，每对象新连接；HTTP/1.1 默认持续，可复用连接，但流水线不是默认必开。持续非流水逐个请求 / 响应，流水可连续发请求，但仍有依赖、响应有序与传输量限制。

<!-- unit-id:u-04-6483283331a4 -->
http 默认 TCP/80，https 常 TCP/443（HTTP/3 等运输不同，计算题以给定版本为准）。缓存可减少响应时间和流量，未命中仍需获取。

<!-- unit-id:s-04-5d53f9d10e40 -->
#### HTTP报文结构

<!-- unit-id:u-04-811786ad1ae7 -->
请求报文：请求行（方法、目标、版本）→首部行→空行→可选实体。响应：状态行（版本、状态码、原因）→首部→空行→实体。

<!-- unit-id:u-04-27072dc27ff3 -->
GET 取资源，HEAD 取类似 GET 的首部但无响应实体，POST 提交处理内容；Host 指目标主机而非客户。状态码类：2xx 成功、3xx 重定向、4xx 客户请求问题、5xx 服务端问题，如 200、301、404、500。

#### HTTP请求时间分析

<!-- unit-id:u-04-741fccd92fc0 -->
先列时间组成：DNS 查询→必要的 TCP 建立→请求 / 首字节往返→对象传输→题设处理开销。各 RTT 不同分别算，文件大还要看带宽、TCP 窗口 / 慢开始。

<!-- unit-id:u-04-69376d1468e3 -->
同一服务器 RTT、忽略传输处理、基本页+N 引用对象的典型模型：

<!-- unit-id:u-04-dee893c1282b -->
| 连接方式 | 从首次建连开始的 RTT 开销 |
| --- | --- |
| 非持续、串行 | 2(N+1)RTT，每对象一建连一请求 |
| 持续、非流水 | (N+2)RTT，一次建连，所有对象各一次请求 |
| 持续、流水 | 约 3RTT：建连 1、基本页 1、无进一步依赖引用对象批量 1 |
| 非持续、引用对象可无限并行 | 约 4RTT：基本页 2、引用批次建连+请求 2 |

<!-- unit-id:u-04-ac087c6ba935 -->
已有连接从发基本页请求计，持续非流水为 (N+1)RTT，流水约 2RTT。并行连接数有限需分批；引用对象有依赖或窗口 / 传输耗时不能用理想批次 1RTT 强行忽略。
