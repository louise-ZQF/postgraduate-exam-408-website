### 三种交换方式

<!-- unit-id:u-04-e4c8f26359dc -->
| 交换方式 | 内容                                                                |
| ------- | ------------------------------------------------------------------ |
| 电路交换 | 类似传统电话网，二者间存在真实线路。电路交换三步：建立连接、传输数据和释放连接。 |
| 报文交换 | 将数据加上地址等信息封装成报文，报文经中间设备不断存储转发，最终到达目的地。    |
| 分组交换 | 将报文以分组为单位存储转发。极大地缩减发送时延，可能出现失序、丢失、重复的情况。 |

<!-- unit-id:u-04-9fb7800cf0a3 -->
> 分组交换中使用虚电路可解决失序问题。虚电路即建立连接时确认一条固定的转发线路，可视为虚拟的电路。

### 网络性能指标

<!-- unit-id:u-04-f10ce4f4f39f -->
| 性能指标        | 含义                                            |
| -------------- | ---------------------------------------------- |
| **发送时延**    | 发送第一个比特到最后一个比特发完所需的时间，也叫传输时延 |
| **传播时延**    | 信道中传播一定距离所需的时间，和数据长度无关           |
| 处理时延        | 分组在节点的处理时间，通常忽略                       |
| 排队时延        | 分组在节点中等待转发的时间，通常忽略                  |
| 时延带宽积      | 带宽和传播时延之积，相当于能有多少比特同时移动          |
| **往返时间RTT** | A到B的总时延 + B到A的总时延                        |
| 信道利用率      | 有数据通过的时间 / 总时间                           |

### 通信指标计算

<!-- unit-id:s-04-57c584df91f8 -->
#### 码元

<!-- unit-id:u-04-417efdc56dcb -->
- 一个固定时长的信号波就是一个码元。该时长称为码元宽度/信号周期。
- 若信号波可能出现4种信号，则称其为4进制码元，即码元一次携带2位二进制数据。
- 一个K进制码元携带的比特数为log<sub>2</sub>K。

<!-- unit-id:s-04-dc1a2d759146 -->
#### 传输速率

<!-- unit-id:u-04-127e7e0574ce -->
| 两种传输速率         | 含义               | 单位                   |
| ------------------ | ----------------- | ---------------------- |
| 码元传输速率 / 波特率 | 每秒传输几个码元     | 码元/秒、波特 Baud       |
| 信息传输速率 / 比特率 | 每秒传输几个二进制位 | 比特/秒、bit/s、bps、b/s  |

<!-- unit-id:s-04-66bcb34e257e -->
#### 奈氏准则

<!-- unit-id:u-04-97bfc25e46d9 -->
奈氏准则适用于无噪声信道，

<!-- unit-id:u-04-6afee2ad6f89 -->
$$
\small极限波特率 = 2W
$$
$$
\small极限比特率 = 2WlogK
$$

<!-- unit-id:u-04-a900cf7aaa55 -->
其中 W 是信道带宽。

<!-- unit-id:u-04-6bc4eacc57b8 -->
奈奎斯特定理说明：

<!-- unit-id:u-04-e9741592dfe4 -->
- 波特率太高，会造成“码间串扰”，即接收方无法识别码元。
- 带宽越大，信道传输码元的能力越强
- 奈奎斯特定理没有解释一个码元最多可以携带多少比特。

<!-- unit-id:s-04-414c7fcc9a1f -->
#### 香农定理

<!-- unit-id:u-04-dddf546f1176 -->
香农定理适用于有噪声信道，

<!-- unit-id:u-04-7911962131e3 -->
$$
\small 极限比特率=W\log_2{(1 + \frac{S}{N})}
$$

<!-- unit-id:u-04-9ff22a8cc6a2 -->
$$
\small 信噪比=10\log_{10}{(\frac{S}{N})}\;,\;单位\text{dB}
$$

<!-- unit-id:u-04-b9fc3154f8d5 -->
香农定理说明：

<!-- unit-id:u-04-d4cbf38919d9 -->
- 提高信道带宽、加强信号功率、降低噪声功率，都可以提高信道的极限比特率
- 在带宽信噪比确定的信道上，波特率和比特率都有极限，故一个码元携带的比特数有上限。

### 物理层设备

<!-- unit-id:s-04-ce2e0877e677 -->
#### 中继器

<!-- unit-id:u-04-d91ab2d19af1 -->
中继器的主要功能是整形、放大、转发信号。消除信号经过长段电缆产生的失真和衰减，让信号的波形和强度达到所需的要求。

<!-- unit-id:s-04-d6837580079a -->
#### 集线器

<!-- unit-id:u-04-3d17c3a21878 -->
集线器Hub一个端口收到数据后，会转发给其余所有端。若同时有多个端输入，则发生冲突它会让这些数据都失效。

<!-- unit-id:u-04-38ec2f342b60 -->
- 冲突：多个设备同时在同一传输介质上发送数据时，数据会碰撞导致失效。
- 冲突域：如果多个设备同时发送会导致数据冲突，则它们所在范围就是一个冲突域。相当于是数据发送的“临界区”。

<!-- unit-id:u-04-f87a28b442af -->
集线器无法分割冲突域，所以集线器端口所连的所有设备同属于一个冲突域。

### 封装成帧

<!-- unit-id:u-04-81d294649eda -->
| 组帧的方法       | 内容                                                         |
| -------------- | ------------------------------------------------------------ |
| 字符计数法       | 帧首添加一个字节保存帧长，出错导致后续所有帧无法定界                 |

| **违规编码法**   | 使用违规信号标记帧首尾，需要物理层配合。                           |

### 差错控制

<!-- unit-id:s-04-d4c688a518fa -->
#### 奇偶校验码

<!-- unit-id:u-04-7902699be42c -->
<img src="./04-计算机网络.assets/奇偶校验.png" style="zoom: 28%;" />

<!-- unit-id:u-04-86c84391a3c2 -->
- 奇校验：整个校验码（有效信息位和校验位）中“1”的个数为奇数。
- 偶校验：整个校验码（有效信息位和校验位）中“1”的个数为偶数。

<!-- unit-id:u-04-07b21567a5d2 -->
奇偶校验码仅能检测奇数个位出错，无纠错能力。

<!-- unit-id:s-04-3ca0ae574184 -->
#### 循环冗余校验码 CRC

<!-- unit-id:u-04-2c624232cdd2 -->
<img src="./04-计算机网络.assets/循环冗余校验.png" style="zoom: 25%;" />

<!-- unit-id:u-04-f13dbd86675c -->
| 求校验码步骤                      | 举例                    |
| ------------------------------- | ----------------------- |
| ① 多项式的最高次数，为校验位位数     | R=3                    |
| ② 多项式的系数，作除数              | 除数=1101              |
| ③ 信息位左移R位，作被除数           | 被除数=101001 000       |
| ④ 模2除运算，余数为校验位           | 余数=001                |
| **校验步骤**                      |                         |
| 信息位+校验位 模2除 除数，余数为0表示未检测出错误，不保证没有错误 | 101001 001 % 1101 = 000 |

<!-- unit-id:u-04-46acdc56499d -->
##### 模2除运算

<!-- unit-id:u-04-48433ab03974 -->
1. 最高位为1则商1，为0商0
2. 抛去最高位（以及连续的多个0），后多位进行异或，异或完下一位下来。

<!-- unit-id:u-04-19581e27de7c -->
<img src="./04-计算机网络.assets/模2除运算.png" style="zoom: 60%;" />

<!-- unit-id:s-04-30e7635b455d -->
#### 海明校验码

<!-- unit-id:u-04-ced9d33af31c -->
假设m位校验位、n位信息位，要求：

<!-- unit-id:u-04-7572e195ef17 -->
$$
\small 2^m≥m+n+1
$$

<!-- unit-id:u-04-6ad481828159 -->
m位校验位可表示2<sup>m</sup>种情况，m+n位数据共有m+n种单位错误可能，在加正确情况一种。

<!-- unit-id:s-04-f1e636dd15f9 -->
### 流量控制和可靠传输

<!-- unit-id:u-04-d6aafccf9e6b -->
> 做到流量控制和可靠传输，需实现滑动窗口、确认机制、重传机制、帧编号。下面三种协议分别是三种具体实现。
>
> - 接收方可通过接收窗口控制发送方发送速度，这就是流量控制。
> - 确认机制和重传机制可保证可靠传输。

<!-- unit-id:s-04-71e6710a0f2d -->
#### 停止等待协议 SW

<!-- unit-id:u-04-0cc7c2e6da52 -->
| 机制     | 内容                                                     |
| ------- | -------------------------------------------------------- |
| 滑动窗口 | 发送窗口 W<sub>T</sub>=1，接收窗口 W<sub>R</sub>=1           |
| 确认机制 | 逐帧确认：收到<mono>i</mono>号帧，需要返回 ACK<sub>i</sub>    |
| 重传机制 | 超时重传：超时未收到 ACK<sub>i</sub>，则重传<mono>i</mono>号帧 |
| 帧编号   | 仅需1bit                                                  |

<!-- unit-id:s-04-43b04ff3121c -->
#### 后退N帧协议 GBN

<!-- unit-id:u-04-a70305d58ae4 -->
| 机制     | 内容                                                                                                                  |
| -------- | -------------------------------------------------------------------------------------------------------------------- |
| 滑动窗口 | W<sub>T</sub>>1 W<sub>R</sub>=1                                                                                        |
| 确认机制 | **累积确认**：ACK<sub>i</sub> 表示确认<mono>i</mono>号帧及其之前所有帧<br/>**主动丢弃**：接收窗口之外的帧，丢弃并返回最后收到帧的ACK |
| 重传机制 | **超时重传**：超时未收到 ACK<sub>i</sub>，则重传<mono>i</mono>号帧及其之后所有帧                                              |
| 帧编号   | 需nbit，要求 W<sub>T</sub>+W<sub>R</sub>≤2<sup>n</sup>，即 W<sub>T</sub>+1≤2<sup>n</sup>                                |

<!-- unit-id:u-04-8bf67af83a08 -->
> 若接收速度慢或信道误码率高，导致发送方经常需要“后退”，传输效率低。

<!-- unit-id:s-04-28abb34768bc -->
#### 选择重传协议 SR

<!-- unit-id:u-04-94963f73d03d -->
| 机制     | 内容                                                                                                                         |
| ------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 滑动窗口 | W<sub>T</sub>>1 W<sub>R</sub>>1                                                                                               |
| 确认机制 | **逐帧确认**：收到<mono>i</mono>号帧，必须返回 ACK<sub>i</sub>，不支持累计确认<br/>**请求重传**：若帧出错，丢弃并返回否认帧NAK<sub>i</sub> |
| 重传机制 | **超时重传**：超时未收到 ACK<sub>i</sub>，则重传<mono>i</mono>号帧                                                                 |
| 帧编号   | 需nbit，要求 W<sub>T</sub>+W<sub>R</sub>≤2<sup>n</sup>，一般 W<sub>T</sub>=W<sub>R</sub>≤2<sup>n-1</sup>                        |

<!-- unit-id:u-04-c2e9eecfb741 -->
::: info SW、GBN、SR 三种协议对比
| 协议       | 窗口大小                         | 确认机制         | 重传机制 | 编号机制                                     |
| --------- | ------------------------------- | --------------- | ------ | ------------------------------------------- |
| 停止等待SW | W<sub>T</sub>=1 W<sub>R</sub>=1 | 逐帧确认          | 超时重传 | 1bit                                        |
| 后退N帧GBN | W<sub>T</sub>>1 W<sub>R</sub>=1 | 累积确认、主动丢弃 | 超时重传 | W<sub>T</sub>+W<sub>R</sub>≤2<sup>n</sup>   |
| 选择重传SR | W<sub>T</sub>>1 W<sub>R</sub>>1 | 逐帧确认、请求重传 | 超时重传 | W<sub>T</sub>=W<sub>R</sub>≤2<sup>n-1</sup> |

<!-- unit-id:u-04-89d8abfc818d -->
- 滑动窗口协议中，序列号个数要大于等于窗口总数（发送窗口大小+接收窗口大小）。
:::

<!-- unit-id:s-04-1e52974d53c0 -->
### 信道利用率

<!-- unit-id:u-04-a47eb6fff6c0 -->
信道利用率，意指发送时间与整个周期之比。

<!-- unit-id:u-04-2ca3fc7bade5 -->
- 停止等待的信道利用率：

<!-- unit-id:u-04-71b4c9bd2280 -->
$$
\small U_{SW}=\frac{T_D}{T_D+RTT+T_A}
$$

<!-- unit-id:u-04-95186df44f9e -->
- 后退N帧、选择重传的信道利用率：

<!-- unit-id:u-04-5897d0a37c5e -->
$$
\small U_{GBN/SR}=\frac{nT_D}{T_D+RTT+T_A}
$$

<!-- unit-id:u-04-0e8805d0fc0d -->
其中T<sub>D</sub>为数据帧发送时延，T<sub>A</sub>为确认帧发送时延，RTT为往返传播时延，n为发送窗口大小。

#### 随机访问 CSMA/CD

<!-- unit-id:u-04-83c627b583ef -->
> CSMA/CD 载波监听多路访问/冲突检测，适用于早期总线型以太网。

<!-- unit-id:u-04-3386b4a7859f -->
先听后发，边听边发，冲突停发，随机重发。

<!-- unit-id:u-04-032d411d2973 -->
::: info 争用期、随机退避、最短帧长
- 争用期：2×最远单向传播时延。
- 截断二进制指数退避算法：k 为冲突次数，等待时长为 r×争用期。
  - k≤10，r在\[0,2<sup>k</sup>-1\]中取随机值
  - k>10，r在\[0,2<sup>10</sup>-1\]中取随机值
  - k=16，放弃传输
- 最短帧长：争用期×信道带宽。

<!-- unit-id:u-04-717e463d8cb7 -->
以太网帧长规定为 64~1518。
:::

##### 信道预约机制

<!-- unit-id:u-04-13562d94f41c -->
> 先预约，再发送。

<!-- unit-id:u-04-40f6b71a29aa -->

### 以太网交换机

<!-- unit-id:s-04-920e03c58648 -->
#### 独占带宽特点

<!-- unit-id:u-04-0d55daa8f0f4 -->

<!-- unit-id:u-04-4dcaefb0c6f7 -->

<!-- unit-id:u-04-d2db98a5003a -->

<!-- unit-id:u-04-a67ec4ce24ac -->
- 有节点发送帧，记录<emp>源MAC地址</emp>和端口号。
- 表中有接收方，直接转发给接收方，若无接收方，就广播到其余所有端口。

### 网络层功能

<!-- unit-id:u-04-f8d35a5fd121 -->
::: info 异构网络互连
物理层或数据链路层的设备，只是把一个网络扩大了。从网络层的角度看，它仍然是同一个网络。

<!-- unit-id:u-04-5495d24a5dbc -->
所以只有路由器才能实现连接两个异构网络，交换机、集线器都不行。
:::

<!-- unit-id:s-04-70b5e7cf7a49 -->
#### 虚电路和数据报

<!-- unit-id:u-04-2299ef965c38 -->
网络层使用分组交换，分组交换又分为虚电路服务和数据报服务。

<!-- unit-id:u-04-7d743bfb4ca5 -->
| 对比        | 虚电路服务                       | 数据报服务                          |
| ---------- | ------------------------------ | ---------------------------------- |
| 思路        | 可靠通信应当由网络来保证           | 可靠通信应当由用户主机来保证           |
| 是否建立连接 | 必须建立网络层连接                | 不需要建立网络层连接                  |
| 是否携带地址 | 仅建立连接时使用，后续使用虚电路号   | 每个分组都有终点的完整地址            |
| 分组转发    | 分组按照同一路由进行转发            | 每个分组可走不同的路由                |
| 结点故障    | 虚电路故障需要重新建立链接          | 故障结点可能丢失分组，路由可能发生变化   |
| 分组顺序    | 总是按序到达终点                  | 不一定按序到达终点                   |

<!-- unit-id:s-04-a8f64ec981ca -->
#### 软件定义网络SDN

<!-- unit-id:u-04-b6ff751b9c27 -->
转发和路由是网络层的核心功能，故网络层可抽象地划分为数据平面和控制平面，数据平面实现转发，控制平面实现路由。

<!-- unit-id:u-04-e9822a5d9db2 -->
路由器间不再相互交换路由信息，控制平面有一个远程控制器，掌握各主机和整个网络的状态，为每个分组计算出最佳路由，通过Openflow协议将转发表（流表）下发给路由器。路由器按此转发即可。

<!-- unit-id:u-04-33b8c26e0ad2 -->
| SDN的可编程性 |
| ---------- |
| ① SDN对应用层提供的编程接口，称为北向接口。<br/>② SDN控制器和转发设备的会话接口称为南向接口，通过不同南向接口协议兼容不同硬件。<br/>③ SDN控制器集群之间的通信接口称为东西向接口，用于增强控制平面的可靠性和可拓展性。 |
|<thd>SDN的优点</thd>|
| ① 集中式控制和分布式高速转发。既利于控制平面的全局优化，又利于高性能的网络转发。<br/>② 可编程与性能的平衡。控制和转发功能分离后，可由自动化工具以编程方式配置网络。<br/>③ 降低成本。控制和数据平面分离后，实现了网络设备的制造与功能软件的开发相分离。 |
|<thd>SDN的问题</thd>|
| ① 安全风险，集中管理容易受攻击，若崩溃，整个网络会受到影响。<br/>② 瓶颈问题，控制平面集中化后，随着网络规模扩大，控制器可能成为网络性能的瓶颈。 |

### IP分片

<!-- unit-id:u-04-ad8fbec74554 -->
链路层帧能承载的最大数据量为MTU。以太网MTU为1500B，如果报文总长度超出下段链路的MTU，就需要分片。

<!-- unit-id:u-04-6f4b6612125f -->
<img src="./04-计算机网络.assets/IP分片.png" style="zoom: 60%;" />

<!-- unit-id:u-04-8ab31c756a86 -->
设有4000B的报文需要发送到MTU为1500B的链路上，

<!-- unit-id:u-04-ca2cfa6b3041 -->
1. 先将首部去掉，4000B-20B=3980B
2. 计算最大数据量，1500B-20B=1480B
3. 按最大数据量拆分，3980B=1480B+1480B+1020B
4. 最后组装成报文，1500B=20B+1480B、1500B=20B+1480B、1040B=20B+1020B

<!-- unit-id:u-04-2f9705abf5af -->
由于片偏移的影响，最大数据量一定要是8B的倍数。

### 路由算法和路由协议

<!-- unit-id:u-04-22b3059efe4d -->
> 路由器内部运行着一种路由协议，一个路由协议使用某种路由算法。路由算法获取网络中各个节点的信息，以生成最佳转发路径。

<!-- unit-id:u-04-00eca689bd5e -->
| 路由算法分类                 | 含义                                                       |
| -------------------------- | --------------------------------------------------------- |
| 静态路由算法                 | 网络管理员手工配置每一条路由。                                 |
| 动态路由算法                 | 路由器根据网络负载和拓扑结构来动态调整路由表。                    |
| <thd>两种抽象路由算法</thd> | <thd>含义</thd>                                         |
| 距离向量路由算法              | 不管网络拓扑结构，只关心自身和相连点、相连点和目的点之间的最短距离。 |
| 链路状态路由算法              | 把完整网络拓扑结构摸清楚之后，再用Dijkstra算法确定最短路径。      |

<!-- unit-id:u-04-a96aa7d4f6a8 -->
自制系统内运行内部路由协议，如：RIP、OSPF，系统外运行外部路由协议，如BGP。

<!-- unit-id:s-04-3e603502ddd6 -->
#### 路由信息协议 RIP

<!-- unit-id:u-04-bcf4483210b8 -->
RIP是基于UDP的应用层协议，端口号520。RIP使用“距离向量路由算法”。

<!-- unit-id:u-04-c2b19f03dadc -->
RIP使用跳数Hop Count来衡量到达目的网络的距离，认为跳数最少就是最佳路由。规定合法距离不能超过15，距离为16表示网络不可达。

<!-- unit-id:u-04-35135aaa6cc2 -->
<img src="./04-计算机网络.assets/RIP路由.png" style="zoom: 25%;" />

<!-- unit-id:u-04-92d7ac182d95 -->
每个路由器都要维护自己的路由表，路由表项有三个关键字段：<mono><目的网络N，距离d，下一跳路由器地址X></mono>。

<!-- unit-id:u-04-adf253009fb7 -->
每个路由器都要维护从它自身到其他目的网络的距离，即距离向量

<!-- unit-id:u-04-9747ead9cce1 -->
##### RIP的工作流程

<!-- unit-id:u-04-a2799d5473a8 -->
1. 路由器启动时，只知道和自身直接相连的网络，距离设为1。
2. 0时刻，路由器向相邻路由器发送RIP响应，其中包含完整路由表。
3. 收到其他路由器的路由表后，“目的网络不变，距离+1，下一跳改为对方”，若路由表中不存在该网络或距离更短，则放到自身路由表中；已有路由下一跳正是该邻居时，距离变大也应更新。
4. 每隔30秒，和相邻路由器交换路由信息。为加快收敛速度，可在网络拓扑变化时自动通知相邻路由器，即“触发更新”机制。
5. 若超过RIP默认超时时间180秒没有收到相邻路由器的路由表，则将该路由器标记为不可达。

<!-- unit-id:u-04-88c1984cd920 -->
##### RIP的优缺点

<!-- unit-id:u-04-e9fd4e9a9d2e -->
优点：

<!-- unit-id:u-04-4051f2ffdad6 -->
1. 实现简单、开销小、收敛较快
2. <emp>好消息传播得快</emp>：若发现了更短的路由，短时间内便可传至所有路由器 (30s)

<!-- unit-id:u-04-0992872ef410 -->
缺点：

<!-- unit-id:u-04-4a5e0533185b -->
1. 限制网络规模，最大距离为15
2. 路由器间交换的是完整的路由表，因此规模越大开销越大
3. “<emp>坏消息传得慢</emp>” / 慢收敛现象：网络故障时，需长时间才能将故障消息传至所有路由器 (180s)

<!-- unit-id:s-04-d620ebaf8965 -->
#### 开放最短路径优先协议 OSPF

<!-- unit-id:u-04-12e113b4ae39 -->
OSPF是网络层协议，使用IP协议，IP首部的协议字段为89。

<!-- unit-id:u-04-17f91763544d -->
> 链路状态：路由器本身、相邻路由器和相邻网络、到相邻节点的距离，是一台路由器可独立探测的信息。
>
> 网络拓扑结构：路由器和网络作为顶点、距离作为边权重的带权有向图。

<!-- unit-id:u-04-624b60c58c9d -->
<img src="./04-计算机网络.assets/OSPF.png" style="zoom: 25%;" />

<!-- unit-id:u-04-71aa79264635 -->
##### OSPF的工作流程

<!-- unit-id:u-04-3aaaa6ba27d6 -->
OSPF通过“洪泛法”，让每个路由器都获悉整个网络拓扑结构。一旦路由器探测到新的链路信息，就立即开始洪泛。

<!-- unit-id:u-04-63d57f3fa199 -->
1. 路由器将链路信息发送到与之相邻的所有路由器，
2. 相邻路由器会接着转发给与自己相邻的所有路由器，
3. 不可“回流”，转发过的信息不可再转。

#### 边界网关协议 BGP

<!-- unit-id:u-04-49722757d8c7 -->
BGP是一种外部网关协议，用于自治系统之间交换路由信息，实现路由选择。BGP是基于TCP的应用层协议。

<!-- unit-id:u-04-8f57fbbf0471 -->
其中路由器称为BGP对等方、TCP连接称为BGP会话。跨越自治系统的BGP会话称为eBGP会话，自治系统内部的BGP会话称为iBGP会话。

<!-- unit-id:u-04-eb1e33e8a81b -->
<img src="./04-计算机网络.assets/BGP.png" style="zoom: 20%;" />

<!-- unit-id:u-04-44ce0875d1d1 -->
##### BGP的特点

<!-- unit-id:u-04-ff5a2f73a46f -->
1. BGP力求找到一条较好路由，而不是最佳路由
2. 外部路由选择须考虑政治安全经济因素
3. BGP采用路径向量路由算法，路由器间交换路由信息时，需告知目的地和到达目的地的完整路径，即经过哪些自治系统

<!-- unit-id:u-04-ebec9bc9aad9 -->
##### BGP的路由算法

<!-- unit-id:u-04-f80608816010 -->
| 路由因素   | 含义                                                              |
| -------- | ----------------------------------------------------------------- |
| 本地偏好值 | 本地偏好值由AS管理员设置，相当于优先级                                  |
| AS跳数    | AS跳数最少，路由器跳数不一定最少                                       |
| 热土豆路由 | 若有多条AS跳数相同的路线，选择一条离开本自治系统内部最快（内部转发最少）的路径 |
| BGP标识符 | 选择BGP标识符最小的“老员工”路由                                        |

<!-- unit-id:u-04-39e2a298517a -->
##### BGP的四种报文

<!-- unit-id:u-04-e48cfc73a9d2 -->
| 四种报文             | 内容                                                                                 |
| ------------------- | ----------------------------------------------------------------------------------- |
| Open打开报文         | 具体作用：与BGP邻居建BGP会话，初始化通信<br />发送时机：TCP连接建立成功                       |
| Update更新报文       | 具体作用：通知对方更新或撤销某些路由信息<br />发送时机：路由状态发生变动                        |
| Keepalive保活报文    | 具体作用：通知BGP邻居保持连接<br />发送时机：周期性发送60秒一次，如180秒未收到，说明BGP会话出问题 |
| Notification通知报文 | 具体作用：检测到报文出现错误，通知发送方并关闭BGP会话<br />发送时机：检测到BGP报文出错           |

### 路由器

<!-- unit-id:s-04-0448ea52e776 -->
#### 冲突域和广播域

<!-- unit-id:u-04-c8f7de2b2a76 -->
- 冲突域：连接到同一介质上的节点的集合，集合内节点必须互斥访问，否则会发生冲突。
- 广播域：接收同样广播消息的节点的集合，集合内节点发送广播帧，其他节点都能收到。

<!-- unit-id:u-04-160a29f36661 -->
> 集线器、中继器等简单复制转发信号的物理层设备所连接的节点属于一个冲突域，也就是说它们不能划分冲突域。
>
> 交换机相连的节点可以收到相互发的广播帧，所以说交换机可以连接广播域。交换机不同端口所连的节点同时发送数据互不影响，所以说普通交换机分割冲突域；配置不同VLAN时才可分割广播域。
>
> 路由器连接两个网络，节点可以收到自身网络中的广播帧，无法收到另一个网络中的广播帧，所以说路由器隔离广播域。

<!-- unit-id:u-04-d4b9bb78e25a -->
- 路由器隔开的是广播域
- 交换机隔开的是冲突域

<!-- unit-id:s-04-84f36ccbe52d -->
#### 路由器的功能

<!-- unit-id:u-04-090796a0bf0f -->
路由器的任务是连接不同的网络并完成分组转发。

<!-- unit-id:u-04-942561849470 -->
从结构上看，路由器由路由选择和分组转发两部分构成：

<!-- unit-id:u-04-aab37b084292 -->
- 控制层面：核心是路由选择处理机，任务是根据路由协议构造出路由表，同时定期更新维护路由表。
- 交换层面：交换结构根据转发表对分组进行处理，将某个输入端口进入的分组从一个合适的输出端口转发出去。

### TCP报文段

<!-- unit-id:u-04-86e501496586 -->

|  标志位  | 解释                             |
| :-----: | ------------------------------- |
|   URG   | 表示紧急报文，紧急指针有效          |
| **ACK** | 表示**确认**报文，确认序号有效      |
|   PSH   | 表示催促接收，接收端尽快读取数据     |
|   RST   | 表明重置连接，底层会重新建立连接     |
| **SYN** | 表示**请求**连接，底层会进行三次握手 |
| **FIN** | 表示**结束**连接，底层会进行四次挥手 |

<!-- unit-id:s-04-89298b338077 -->
### TCP连接管理

<!-- unit-id:s-04-8bc0d5eef13c -->
#### 三次握手

<!-- unit-id:u-04-f70d27a49dc6 -->
1. 客户端发送SYN报文，请求连接
2. 服务端返回SYN+ACK报文，请求连接并应答
3. 客户端发送ACK报文，应答

<!-- unit-id:u-04-9f14025af006 -->
<img src="./04-计算机网络.assets/三次握手.png" style="zoom: 25%;" />

<!-- unit-id:u-04-a30e0626700b -->
::: info 字段分析、耗时分析
- 前两次请求连接的握手中SYN=1，第三次纯应答的握手中SYN=0。
- 前两次请求连接的握手不能携带数据，但仍要消耗一个序号。
---
- 从第一次握手发出，到客户端进程可以发送数据，需要多久？1RTT
- 从第一次握手发出，到服务器进程可以发送数据，需要多久？1.5RTT
:::

<!-- unit-id:u-04-906eb9fb3804 -->
> 客户端收到第二次握手，认为连接建立完成，可发数据。
>
> 服务器收到第三次握手，认为连接建立完成，可发数据。

<!-- unit-id:s-04-7a7c58176dc3 -->
#### 四次挥手

<!-- unit-id:u-04-e60f9b12f5a4 -->
1. 客户端发送FIN报文，请求关闭连接
2. 服务端返回ACK报文，应答
3. 服务端发送FIN报文，请求关闭连接
4. 客户端返回ACK报文，应答

<!-- unit-id:u-04-7fc1551fd325 -->
> 第二次挥手可携带数据；单独的第四次确认通常不带数据，是否可带数据应结合连接状态与题设。

<!-- unit-id:u-04-76a50887d8f1 -->
<img src="./04-计算机网络.assets/四次挥手.png" style="zoom: 25%;" />

<!-- unit-id:u-04-004c6b8c4739 -->
> 等待2MSL最长报文段寿命后，再关闭连接，以免第四次挥手丢失。

<!-- unit-id:u-04-aa20cecee933 -->
::: info 字段分析、耗时分析
- 只有请求断开的第一次和第三次挥手中FIN=1。
- FIN可与数据同段发送；FIN本身额外消耗一个序号。
---
- 从客户发出第一次挥手，到客户进程进入CLOSED状态，需要多久？仅在服务端立即发送FIN等简化假设下为1RTT+2MSL，否则依题设时间线
- 从客户发出第一次挥手，到服务器进程进入CLOSED状态，需要多久？仅在服务端立即发送FIN等简化假设下为1.5RTT，否则依题设时间线
:::

<!-- unit-id:u-04-7a61b53701be -->
<img src="./04-计算机网络.assets/挥手耗时分析.png" style="zoom: 25%;" />

### TCP可靠传输

<!-- unit-id:u-04-d90c153e328f -->
| 确认机制 | 含义                                                                           |
| ------- | ----------------------------------------------------------------------------- |
| 累计确认 | 如果ack_seq=n，说明序号n之前的所有字节都已正确接收                                   |
| 延迟确认 | TCP标准规定，推迟时间最多0.5秒，<br/>若连续收到两个长度为最大段长MSS的报文，应立即返回应答 |
| 捎带确认 | 如果需要应答且有数据要发送，立即发送应答报文并带上数据                                 |

<!-- unit-id:u-04-a6f287fb716e -->
| 重传机制 | 含义                                                                                                |
| ------- | -------------------------------------------------------------------------------------------------- |
| 超时重传 | 发送报文时设置计时器，计时器超时未收到应答，则重传报文                                                       |
| 快重传   | 收到报文立即应答，失序报文也要立即应答，失序报文返回的是冗余应答，发送方连续收到三个冗余确认，就立即重传该位置数据 |

### TCP流量控制

<!-- unit-id:u-04-077e28fba4a5 -->
| 窗口机制 | 含义                             |
| ------- | ------------------------------- |
| 接收窗口 | 接收窗口大小受限于接收缓冲区         |
| 发送窗口 | 发送窗口大小受限于发送缓冲区、接收窗口和拥塞窗口 |

<!-- unit-id:u-04-f99c654e836f -->
TCP首部中仅有接收窗口字段，发送方用对方的接收窗口调整自身发送窗口。

<!-- unit-id:u-04-6a1f778899be -->

最大段长MSS实际作用于报文切分。考试中MSS只会联系拥塞窗口，进而决定发送窗口。

<!-- unit-id:u-04-86498965e62f -->
> 报文切分不影响发送和传播时延。
:::

### TCP拥塞控制

<!-- unit-id:u-04-f21b72003c57 -->
发送窗口大小受限于接收窗口和拥塞窗口，拥塞窗口值的含义为nMSS的n，考查拥塞窗口时只会立即确认，不管延迟确认。

<!-- unit-id:s-04-16d66afdcd8d -->
#### 慢开始和拥塞避免

<!-- unit-id:u-04-0b918943df09 -->
<img src="./04-计算机网络.assets/拥塞控制.png" style="zoom: 20%;" />

<!-- unit-id:u-04-25826a2b61af -->
| 阶段 | 增长速度 | 临界情况、触发条件 | 内容 |
| ---- | ---- | ---- | --- |
| 慢开始 | 指数增长 | cwnd=1 ssthresh=16 | 每收到新数据的确认增加窗口，典型简化模型下每RTT近似翻倍 |
| 拥塞避免 | 线性增长 | cwnd==ssthresh | 典型简化模型下每RTT增加约1MSS |
| 慢开始 | 指数增长 | ssthresh=cwnd/2 cwnd=1 | 发生超时重传，ssthresh下降，cwnd恢复 |
| 拥塞避免 | 线性增长 | cwnd>=ssthresh | 典型简化模型下每RTT增加约1MSS |

<!-- unit-id:u-04-f0ee4cd83a87 -->
::: info 慢开始和拥塞避免算法描述
- 刚开始，采用慢开始算法，拥塞窗口指数增长，
- 到达阈值，采用拥塞避免算法，拥塞窗口线性增长，
- 发生超时重传，<emp>阈值设为拥塞窗口的一半</emp>，拥塞窗口恢复为1，重新开始。
:::

<!-- unit-id:u-04-16fb8da81d21 -->
> cwnd×2 > ssthresh时，将cwnd设为ssthresh。

<!-- unit-id:s-04-19295faa1e48 -->
#### 快恢复算法

<!-- unit-id:u-04-d59eced1ded0 -->
<img src="./04-计算机网络.assets/快恢复.png" style="zoom: 25%;" />

<!-- unit-id:u-04-2db60da9996c -->
| 阶段 | 增长速度 | 临界情况、触发条件 | 内容 |
| ---- | ---- | ---- | --- |
| 慢开始 | 指数增长 | cwnd=1 ssthresh=16 | 每收到新数据的确认增加窗口，典型简化模型下每RTT近似翻倍 |
| 拥塞避免 | 线性增长 | cwnd==ssthresh | 典型简化模型下每RTT增加约1MSS |
| 快恢复后的拥塞避免（教材简化） | 线性增长 | cwnd=ssthresh=cwnd/2 | 收到三个重复ACK触发快重传；超时仍回到慢开始 |

<!-- unit-id:u-04-d30ab183bc9a -->
::: info 快恢复算法描述
- 刚开始，采用慢开始算法，拥塞窗口指数增长，
- 到达阈值，采用拥塞避免算法，拥塞窗口线性增长，
- 触发快重传，认定轻微拥塞，ssthresh和cwnd都设为拥塞窗口的一半，继续拥塞避免。
:::

| 顶级域名服务器 | 负责管理在该顶级域名注册的所有二级域名        |
| 权限域名服务器 | 保存该区中的所有主机的域名到IP地址的映射      |
| 本地域名服务器 | 主机最先询问的是本地域名服务器               |

#### 递归查询和迭代查询

<!-- unit-id:u-04-73475cb40a56 -->

<!-- unit-id:u-04-7744d5f0aeed -->
- 递归查询中，主机和各级服务器都采用递归查询。
- 迭代查询中，主机和本地服务器采用递归查询，本地服务器向其他服务器采用迭代查询。

<!-- unit-id:u-04-260ff729d956 -->
> 递归查询会造成根服务器负载严重，实际上几乎不用。

<!-- unit-id:u-04-9012c0f4b54f -->
::: info 实际查询过程
查询www.abc.xyz.com，假设采用迭代查询，过程如下：

<!-- unit-id:u-04-dd0ccce44235 -->

2. 本地服务器向<warn>根</warn>域名服务器查询，查询未果，返回.com顶级域名服务器的地址。
3. 本地服务器向<warn>顶级</warn>域名服务器查询，查询未果，返回xyz.com权限域名服务器的地址。
4. 本地服务器向<warn>权限</warn>域名服务器查询，查询未果，返回abc.xyz.com权限域名服务器的地址。
4. 本地服务器向<warn>权限</warn>域名服务器查询，查询成功，返回www.abc.xyz.com服务器的地址。

<!-- unit-id:u-04-957097a88fc6 -->
> www只是万维网标识，不是域。
:::

### 文件传输协议 FTP

<!-- unit-id:u-04-6f6402b20b01 -->
FTP采用C/S应用模型，使用TCP协议。FTP使用控制连接与数据连接；服务器控制端口为21，主动模式的数据连接通常由服务器20端口发起，被动模式的数据端口另行协商。

<!-- unit-id:u-04-5be4f7eb1ae6 -->
| 设计     |  内容              |
| ------- | ------------------ |
| 控制连接 | • 21号端口上的连接称为控制连接，用来传输控制信息。<br/>• 客户发出的请求，通过控制连接发送给控制进程。<br/>• 传输中还可以中途控制，因此控制连接在整个会话期间一直保持打开。|
| 数据连接 | • 控制进程接收到传输请求后，就创建“数据传送进程”和“数据连接”。<br/>• 数据传送进程实际完成文件的传送，在传送完毕后关闭“数据传送连接”并结束运行。|

<!-- unit-id:s-04-def3ce8a69b0 -->
#### 工作模式

<!-- unit-id:u-04-6d0bfbac74ee -->
数据连接有两种传输模式：主动模式PORT和被动模式PASV。

<!-- unit-id:u-04-a3dbd8fd39a3 -->
- 主动模式：客户端开放一个端口，发送命令到服务器，服务器通过20端口向开放端口通信。
- 被动模式：客户端发送命令到服务器，服务器开放一个端口，客户端连接到该端口通信。

<!-- unit-id:u-04-d26077b95729 -->
主动模式是服务器连接到客户端的端口，被动模式是客户端连接到服务器的端口。

#### 多用途因特网邮件扩展 MIME

<!-- unit-id:u-04-a4c22b7bf7dd -->

<!-- unit-id:u-04-5b49c83d3508 -->
若邮件中存在非ASCII码数据，要通过MIME将其转换为ASCII码数据。发送时要转换，接收时要逆转换。

<!-- unit-id:u-04-cd770bf6d868 -->
::: info SMTP和POP3的特点
- SMTP用于发送邮件，C/S模型，基于TCP，端口号25。
- POP3用于读取邮件，C/S模型，基于TCP，端口号110。
---
- SMTP是推Push，SMTP将邮件推送到SMTP服务器。
- POP3是拉Pull，POP3从POP3服务器上拉取邮件。
---
- SMTP通信三个阶段：连接建立、邮件传送、连接释放。
- POP3读取邮件时，支持“下载并删除”、“下载并保留”两种功能。
:::

### 万维网 WWW

<!-- unit-id:s-04-0c13b55a39c6 -->
#### HTTP协议特点

<!-- unit-id:u-04-87f0da236299 -->
HTTP/1.x和HTTP/2通常使用TCP；HTTP/3使用基于UDP的QUIC。HTTP无状态不意味着不使用连接。实际应用中，常用Cookie跟踪用户活动。

<!-- unit-id:u-04-d9be82583e0a -->
::: info Cookie的工作原理
1. 用户初次浏览时，网站为用户生成一个唯一的Cookie识别码，以此为索引在数据库中记录用户信息。
2. 之后的响应报文中多了一个首部行“Setcookie:xxxx-xxxx”，浏览器会将网站信息记录到本地。
3. 之后的请求报文中就多一个首部行“Cookie:xxxx-xxxx”，服务器根据Cookie识别码就能从数据库中查询到该用户的活动记录。
:::
