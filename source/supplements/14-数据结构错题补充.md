<!-- unit-id:s-14-9adff3008e4b -->
## 栈、队列与递归

<!-- unit-id:s-14-5def76e34247 -->
### 顺序栈和共享栈的边界

<!-- unit-id:u-14-2e8826edd629 -->
**先看约定｜** 以下数组容量均为 `n`，有效下标为 `0～n-1`。同名 `top` 可以有不同含义，必须先确定它指“当前栈顶”还是“下一空位”，再套判空、判满表达式。

<!-- unit-id:s-14-d3b6a48b0a5e -->
#### 顺序栈：top 指向当前栈顶

<!-- unit-id:u-14-49b5ecc6c574 -->
**判空｜** `top == -1`。

<!-- unit-id:u-14-d8939acab723 -->
**判满｜** `top == n-1`。

<!-- unit-id:u-14-f45470593db5 -->
| 要看什么 | 表达式 / 操作 |
| --- | --- |
| 初值 | `top = -1` |
| 元素个数 | `top+1` |
| 入栈（先判满） | `a[++top] = x`，先把 top 移到新位置，再写入 |
| 出栈（先判空） | `x = a[top--]`，先读取当前栈顶，再后退 |

<!-- unit-id:s-14-77e66fe2a111 -->
#### 顺序栈：top 指向下一空位

<!-- unit-id:u-14-dfa812993dfb -->
**判空｜** `top == 0`。

<!-- unit-id:u-14-ac578ad974e2 -->
**判满｜** `top == n`。

<!-- unit-id:u-14-91db1b589c69 -->
| 要看什么 | 表达式 / 操作 |
| --- | --- |
| 初值 | `top = 0` |
| 元素个数 | `top` |
| 入栈（先判满） | `a[top++] = x`，先写当前空格，再让 top 后移 |
| 出栈（先判空） | `x = a[--top]`，先退回已有元素，再读取 |

<!-- unit-id:s-14-71aaa4827251 -->
#### 共享栈：两端向中间生长

<!-- unit-id:u-14-113783e23d65 -->
**先看约定｜** `top1`、`top2` 都指各自的当前栈顶；左栈向右长，右栈向左长，初值 `top1=-1`、`top2=n`。

<!-- unit-id:u-14-1dae2b962eeb -->
**左栈判空｜** `top1 == -1`。

<!-- unit-id:u-14-7b3845ada061 -->
**右栈判空｜** `top2 == n`。

<!-- unit-id:u-14-35588ee3f245 -->
**易错｜** 其中一个栈空，不代表另一个也空。

<!-- unit-id:u-14-a540cf777a10 -->
**整体判满｜** `top2-top1 == 1`，等价于 `top1+1 == top2`。

<!-- unit-id:u-14-71af0e9c57d2 -->
| 要看什么 | 表达式 / 操作 |
| --- | --- |
| 两栈都空 | `top1 == -1 && top2 == n` |
| 中间剩余空位 | `top2-top1-1` |
| 已存元素总数 | `(top1+1)+(n-top2)` |
| 左栈入 / 出 | `a[++top1]=x` / `x=a[top1--]` |
| 右栈入 / 出 | `a[--top2]=x` / `x=a[top2++]` |

<!-- unit-id:u-14-1b4d43aa8519 -->
**为什么相邻就满｜** 例如 `n=6`，左栈占下标 `0、1、2`，右栈占下标 `3、4、5`，此时 `top1=2`、`top2=3`，中间空位为 `3-2-1=0`；若等到两个 top 重合再判满，就已覆盖原元素。

<!-- unit-id:u-14-4f3d24eb97b7 -->
**易错｜** 共享栈满看“两栈之间有没有空位”，不能把数组机械地各分一半；共享栈降低上溢概率，但不能消除对空栈出栈造成的下溢。

<!-- unit-id:s-14-ed1e8426fddf -->
### 循环队列的判空与判满

<!-- unit-id:u-14-a518b98853b3 -->
**先看约定｜** 容量为 `M`，`front` 指向队头元素，`rear` 指向下一入队位置；本节先采用“牺牲一个单元”的实现。

<!-- unit-id:u-14-5adb59d3e048 -->
**判空｜** `front == rear`。

<!-- unit-id:u-14-c3715c09027f -->
**判满｜** `(rear+1)%M == front`。

<!-- unit-id:u-14-5326613dc93c -->
| 要看什么 | 表达式 / 操作 |
| --- | --- |
| 初值 | `front = rear = 0` |
| 元素个数 | `(rear-front+M)%M` |
| 最多存放 | `M-1` 个元素 |
| 入队（先判满） | 先 `a[rear]=x`，再 `rear=(rear+1)%M` |
| 出队（先判空） | 先 `x=a[front]`，再 `front=(front+1)%M` |

<!-- unit-id:u-14-e80417f88959 -->
**为什么要取模｜** 下标 `M-1` 的下一格是 `0`；例如 `M=4、front=3、rear=1`，有效元素位于 `3、0` 两格，数量是 `(1-3+4)%4=2`，不能直接算 `rear-front`。

<!-- unit-id:s-14-2ea413f13425 -->
#### 另一种实现：额外维护 size

<!-- unit-id:u-14-d7d81ec814eb -->
**判空｜** `size == 0`。

<!-- unit-id:u-14-5c4a092da5b6 -->
**判满｜** `size == M`。使用这套约定可存满 `M` 个元素；入队后 `size++`，出队后 `size--`。

<!-- unit-id:u-14-6b63dc2a6854 -->
**易错｜** size 实现中，`front==rear` 既可能表示空，也可能表示满，必须结合 size；不能再照搬“牺牲一格”的判满式。若题设用 tag 区分空满，先读清 tag 取值的定义。

<!-- unit-id:s-14-119379ba1397 -->
### 合法出栈序列与调用次数

<!-- unit-id:u-14-3c46ba43cd99 -->
**重点｜** 判断固定输入顺序的出栈序列，要逐步记录已输入元素、当前栈顶和目标输出；开始出栈后仍允许继续入栈，栈内剩余元素也不能任意重排。

<!-- unit-id:u-14-a589624f2a72 -->
三个不同元素在固定入栈顺序下只有五种合法出栈序列，并非 $3!$ 种。

<!-- unit-id:s-14-edc75e521657 -->
#### 递归调用次数

<!-- unit-id:u-14-5ead5a276b26 -->
**重点｜** 递归题要分清返回值、调用次数和最大深度：`2*F(n/2)` 只有一次递归调用，`F(n/2)+F(n/2)` 才有两次；计算总调用次数时，递归调用树中的当前结点也要计一次。

<!-- unit-id:s-14-044d96a4ebf3 -->
### 双端队列与两个队列重排

<!-- unit-id:u-14-7f85308ce937 -->
**重点｜** 输入受限双端队列只允许从指定一端入队，但两端都可出队；输出受限双端队列允许两端入队，但只能从指定一端出队，新元素始终只能放在端点。

<!-- unit-id:u-14-20240dbeebd4 -->
用两个普通队列重排固定输入时，每个队列内部必须保留输入的相对顺序；对递增输入，目标输出能否实现可转化为它能否拆成两个递增子序列。

<!-- unit-id:u-14-613d7f7d8363 -->
若每条铁路调车轨道相当于一个队列、最终按编号递增输出，所需最少轨道数等于输入序列的最长下降子序列长度；证明最少数量时还应构造可行的轨道分配。

<!-- unit-id:s-14-b18737fea4d4 -->
### 表达式与括号栈

<!-- unit-id:u-14-660c7fbd1676 -->
**重点｜** 后缀表达式求值时，若依次弹出 `a`、`b`，题目规定的二元运算通常应计算 `b op a`，减法和除法尤其不能交换次序。

<!-- unit-id:u-14-4425fefeb5ea -->
括号匹配需要的最大栈容量等于扫描过程中尚未匹配的左括号数的最大值，也就是最大嵌套深度，而非整串括号总数。

<!-- unit-id:s-14-4195a3784b02 -->
## 链表操作中的边界

<!-- unit-id:s-14-a4813d9ba1ee -->
### 查找位置与改指针分开计时

<!-- unit-id:u-14-433c8c26066c -->
**重点｜** 已知结点位置后修改少量链接通常是 $O(1)$，但“在有序单链表中找到插入位置并插入”的完整操作仍可能是 $O(n)$。

<!-- unit-id:u-14-7792e27e38be -->
普通单链表即使持有尾指针，删除尾结点仍要寻找前驱，通常为 $O(n)$；若是双链表，尾结点的 `prior` 可直接定位前驱。

<!-- unit-id:u-14-f5013e04e450 -->
静态链表虽然用数组保存结点，结点之间仍靠游标链接，插删不需要像顺序表那样移动大量数据元素。

<!-- unit-id:s-14-c4ca603802f3 -->
### 删除循环链表首元与双链表插入

<!-- unit-id:u-14-7b92eb0abf21 -->
**先分结构｜** `h` 是头指针，`r` 是维护的尾指针；“头结点”是不存数据的哨兵，“首元结点”才是第一个数据。下面的判空式不能跨结构混用。

<!-- unit-id:s-14-017c186e863d -->
#### 循环单链表：带头结点 H

<!-- unit-id:u-14-ad0d37571815 -->
**判空｜** `h->next == h`；空表仍保留头结点 H。

<!-- unit-id:u-14-2174597ea4b9 -->
**尾部关系｜** 若同时维护尾指针 r，始终有 `r->next == h`，空表时 `r == h`。

<!-- unit-id:u-14-6004d0881a30 -->
| 考察点 | 明确写法 |
| --- | --- |
| 只有一个数据结点 | `h->next != h && h->next->next == h` |
| 遍历结束 | 从 `p=h->next` 开始，循环条件 `p != h` |
| 删除首元（先判非空） | `q=h->next; h->next=q->next; if(r==q) r=h; free(q);`，其中更新 r 的语句只在维护尾指针时需要 |

<!-- unit-id:u-14-a3ed549c390b -->
**易错｜** 空表是 `H→H`，不是 `h==NULL`；删除最后一个数据结点后，尾指针必须回到 H。

<!-- unit-id:s-14-91dfdbd39541 -->
#### 循环单链表：不带头结点

<!-- unit-id:u-14-152d60ae8f76 -->
**判空｜** `h == NULL`，这里约定空表用空指针表示；非空时 h 直接指首元。

<!-- unit-id:u-14-48e93a5cb84f -->
**首尾关系｜** 非空时 `r->next == h`；只剩一个结点时 `h->next == h`，这表示“一个数据”，不是空表。

<!-- unit-id:u-14-72f54a565ad0 -->
| 考察点 | 明确写法 |
| --- | --- |
| 只有一个数据结点 | `h != NULL && h->next == h` |
| 遍历结束 | 先判断 h 非空，从 h 开始用 do-while；处理当前结点后前进，再判断 `p != h` |
| 删除唯一结点 | 保存旧 h，令 `h=NULL`；若维护 r，同步 `r=NULL`，再释放旧结点 |
| 删除多结点表首元 | 保存旧 h，令 `h=h->next`，再令 `r->next=h`，最后释放旧首元；若没有尾指针，需先遍历找到尾结点 |

<!-- unit-id:s-14-03694c96b05b -->
#### 循环双链表：带头结点 H

<!-- unit-id:u-14-2098ef222a60 -->
**判空｜** `h->next == h`，并保持 `h->prior == h`。

<!-- unit-id:u-14-800db8bedb68 -->
**首尾关系｜** 非空时首元是 `h->next`，尾结点是 `h->prior`，尾结点的 next 指向 h，首元的 prior 指向 h。

<!-- unit-id:s-14-52082e07eea7 -->
#### 链队列：带头结点

<!-- unit-id:u-14-1da9b000eecc -->
**判空｜** `front == rear`；空时两者都指向头结点。

<!-- unit-id:u-14-8dca21b7af07 -->
**易错｜** 删除最后一个数据结点后，要执行 `rear=front`；否则 rear 会指向已释放结点。无头结点的链队列通常用 `front==NULL` 判空，不能直接混用。

<!-- unit-id:u-14-8e0f34e381d5 -->
**判满说明｜** 链表和链队列通常没有“尾指针到某处就满”的固定判满式，能否继续插入取决于结点分配是否成功；若题目设置固定容量或使用静态链表，则按题设另判。

<!-- unit-id:s-14-9b7756bc59b0 -->
#### 双链表：在 p 与旧后继 q 之间插入 s

<!-- unit-id:u-14-8ddf5c745433 -->
**操作顺序｜** 在 p 存在且 q 非空的前提下，先保存 `q=p->next`，再执行 `s->prior=p; s->next=q; q->prior=s; p->next=s;`。

<!-- unit-id:u-14-84ba2e90c337 -->
带头结点的循环双链表中 q 可以是头结点；普通非循环双链表若 q 为 NULL，应跳过 `q->prior=s` 并同步维护尾指针。

<!-- unit-id:u-14-39ecd2939b2b -->
**易错｜** 不要先覆盖 `p->next` 再通过它寻找旧后继；先保存地址，再把新结点两边接好。

<!-- unit-id:s-14-a0774726a6d4 -->
## 树、编码与并查集

<!-- unit-id:s-14-716ec3a11b4d -->
### 特殊矩阵的压缩下标

<!-- unit-id:u-14-0ece7346407d -->
**重点｜** 对称矩阵只存上三角或下三角时，先确认矩阵下标从 0 还是 1 开始、压缩数组下标从 0 还是 1 开始，以及按行还是按列存；目标落在未存储的半区，须先用 $a_{ij}=a_{ji}$ 交换行列。

<!-- unit-id:u-14-51f28fa3a8bb -->
**公式与条件｜** 以下三角按行存储、两个下标都从 0 开始为例，$a_{ij}$（$i\ge j$）的压缩下标是 $i(i+1)/2+j$，其中 $i(i+1)/2$ 是第 $i$ 行之前已有的元素数。

<!-- unit-id:u-14-211ee7eb7650 -->
$n$ 阶三对角矩阵（$n\ge2$）最多有 $3n-2$ 个非零元，首尾两行各 2 个，其余行各 3 个。

<!-- unit-id:u-14-8490e497f0f7 -->
按行优先的二维数组地址差可由 $[(\Delta i)N+\Delta j]L$ 求出，$N$ 为每行元素数，$L$ 为每元素占用字节数。

<!-- unit-id:s-14-90a8bc8ea3b8 -->
### 完全二叉树的编号与形态

<!-- unit-id:u-14-027b3babe086 -->
**重点｜** 完全二叉树按层从 1 编号时，结点 $i$ 的两个孩子候选编号是 $2i$ 与 $2i+1$，只有不超过总结点数 $n$ 才存在；最后一个非叶结点编号为 $\lfloor n/2\rfloor$，叶结点数为 $\lceil n/2\rceil$。

<!-- unit-id:u-14-007158985182 -->
因此若已知叶子数 $L$，总结点数只能是 $2L-1$ 或 $2L$。

<!-- unit-id:u-14-f22525bc00f2 -->
**易错｜** 任意非空二叉树满足 $n_0=n_2+1$，不能只对完全二叉树使用；但完全二叉树至多只有一个度为 1 的结点，且只能有左孩子。

<!-- unit-id:u-14-7f7c0df46e94 -->
只给先序或后序遍历通常无法唯一确定二叉树，需结合中序；固定入栈顺序的合法出栈序列数则为卡特兰数 $C_n=\binom{2n}{n}/(n+1)$。

<!-- unit-id:s-14-4e2be59f4d38 -->
### 树的度和叶结点数

<!-- unit-id:u-14-5e5909dce89c -->
**重点｜** “树的度为 $m$”表示至少一个结点有 $m$ 个孩子，不表示每个结点都有 $m$ 个孩子。

<!-- unit-id:u-14-ddaa714bdc51 -->
若 $n_i$ 是度为 $i$ 的结点数，则叶结点数满足 $n_0=1+\sum_{i=2}^{m}(i-1)n_i$；度为 1 的结点只延长路径，不增加叶结点数量。

<!-- unit-id:u-14-9a48a2f7650c -->
高度为 $h$ 的 $m$ 叉树最多有 $(m^h-1)/(m-1)$ 个结点（$m>1$）；讨论最少结点数时，还必须满足确实存在度为 $m$ 的结点。

<!-- unit-id:s-14-ad99f867a6ea -->
### AVL 树最少结点递推

<!-- unit-id:u-14-dbd937b18cfb -->
**重点｜** 以单个根结点高度为 1 计，高度为 $h$ 的 AVL 树最少结点数满足 $N_1=1$、$N_2=2$、$N_h=N_{h-1}+N_{h-2}+1$，前几项为 $1,2,4,7,12,20$。

<!-- unit-id:u-14-62e2a3df82ca -->
这是求“给定高度的最少结点数”或“给定结点数的最大可能高度”的边界，并不表示每棵高度为 $h$ 的 AVL 树都恰有 $N_h$ 个结点；若某个结点的左右子树高度相等，它在该处所需结点数会更多。

<!-- unit-id:s-14-275838c83433 -->
### 前缀码与哈夫曼编码

<!-- unit-id:u-14-0f01587a2ee0 -->
**重点｜** 前缀码只要求任一码字都不是另一码字的开头，不要求码字等长；等长编码必然满足前缀条件，但满足前缀条件的编码未必是给定频率下的最优哈夫曼编码。

<!-- unit-id:u-14-f9211cddd382 -->
例如 `{0,10,110,111}` 是不等长前缀码，而 `{0,1,00,11}` 不是。

<!-- unit-id:u-14-9b8eb59161e1 -->
判断新增码字是否可用时，应检查它与已有每个码字的前缀包含关系。

<!-- unit-id:s-14-12820a219d4a -->
### 并查集的 `Find`、`Union` 与复杂度

<!-- unit-id:u-14-940692bb13d2 -->
**重点｜** `Find(x)` 返回元素所属集合的代表元；根在数组中可能用负数保存集合大小，但那个负数不是 `Find` 的返回定义。

<!-- unit-id:u-14-379195f132a8 -->
`Union(x,y)` 合并的是两个完整集合，只有代表元原本不同、实际发生合并时，集合总数才减 1；重复合并同一集合不减少集合数。

<!-- unit-id:u-14-2a9a92751bdd -->
未优化的树可能退化为链，使 `Find` 最坏达到 $O(n)$；按规模合并可将树高限制在 $O(\log n)$，再配合路径压缩，均摊代价接近常数。

<!-- unit-id:u-14-79ef3a35786e -->
Kruskal 算法处理边 $(u,v)$ 时，若两端代表元相同，加入该边会形成环。

<!-- unit-id:s-14-12689f1ef707 -->
### B 树与 B+ 树的高度

<!-- unit-id:u-14-ca22ea9b2efd -->
**重点｜** 按“根所在层为第 1 层”的定义，$m$ 阶 B 树的非根内部结点至少有 $d=\lceil m/2\rceil$ 个孩子，根若不是叶结点至少有 2 个孩子。

<!-- unit-id:u-14-3f5647bb1c79 -->
**公式与条件｜** 高度为 $h$ 时，最少关键字数为 $2d^{h-1}-1$，最多为 $m^h-1$；求给定关键字数的最大高度，要让树尽量稀疏，求最小高度则让结点尽量满。

<!-- unit-id:u-14-77c7465d3866 -->
某一层有 $T$ 个非叶结点、共 $K$ 个关键字时，下一层真实孩子数为 $K+T$。

<!-- unit-id:u-14-5432d95c2b37 -->
B 树可能在内部结点找到记录而提前成功，B+ 树内部结点仅供导航，成功查找通常都要走到叶结点。

<!-- unit-id:s-14-5e4f811861ae -->
## 图的可达性、存储与遍历

<!-- unit-id:s-14-56204cf9ae44 -->
### 路径、直接边与保证连通

<!-- unit-id:u-14-9d779cbd4224 -->
**重点｜** “从 $u$ 可到达 $v$”只说明存在一条经过零个或多个中间顶点的路径，不能推出两点直接相邻。

<!-- unit-id:u-14-c33097943e64 -->
对无自环、无重边且 $n\ge2$ 的 $n$ 顶点无向简单图，构造一个连通图至少需要 $n-1$ 条边；要保证不管边如何分布都连通，则至少需要 $\binom{n-1}{2}+1$ 条边，因为非连通图最多可由一个 $K_{n-1}$ 和一个孤立顶点构成。

<!-- unit-id:u-14-be43a27ba81a -->
两种问法的量词不同，不能共用 $n-1$ 作为答案。

<!-- unit-id:s-14-ce818fe3c804 -->
### 邻接矩阵的幂与特殊存储

<!-- unit-id:u-14-685147134f49 -->
**重点｜** 对无权图的普通邻接矩阵 $A$，$(A^k)[i][j]$ 表示从 $i$ 到 $j$ 长度**恰好为** $k$ 的游走数量，元素值是“条数”，指数才是“长度”；游走允许重复顶点，因此不能直接把它解释为简单路径数。

<!-- unit-id:u-14-c7e881daf6ba -->
无向图的邻接多重表让一条边只对应一个边结点；有向图的十字链表让一条弧同时进入弧尾的出边链和弧头的入边链。

<!-- unit-id:s-14-ea1d0ef38db3 -->
### DFS、BFS 的约束

<!-- unit-id:u-14-51335058137f -->
**重点｜** DFS 在当前顶点仍有未访问邻接点时应继续深入，不能提前回溯去访问另一分支。

<!-- unit-id:u-14-2e71ef43ceff -->
BFS 按距离起点的边数逐层扩展，相邻输出的两个顶点不要求直接相邻；在无权图或所有边权相同且非负的图中，它得到的是最少边数路径，边权不同则不能据此断定总权值最小。

<!-- unit-id:u-14-97c452d308c1 -->
有向图即使无环也要记录访问状态，因为不同路径可以汇合到同一顶点。

<!-- unit-id:s-14-20f3a07d6f01 -->
### 拓扑序列与关键路径

<!-- unit-id:u-14-d113b57d5e4a -->
**重点｜** 拓扑序列中 $a$ 排在 $b$ 前，不代表一定有直接弧 $a\to b$；若按拓扑序排列 DAG 顶点，其邻接矩阵呈上三角形式。

<!-- unit-id:u-14-0175dc8469a1 -->
关键活动变长会使经过它的关键路径变长，但缩短某一条关键路径上的活动不一定缩短总工期，因为其他关键路径可能保持原长；要缩短工期，必须让所有当前关键路径都受到有效缩短。

<!-- unit-id:s-14-ca3f54d23c60 -->
## 查找、散列与排序

<!-- unit-id:s-14-6adacc9289df -->
### 折半查找与散列失败查找

<!-- unit-id:u-14-128f0434fa20 -->
**重点｜** 折半查找同时需要关键字有序和按逻辑次序随机存取；有序链表与按游标链接的静态链表都不能直接套用普通数组的二分下标。

<!-- unit-id:u-14-874b3cf90c17 -->
**易错｜** 开放定址法计算失败查找长度时，从每个可能的初始散列地址出发，探测到第一个空位置并把这次探测计入长度；题设中各初始散列地址等概率时，失败 ASL 的分母是散列函数可能产生的初始地址数，不一定等于物理表长。

<!-- unit-id:u-14-17a99cb84437 -->
例如 `H(key)=key mod 7` 只有七个可能初始地址，即使表长为 11，分母仍取 7。

<!-- unit-id:u-14-6bcecd5fb4f4 -->
线性探测可能形成主聚集；平方探测的探测序列未必覆盖全表，所以“表未满”不总能保证在该序列中找到空位。

<!-- unit-id:s-14-6cdbc7be3b49 -->
### 堆查找与快速排序的“趟”

<!-- unit-id:u-14-e23ff8de6357 -->
**重点｜** 堆只保证父结点与孩子的偏序，不保证左、右子树像二叉搜索树那样分隔关键字；查找普通关键字最坏仍需检查 $O(n)$ 个结点。

<!-- unit-id:u-14-362906958816 -->
快速排序的一次划分只保证枢轴到达最终位置，左右子表内部尚未有序；题目若把“一趟”定义为处理当前全部待排子表，则第二趟可能需要分别处理第一趟产生的两个子表，不能只划分其中一个。

<!-- unit-id:s-14-60c55809e2ef -->
### 插入、希尔和建堆的过程

<!-- unit-id:u-14-8287c8cfe489 -->
**重点｜** 折半插入排序仅减少确定插入位置所需的关键字比较，腾出位置时仍要移动元素，总时间通常仍为 $O(n^2)$。

<!-- unit-id:u-14-09f64c5571ce -->
希尔排序某个增量 $d$ 的一趟，是分别对下标相差 $d$ 的各组做插入排序；只保证各组内部有序，最后增量必须为 1。

<!-- unit-id:u-14-ef3e7e3c6c6e -->
逐个插入建堆与对完整数组自底向上建堆，可能产生不同但都合法的堆；模拟题须按指定过程作答。

<!-- unit-id:u-14-ea09abfc98fa -->
堆的调整比较次数也包含最后发现无需继续交换的比较，不能只数交换次数。

<!-- unit-id:s-14-762d3a1316df -->
### 外部排序的三种工具

<!-- unit-id:u-14-c358b7e5c455 -->
**重点｜** 普通方法在内存工作区可容纳 $M$ 条记录时，$n$ 条记录约形成 $r=\lceil n/M\rceil$ 个初始归并段，$k$ 路归并的归并趟数为 $\lceil\log_k r\rceil$；题目只问“归并趟数”时，生成初始段通常不算一趟。置换选择排序用于产生长度可变的初始段，不能独立完成外部排序；随机输入模型下，段长平均值可能接近工作区大小的两倍，但不是每段必然如此。败者树用于高效选出多路归并的当前最小记录，每输出一条后的调整为 $O(\log k)$；最佳归并树负责安排不同长度段的合并顺序，使总读写代价最小，两者用途不同。构造 $k$ 路最佳归并树时可补零权虚段，使叶子总数满足 $(n-1)\bmod(k-1)=0$，虚段不增加实际读写量。
