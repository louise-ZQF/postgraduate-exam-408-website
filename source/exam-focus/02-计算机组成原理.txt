第一章 计算机系统概述|掌握存储程序思想、软硬件层次、字长与性能指标。|辨析概念，按指令数、CPI、时钟周期计算执行时间。|主频高不必然更快，性能比较必须统一工作负载。
冯诺依曼机的特点|指令与数据存储在存储器中，由控制器按指令组织执行；掌握五大部件。|判断部件功能、结构特点和指令/数据的区别。|同一位串的含义取决于访问用途，不靠位串本身区分。
三种翻译程序|汇编把汇编语言译成机器语言；编译通常先翻译；解释逐段执行。|区分汇编、编译、解释及其输入输出。|高级语言不等于只能编译，解释程序本身也是程序。
计算机系统层次与软硬件关系|ISA 是软硬件接口；不同层次通过翻译或解释实现。|区分体系结构与具体实现，判断软硬件逻辑等价的含义。|逻辑功能等价不意味着性能、成本和实现方式相同。
三种常见字长|机器字长、指令字长、存储字长分别描述处理、指令编码、存储单元。|根据题设推数据宽度、指令占用单元与访存次数。|三个字长不必相等；地址步长还取决于按字或按字节编址。
计算机性能指标|CPU 时间=指令数×平均 CPI×时钟周期；吞吐量与响应时间分别衡量不同方面。|算加权 CPI、执行时间、加速比及性能变化。|平均 CPI 按指令比例加权；MIPS 等不能跨不同指令集直接代表性能。
第二章 数据的表示和运算|先统一字长、编码、有无符号，再讨论范围、扩展、运算和溢出。|在真值与机器数间转换，计算结果与标志位。|位串不变时，解释方式变化仍可改变数值和比较结果。
定点数的机器数转换|原码看符号与绝对值；补码负数可按取反加一或模运算转换。|给定位宽求原码、反码、补码与对应真值。|补码最小负数没有同位宽正数绝对值；不能越过范围后仍按普通数解释。
定点数的表示范围|n 位补码整数范围 −2^(n−1)～2^(n−1)−1，无符号范围 0～2^n−1。|求最大最小值、位数和编码方案的区别。|原码/反码存在正负零，补码只有一个零；定点小数范围另算。
定点数的格式转换|无符号扩展补 0，补码有符号扩展补符号位；截断只保留低位。|判断扩展前后值是否改变，分析截断与类型转换。|符号扩展不是统一补 0；截断可能改变符号和数值。
加法器与算术逻辑部件|全加器由和位、进位组成；ALU 在控制信号选择下完成算术逻辑操作。|推和位、进位、控制线作用及串行/并行进位延迟。|ALU 功能由控制选择，不把每条连线都当独立加法器。
定点数的加减法|补码加减统一为加法，减法可用被减数加减数的补码负值。|手算保留 n 位结果，求进位、借位、符号和溢出。|结果截为 n 位；位外进位与有符号溢出不是同一概念。
定点数的溢出判断|同号相加异号结果会溢出；异号相减结果符号异常可能溢出。|根据操作数和结果符号或最高两位进位求 OF。|OF 判断有符号范围，CF 判断无符号进位/借位，不能互相代替。
双符号位溢出判断|双符号位结果 00/11 正常，01 正溢出，10 负溢出。|由运算后的双符号位判断溢出方向。|最高符号位保持真实符号；两位不能只取其中一位判断溢出。
定点数的移位乘除法|乘法反复加与移位；除法反复试减、恢复或不恢复并形成商位。|逐步填写寄存器值、商/余数与运算次数。|算术右移补符号位；左移可能溢出，算法的联动移位方向按硬件模型。
乘除运算电路的基本结构|识别部分积/余数、乘除数、商寄存器、ALU 与控制计数器。|跟踪每轮数据通路，判断寄存器位宽与移位对象。|联动寄存器的移位与单独算术移位不一定相同。
一般浮点数|浮点数由符号、阶码、尾数组成；阶码决定范围，尾数有效位决定精度。|按给定阶码编码和尾数格式还原真值。|不能把所有浮点格式都按 IEEE 754 隐含位解释。
IEEE754浮点数|正规格化值=(−1)^s×(1.f)₂×2^(E−Bias)；单精度 1/8/23 位、Bias=127，双精度 1/11/52 位、Bias=1023。|编码/解码单精度双精度，辨认零、非规格化数、无穷和 NaN。|阶码全 0 不使用普通隐含 1，阶码全 1 不是普通最大规格化数。
浮点数的表示范围|规格化数上下界由有效数和阶码共同决定，另有非规格化数补充零附近范围。|求最大有限值、最小正规格化/非规格化值。|问最小正数时须分是否包含非规格化数。
浮点数的精度问题|有效位数决定可精确区分的相邻数；二进制有限小数不覆盖所有十进制有限小数。|判断整数或小数能否精确表示、求间隔与舍入结果。|位数少的整数不一定难表示；大整数若低位为 0 仍可能精确表示。
浮点数的加减法|对阶→尾数加减→规格化→舍入→检查范围。|手算对阶位移、尾数结果与最近偶数舍入。|小阶向大阶对齐；右移丢失低位，舍入进位可能再次规格化。
浮点数的溢出判断|规格化和舍入后检查阶码；上溢与下溢分别对应范围的不同端。|根据阶码变化判断结果是否仍可表示。|尾数暂时进位不等于最终上溢；先完成规格化。
大小端存储|大端低地址放高有效字节，小端低地址放低有效字节。|画连续地址中的字节排列，求某地址读取的值。|端序讨论多字节数据的字节顺序，不反转每字节内部的位。
边界对齐|数据起始地址满足对齐要求，结构体成员和总长可能有填充。|按题设对齐规则计算成员偏移、结构体大小与跨界访问。|有效数据字节数不一定等于实际占用空间。
第三章 存储系统|区分层次、映射、容量、速度、带宽与地址转换。|综合计算 Cache、主存、辅存和虚拟存储访存过程。|缓存命中、TLB 命中、页在主存是三个不同判断。
存储器分类|按介质、存取方式、读写性质与层次分别分类。|辨认寄存器、Cache、RAM、ROM、磁盘、SSD 的性质。|“随机存取”描述访问方式，不等于“随机存取存储器 RAM”的所有性质。
三级存储系统|Cache—主存解决速度差，主存—辅存支持更大逻辑空间。|比较层次作用、局部性及命中率对访问时间的影响。|更下层通常更大更慢，不能把虚拟存储容量直接当物理内存容量。
按存储介质分类|区分半导体、磁表面、光存储等介质及易失性。|根据器件性质选择正确分类。|半导体存储器不全是易失性的，Flash 属于非易失性。
按存取方式分类|随机存取访问任意单元，顺序存取依序定位，直接存取先定位区域再顺序访问。|判断 RAM、磁带、磁盘等访问方式。|存储介质分类与存取方式分类不能混成同一维度。
存储器性能指标|访问时间看一次读写延迟，存储周期看两次访问最小间隔，带宽看单位时间传输量。|给字宽和周期算带宽，比较延迟与连续传输能力。|存储周期可能长于存取时间；并行/交叉会改变持续带宽。
随机存储器 SRAM/DRAM|SRAM 用双稳态单元，DRAM 用电容电荷；都通常具有随机访问能力。|比较速度、集成度、成本、刷新与应用位置。|静态/动态不等于是否允许随机访问，也不等于是否易失。
静态随机存储器 SRAM|通常不需刷新，速度快、单位容量成本高，常用于 Cache。|判断读写单元特点与典型用途。|不刷新不代表掉电仍保留数据。
动态随机存储器 DRAM|需定时刷新，读出通常要再生，行列地址可分时复用。|计算地址引脚、刷新周期与开销，分析行缓冲访问。|逻辑地址位数与芯片地址引脚数不是一回事。
SRAM和DRAM对比|比较存储原理、刷新、集成度、速度和成本，而非只背缩写。|给性质反推器件类型或解释层次选用原因。|两者的共同易失性不能用于区分 SRAM 与 DRAM。
存储芯片的扩展|位扩展增加字宽，字扩展增加字数；片内地址与片选地址分工不同。|计算芯片片数，画片选连接并求地址范围。|总容量先统一位/字节；片选有效电平与地址译码以器件图为准。
DRAM芯片、内存条与CPU连接|芯片先组织数据宽度和容量，再由地址、片选和控制信号连接 CPU。|求芯片/内存条组织、地址线、数据线及可寻址空间。|行列地址复用影响芯片引脚，不自动缩短 CPU 逻辑地址。
多模块存储器|低位交叉让连续地址分散到不同模块，高位交叉让连续区域落在同一模块。|给模块数与周期算连续访问时间，判断模块冲突。|首字延迟与后续流水间隔分别算；题设访问模式决定交叉收益。
闪存 Flash|非易失性，可电擦写；读、编程和擦除的粒度与代价不同。|比较 Flash 与 RAM/磁盘，判断擦写约束。|不能把 Flash 当作可任意逐字节原位覆盖的 DRAM。
机械硬盘 HDD|访问通常包括寻道、旋转等待和传输；磁盘靠机械定位。|求平均访问时间、容量及地址映射。|旋转等待平均常取半圈，最坏一圈；单位须统一。
磁盘物理结构|盘面、磁道、柱面、扇区分别表示不同层次位置。|计算柱面、盘面、扇区数量与容量。|同半径不同盘面的磁道属于同一柱面，不是同一个磁道。
磁盘地址结构|地址按题设拆为柱面/盘面/扇区或逻辑块编号。|在逻辑块号与物理字段间换算，计算字段位数。|编号是否从 0 开始要确认，不能把计数值直接当最大编号。
性能指标|平均访问时间要组合定位与传输，持续传输率还取决于转速和每轨数据量。|由转速、扇区大小、磁道容量求时间或带宽。|转每分换转每秒；一次访问多个连续块时定位开销不必重复计每块。
固态硬盘 SSD|通过闪存和控制器访问，无机械寻道与旋转，仍有擦写和管理开销。|比较随机/顺序性能、寿命和写放大原因。|没有机械延迟不表示写入无代价或所有访问时间相同。
固态内部结构|页通常是读写单位，块通常是擦除单位；FTL 负责逻辑到物理映射。|解释异地写、垃圾回收与写放大。|读写粒度与擦除粒度不同，不能逐页直接擦除。
磨损均衡技术|把擦写压力分散到不同物理块以延长寿命。|区分动态/静态磨损均衡，分析数据搬移的意义。|搬移静态冷数据也可能是均衡策略，并非无用复制。
高速缓存 Cache|利用时间和空间局部性缓存主存块；硬件按地址和有效标记判断命中。|综合地址拆分、映射、替换、写策略和容量计算。|数据区容量与包括标记、状态位的实际容量不同。
Cache的基本原理|命中则从 Cache 供数，未命中按块调入；局部性解释其有效性。|求命中率和平均访问时间，判断访问串的局部性。|平均时间公式取决于是否重叠访问以及缺失代价是否含原访问时间。
Cache的映射方式|直接映射固定行，全相联任意行，组相联固定组内任选行；A 位字节地址、B 字节块、S 组：偏移 log₂B、组号 log₂S、标记 A−log₂B−log₂S（B、S 为 2 的幂）。|将主存地址拆为标记、组/行号、块内偏移，模拟落位。|组数=总行数/路数；偏移位数按块字节数及编址单位求。
Cache的比较器|组相联通常并行比较被选组内各路标记，并结合有效位。|求比较器数量、比较位宽和命中逻辑。|比较的是标记字段，不是完整地址；直接映射只选定一行。
Cache块的替换算法|LRU 看最后使用时间，FIFO 看装入顺序；替换只在映射允许的候选集合内。|给访问串模拟命中、缺失和被换块。|命中会更新 LRU 次序，通常不更新 FIFO 装入次序。
Cache的写策略|全写/写回决定命中写法；写分配/非写分配决定写未命中处理。|分析一次写访问涉及 Cache、主存和脏位哪些变化。|两组策略是两个维度；写回脏块替换时可能额外访存。
Cache的容量|实际位数=数据位+总行数×(标记位+有效位+脏位等每行状态)+必要替换信息。|由地址位数、映射和块大小算总位数或存储开销。|题目只问数据容量时不要擅加控制位；LRU 位数按具体实现。
虚拟存储器|把虚拟地址映射到主存，未驻留页触发缺页，由操作系统调入。|分清虚拟空间、物理空间、页表容量与缺页处理。|虚拟存储并非把所有虚拟页同时放入主存。
CPU访存全过程|虚拟地址先查 TLB/页表得到物理页框，必要时处理缺页，再访问相应缓存/主存。|按给定结构画命中与未命中分支，计算访问次数与时间。|TLB 未命中不等于缺页；实际 Cache 与地址转换重叠方式按题设。
段式/段页式虚拟存储器|分段用段号与段内偏移；段页式先确定段，再在段内分页。|拆地址、查表、检查越界，求最终物理地址。|段长按字节或页计要确认；段号越界与段内地址越界分别检查。
页表 Page|页表记录虚页到页框的映射及有效、保护、修改等状态。|算页表项数、页表大小和物理地址。|页内偏移不变；页表项大小由题设字段与对齐决定。
快表 TLB|TLB 缓存近期页表项，用虚页号及必要标识匹配地址转换。|求 TLB 标记、命中访问时间和未命中查表代价。|TLB 是地址转换缓存，内容不是普通 Cache 的数据块。
访存命中分析|按 TLB、页表驻留状态、Cache 的先后依赖逐层分析。|给命中率求平均时间，或判断一次访问在哪一层发生缺失。|命中率的条件概率和缺失代价定义要一致，避免重复计时。
第四章 指令系统|指令由操作码和地址/寄存器字段组织，寻址决定操作数取得方式。|编码容量、扩展操作码、有效地址与机器级程序分析。|指令地址与操作数地址是两个问题，分别看取指与执行。
指令的概念|机器指令规定一次机器级操作，由微操作序列实现。|区分指令、微指令、微操作和高级语句。|一条指令通常不等于一个时钟周期，也不等于一次访存。
指令的格式|字长分给操作码、地址字段及其他控制字段，字段位数决定编码空间。|求可编码指令数、寄存器数、地址范围与指令长度。|地址字段位数不一定等于整个机器可寻址位数，寻址方式可能扩展。
操作码扩展|短操作码留出前缀给长操作码，在字段预算内分配不同地址数指令。|计算零/一/二/三地址指令的最大数量，检验前缀冲突。|被占用的前缀不能再次作为完整短指令使用。
指令的寻址方式|顺序寻址按指令长度推进 PC，跳转则按目标地址改变取指位置。|计算下一条指令地址、跳转目标和取指位置。|PC 增量按字节/字编址与指令长度确定，不固定为 1。
数据的寻址方式|分别掌握立即、直接、间接、寄存器、寄存器间接、基址、变址和相对寻址。|写有效地址表达式，计算访存次数和最终操作数。|形式地址、有效地址、操作数三者分开；PC 相对基准通常是规定时点的 PC。
复杂精简指令集 CISC/RISC|比较指令复杂度、格式、访存方式、控制实现与流水线友好程度。|根据特征判断设计倾向和性能权衡。|RISC 不意味着程序指令总数更少，也不代表所有指令永远单周期。
程序的机器级表示|寄存器、访存、标志、分支和调用共同实现高级语言的表达式与控制结构。|把汇编与条件、循环、数组和函数调用对应。|先确认数据宽度和有无符号，再解释比较与扩展指令。
常用汇编指令|区分数据传送、算术逻辑、比较、移位与控制转移的效果。|逐条跟踪寄存器、内存和标志位。|CMP 通常更新标志而不保存减法结果；指令副作用按具体 ISA。
选择结构的机器级表示|比较设置标志，条件转移选择分支，必要时用无条件跳转越过另一分支。|根据跳转条件还原 if/else，求实际执行路径。|有符号与无符号比较使用的条件不同，不能只看结果符号。
循环结构的机器级表示|找初始化、条件、循环体、更新和回跳，明确先判断还是先执行。|还原 while/do-while/for，计算循环次数。|循环体可能修改控制变量，不能只读表面上界。
过程调用的机器级表示|调用保存返回信息，建立局部状态；返回恢复约定的现场与控制位置。|分析参数、栈帧、返回地址和调用者/被调用者保存责任。|栈增长方向和调用约定按题设，不能把某 ISA 的细节当通用规则。
第五章 中央处理器|CPU 用数据通路传送/运算数据，用控制器安排各阶段微操作。|看结构图写控制信号、时序，分析异常、中断和流水线。|一次逻辑传送不自动等于一个硬件周期。
CPU的功能和结构|取指、译码、执行、处理中断；运算器与控制器协作完成。|将功能对应到部件和执行阶段。|程序员可见寄存器与 CPU 内部暂存器并非同一集合。
CPU的组成|PC、IR、通用寄存器、ALU、控制逻辑及接口寄存器各有职责。|判断信息保存位置与所需连接。|MAR 保存地址，MDR 保存读写数据；IR 保存当前指令。
PC的位数问题|PC 表示可定位的指令地址，其位数结合编址单位和地址空间判断。|由容量、字长和编址方式求 PC 位数或地址范围。|按字编址和按字节编址的地址位数可能不同。
可见或透明的寄存器|通用寄存器、PC 等是否可见取决于 ISA；IR、MAR、MDR 通常对应用程序透明。|分类寄存器，区分体系结构状态与实现暂存状态。|某寄存器存在不代表程序可以直接用指令读写。
指令周期的数据流向|区分取指、间址、执行、中断各阶段传送的地址和数据。|按指令种类追踪 PC/MAR/MDR/IR 的变化。|不是每条指令都有间址或中断周期，访存次数随操作数位置而变。
取指周期|PC 给地址，经存储器取得指令进入 IR，并按规定推进 PC。|写寄存器传送和控制信号顺序，求取指开销。|IR 接收的是 MDR 中的指令内容，不是 MAR 的地址。
间址周期|形式地址先指向保存有效地址的位置，再取得真正操作数地址。|追踪间接寻址的额外访存与寄存器更新。|间址取得的是有效地址，通常还需另访存取操作数。
执行周期|由操作码和寻址方式完成取操作数、运算、写回或转移。|比较不同指令的微操作序列与访存次数。|寄存器运算与存储器运算的执行访存不能混算。
各周期访存对比|取指访问指令，间址取得有效地址，执行可能读写数据，中断可能保存状态。|按具体指令和硬件结构累计访存次数。|题目是否计取指、是否含间址必须明确。
数据通路的概念|数据通路是部件及传送路径的集合，控制信号决定何时由谁驱动和接收。|从目标操作反推寄存器和 ALU 的数据依赖。|有物理连接不代表可以在同一拍无条件同时使用。
数据通路的定义|沿寄存器、总线、运算部件和接口识别数据实际经过的位置。|判断某微操作是否可由给定通路实现。|数据流与控制信号是不同类型的信息。
数据通路的组成|寄存器暂存数据，ALU 运算，选择器选源，总线与连线传递结果。|解释暂存寄存器、选择器和独立增量器的作用。|单总线运算常需暂存一个操作数，不能凭空给 ALU 两个独立总线源。
数据通路的结构|单/多总线、专用通路在并行度、硬件开销和周期数间取舍。|判断哪些传送能并行，计算最少步骤。|总线冲突和结果锁存时序会限制并行。
单总线结构|同一时刻通常只有一个源驱动内部总线，可有多个目的接收。|写 Y/Z 暂存、ALU 运算和写回的逐拍控制信号。|两个源同时输出会冲突；不能把读存储器当作 MDR 从内部总线输入。
取指间址的信号序列|先建立地址并发读请求，数据有效后再送入目的寄存器。|补全 PCout、MARin、Read、MDRout、IRin 等信号。|存储器等待周期不能跳过；信号名称和可并行操作以题图为准。
单周期和多周期CPU|单周期周期长由最慢路径决定；多周期分阶段，可让不同指令用不同拍数。|比较时钟周期、CPI、总执行时间与资源复用。|CPI 小不一定快，要同时乘时钟周期。
控制器的概念|控制器根据指令、时序、状态和请求产生控制信号。|判断控制输入输出和控制实现方式。|控制器通常不直接承担 ALU 的数据运算。
控制器的输入输出|输入含操作码、节拍、条件标志及请求；输出驱动数据通路和外部读写。|按一个控制信号的产生条件写逻辑或判断阶段。|相同操作码在不同节拍下的控制输出可以不同。
控制器的分类|硬布线由逻辑电路生成控制，微程序由控制存储器中的微指令组织控制。|比较速度、设计复杂度、扩展与修改能力。|微程序控制仍依赖硬件，不是由应用软件逐条解释普通指令。
微程序控制器|微指令给出控制操作及后继微地址，微程序实现机器指令。|区分机器指令、微程序、微指令和微命令。|一条机器指令对应一段微程序，不等于一条微指令。
微程序控制的概念|通过执行控制存储器中的微指令序列产生机器级控制。|判断公共取指微程序和各指令入口的关系。|取指是公共流程仍需要微命令，不能当成没有控制的空阶段。
微程序控制器的组成|CM 存微程序，微地址寄存器定位，微指令寄存器保存当前微指令，后继地址逻辑决定下一位置。|识别图中部件，计算控制存储器容量。|微地址属于控制存储器地址，与主存指令地址不同。
微程序控制器的工作过程|取微指令、形成控制、执行微操作、确定后继，直到返回公共取指入口。|按时序跟踪一条机器指令所需的微指令。|微指令中的并行微操作仍受数据通路资源限制。
微指令地址的生成方式|后继可由顺序、下地址、操作码入口映射和条件转移生成。|计算微地址字段位数，判断分支目标。|断定方式是显式给后继，不是随意猜地址。
微指令的格式和编码方式|水平型控制字段并行性强；编码可压缩字段但需译码，互斥命令可分组。|求微指令字长、字段位数和并发能力。|同组通常互斥；不能把需同时发出的微命令编码到同一互斥字段。
异常和中断机制|异常通常源自当前指令内部事件，中断通常来自外部异步请求。|判断事件类型、响应时点和返回位置。|不能仅凭“出错/不出错”区分中断与异常。
异常和中断的概念|故障、陷阱、终止的处理与恢复语义不同，外中断与当前指令通常异步。|按事件来源、触发方式、可否恢复分类。|故障可能重执行当前指令，陷阱通常从后继继续，按具体体系结构确认。
异常和中断的响应流程|完成允许的边界、保存断点和状态、转入处理程序入口。|安排硬件响应动作，分析开关中断与特权变化。|响应时点和返回地址不是对所有事件统一取下一条。
异常和中断的处理流程|保存必要现场、识别原因、服务、恢复状态并返回。|分析哪些动作由硬件完成、哪些由处理程序完成。|保护断点与保护通用寄存器现场不是同一件事。
中断向量和中断向量表|中断类型号定位相应入口信息，表项组织按系统定义。|求向量表项地址、处理程序入口和相关访存。|向量、类型号、向量表地址、处理程序地址要分开。
多重中断和中断屏蔽|响应优先级决定先响应谁；屏蔽可决定处理中允许哪些请求打断。|根据屏蔽字推处理优先级和嵌套次序。|响应优先级不必等于处理优先级；嵌套需正确保存并恢复屏蔽状态。
指令流水线|把指令执行划成阶段，多条指令重叠推进以提高吞吐量。|画时空图、分析冒险和执行时间。|流水线主要提高吞吐量，不必缩短单条指令延迟。
指令流水线的概念|不同指令在不同阶段并行，同一指令仍按依赖顺序经过阶段。|判断流水执行与普通并行/串行的区别。|阶段划分越多并非无限加速，还受不均衡和流水寄存器开销限制。
流水线的逻辑结构|各段组合逻辑由流水寄存器分隔，时钟周期由最慢段及寄存开销约束。|计算重划分后的周期，分析级间传递。|不能仅用平均段延迟决定同步流水线周期。
流水线的指令要求|阶段组织和资源安排应支持连续流动，指令差异会引入空泡或冲突。|判断指令集或资源设计是否利于流水。|多周期指令、共享存储端口等可能打断理想流动。
流水线的性能指标|理想等长 k 段执行 n 条需 (k+n−1) 个周期；实际再加停顿/冲刷。|求执行时间、吞吐率、加速比与效率。|分清完成 n 条的总时间与稳态完成间隔。
流水线冒险和处理|结构冒险争资源，数据冒险有依赖，控制冒险来自分支改变路径。|画有转发/停顿的执行表，计算空泡与冲刷代价。|有依赖不必一定停顿；load-use 常需等待，具体按结果可用时点。
高级流水线|多发射、超流水和动态调度从不同维度提高并行度。|区分每周期发射数、流水深度和乱序执行。|多发射不代表每周期都能满发，仍受依赖和资源限制。
多处理器|多核心/多处理器可并行执行任务，需考虑通信、同步和共享数据。|分析并行加速上限，区分指令级与线程级并行。|串行部分与协调开销使加速通常低于处理器数量。
计算架构的概念|按指令流/数据流区分 SISD、SIMD、MIMD 等组织。|给计算场景匹配体系结构分类。|SIMD 不是所有处理单元各取独立指令流。
多处理器的概念|共享内存和分布式组织在地址空间与通信方式上不同。|判断共享地址、通信方式及扩展特性。|有多个处理器不代表全部访问延迟相同。
硬件多线程|通过多个线程状态切换或同拍发射隐藏停顿，区别细粒度、粗粒度与同时多线程。|判断切换时机、每周期指令来源和资源共享。|硬件线程共享执行资源，不等于为每线程复制完整核心。
向量处理器与共享内存多处理器|向量操作利用数据级并行；共享内存多处理器还需考虑一致性与同步。|区分向量运算、SIMD 与共享内存访问行为。|Cache 一致性保证副本规则，不自动保证应用程序无数据竞争。
第六章 总线|总线在共享连线上完成部件通信，需寻址、仲裁、定时和数据传输。|计算带宽与事务时间，区分不同总线层次。|标称宽度或频率单独都不能决定有效吞吐量。
总线分类|按位置、连接对象或功能分内部/系统/外部，以及地址/数据/控制。|识别总线传什么、连接什么和是否复用。|同一组线可分时复用地址与数据，但同一时刻功能不同。
系统总线|CPU、主存与 I/O 接口通过约定连接，信号方向随用途确定。|判断地址、数据和控制线的方向与宽度。|数据线常双向；不同控制信号的方向不能一概而论。
总线的性能指标|带宽=每次有效数据量×每秒传输次数，结合突发、复用和协议开销。|由宽度、频率、每拍传输次数求理论/有效带宽。|MB/s 与 Mb/s 差 8 倍；DDR 类传输次数不等于时钟频率本身。
总线事务|一次事务包括请求、仲裁、寻址、数据及结束等阶段，具体可重叠。|算单次/突发传输时间与利用率。|地址和握手开销不能在需要时遗漏，也不能每个突发数据重复计固定开销。
总线定时|同步按公共时钟，异步按握手；半同步结合时钟和等待。|分析请求/应答先后及等待状态。|异步不等于无时序约束；握手次数和信号撤销顺序按协议。
第七章 输入输出系统|由接口衔接外设，查询/中断/DMA 分配 CPU 与控制器的不同职责。|比较数据通路、CPU 介入次数和传输效率。|控制命令、状态信息、实际数据须分别追踪。
IO接口|接口提供缓冲、状态/控制、设备选择与时序转换。|识别数据/状态/控制寄存器及 CPU 访问。|I/O 接口不等于具体外部设备本体。
IO接口和系统总线的连接|地址选端口，控制说明读写，数据线传命令、状态或数据。|按接口图判片选、寄存器地址和信号作用。|地址译码与寄存器选择可分层，不能把所有地址位都接到数据寄存器。
IO端口的编址|统一编址与内存共享地址空间，独立编址使用单独端口空间及相关指令。|求可用地址范围，判断访存/I/O 指令和端口译码。|统一编址不意味着外设数据就在普通 RAM 中。
IO方式|查询轮询状态，中断按请求服务，DMA 由控制器组织批量数据搬运。|针对速度和批量要求选方式，比较 CPU 开销。|三者的“CPU 是否参与”应拆成发起、传输、结束三个阶段。
程序查询方式|CPU 反复读状态，设备就绪后由 CPU 执行数据传送。|计算轮询频率、忙等时间与 CPU 占用。|等待期间通常消耗 CPU，不等于进程阻塞让出处理器。
程序中断方式|设备就绪发请求，CPU 响应并执行服务程序传送数据。|求中断频率、服务开销和可支持数据率。|中断传送数据仍由 CPU 执行，不能当作 DMA。
DMA方式|CPU 初始化块传输，DMA 控制器在设备与内存间搬运，结束通常通知 CPU。|计算块传输时间、周期挪用开销及 CPU 介入次数。|DMA 请求取主存/总线资源；不是每字都让 CPU 运行中断服务程序。
IO方式的比较|比较发起者、状态等待、数据搬运者、结束通知和 CPU 占用。|综合计算查询/中断/DMA 的时间或效率差异。|必须统一统计范围，避免一种计初始化而另一种只计传输。
DMA控制器的组成|包含地址、计数、数据缓冲、控制/状态及请求仲裁相关部件。|跟踪每次传输地址与计数变化，判断块完成条件。|计数初值和递减结束约定按题设，不能固定写成某个数。
